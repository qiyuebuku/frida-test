# 采集质量校验策略

## 为什么需要质量校验

直接 HTTP 抓取在大部分文档站（有 SSR）都能正常工作，但 SPA 站点、反爬站点、
需要登录的站点等场景下，抓取到的内容可能是不完整或无效的。
**必须在采集后立刻校验内容质量**，在发现问题时自动回退到更强的采集方式。

## 校验维度

### 1. 内容长度检查

- **最小长度阈值**：Markdown 内容 < 500 chars 大概率是采集失败
- **API 文档页面**：通常 2000+ chars，< 800 chars 应视为可疑
- **概览/介绍页面**：可能较短，但 < 200 chars 仍然可疑

### 2. 业务内容存在性

检查提取的内容中是否包含预期的业务关键词：

- **API 文档**：应包含 `request`/`response`/`parameter`/`schema` 等关键词
- **技术文档**：应包含代码块（`` ``` ``）或技术术语
- **教程文档**：应包含步骤性内容

### 3. 模板/骨架内容检测

SPA 骨架页面的特征：
- 标题是框架默认名（如 `vitepress-openapi`、`Swagger UI`）
- 内容中有组件占位符文字（粘连的属性名如 `SchemaJSONobject`）
- 多个不同 URL 提取出高度相似的内容

### 4. 噪声比检测

检查实际文本内容占 Markdown 总长度的比例：
- 健康文档：文本占比 > 60%
- 噪声过多：导航菜单、面包屑、侧边栏等非正文内容
- meta 残留：frontmatter、HTML 属性等

## 校验流程

```
采集完成
  ↓
长度检查 → 过短 → 标记为低质量
  ↓
骨架检测 → 匹配骨架特征 → 标记为低质量
  ↓
噪声比检测 → 噪声过高 → 尝试更精确的选择器
  ↓
业务关键词检查 → 缺少预期关键词 → 标记为可疑
  ↓
通过 → 接受内容
```

**低质量内容的处理**：
1. 如果当前模式是 `direct` → 回退到 `browser`
2. 如果当前模式是 `browser` → 尝试更长的等待时间 + 点击展开
3. 如果都失败 → 报告采集失败，建议手动检查或提供 OpenAPI spec URL

## 批量采集的质量汇总

批量采集完成后，输出质量汇总报告：
```
采集完成: 25 页
  优质 (>2000 chars): 5 页
  正常 (500-2000 chars): 1 页
  可疑 (<500 chars): 19 页 ← 提示用户关注
```

当可疑页面占比 > 50% 时，应主动提醒用户考虑使用浏览器模式或检查是否为 SPA 站点。
