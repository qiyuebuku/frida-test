# 数据采集需求

本章从 **数据类型 → 渠道 → 更新频率 → 数据质量控制** 四个维度，完整定义系统需要采集的所有数据。

---

## 一、数据类型总览

针对基金交易 + 事件驱动策略，数据分为 5 大类：

| 类别 | 核心作用 | 对决策的影响 |
|------|---------|------------|
| 基础市场数据 | 计算收益、回测、仓位控制 | 交易执行的基础 |
| 新闻与事件数据 | 事件驱动的核心原料 | 决策信号的直接来源（α） |
| 资金流与验证数据 | 验证事件是否被市场认可 | 决策的"确认信号" |
| 宏观政策数据 | 确定可投方向、方向性约束 | 决策的"大前提" |
| 情绪与舆情数据 | 判断市场温度、过热/恐慌 | 风控辅助 |
| 事件反馈数据 | 回填事件发生后的市场反应 | 历史类比、策略进化 |

### α 来源优先级排序

系统各类数据对盈利的贡献度不同，开发和采集应按此优先级推进：

1. **新闻事件流 + 情绪** → 决策信号（最核心的 α 来源）
2. **板块/资金流 + 基金持仓** → 验证事件发酵（确认信号）
3. **宏观政策** → 决策方向约束（大方向对错决定上限）
4. **基础市场数据** → 执行 & 仓位控制（交易基础设施）

## 二、基础市场数据

这是系统运行的地基。没有净值就无法计算收益，没有持仓就无法将事件映射到基金。

### 2.1 基金净值

| 字段 | 类型 | 说明 |
|------|------|------|
| fund_code | string | 基金代码 |
| nav | float | 当日单位净值 |
| acc_nav | float | 累计净值 |
| nav_date | date | 净值日期 |
| change_pct | float | 日涨跌幅 |

**数据源：** 同花顺（已有）
**采集频率：** 每天收盘后（15:30）
**用途：** 计算收益、回测绩效、动态仓位因子

### 2.2 基金持仓

| 字段 | 类型 | 说明 |
|------|------|------|
| fund_code | string | 基金代码 |
| stock_code | string | 重仓股代码 |
| stock_name | string | 重仓股名称 |
| hold_pct | float | 持仓占比 |
| industry | string | 所属行业 |
| report_date | date | 报告期 |

**数据源：** 同花顺（已有）
**采集频率：** 每季度更新（基金季报发布后）、每周检查一次是否有新报告
**用途：** **关键桥梁** —— 将新闻事件通过"重仓股行业"映射到具体基金

### 2.3 指数数据

| 字段 | 类型 | 说明 |
|------|------|------|
| index_code | string | 指数代码 |
| index_name | string | 上证指数 / 沪深300 / 创业板指 / 中证500 |
| close | float | 收盘价 |
| change_pct | float | 涨跌幅 |
| volume | float | 成交量 |
| trade_date | date | 交易日期 |

**数据源：** 东方财富（已有）
**采集频率：** 盘中每 15 分钟 + 收盘后日终快照
**用途：**
- 市场状态判断（牛/熊/震荡）
- 动态仓位的市场因子：大盘趋势（收盘价 vs 5 日/20 日均线）、成交量 vs 5 日均量
- 需保留足够历史数据以计算均线（至少 20 个交易日）

### 2.4 板块指数

| 字段 | 类型 | 说明 |
|------|------|------|
| sector_code | string | 板块代码 |
| sector_name | string | 板块名称（人工智能、新能源、半导体…） |
| close | float | 收盘价 |
| change_pct | float | 当日涨跌幅 |
| change_pct_3d | float | 近 3 日累计涨跌幅 |
| change_pct_5d | float | 近 5 日累计涨跌幅 |
| volume | float | 成交额 |
| trade_date | date | 交易日期 |

**数据源：** 新浪财经（已有）
**采集频率：** 盘中每 30 分钟
**用途：**
- 判断事件影响的具体行业板块走势
- **过热过滤**：行业近 3 天涨幅 > 5% 时降低权重或不买（决策打分模型需要）
- **主线检测**：结合事件数量 + 资金流入 + 涨停数量，判断是否为当前市场主线

### 2.5 持仓股估值

| 字段 | 类型 | 说明 |
|------|------|------|
| stock_code | string | 股票代码 |
| pe_ttm | float | 市盈率（TTM） |
| pb | float | 市净率 |
| market_cap | float | 总市值 |

**数据源：**
- 实时估值：腾讯证券（已有）
- 历史估值：东方财富（已有）

**采集频率：** 每天盘后
**用途：** 基金重仓股估值分析

### 2.6 基金交易数据

已有完整实现（`ft_trades`、`ft_positions` 表），无需新增采集。

**数据源：** 天天基金（已有）
**现有能力：**
- 买入/卖出/撤单记录
- 当前持仓（成本、份额、收益率）
- 支付宝持仓快照对比

## 三、新闻与事件数据（核心 α 来源）

事件驱动系统的输入就是新闻。没有新闻采集，后续的事件抽取、事件流聚合、决策打分全部无法运行。

### 3.1 采集字段定义

**每条新闻需要保存以下字段：**

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| title | string | 标题 | "国家发改委：加快推进算力基础设施建设" |
| content | string | 正文（快讯可能为空） | 详细内容 |
| source | string | 来源标识 | "cls" / "eastmoney" / "ths" |
| source_reliability | float | 来源可靠性评分（0-1） | 官媒 0.95，自媒体 0.3 |
| category | string | 分类 | "macro" / "industry" / "policy" / "company" |
| url | string | 原文链接 | |
| tags | string[] | 原始标签 / 关键词 | ["算力", "政策"] |
| related_stocks | string[] | 关联股票代码（部分源自带） | ["688981", "002230"] |
| published_at | datetime | 原始发布时间 | 2026-03-17 09:12:00 |

### 3.2 新闻数据源

#### 财联社快讯（P0 — 最高优先级）

**选择理由：**
- A 股最快的中文财经快讯源，盘中延迟 < 1 分钟
- 内容简洁、一条快讯约等于一个事件，信号密度极高
- 自带分类标签（宏观、行业、公司、要闻）
- 有公开可用的 H5 接口

**接口信息：**
- 地址：`https://www.cls.cn/nodeapi/updateTelegraph`
- 方法：GET
- 参数：`rn=20`（条数）、`channel=`（频道）、`category=`（分类）
- 返回格式：JSON，包含 `data.roll_data[]` 数组
- 无需认证

**采集内容：** 快讯标题 + 摘要、发布时间、标签、关联股票/板块
**采集频率：** 盘中每 3 分钟，盘后每小时
**预期数据量：** 日均 200-400 条

---

#### 东方财富资讯（P1）

**选择理由：**
- 覆盖面最广（个股、行业、宏观全有）
- 数据结构化程度高
- 接口稳定

**采集内容：** 财经要闻、行业资讯、公司公告
**采集频率：** 盘中每 15 分钟

---

#### 同花顺资讯（P2）

**选择理由：**
- 已有同花顺新闻采集接口（头条、快讯、新闻 feed 等）

**采集内容：** 基金相关新闻、行业动态
**采集频率：** 每 30 分钟

---

### 3.3 专业分析数据

#### 券商研报摘要（P2）

| 字段 | 类型 | 说明 |
|------|------|------|
| title | string | 研报标题 |
| broker | string | 券商名称 |
| analyst | string | 分析师 |
| industry | string | 研究行业 |
| rating | string | 评级（买入/增持/中性/减持） |
| summary | string | 核心观点摘要 |

**数据源：** 东方财富研报中心 / 同花顺研报（待实现，需新增采集接口）
**采集频率：** 每天 2 次（9:00, 18:00）
**用途：** 专业机构观点可增强事件的 `certainty` 评分

---

### 3.4 去重策略

新闻最大的问题是**重复**。同一条消息会被多个平台转发，措辞略有不同。

**去重规则：**
1. **精确去重**：`fingerprint = SHA256(title + source)`，数据库 UNIQUE 约束
2. **跨源近似去重**（Phase 2）：同一天内，title 相似度 > 0.85 的视为重复，保留最早的一条

## 四、宏观政策数据

### 为什么单独列为一类

对基金来说，**政策 + 宏观环境决定了"可投方向"，事件只是局部 alpha**。一条国务院政策可以让整个板块涨停（如"双碳"之于新能源，"东数西算"之于算力）。

### 4.1 政策公告

| 字段 | 类型 | 说明 |
|------|------|------|
| title | string | 公告标题 |
| content | string | 正文或前 500 字摘要 |
| source | string | "gov" / "csrc" / "ndrc" / "miit" / "pboc" |
| level | string | 国务院 / 部委 / 地方 |
| url | string | 原文链接 |
| published_at | datetime | 发布日期 |

#### 中国政府网（P0）

- **内容：** 国务院常务会议决定、国务院政策文件、部委联合发文
- **来源：** `www.gov.cn/zhengce/zuixin.htm`
- **频率：** 每天 3 次（9:00, 12:00, 18:00）

#### 证监会（P0）

- **内容：** 新闻发布会通稿、监管政策、行政处罚
- **来源：** `www.csrc.gov.cn/csrc/c100028/common_list.shtml`
- **频率：** 每天 3 次

#### 发改委（P1）

- **内容：** 产业政策（新能源、AI、半导体）、价格政策、重大项目审批
- **来源：** `www.ndrc.gov.cn/xwdt/xwfb/`
- **频率：** 每天 2 次

#### 工信部（P2）

- **内容：** 行业规划、技术标准、产业扶持
- **频率：** 每天 1 次

#### 人民银行（P1）

- **内容：** 利率决议、货币政策报告、公开市场操作
- **频率：** 每天 2 次

**特殊处理：**
- 正文太长时只存标题 + 前 500 字摘要，原文通过 URL 按需获取
- 国务院级 vs 地方通知影响天差地别，必须在 `level` 字段区分
- 部分政策发布时间晚于实际决定时间，注意时间差

### 4.2 宏观经济指标

| 指标 | 频率 | 来源 | 状态 | 对基金的影响 |
|------|------|------|------|------------|
| CPI / PPI | 月度 | 国家统计局 | 待实现 | 通胀预期 → 影响消费/周期基金 |
| M2 货币供应量 | 月度 | 人民银行 | 待实现 | 流动性信号 → 影响整体仓位 |
| LPR 利率 | 月度 | 人民银行 | 已有 | 利率方向 → 影响债基/银行基金 |
| Shibor | 日度 | 人民银行 | 已有 | 短期流动性 |
| PMI | 月度 | 国家统计局 | 待实现 | 经济景气度 → 影响周期/成长基金配比 |
| 社融数据 | 月度 | 人民银行 | 待实现 | 信用环境 → 影响整体风险偏好 |
| 美联储利率决议 | 约 6 周一次 | Federal Reserve | 待实现 | 影响 QDII 基金、北向资金方向 |
| 美国 CPI / 非农 | 月度 | BLS | 待实现 | 影响全球风险偏好 |
| USD/CNY 汇率 | 日度 | CFETS | 已有 | 影响外资流向和 QDII |

**采集方式：** 这些指标更新频率低（月度/季度），可通过东方财富宏观数据页或专业数据源获取
**采集频率：** 每天 1 次检查是否有新数据发布
**存储：** 统一存入 `ft_macro_indicators` 表

## 五、资金流与验证数据

新闻告诉你"发生了什么"，资金流告诉你"市场怎么看"。一个利好消息如果没有资金跟进，说明市场不认可，不应该交易。

### 5.1 北向资金（沪深港通）

北向资金被称为"聪明钱"，其流入/流出方向对 A 股短期走势有显著参考价值。

| 字段 | 类型 | 说明 |
|------|------|------|
| trade_date | date | 交易日期 |
| net_flow | float | 净流入金额（亿元，正为流入） |
| sh_flow | float | 沪股通净流入 |
| sz_flow | float | 深股通净流入 |
| captured_at | datetime | 采集时间点 |

**数据源：** 东方财富（已有）
**采集频率：** 盘中每 10 分钟
**关键信号：**
- 单日净流入 > 100 亿 → 强烈看多信号
- 连续 3 日净流出 → 警惕回调

### 5.2 板块资金流向

| 字段 | 类型 | 说明 |
|------|------|------|
| sector_name | string | 板块名称（如"人工智能"、"新能源"） |
| net_flow | float | 净流入金额（亿元） |
| change_pct | float | 板块涨跌幅 |
| leading_stock | string | 领涨股 |

**数据源：** 东方财富（已有）
**采集频率：** 盘中每 30 分钟
**用途：** 与事件的 `entities.industries` 交叉验证 —— 如果事件利好 AI 板块，而 AI 板块确实在流入资金，则信号增强

### 5.3 主力资金净流入（按行业）

### 5.4 基金申购赎回数据

### 5.5 个股涨跌幅 & 成交量

## 六、情绪与舆情数据

情绪数据反映市场的"温度"。当一个板块被过度讨论、情绪过热时，往往是风险信号而非机会。

### 6.1 股吧热度

|------|------|------|
| topic | string | 热议话题 / 板块 |
| heat_score | int | 热度值 |
| post_count | int | 帖子数量 |
| sentiment | string | 整体情绪（偏多/偏空/中性） |

**数据源：** 东方财富股吧
**采集频率：** 盘中每 30 分钟

### 6.2 社交媒体舆情

| 平台 | 采集内容 | 优先级 | 采集方式 |
|------|---------|--------|---------|
| 雪球 | 热帖、话题讨论、大V观点 | P1 | 话题页接口 |
| 微博财经 | 财经超话、热搜相关 | P2 | 热搜 API |
| 微信公众号 | 头部财经号文章 | P3 | 搜狗微信搜索 |

**采集频率：** 每 30 分钟（盘中）
**用途：** 市场情绪异常检测、事件发酵验证

### 6.3 涨停/跌停统计

| 字段 | 类型 | 说明 |
|------|------|------|
| limit_up_count | int | 涨停家数 |
| limit_down_count | int | 跌停家数 |

| trade_date | date | 交易日期 |

**数据源：** 同花顺（已有）
**采集频率：** 盘后 1 次（15:10）
**用途：**

### 6.4 搜索热度（P3，可选）

- 同花顺"问财"热搜关键词
- 百度指数财经类关键词

### 6.5 大宗交易 / 机构动向（P3，可选）

- 大宗交易溢价/折价数据
- 机构调研记录
- 如果可获取，对判断机构态度有帮助

## 七、事件反馈数据

事件抽取后并非结束——系统还需要**回填事件发生后的市场反应**，形成闭环。这类数据是策略进化和历史类比交易的基础。

### 7.1 事件市场反应（回填采集）

事件入库后，需要在 T+1、T+3 回填对应行业板块的市场反应数据。

| 字段 | 类型 | 说明 |
|------|------|------|
| event_id | int | 关联的事件 ID |
| sector_change_1d | float | 对应板块 T+1 涨跌幅 |
| sector_change_3d | float | 对应板块 T+3 涨跌幅 |
| sector_volume_change | float | 对应板块成交量变化（相对均量） |
| north_flow_1d | float | T+1 北向资金净流入 |
| reaction_delay_minutes | int | 市场反应延迟（事件发布到板块明显波动的时间差） |

**采集方式：** 不是实时采集，而是**定时回填任务**——每天盘后扫描近 3 天的事件，回填市场反应字段
**采集频率：** 每天盘后 1 次（15:30）
**用途：**
- **判断消息是否已被市场消化**：如果事件发布时板块已涨 3%+，说明信息已 price-in
- **历史类比交易**：找到相似历史事件后，查看当时的市场反应来预判当前事件的可能走向
- **策略复盘**：评估事件抽取的准确性——高 strength 事件是否确实带动了板块上涨

### 7.2 事件流衰退监控

买入基金后，需要持续追踪关联事件流的发酵/衰退状态，作为**事件失效止损**的数据依据。

需要持续监控的指标：

| 监控维度 | 具体指标 | 衰退信号 |
|---------|---------|---------|
| 新闻密度 | 该行业近 24h 新增新闻条数 | 新增 < 3 条/天 |
| 资金方向 | 该行业板块资金净流入 | 连续 2 天净流出 |
| 情绪变化 | 该行业相关舆情情绪分 | 情绪从正转中性/负 |
| 事件流 momentum | EventStream 的 trend.momentum | 从 increasing 变为 decreasing |

**采集方式：** 不需要新数据源，复用已有的新闻、资金流、情绪采集数据，通过**定时聚合任务**计算上述指标
**采集频率：** 每天盘后 + 盘中每小时（仅针对已持仓关联的行业）
**用途：** 当多个衰退信号同时触发时，产生"事件失效"止损信号

### 7.3 Embedding 向量数据

系统需要为事件、行业、基金生成语义向量（embedding），用于增强匹配和历史类比。

| 对象 | 输入文本 | 更新频率 | 用途 |
|------|---------|---------|------|
| 事件 | event.title + event.summary | 事件入库时实时生成 | 相似事件检索、事件聚类 |
| 行业 | 行业名称 + 关键词列表 | 行业映射表变更时 | 语义匹配（替代关键词匹配的兜底） |
| 基金 | 基金名称 + 投资方向描述 + 重仓股行业 | 基金持仓更新时 | 事件→基金直接语义匹配 |

**生成方式：** 调用 embedding API（如 OpenAI text-embedding-3-small 或本地模型）
**存储：** 向量存入 PostgreSQL（pgvector 扩展）或独立的向量表
**用途：**
- **替代关键词匹配**："算力" ≠ "AI基础设施" ≠ "数据中心"，embedding 能识别同义关系
- **历史类比**：当前事件 → 找 topK 相似历史事件 → 查看历史市场反应 → 辅助决策

## 九、数据清洗 & 质量控制

采集的原始数据不能直接使用，必须经过清洗：

### 9.1 去重

| 层级 | 方法 | 说明 |
|------|------|------|
| 同源精确去重 | `SHA256(title + source)` | 数据库 UNIQUE 约束，入库时自动去重 |
| 跨源近似去重 | title 相似度 > 0.85 | 同一天内，保留最早的一条 |
| 事件级去重 | `SHA256(event_title + 核心实体)` | 避免同一事件从不同新闻重复抽取 |

### 9.2 时间标准化

- 所有时间统一为 `Asia/Shanghai` 时区
- 不同源的时间格式统一转为 ISO 8601（`YYYY-MM-DD HH:MM:SS+08:00`）
- 区分"发布时间"和"事件发生时间"

### 9.3 分类标签标准化

不同数据源的分类体系不同，需要映射到统一标签：

```
财联社"宏观" / 东方财富"宏观经济" → category: "macro"
财联社"公司" / 东方财富"个股"     → category: "company"
财联社"行业" / 东方财富"板块"     → category: "industry"
```

### 9.4 来源可靠性评分

| 来源类型 | 可靠性基线 | 说明 |
|---------|-----------|------|
| 官媒（新华社、政府网） | 0.95 | 政策确定性极高 |
| 专业财经媒体（财联社、第一财经） | 0.85 | 快速且基本准确 |
| 券商研报 | 0.80 | 专业但有利益倾向 |
| 财经门户（东方财富、同花顺） | 0.75 | 覆盖广但质量参差 |
| 社交媒体（雪球、微博） | 0.40 | 噪音大，需交叉验证 |
| 自媒体 / 匿名来源 | 0.20 | 仅做情绪参考 |

### 9.5 映射基金

新闻/事件采集后，需要建立与基金的关联：

```
新闻 → 提取行业/公司 → 匹配基金持仓的重仓股行业 → 关联到具体基金
```

具体映射逻辑详见 `4. 事件 → 基金 映射系统.md`

## 十、数据流转关系

```
          采集层                        处理层                          消费层
  ┌─────────────────┐          ┌──────────────────┐           ┌────────────────┐
  │ 新闻快讯         │          │                  │           │                │
  │ (cls/eastmoney) │─→ft_news─→ AI 事件抽取 ─────→ ft_events─→               │
  ├─────────────────┤          │                  │           │                │
  │ 政策公告         │─→ft_news─→ AI 事件抽取 ─────→ ft_events─→  事件流聚合    │
  │ (gov/csrc/ndrc) │          │                  │           │ (EventStream)  │
  ├─────────────────┤          │                  │           │                │
  │ 券商研报 / 舆情  │─→ft_news─→ AI 事件抽取 ─────→ ft_events─→       ↓        │
  └─────────────────┘          └──────────────────┘           │                │
                                                              │  决策引擎输入   │
  ┌─────────────────┐                                         │                │
  │ 资金流向         │─→ ft_market_flow ─────────────────────→ │                │
  │ (北向/板块/主力) │                                         │                │
  ├─────────────────┤                                         │                │
  │ 情绪指标         │─→ ft_sentiment ──────────────────────→  │                │
  │ (股吧/雪球/涨停)│                                         │                │
  ├─────────────────┤                                         │                │
  │ 宏观指标         │─→ ft_macro_indicators ───────────────→  │                │
  │ (CPI/M2/利率)   │                                         │                │
  └─────────────────┘                                         │                │
                                                              │                │
  ┌─────────────────┐                                         │                │
  │ 基础市场数据     │─→ ft_cache / ft_market_cache ────────→  │                │
  │ (净值/持仓/指数) │  （已有表，复用）                         │                │
  └─────────────────┘                                         └────────────────┘
```

**关键数据流：**

1. **新闻 + 政策 + 研报 → ft_news → AI 抽取 → ft_events → ft_event_streams**
   - 主线。所有文本类信息统一进入 `ft_news`，AI 抽取出结构化事件
2. **资金流向 → ft_market_flow → 直接输入决策引擎**
   - 资金数据不经过事件抽取，直接作为决策打分的"确认信号"
3. **宏观指标 → ft_macro_indicators → 方向性约束**
   - 低频但决定"大方向"，如降息周期利好成长基金
4. **情绪指标 → 辅助风控**
   - 过热预警、恐慌检测
5. **基础市场数据 → 复用已有表 → 执行 & 仓位控制**
   - 已有完善的数据基础设施
6. **事件反馈回填 → ft_events.market_reaction → 策略进化**
   - 盘后定时回填事件的市场反应，用于历史类比和策略复盘
7. **事件流监控 → 止损信号**
   - 复用新闻密度 + 资金流 + 情绪数据，聚合计算事件流衰退指标
