## 二、核心设计：ft_raw_data（原始数据归档）

**每次客户端请求外部 API 的返回值，原样存入 `ft_raw_data`，永久保留。**

这张表同时承担两个角色：
1. **缓存**：参数相同 + 未过期 → 直接返回，不请求外部
2. **历史归档**：聚合逻辑改了 → 从历史原始数据重放，不需要重新拉取外部

```sql
CREATE TABLE ft_raw_data (
    id              BIGSERIAL PRIMARY KEY,

    -- 定位（缓存命中的 key）
    source          VARCHAR(32) NOT NULL,        -- 客户端: cls/eastmoney/ths/sina/tencent/pboc/gov/xueqiu
    method          VARCHAR(64) NOT NULL,        -- 方法名: get_telegraph/get_northbound_recent
    params_hash     VARCHAR(64) NOT NULL,        -- SHA256(规范化参数JSON)，缓存快速命中
    params          JSONB NOT NULL DEFAULT '{}', -- 完整调用参数（可读，用于回放）

    -- 数据
    data            JSONB NOT NULL,              -- 客户端方法的完整返回值（原始，不做任何清洗）
    data_count      INT DEFAULT 0,               -- 返回条数（列表型接口，方便统计）

    -- 时间
    fetched_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    expires_at      TIMESTAMPTZ,                 -- 缓存过期时间（NULL=不过期）
    api_latency_ms  INT,                         -- 外部API响应耗时（监控）

    -- 元信息（为重放和分析预留）
    source_name     VARCHAR(50) DEFAULT '',       -- 中文名: 财联社/东方财富
    data_domain     VARCHAR(32) DEFAULT '',       -- 数据领域: news/fund_flow/macro/sentiment/market
    data_frequency  VARCHAR(16) DEFAULT '',       -- 频率: realtime/minute/daily/weekly/monthly
    market          VARCHAR(16) DEFAULT '',       -- 市场: a_share/hk/us/futures/forex/fund/macro

    -- 关联信息
    related_codes   JSONB DEFAULT '[]',           -- 关联证券代码: ["sh600519","hk00700"]
    trade_date      DATE,                         -- 交易日（行情类数据）

    -- 状态
    is_success      BOOLEAN DEFAULT TRUE,         -- 失败也记录，用于监控
    error_msg       TEXT DEFAULT ''
);

-- 缓存命中（最核心的索引）
CREATE INDEX idx_raw_cache ON ft_raw_data(source, method, params_hash, fetched_at DESC);
-- 按领域+时间查历史（聚合层重放用）
CREATE INDEX idx_raw_domain_time ON ft_raw_data(data_domain, fetched_at);
-- 按关联代码查（某只股票的所有历史数据）
CREATE INDEX idx_raw_codes ON ft_raw_data USING GIN(related_codes);
-- 按交易日查（某天的所有数据快照）
CREATE INDEX idx_raw_trade_date ON ft_raw_data(trade_date) WHERE trade_date IS NOT NULL;
```

| 数据类型 | TTL | 示例接口 |
|---------|-----|---------|
| 实时行情 | 1 分钟 | `get_realtime_quotes` / `get_stock_quote` |
| 分时数据 | 5 分钟 | `get_minute_data` |
| 新闻快讯 | 5 分钟 | `get_telegraph` / `get_live_news` |
| 资金流向 | 10 分钟 | `get_northbound_recent` / `get_stock_fund_flow` |
| 板块排行 | 15 分钟 | `get_sector_ranking` / `get_sector_money_flow` |
| 股吧/舆情 | 30 分钟 | `get_guba_posts` / `get_hot_topics` |
| 宏观指标 | 1 小时 | `get_macro_cpi` / `get_currency_data` |
| 政策公告 | 1 小时 | `get_announcements` / `get_omo_announcements` |

## 三、分层职责

| 层 | 职责 | 划分维度 |
|----|------|---------|
| **客户端层** | 对接外部 API + **透明缓存 + 原始数据入库** | 按数据来源（9 个客户端） |
| **聚合层** | 定时采集 + 格式转换 + 去重 + 入库 + 查询 API + 历史重放 | 按数据类型（6 个聚合，每维度一个串行任务） |
| **知识层** | 把原始/聚合材料编译成节点、边、证据、版本、Wiki 和检索上下文，并通过 API/CLI 对外服务化 | 通用基础设施 + 领域 Adapter + KnowledgeService |
| **业务层** | 决策/风控/交易/投研问答。优先读知识层，必要时读聚合结果表 | 业务逻辑 |

### 数据流

```
定时采集：
  聚合任务(定时触发) → 串行遍历源 → [到期?]
    ├─ 未到期 → 跳过
    └─ 到期 → 客户端方法 → [缓存命中?]
                            ├─ YES → 返回缓存
                            └─ NO → 外部API → 存 ft_raw_data → 返回
              → 转换格式 → 立即写入结果表

查询 API：
  业务层 → 聚合层.query() → 读结果表 → 返回

知识编译：
  HTTP / CLI / 定时任务 → KnowledgeService
    → AdapterRegistry 选择领域 Adapter
    → Knowledge Compiler 读聚合结果表或 ft_raw_data
    → Adapter.normalize() → nodes / edges / evidence / version
    → 写入 kg_* 事实库 → 重建 Wiki / 检索索引

知识查询：
  业务层 / 事件抽取 / 投研问答
    → /api/kg/research-context 或 KnowledgeService
    → Knowledge Runtime
    → keyword + semantic + graph + wiki + chunk_read
    → 返回结构化上下文和证据

重放：
  手动触发 → 聚合层.replay(start, end) → 读 ft_raw_data → 新逻辑处理 → 返回
```

## 五、聚合层（🔜 下一阶段）

位于 `services/aggregators/`，6 个聚合服务。

```
services/aggregators/
  news.py              # 新闻事件聚合（7 源）
  fund_flow.py         # 资金流聚合（3 源）
  macro.py             # 宏观政策聚合（2 源）
  sentiment.py         # 情绪舆情聚合（4 源）
  market.py            # 基础市场数据聚合（4 源）
  event_feedback.py    # 事件反馈聚合（跨聚合计算）
```

**聚合层职责：**
- **每维度一个定时任务**：串行遍历源，到期才请求，拿到即入库，无死锁
- 调用客户端方法（客户端自动处理缓存）
- 聚合/转换/去重 → 写入结果表
- **对外提供查询 API**：业务层读结果表，不触发采集
- **支持历史重放**：从 ft_raw_data 读取历史原始数据，用新逻辑重跑

详见 [数据聚合总览](./2.%20数据聚合/1.%20总览.md)

## 六、知识层

知识层位于聚合层之后、业务层之前。它不是金融专用模块，而是通用知识基础设施：

```text
聚合结果 / 原始数据 / 事件 / 人工反馈
  -> Domain Adapter
  -> Knowledge Compiler
  -> kg_nodes / kg_edges / kg_evidence / kg_versions
  -> Wiki / 检索索引 / 图算法
  -> KnowledgeService
  -> /api/kg 或 kg CLI
  -> 业务层消费
```

第一阶段先建设通用层：

- 通用节点、边、证据、版本模型。
- 自定义领域 Adapter 协议。
- Compiler 最小闭环。
- PostgreSQL 事实库。
- keyword / graph / wiki / chunk_read 最小检索。
- 图质量治理。

第二阶段再建设 Financial KG Adapter：

- 股票、基金、行业、概念、事件、政策等实体。
- 持有、属于、影响、受益、相关等关系。
- L1/L2/L3 如何消费知识层。

知识层的关键边界：

- `kg_*` 表是知识事实源。
- Wiki、FTS、向量索引、graphify 导出都是可重建索引。
- 业务层不能绕过 Compiler 直接写 active 边。
- 金融规则只能写在 Financial KG Adapter，不能污染通用基础设施。
- API 和 CLI 不能直接操作 `kg_*` 表，只能调用 `KnowledgeService` 用例入口。
- `KnowledgeService` 通过 Adapter Registry 选择领域适配器，避免 HTTP route 写死金融逻辑。

知识层第一批对外服务能力：

| 能力 | 入口 | 用途 |
|---|---|---|
| 编译图谱 | `/api/kg/compile`、`kg compile` | 把原始/聚合材料编译为节点、边、证据 |
| 重建 Wiki | `/api/kg/rebuild-wiki`、`kg rebuild-wiki` | 从事实库生成可读知识页 |
| 重建索引 | `/api/kg/rebuild-indexes`、`kg rebuild-indexes` | 重建图邻接、证据 chunk 等可重建索引 |
| 构建上下文 | `/api/kg/research-context`、`kg query` | 给 L1/L2/L3 和投研问答提供结构化上下文 |
| 质量扫描 | `/api/kg/quality-scan`、`kg quality-scan` | 发现无证据边、冲突、弱边滥用等问题 |

详见 [知识图谱实施方案](../3.%20实施方案/4.%20知识图谱/)。

## 七、业务层

业务层（决策引擎/风控/策略）的数据获取方式：

- **语义场景**：读知识层，获取实体、关系、证据、路径、Wiki 和混合检索上下文。
- **常规数据场景**：读聚合结果表（`ft_news` / `ft_market_flow` / ...）
- **延迟敏感场景**：直接调用聚合层获取最新数据

## 八、数据库表

### 原始数据层

| 表名 | 用途 | 写入方 | 生命周期 |
|------|------|--------|---------|
| `ft_raw_data` | 所有客户端方法的原始返回值 | 客户端层（自动） | **永久保留** |

### 聚合结果层

| 表名 | 用途 | 写入方 | 生命周期 |
|------|------|--------|---------|
| `ft_news` | 新闻/快讯/公告（统一格式） | 新闻事件聚合 | 90 天（可从 raw 重建） |
| `ft_market_flow` | 资金流（北向/板块/主力） | 资金流聚合 | 180 天（可从 raw 重建） |
| `ft_macro_indicators` | 宏观经济指标 | 宏观政策聚合 | 永久 |
| `ft_sentiment` | 情绪/舆情数据 | 情绪舆情聚合 | 90 天（可从 raw 重建） |
| `ft_events` | AI 抽取的结构化事件 | 数据处理层 | 永久 |
| `ft_event_streams` | 事件流聚合 | 数据处理层 | 永久 |

> 聚合结果表的数据**随时可从 ft_raw_data 重建**。聚合逻辑改了只需重跑聚合层，不需要重新拉取外部 API。

### 知识事实层

| 表名 | 用途 | 写入方 | 生命周期 |
|------|------|--------|---------|
| `kg_nodes` | 通用实体节点 | Knowledge Compiler | 永久，支持合并/废弃 |
| `kg_edges` | 通用实体关系 | Knowledge Compiler | 永久，支持版本和失效 |
| `kg_evidence` | 事实证据 | Evidence Manager | 永久 |
| `kg_edge_evidence` | 边与证据关联 | Knowledge Compiler | 永久 |
| `kg_versions` | schema、adapter、compiler 版本 | Version Manager | 永久 |
| `kg_compilation_runs` | 编译批次记录 | Knowledge Service | 永久 |
| `kg_review_items` | 冲突、候选、高风险复核项 | Quality / Review | 按复核状态保留 |
| `kg_wiki_pages` | 可重建知识页面 | Wiki Builder | 可重建 |

> 知识事实层也必须可重建：`kg_*` 的基础事实来自 raw/聚合结果/人工反馈；Wiki、向量索引、全文索引和图算法结果都不是事实源。
