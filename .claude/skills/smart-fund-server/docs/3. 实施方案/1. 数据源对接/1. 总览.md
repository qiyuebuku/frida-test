## 🆕 2026-04-11 更新：正文抓取能力

### 背景

客户端早期只从各数据源的"列表页 API"拿数据，但列表页的 `summary`/`digest`/`intro` 字段通常是短摘要或通用描述，不适合 AI 事件抽取。

实际观察到的问题：
- **sina**：`summary` 字段经常是会议整体介绍，对同一会议的多篇文章返回相同内容
- **ths**：列表页只有 `digest`（80 字左右），无法支撑完整的事件分析
- **eastmoney**：`content` 字段包含搜索高亮标签，不干净
- **gov/pboc**：列表页完全没有正文字段

### 解决方案：详情页并发抓取

在 `BaseClient` 中新增两个通用方法：

```python
async def _fetch_article_html(self, url: str, referer: str = "") -> str:
    """抓取详情页 HTML
    - 强制桌面端 User-Agent（避免返回移动版）
    - 自动跳过 PDF/图片/二进制
    - Content-Type 只处理 html/text
    """

@staticmethod
def _extract_article_text(html: str, start_patterns: list[str]) -> str:
    """从 HTML 按 div 嵌套深度配对提取正文
    - 按多个起始正则尝试匹配正文 div（优先级）
    - 计数 <div>/</div> 深度找到配对闭标签
    - 剥离 <script>/<style> 整块
    - 去 HTML 标签，规范化空白
    - 截断"新浪声明"/"责任编辑"等尾巴
    - 限长 5000 字
    """
```

### 各源的正文抓取方法

| Client | 方法 | 起始 pattern | 实测字数 |
|--------|------|-------------|---------|
| sina | `fetch_article_content(url)` | `<div id="artibody">` 等 | 平均 1050 字，最大 3971 字 |
| ths | `fetch_article_content(url)` | `<div class="*main-text*">` 等 | 平均 184 字（快讯） |
| eastmoney | `fetch_article_content(url)` | `<div id="ContentBody">` | 平均 803 字 |
| pboc | `get_content(url)` | `<div id="zoom">` | 平均 128 字（公告精简） |
| gov | `get_content(url)` | 按部委定制规则 | 平均 4572 字（政府公告） |

每个 `get_news*` 方法支持 `with_content=True` 参数（默认开启），在拉列表后并发请求所有详情页 URL 填充 `content` 字段。

## 一、开发规范

### 客户端结构

```python
"""数据源名称 (域名)"""
from services.clients.base import BaseClient

class XxxClient(BaseClient):
    """数据源描述"""

    async def get_xxx_list(self, ...) -> list:
        """获取列表数据"""
        ...

    async def get_xxx_since(self, since_xxx: int, ...) -> list:
        """增量采集：只获取 since 之后的新数据"""
        ...
```

### 核心规则

- **必须支持增量采集**：提供 `get_xxx_since(since_xxx)` 方法，客户端不持有状态
- **必须包含 `if __name__`**：`python -m services.clients.xxx` 可直接运行验证
- **WSL2 代理**：`if __name__` 中必须清理代理环境变量
- **httpx 注意**：`BaseClient` 的 `DEFAULT_HEADERS` 带同花顺 Referer，其他数据源需覆盖 `__init__`（参考 `CLSClient`）

### 注册流程

1. `services/clients/__init__.py` — 添加 import 和 `__all__`
2. `routers/_utils.py` — 添加全局实例、`init_clients()` 初始化、`close_clients()` 关闭

### 透明缓存 + 原始数据持久化（待实现）

客户端层除了对接外部 API 外，还负责**透明缓存**和**原始数据归档**：

```
聚合层调用客户端方法（调用方式不变）
  → 客户端检查 ft_raw_data（source + method + params_hash + 未过期）
    ├─ 命中 → 直接返回缓存数据
    └─ 未命中 → 请求外部 API → 原始返回值存入 ft_raw_data → 返回
```

**对聚合层完全透明**：聚合层代码不需要任何改动，正常调客户端方法即可。

每个方法有独立的 **缓存 TTL**：

| 数据类型 | TTL | 示例 |
|---------|-----|------|
| 实时行情 | 1 分钟 | `get_realtime_quotes` |
| 新闻快讯 | 5 分钟 | `get_telegraph` |
| 资金流向 | 10 分钟 | `get_northbound_recent` |
| 宏观指标 | 1 小时 | `get_macro_cpi` |
| 基金持仓 | 24 小时 | `get_fund_positions` |

原始数据**永久保留**在 `ft_raw_data`，聚合逻辑变更时可从历史数据重放。

详见 [技术架构 — ft_raw_data](../0.%20技术架构.md#二核心设计ft_raw_data原始数据归档)
