## 一、核心设计：每维度一个 Task

### 设计理念

jettask-python 以 **task 为核心单元**：框架负责调度（何时执行）、重试、限流、监控；开发者只需在 task handler 中编写**业务逻辑**（采集什么、怎么转换、写到哪里）。

```
每个聚合维度 = 一个 @router.task handler + 一个 Schedule + 一张结果表

jettask 框架管理：
  - 定时触发（Schedule: interval / cron）
  - 消息队列（Redis）
  - 并发控制 / 限流
  - 失败重试
  - 状态监控

开发者只写：
  - task handler 内的业务逻辑
    → 遍历数据源 → 调用客户端 → 格式转换 → 去重入库
```

### 源级间隔控制

同一个维度（如新闻）有多个数据源，频率不同：

| 数据源 | 频率 | 原因 |
|--------|------|------|
| 财联社快讯 | 3 分钟 | A 股最快新闻源 |
| 东方财富资讯 | 15 分钟 | 覆盖面广 |
| 政府网站 | 3 小时 | 日更 |
| 人民银行 | 24 小时 | 每天早上发一次 |

task 被 Schedule 以最高频率触发（如新闻 = 3 分钟），handler 内部用 `_last_fetch` 控制每个源的独立间隔——这是纯业务逻辑，不是调度逻辑：

```
task 被触发（每 3 分钟）
  → 源1(cls): 上次3分钟前 → 到期 → 请求 → 入库 ft_news
  → 源2(em):  上次10分钟前，间隔要求15分钟 → 未到期 → 跳过
  → 源3(gov): 上次1小时前，间隔要求3小时 → 未到期 → 跳过
```

### 与客户端缓存的关系

| | 客户端 @cached | task 内间隔控制 |
|--|---------------|--------------|
| 粒度 | 请求级（相同参数命中） | 源级（到没到时间） |
| 控制方 | 被动（被调用时判断） | 主动（到时间才调） |
| 作用 | 防止重复请求外部 API | 控制采集节奏 |
| 是否冲突 | **不冲突，双层保护** | task 控频 + 客户端兜底 |

## 二、设计原则

| | 客户端层 | 聚合层 |
|--|---------|--------|
| 划分维度 | 按数据来源 | 按数据类型 |
| 职责 | 对接外部 API + 透明缓存 + 原始数据入库 | 采集 + 格式转换 + 去重 + 写入结果表 + 查询 API |
| 输出格式 | 各客户端自定义 | **统一格式**，面向业务层消费 |
| 写入 | ft_raw_data（原始数据） | ft_news / ft_market_flow / ...（聚合结果） |

### 核心规则

- **每个维度一个 task + 一张结果表**：避免多 task 并发写同一张表
- **task handler 就是业务逻辑**：不再包裹在类的 `tick()` 方法里
- **拿到即入库**：不等所有源完成，单个源请求成功立即写入
- **异常隔离**：单个源失败不影响其他源，记录日志继续
- **不直接对接外部 API**：只调用客户端层
- **对外提供查询 API**：业务层通过路由读取已入库的聚合结果

### 文件组织

```
src/interfaces/tasks/                  # ── 接口层：task 入口（薄层）──
  __init__.py                          # Jettask app 实例
  collection_tasks.py                  # 7 个聚合 task 入口（只调用 domain）

src/interfaces/cli/                    # ── 接口层：管理命令 ──
  schedules.py                         # Schedule 注册（cron/interval 配置）
  main.py                              # CLI 命令（materialize-sentiment 等）

src/domain/collection/services/        # ── 领域层（厚逻辑）──
  __init__.py
  base.py                              # BaseAggregator + SourceDef 基类框架
  news.py                              # 新闻聚合
  fund_flow.py                         # 资金流聚合
  macro.py                             # 宏观政策聚合
  macro_regime.py                      # MacroRegimeEngine 五维度打分
  sentiment.py                         # 情绪舆情聚合（含 L2 信号方法）
  market.py                            # 基础市场数据聚合（含 sector_kline）
```

**分层原则：task 层薄、service 层厚。** task 只是入口，真正的源定义、采集逻辑、格式转换、去重入库全部放在 `src/domain/collection/services/` 中，通过 BaseAggregator + SourceDef 框架统一管理。

> 完整重构步骤见 [系统重构实施方案](../3.%20系统重构/)。

## 三、Task 与 Service 分层

### Task 层（薄入口）

`src/interfaces/tasks/collection_tasks.py` — 只做参数定义和调用 service，保持简洁：

```python
# src/interfaces/tasks/collection_tasks.py
from jettask import TaskRouter
from src.application.services.collection_app_service import CollectionAppService

router = TaskRouter()
_collection = CollectionAppService()

@router.task(queue="collect_news", max_retries=2, retry_backoff=True)
async def collect_news():
    result = await _collection.run_aggregator("collect_news")
    return result.to_dict()

@router.task(queue="collect_fund_flow", max_retries=2, retry_backoff=True)
async def collect_fund_flow():
    result = await _collection.run_aggregator("collect_fund_flow")
    return result.to_dict()

# ... 其余 5 个 task 同理（collect_market/collect_sentiment/collect_macro/agg_event_feedback/materialize_sentiment_signal）
```

### Service 层（厚逻辑）

`src/domain/collection/services/` — 每个 service 继承 `BaseAggregator`，通过 `SOURCE_CONFIGS` 定义源，框架统一管理采集节奏、normalize、入库：

```python
# src/domain/collection/services/market.py
class MarketAggregator(BaseAggregator):
    SOURCE_CONFIGS = {
        "market_overview":    {"target_days": 0, "interval": 120, "default_mode": "incremental"},
        "market_environment": {"target_days": 0, "interval": 300, "default_mode": "incremental"},
        "global_index":       {"target_days": 0, "interval": 300, "default_mode": "incremental"},
        "futures_domestic":   {"target_days": 0, "interval": 300, "default_mode": "incremental"},
        "futures_intl":       {"target_days": 0, "interval": 300, "default_mode": "incremental"},
        "forex":              {"target_days": 0, "interval": 300, "default_mode": "incremental"},
        "sector_ranking":     {"target_days": 0, "interval": 300, "default_mode": "incremental"},
        "sector_kline":       {"target_days": 0, "interval": 900, "default_mode": "incremental"},
    }

    def _init_sources(self):
        self._sources = [
            SourceDef(name="market_overview",    fetch_fn=self._fetch_market_overview, ...),
            SourceDef(name="market_environment", fetch_fn=self._fetch_market_environment, ...),
            # ...
            SourceDef(name="sector_kline",       fetch_fn=self._fetch_sector_kline, ...),
        ]
```

### 分层对比

| | Task 层 | Service 层 |
|--|---------|-----------|
| 文件 | `src/interfaces/tasks/collection_tasks.py` | `src/domain/collection/services/*.py` |
| 职责 | 参数定义 + 调用 app service | BaseAggregator 管理源级采集节奏、normalize、入库 |
| 代码量 | 每个 task 3-5 行 | 每个 service 200-500 行 |
| 依赖 | 只依赖 jettask + CollectionAppService | 依赖客户端层 + ORM + normalize |

## 四、Schedule 注册（纯配置）

```python
from jettask import Schedule

# 每个维度一个 Schedule，配置触发频率
app.schedule_register([
    Schedule(name="collect_news_3min",       queue="collect_news",
             interval_seconds=180),                           # 新闻：每 3 分钟
    Schedule(name="collect_fund_flow_5min",  queue="collect_fund_flow",
             interval_seconds=300),                           # 资金流：每 5 分钟
    Schedule(name="collect_market_1min",     queue="collect_market",
             interval_seconds=60),                            # 市场：每 1 分钟
    Schedule(name="collect_sentiment_15min", queue="collect_sentiment",
             interval_seconds=900),                           # 情绪：每 15 分钟
    Schedule(name="collect_macro_1h",        queue="collect_macro",
             interval_seconds=3600),                          # 宏观：每 1 小时
```

### 5. 注册 Schedule

```bash

```

### 6. 启动服务

```bash
# 1. Worker — 消费队列，执行 task handler
python -m jettask worker start -a tasks:app \
    -t collect_news,collect_fund_flow,collect_macro,collect_sentiment,collect_market,agg_event_feedback \
    -c 1

# 2. Scheduler — 按 Schedule 配置定时发消息到队列
python -m jettask scheduler start -a tasks:app --db-url postgresql://...

# 3. Persist — 任务记录持久化（生产建议开启）
python -m jettask persist start -a tasks:app --db-url postgresql://...
```

> **并发数 `-c 1`**：每个聚合 task 串行写一张表，无需并发。如需并发可按队列拆分 Worker。

## 十一、去重策略

| 层级 | 方法 | 实现位置 |
|------|------|---------|
| 同源精确去重 | `SHA256(title + source)` | 数据库 UNIQUE 约束 |
| 跨源近似去重 | 同一天内 title 相似度 > 0.85 | task handler 内 |
| 事件级去重 | `SHA256(event_title + 核心实体)` | 数据处理层（AI 抽取后） |

## 十二、错误处理

两层错误隔离：service 层隔离单个源，框架层兜底整个 task：

| 层级 | 机制 | 效果 |
|------|------|------|
| 源级（service 内） | `try/except` 包裹每个源 | 单源失败不中断，下次重试该源 |
| task 级（框架） | `max_retries` + 指数退避 | 整个 task 异常时自动重试 |
| Worker 级（框架） | 崩溃后消息自动回队列 | 不丢失任务 |

```python
# tasks 层：配置重试策略
@router.task(queue="collect_news", max_retries=3, retry_backoff=30)
async def collect_news():
    await news.run()    # 源级异常在 service 内部已隔离

# service 层：隔离单个源的失败
async def run():
    for name, fetch_fn, interval, normalize_fn in SOURCES:

            ...
        except Exception as e:
            logger.warning(f"[{name}] 失败: {e}")

```
