# 数据聚合总览

聚合层位于客户端层之上，按**数据类型**（而非数据来源）组织。每个聚合维度对应一个 jettask task，负责从多个数据源采集数据、统一格式、去重后入库，同时对外提供查询 API。

**技术框架：** [jettask-python](pip install jettask-python)（Rust 底层，高性能分布式任务队列）
**参考文档：** `/home/yuyang/easy-task/backend/jettask-rs/docs/index.md`

**前置依赖：**
- 客户端层 ✅ 已完成（9 个客户端、150+ 方法）
- ft_raw_data 表 + 客户端缓存机制 ✅ 已完成

## 一、核心设计：每维度一个 Task

### 设计理念

jettask-python 以 **task 为核心单元**：框架负责调度（何时执行）、重试、限流、监控；开发者只需在 task handler 中编写**业务逻辑**（采集什么、怎么转换、写到哪里）。

```
每个聚合维度 = 一个 @router.task handler + 一个 Schedule + 一张结果表

jettask 框架管理：
  - 定时触发（Schedule: interval / cron）
  - 消息队列（Redis）
  - 并发控制 / 限流
  - 失败重试
  - 状态监控

开发者只写：
  - task handler 内的业务逻辑
    → 遍历数据源 → 调用客户端 → 格式转换 → 去重入库
```

### 源级间隔控制

同一个维度（如新闻）有多个数据源，频率不同：

| 数据源 | 频率 | 原因 |
|--------|------|------|
| 财联社快讯 | 3 分钟 | A 股最快新闻源 |
| 东方财富资讯 | 15 分钟 | 覆盖面广 |
| 政府网站 | 3 小时 | 日更 |
| 人民银行 | 24 小时 | 每天早上发一次 |

task 被 Schedule 以最高频率触发（如新闻 = 3 分钟），handler 内部用 `_last_fetch` 控制每个源的独立间隔——这是纯业务逻辑，不是调度逻辑：

```
task 被触发（每 3 分钟）
  → 源1(cls): 上次3分钟前 → 到期 → 请求 → 入库 ft_news
  → 源2(em):  上次10分钟前，间隔要求15分钟 → 未到期 → 跳过
  → 源3(gov): 上次1小时前，间隔要求3小时 → 未到期 → 跳过
```

### 与客户端缓存的关系

| | 客户端 @cached | task 内间隔控制 |
|--|---------------|--------------|
| 粒度 | 请求级（相同参数命中） | 源级（到没到时间） |
| 控制方 | 被动（被调用时判断） | 主动（到时间才调） |
| 作用 | 防止重复请求外部 API | 控制采集节奏 |
| 是否冲突 | **不冲突，双层保护** | task 控频 + 客户端兜底 |

## 二、设计原则

| | 客户端层 | 聚合层 |
|--|---------|--------|
| 划分维度 | 按数据来源 | 按数据类型 |
| 职责 | 对接外部 API + 透明缓存 + 原始数据入库 | 采集 + 格式转换 + 去重 + 写入结果表 + 查询 API |
| 输出格式 | 各客户端自定义 | **统一格式**，面向业务层消费 |
| 写入 | ft_raw_data（原始数据） | ft_news / ft_market_flow / ...（聚合结果） |

### 核心规则

- **每个维度一个 task + 一张结果表**：避免多 task 并发写同一张表
- **task handler 就是业务逻辑**：不再包裹在类的 `tick()` 方法里
- **拿到即入库**：不等所有源完成，单个源请求成功立即写入
- **异常隔离**：单个源失败不影响其他源，记录日志继续
- **不直接对接外部 API**：只调用客户端层
- **对外提供查询 API**：业务层通过路由读取已入库的聚合结果

### 文件组织

```
src/interfaces/tasks/                  # ── 接口层：task 入口（薄层）──
  __init__.py                          # Jettask app 实例
  aggregator_tasks.py                  # 6 个聚合 task 入口（只调用 domain）

src/interfaces/cli/                    # ── 接口层：管理命令 ──
  register_schedules.py                # Schedule 注册（一次性管理操作）

src/domain/aggregation/                # ── 领域层（厚逻辑）──
  __init__.py
  news.py                              # 新闻聚合（源定义、采集、转换、入库）
  fund_flow.py                         # 资金流聚合
  macro.py                             # 宏观政策聚合
  sentiment.py                         # 情绪舆情聚合
  market.py                            # 基础市场数据聚合
  event_feedback.py                    # 事件反馈聚合
  helpers.py                           # 通用工具（源级间隔控制、去重、入库）
  normalize.py                         # 各源的格式转换函数
```

**分层原则：task 层薄、service 层厚。** task 只是入口，防止 task 文件膨胀；真正的源定义、采集逻辑、格式转换、去重入库全部放在 `src/domain/aggregation/` 中。

### Service 层（厚逻辑）

`src/domain/aggregation/news.py` — 源定义、采集、转换、去重、入库全在这里：

```python
# src/domain/aggregation/news.py
from src.domain.aggregation.helpers import should_fetch, mark_fetched
from src.domain.aggregation.normalize import normalize_cls, normalize_em, ...

SOURCES = [
    # (名称, 客户端方法, 间隔秒数, normalize函数)
    ("cls",      cls.get_telegraph_since,    180,   normalize_cls),    # 3 分钟
    ("em_news",  em.get_news_by_keyword_since, 900, normalize_em),    # 15 分钟
    ("gov",      gov.get_announcements_since, 10800, normalize_gov),  # 3 小时
    ("pboc_omo", pboc.get_omo_announcements_since, 86400, normalize_pboc),
    ("ths",      ths.get_news,               1800,  normalize_ths),   # 30 分钟
    ("sina",     sina.get_news,              3600,  normalize_sina),  # 1 小时
    ("xueqiu",   xueqiu.get_live_news_since, 1800,  normalize_xq),   # 30 分钟
]


async def run():
    """串行遍历所有源，到期的采集+转换+入库"""
    for name, fetch_fn, interval, normalize_fn in SOURCES:
        if not should_fetch(name, interval):
            continue
        try:
            raw_items = await fetch_fn(get_checkpoint(name))
            if not raw_items:
                mark_fetched(name)
                continue
            items = normalize_fn(raw_items)
            saved = save_to_ft_news(items)     # 拿到即入库
            mark_fetched(name)
            logger.info(f"[{name}] 采集 {len(raw_items)} 条，入库 {saved} 条")
        except Exception as e:
            logger.warning(f"[{name}] 采集失败: {e}")
            # 不 mark_fetched → 下次继续尝试
```

### 分层对比

| | Task 层 | Service 层 |
|--|---------|-----------|
| 文件 | `src/interfaces/tasks/aggregator_tasks.py` | `src/domain/aggregation/*.py` |
| 职责 | 参数定义 + 调用 service | 源定义、采集、转换、去重、入库 |
| 代码量 | 每个 task 3-5 行 | 每个 service 100-300 行 |
| 依赖 | 只依赖 jettask + service | 依赖客户端层 + DB + normalize |

from jettask import Schedule

app.schedule_register([
    Schedule(name="agg_news_3min",       queue="agg_news",
             interval_seconds=180),                           # 新闻：每 3 分钟

             interval_seconds=300),                           # 资金流：每 5 分钟

## 十一、去重策略

| 层级 | 方法 | 实现位置 |
|------|------|---------|
| 同源精确去重 | `SHA256(title + source)` | 数据库 UNIQUE 约束 |
| 跨源近似去重 | 同一天内 title 相似度 > 0.85 | task handler 内 |
| 事件级去重 | `SHA256(event_title + 核心实体)` | 数据处理层（AI 抽取后） |

## 十二、错误处理

两层错误隔离：service 层隔离单个源，框架层兜底整个 task：

| 层级 | 机制 | 效果 |
|------|------|------|
| 源级（service 内） | `try/except` 包裹每个源 | 单源失败不中断，下次重试该源 |
| task 级（框架） | `max_retries` + 指数退避 | 整个 task 异常时自动重试 |
| Worker 级（框架） | 崩溃后消息自动回队列 | 不丢失任务 |

```python
# tasks 层：配置重试策略
@router.task(queue="agg_news", max_retries=3, retry_backoff=30)
async def agg_news():
    await news.run()    # 源级异常在 service 内部已隔离

# service 层：隔离单个源的失败
async def run():
    for name, fetch_fn, interval, normalize_fn in SOURCES:
        try:
            ...
        except Exception as e:
            logger.warning(f"[{name}] 失败: {e}")
            # 不 mark_fetched → 下次继续尝试
```
