# 待优化整改方案（✅ 已完成 2026-04-15）

## 1. 需求分析

### 核心需求拆解

1. **项1 — guba_posts watchlist 维度**：在 `_fetch_watchlist_data` 中，按自选标的代码逐个采集股吧帖子，写入 `ft_watchlist_data`（区别于 `sentiment.py` 中已有的全市场 `guba_posts`，那个写 `ft_sentiment`）。
2. **项1 — research watchlist 维度**：在 `_fetch_watchlist_data` 中采集全市场研报，以 `code='_market'` 写入 `ft_watchlist_data`。
3. **项2 — flow_trend_summary 文档补录**：在 `3. 资金流聚合.md` 的维度表中补充 `flow_trend_summary` 行。

### 边界条件和约束

- `ft_watchlist_data` 有唯一约束 `(code, data_type, trade_date)`，同一标的同一天只能有一条记录。
- `guba_posts` 的 Eastmoney API 要求**纯数字代码**（`600036`），不能带 `sh`/`sz` 前缀；基金代码（`007380`、`159915`）本身已是纯数字，无需剥离。
- `em_client` 是 `_fetch_watchlist_data` 的可选参数，所有使用处必须 `if em_client:` 守卫。
- 两个新维度均为低频（`collect_low` 时才采集），符合已有分级策略。
- `research` 是全市场数据，不按个股代码区分，存为 `code='_market'`，写入现有 `_market` 段落。

### 复杂度判定：**中等**

原因：涉及 1 个核心文件（`fund_flow.py`）的两处独立改动 + 1 个文档更新，无 ORM/表结构变更，每处改动可独立验收。

---

## 2. 技术方案

### 整体设计

**guba_posts（watchlist 级）**：
- 加入 fund 类型的低频 `dim_tasks` 和 stock 类型的低频 `stock_tasks`，调用 `em_client.get_guba_posts(pure_code)`。
- 返回格式 `{"status_code": 0, "data": {"code": "600036", "count": N, "posts": [...]}}` — 标准提取后 `data = {"code": ..., "count": ..., "posts": [...]}` 是非空 dict，**必须在 `_expand_timeseries` 新增专用分支**过滤空 posts（`posts=[]` 时 dict 非空，会被兜底路径误存）。
- 每只标的每天一条快照，`trade_date = today`。

**research（market 级）**：
- 在 `_market` 段落中，加入 `em_client.get_research_reports_since(since)` 或 `get_research_reports(page_size=50)`。
- 存储格式：`code='_market', data_type='research', trade_date=today, data={"count": N, "reports": [...]}`（每天一行快照，不按 `publishDate` 逐条展开）。
- 不走 `_expand_timeseries`，inline 包装数据，和 `global_index`/`forex` 保持一致。

### 关键技术选型

- **_expand_timeseries 新增 guba_posts 分支**（不走兜底）：放在末尾快照兜底之前，过滤 `posts=[]`。
- **research 不经 _expand_timeseries**：在 `_market` 段落 inline 处理，和 `global_index`/`forex` 一致。
- **代码前缀剥离**：统一用 `code[2:] if code[:2] in ("sh","sz","bj") else code`（与 `sentiment.py` L169 保持一致）。

## 7. 风险与注意事项

1. **guba_posts SSR HTML 解析稳定性**：`get_guba_posts` 是 HTML 解析，页面结构变化会导致解析失败。失败被 `gather(return_exceptions=True)` 捕获为 debug 日志，不影响其他维度。

2. **基金代码的股吧可访问性**：OTC 基金可能无股吧页面，返回 `posts=[]`。Step 1 的 `_expand_timeseries` 专用分支过滤空 posts，不入库。

3. **research `since` 语义局限**：`get_research_reports_since` 只扫前 50 条数据做客户端过滤，`since` 较早时不会补全历史研报——P3 可接受。

4. **唯一键 upsert**：两个新维度均为今日快照，`WatchlistDataRepositoryImpl.save_batch` 已走 `ON CONFLICT DO UPDATE`，重复采集无需额外处理。

5. **并发影响**：`guba_posts` 在 `dim_tasks` 中并发执行，SSR HTML 请求比 JSON API 慢。`Semaphore(8)` 已限制标的级并发，单个超时或失败不阻塞其他维度。
