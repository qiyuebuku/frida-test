**Service：** `src/domain/aggregation/news.py`
**Task 入口：** `src/interfaces/tasks/aggregator_tasks.py` → `agg_news`（队列 `agg_news`，Schedule 每 3 分钟）
**优先级：** P0 — 决策信号的核心输入

**状态：** ✅ 已上线（含真实正文抓取）

---

## 职责

从 9 个数据源采集新闻/快讯/公告/研报，**抓取详情页真实正文**，统一格式后写入 `ft_news`。后续经 AI 事件抽取变为 `ft_events`。

这是整个系统的**核心数据管线** — 没有新闻输入，事件抽取、事件流聚合、决策打分全部无法运行。

### 关键能力

- **真实正文抓取**：所有源（除 cls/pboc 外）都会并发请求详情页 URL，用 HTML 解析提取正文
- **summary + content 双字段**：summary 是列表页摘要（短），content 是详情页正文（长，用于 AI 抽取）
- **批次内 content 去重**：相同 content 不同标题的记录只保留一条（避免 sina 编辑拆稿污染）
- **多部委并发**：政府网站采集时，`_fetch_gov_all_depts` 并发拉取 7 个部委（miit/miit_policy/ndrc/ndrc_notice/csrc/csrc_press/gov）

## 统一输出格式

所有来源的新闻统一转换为以下格式后写入 `ft_news`：

```python
{
    "title": str,                      # 标题
    "summary": str,                    # 列表页摘要（快速预览用，短）
    "content": str,                    # 真实正文（AI 事件抽取用，长，从详情页抓取）
    "source": str,                     # 来源标识: cls/eastmoney/ths/sina/xueqiu/pboc/gov/miit/ndrc/csrc/...
    "source_name": str,                # 来源中文名
    "source_reliability": float,       # 来源可靠性 0-1
    "category": str,                   # macro/industry/policy/company
    "url": str,                        # 原文链接
    "tags": list[str],                 # 关键词/标签
    "related_stocks": list[str],       # 关联股票代码（部分源自带）
    "published_at": str,               # ISO 8601 时间
    "fingerprint": str,                # SHA256(title + source) 去重指纹
}
```

### summary vs content 的设计理念

| 字段 | 用途 | 长度 | 填充方式 |
|------|------|------|---------|
| `summary` | 快速预览（列表展示、粗筛） | 20-200 字 | 列表页的 `digest`/`intro`/`abstract` 字段 |
| `content` | AI 事件抽取输入（完整信息） | 200-5000 字 | 详情页 `<div id="artibody">` 等解析 |

**为什么要双字段**：
- 列表页只有摘要时，前端展示够用（不浪费 DB 空间）
- AI 事件抽取需要完整正文（才能提取事件实体、时间、影响等）
- 如果只保留一个，要么损失展示效率，要么损失 AI 召回率

### 来源可靠性评分

| 来源 | source 标识 | 可靠性 |
|------|-----------|--------|
| 政府网站 | gov_* | 0.95 |
| 人民银行 | pboc / pboc_omo / pboc_monetary | 0.95 |
| 财联社 | cls | 0.85 |
| 东方财富 | eastmoney | 0.75 |
| 券商研报 | eastmoney_report | 0.80 |
| 同花顺 | ths | 0.75 |
| 新浪财经 | sina | 0.70 |
| 雪球 | xueqiu | 0.50 |

## 去重策略

| 层级 | 方法 | 时机 | 状态 |
|------|------|------|------|
| 同源精确去重 | `fingerprint = SHA256(title + source)` | 入库时 UNIQUE 约束 `ON CONFLICT DO NOTHING` | ✅ 已实现 |
| 批次内 content 去重 | 同 content hash 只保留第一条 | `_save()` 入库前 | ✅ 已实现 |
| 跨源近似去重 | 同一天内 title 相似度 > 0.85，保留最早一条 | 聚合层批量采集后 | 🔜 待实现 |

### 批次内 content 去重的背景

sina 编辑常把同一次发言拆成多篇不同标题的文章（如卓驭 CEO 的会议发言）。这些文章正文完全相同但标题不同，fingerprint 精确去重无法识别，会污染事件抽取的输入。

实现方式：在 `NewsAggregator._save()` 中计算每条记录的 `SHA256(content)`，已入库过的 content hash 直接跳过。

## 建表 DDL

```sql
CREATE TABLE IF NOT EXISTS ft_news (
    id              SERIAL PRIMARY KEY,
    title           TEXT NOT NULL,
    summary         TEXT DEFAULT '',        -- 列表页摘要（快速预览用，短）
    content         TEXT DEFAULT '',        -- 真实正文（AI 事件抽取用，长，从详情页抓取）

    source_name     VARCHAR(50) DEFAULT '',
    source_reliability FLOAT DEFAULT 0.5,

    url             TEXT DEFAULT '',
    tags            JSONB DEFAULT '[]',
    related_stocks  JSONB DEFAULT '[]',
    published_at    TIMESTAMPTZ NOT NULL,
    fingerprint     VARCHAR(64) NOT NULL,
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_ft_news_fingerprint ON ft_news(fingerprint);
CREATE INDEX IF NOT EXISTS idx_ft_news_source_time ON ft_news(source, published_at);
CREATE INDEX IF NOT EXISTS idx_ft_news_category ON ft_news(category, published_at);
```

## 正文抓取实现

### Client 层：通用工具

`src/infrastructure/clients/base.py` 提供两个通用方法：

```python
async def _fetch_article_html(self, url: str, referer: str = "") -> str:
    """抓取详情页 HTML
    - 强制桌面端 User-Agent（避免返回移动版）
    - 自动跳过 PDF/图片/二进制文件
    - Content-Type 检查，只处理 html/text
    """

@staticmethod
def _extract_article_text(html: str, start_patterns: list[str]) -> str:
    """从 HTML 中按 div 嵌套深度配对提取正文
    - 按起始正则匹配正文 div
    - 按 <div>/</div> 深度计数找到配对的闭标签
    - 剥离 <script>/<style> 整块内容
    - 去 HTML 标签，规范化空白
    - 截断"新浪声明"/"责任编辑"等尾巴噪音
    - 限长 5000 字
    """
```

### 各 source 的正文抓取方法

| Client | 方法 | 起始 pattern |

| sina | `fetch_article_content(url)` | `<div id="artibody">` |

### 列表页 + 正文并发抓取

每个 news client 方法都支持 `with_content=True` 参数（默认开启）：

```python
@cached(...)
async def get_news(self, num=20, with_content=True):
    # 1. 拉取列表
    raw = await self._client.get(list_url, ...)
    articles = parse_list(raw)

    # 2. 并发抓所有文章正文
    if with_content:
        urls = [a["url"] for a in articles]
        contents = await asyncio.gather(*[self.fetch_article_content(u) for u in urls])
        for article, content in zip(articles, contents):
            article["content"] = content     # 真实正文
            article["summary"] = article["intro"]  # 列表摘要保留

    return {"data": {"articles": articles}}
```

**gov 多部委并发**：

```python
async def _fetch_gov_all_depts(gov_client, checkpoint=None):
    # 第一阶段：7 个部委并发拉列表
    list_results = await asyncio.gather(*[
        gov_client.get_announcements(dept) for dept in GOV_DEPARTMENTS
    ])
    merged = merge_and_dedup_by_url(list_results)

    # 第二阶段：分批并发抓详情（每批 10 条）
    for batch in chunks(merged, 10):
        contents = await asyncio.gather(*[
            gov_client.get_content(item["url"]) for item in batch
        ])
        for item, c in zip(batch, contents):
            if c:
                item["content"] = c
    return merged
```
