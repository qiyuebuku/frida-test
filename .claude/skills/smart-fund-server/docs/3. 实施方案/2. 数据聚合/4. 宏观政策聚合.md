# 宏观政策聚合（重新设计）

## 1. 需求分析

### 1.1 核心需求拆解

**角色重定位**：宏观政策聚合在 α 优先级中排第 3（方向约束层），不产生直接买入信号，但决定仓位上限。因此该模块的产出必须**可被决策引擎直接消费**，不能停留在"收集一堆指标"层面。

因此本模块的最终价值体现在两层：
- **L1 指标层**：全面、结构化、标签化的宏观指标时序数据（ft_macro_indicators）
- **L2 信号层**：将 L1 合成为一个可乘入仓位公式的 `regime_multiplier`（ft_macro_regime）

缺失 L2，L1 就是数据仓库陈列品；只有 L2 到位，宏观模块才能真正闭合"方向约束"职责。

### 1.2 边界与约束

1. **职责边界（纠正旧方案的越界）**：
   - 本模块只负责**数值型宏观指标**与其合成出的 **regime 信号**。
   - 政策文件/新闻公告（PBOC 公告、国务院发文、证监会政策解读、FOMC 声明原文）属于**文本事件**，归 `agg_news`（ft_news）采集、归 AI 事件抽取链路处理。不在本模块重复实现。
   - 美联储利率决议的**决议值（利率数值）**进本模块；**声明文本**走 agg_news。
2. **已有基础设施必须复用**：
   - `eastmoney.get_macro_indicator(report_name, page_size)` 已是通用入口，扩 EM 指标只需加一行配置，不写新方法。
   - BaseAggregator + SourceDef + ft_collection_state 增量机制已经成熟，沿用资金流聚合模板。
   - UPSERT 统一走 `MacroRepositoryImpl.upsert_batch()`（已实现）。
3. **数据一致性**：
   - ft_macro_indicators 是 SSOT，ft_market_cache 中的 shibor/lpr/usdcny 快照允许保留（供高频查询），但不再视为冗余问题——因为二者目标不同（时序 vs 最新快照），**不清除**。
4. **海外数据现实**：代码库无 FRED/BLS/Fed 原生客户端。**本轮方案先用东方财富数据中心可覆盖的海外指标**（美国 CPI/联邦基金利率/美债收益率通常 EM 有对应 report），避免阻塞在新客户端开发。若 EM 某项缺失则记入 `9. 待优化.md`，不在本轮硬啃。
5. **ORM 约束**：所有写入必须走 Repository + `insert().on_conflict_do_update()`，不写裸 SQL。

### 1.3 复杂度判定

**复杂度：中等偏复杂（拆 5 步）**

- 不算简单：涉及新表、信号合成引擎、决策层对接；
- 不算超复杂：绝大部分代码复用现有 BaseAggregator/通用客户端/Repository 模式，无跨模块架构级改动。

## 2. 技术方案

### 2.1 整体设计

```
┌──────────────────────────────────────────────────────────────┐
│  数据采集层 (MacroAggregator)                                 │
│  ┌──────────────────────┐   ┌──────────────────────────┐    │
│  │  EM 数据中心 (扩展)   │   │  PBOC 日度 (保持)         │    │
│  │  14 个月度/季度指标    │   │  Shibor/LPR/USDCNY/OMO   │    │
│  └──────────┬───────────┘   └────────────┬─────────────┘    │
│             └────────────┬────────────────┘                  │
│                          ▼                                   │
│                ft_macro_indicators (SSOT, 时序)              │
│  每行带 dim_tag ∈ {liquidity,growth,inflation,external,policy}│
└──────────────────────────┬───────────────────────────────────┘
                           │ 读 latest_per_indicator()
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  信号合成层 (MacroRegimeEngine) — 纯规则，幂等，可重算         │
│  1. 读每个指标最新值 + 同比/环比衍生                          │
│  2. 按 dim_tag 分组，每维度计算 sub_score ∈ [-1, +1]          │
│  3. 加权求和 → overall_score ∈ [-1, +1]                       │
│  4. 映射 regime ∈ {risk_off, neutral, risk_on}                │
│  5. 映射 multiplier ∈ [0.6, 1.2]                              │
└──────────────────────────┬───────────────────────────────────┘
                           ▼
                   ft_macro_regime (快照 + 历史)
                           │
                           ▼
┌──────────────────────────────────────────────────────────────┐
│  决策引擎 (Phase 4, 本轮只做对接接口)                          │
│  base_position × winrate_factor × market_factor               │
│                       × regime_multiplier  ←                  │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 关键技术选型及理由

| 决策点 | 选型 | 理由 |
|---|---|---|
| 指标扩展入口 | 直接用 `get_macro_indicator(report_name)` 通用方法 | 已有通用方法，避免为每个指标包一层薄 wrapper |
| 指标标签 | 在 `ft_macro_indicators` 表新增 `dim_tag` 列（NULLABLE，带默认回填）| 比 "在代码里硬编码 indicator → dim 映射表" 更清晰；查询/追踪方便 |
| 信号合成 | 独立 Engine 类（`MacroRegimeEngine`），在 Aggregator 每次入库成功后触发一次 recompute | 分层清晰；Engine 幂等，可手动 CLI 重算 |
| regime 存储 | 新表 `ft_macro_regime`（每次重算 INSERT 一条）| 保留历史，便于回测验证 regime 与市场后验表现相关性 |
| multiplier 范围 | [0.6, 1.2] | 下限 0.6 = 极端逆风只留 60% 仓位（不清仓保观察），上限 1.2 = 极端顺风加 20%（不过度加杠杆） |
| 政策文本 | **不进本模块**，走 agg_news；本轮只验证 PBOC/Gov 源已在 agg_news 开启并打 `macro` 标签 | 本模块专注数值，文本事件链路已有 AI 抽取 |
| 海外指标 | 本轮只做 EM 能覆盖的（美国 CPI/联邦基金利率 EM 有对应 report）；FRED/BLS 客户端延期 | 避免阻塞；可增量迭代 |

## 3. 数据模型

### 3.1 ft_macro_indicators 扩展（仅加列，不改既有列）

```sql
ALTER TABLE ft_macro_indicators
    ADD COLUMN IF NOT EXISTS dim_tag VARCHAR(16) DEFAULT '',
    ADD COLUMN IF NOT EXISTS yoy double precision,        -- 同比 %（可空）
    ADD COLUMN IF NOT EXISTS mom double precision;        -- 环比 %（可空）

CREATE INDEX IF NOT EXISTS idx_macro_indicators_dim
    ON ft_macro_indicators(dim_tag, published_at DESC);
```

- `dim_tag` 枚举值：`liquidity` / `growth` / `inflation` / `external` / `policy`（空串表示未分类，兼容历史数据）。
- `yoy` / `mom` 由 normalize 阶段计算后写入，**空值允许**（首期无前值时）。

### 3.2 新增 ft_macro_regime

```sql
CREATE TABLE IF NOT EXISTS ft_macro_regime (
    id              SERIAL PRIMARY KEY,
    computed_at     TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    snapshot_date   DATE NOT NULL,                         -- 业务日
    regime          VARCHAR(16) NOT NULL,                  -- risk_off / neutral / risk_on
    overall_score   double precision NOT NULL,             -- [-1, 1]
    multiplier      double precision NOT NULL,             -- [0.6, 1.2]
    liquidity_score  double precision NOT NULL DEFAULT 0,
    growth_score     double precision NOT NULL DEFAULT 0,
    inflation_score  double precision NOT NULL DEFAULT 0,
    external_score   double precision NOT NULL DEFAULT 0,
    policy_score     double precision NOT NULL DEFAULT 0,
    contributors     JSONB NOT NULL DEFAULT '{}'::jsonb,   -- 指标级贡献明细（解释性）
    UNIQUE(snapshot_date)
);

CREATE INDEX IF NOT EXISTS idx_macro_regime_date
    ON ft_macro_regime(snapshot_date DESC);
```

- `UNIQUE(snapshot_date)` + UPSERT：每天一条最新态；同一天内多次重算覆盖。
- `contributors` 示例：
  ```json
  {
    "liquidity": [
      {"indicator": "m2", "value": 8.7, "yoy": 8.7, "score": 0.6, "weight": 0.40},
      {"indicator": "shibor_on", "value": 1.52, "score": 0.3, "weight": 0.30},
      {"indicator": "lpr_1y", "value": 3.10, "score": 0.2, "weight": 0.30}
    ],
    ...
  }
  ```

YoY/MoM 计算（在 normalize 末尾、数据已按 period 升序）：
```python
def _compute_yoy_mom(rows: list[dict]) -> None:
    """对同一 indicator 的升序列表回填 yoy、mom。
    - mom = (value - prev_value) / prev_value * 100（prev_value 是上一期）
    - yoy = (value - value_12m_ago) / value_12m_ago * 100（同比要去 12 期前）
    原始单位已是 % 的指标（cpi/ppi/pmi/fai）value 本身就是同比 → yoy 直接等于 value，mom 留空。
    """
    PERCENT_IS_YOY = {"cpi", "ppi", "fai"}  # pmi 是扩散指数，另行处理
    by_ind = defaultdict(list)
    for r in rows:
        by_ind[r["indicator"]].append(r)
    for ind, lst in by_ind.items():
        lst.sort(key=lambda x: x["period"])
        for i, r in enumerate(lst):
            if ind in PERCENT_IS_YOY:
                r["yoy"] = r["value"]
                r["mom"] = None
                continue
            r["mom"] = ((r["value"] - lst[i-1]["value"]) / lst[i-1]["value"] * 100) if i >= 1 and lst[i-1]["value"] else None
            r["yoy"] = ((r["value"] - lst[i-12]["value"]) / lst[i-12]["value"] * 100) if i >= 12 and lst[i-12]["value"] else None
```

**坑**：
- Model 加列后 `on_conflict_do_update` 的 `set_` 必须同步列出新列，否则 UPSERT 只更新旧列，新列永远保持默认值——**易错点 1**。
- yoy/mom 对 "本身就是同比" 的 CPI/PPI 要特判，否则重复求同比产生无意义数字——**易错点 2**。
- PMI 是扩散指数（50 为荣枯线）既不是 yoy 也不是 mom；yoy/mom 都设 None，打分时直接用 `value - 50`。

**测试用例**：

### Step 3：MacroRegimeEngine（信号合成核心）

**目标**：把 L1 指标合成为 L2 regime，每次 agg_macro 入库结束后自动 recompute 一次，写入 ft_macro_regime。

**涉及文件**：
- 新建 `src/domain/collection/services/macro_regime.py` — Engine 类
- `src/domain/collection/services/macro.py` — `_save` 成功后触发 `MacroRegimeEngine().recompute()`（静默失败不影响入库）
- `src/infrastructure/persistence/repositories/macro_repository_impl.py` — `upsert_regime` / `get_current_regime`

**实现要点（核心算法，必须这样写）**：

```python
# macro_regime.py
class MacroRegimeEngine:
    # 维度权重（合计 = 1.0）
    DIM_WEIGHTS = {
        "liquidity": 0.30,
        "growth":    0.25,
        "inflation": 0.15,
        "external":  0.15,
        "policy":    0.15,
    }

    # 每指标的打分规则：(indicator, weight_within_dim, scoring_fn)
    # scoring_fn 输入最新 row（含 value/yoy/mom/prev_value），输出 [-1, +1]
    RULES = {
        "liquidity": [
            ("m2",             0.25, lambda r: clip((r["yoy"] - 8) / 3)),          # m2 yoy 8% 基准，>11%→+1
            ("social_finance", 0.20, lambda r: clip((r["yoy"] - 9) / 3)),
            ("rmb_loan",       0.15, lambda r: clip(r["mom"] / 10) if r["mom"] else 0),
            ("shibor_on",      0.15, lambda r: clip((2.0 - r["value"]) / 1.0)),   # 利率越低越宽松
            ("lpr_1y",         0.10, lambda r: clip((3.45 - r["value"]) / 0.5)),  # 基准 3.45
            ("omo_net",        0.15, lambda r: clip(r["value"] / 3000)),          # 净投放 3000 亿 →+1
        ],
        "growth": [
            ("pmi",            0.30, lambda r: clip((r["value"] - 50) / 2)),      # 荣枯线
            ("gdp",            0.20, lambda r: clip((r["yoy"] - 5) / 2)),
            ("industry_added", 0.20, lambda r: clip((r["yoy"] - 4) / 3)),
            ("retail_sales",   0.15, lambda r: clip((r["yoy"] - 5) / 3)),
            ("fai",            0.15, lambda r: clip((r["yoy"] - 4) / 3)),
        ],
        "inflation": [
            # 通胀"适中"得分高：CPI 2%、PPI 0% 附近为佳，过高/过低都减分（倒 U）
            ("cpi",            0.50, lambda r: clip(1 - abs(r["yoy"] - 2.0) / 3)),
            ("ppi",            0.50, lambda r: clip(1 - abs(r["yoy"]) / 5)),
        ],
        "external": [
            ("usdcny",         0.40, lambda r: clip((7.3 - r["value"]) / 0.2)),   # 人民币越强越好
            ("forex_reserve",  0.25, lambda r: clip(r["mom"] / 2) if r["mom"] else 0),
            ("fdi",            0.20, lambda r: clip(r["yoy"] / 20) if r["yoy"] else 0),
            ("customs_export", 0.15, lambda r: clip(r["yoy"] / 10) if r["yoy"] else 0),
        ],
    }

    def recompute(self) -> dict:
        repo = MacroRepositoryImpl()
        latest = {row["indicator"]: row for row in repo.latest_per_indicator()}
        contributors = {}
        dim_scores = {}
        for dim, rules in self.RULES.items():
            total_w, weighted_sum, items = 0.0, 0.0, []
            for ind, w, fn in rules:
                row = latest.get(ind)
                if not row or row.get("value") is None:
                    continue
                try:
                    s = float(fn(row))
                except Exception:
                    continue
                s = max(-1.0, min(1.0, s))
                weighted_sum += s * w
                total_w += w
                items.append({"indicator": ind, "value": row["value"], "yoy": row.get("yoy"),
                              "score": round(s, 3), "weight": w})
            dim_scores[dim] = (weighted_sum / total_w) if total_w > 0 else 0.0
            contributors[dim] = items

        # policy 维度从 agg_news 事件密度派生（见下方）
        dim_scores["policy"], contributors["policy"] = self._policy_score()

        overall = sum(dim_scores[d] * self.DIM_WEIGHTS[d] for d in self.DIM_WEIGHTS)
        overall = max(-1.0, min(1.0, overall))

        if overall >= 0.3:   regime = "risk_on"
        elif overall <= -0.3: regime = "risk_off"
        else:                 regime = "neutral"

        multiplier = round(0.9 + overall * 0.3, 3)        # [-1,+1] → [0.6, 1.2]
        multiplier = max(0.6, min(1.2, multiplier))

        snapshot = {
            "snapshot_date": date.today(),
            "regime": regime,
            "overall_score": round(overall, 3),
            "multiplier": multiplier,
            "liquidity_score": round(dim_scores["liquidity"], 3),
            "growth_score":    round(dim_scores["growth"], 3),
            "inflation_score": round(dim_scores["inflation"], 3),
            "external_score":  round(dim_scores["external"], 3),
            "policy_score":    round(dim_scores["policy"], 3),
            "contributors":    contributors,
        }
        repo.upsert_regime(snapshot)
        return snapshot

    def _policy_score(self) -> tuple[float, list]:
        """从 ft_news 读近 7 天 tag=macro 的事件，按方向计数
        - 含关键词 {降准,降息,减税,刺激,扩内需,宽松} → +1 每条
        - 含关键词 {加息,监管,收紧,反垄断,整顿} → -1 每条
        截断到 [-1, +1]，count 归一到 ±5 条为满分
        """

def clip(x): return max(-1.0, min(1.0, x))
```

**坑**：
- **某个指标最新值缺失时**（比如 omo_net 当天无公告），要跳过该条 rule 并按剩余权重重新归一化（代码里的 `weighted_sum / total_w`）。不能缺失一个指标整维度变 0。
- `_policy_score` 对 agg_news 有依赖。**如果 ft_news 还没有 macro tag 数据**（Step 5 才补齐），`_policy_score` 返回 `(0.0, [])` 即可，不阻塞。
- 所有打分函数写成**纯函数 + clip 包裹**，避免极端值拉爆 overall。
- recompute 必须幂等：同一天多次调用，ft_macro_regime 只会 UPSERT 一行。

```python
MACRO_POS_KW = ["降准","降息","减税","刺激","扩内需","宽松","再贷款","定向","支持"]
MACRO_NEG_KW = ["加息","从严","整顿","监管","收紧","反垄断","限制","处罚"]

def _policy_score(self) -> tuple[float, list]:
    since = datetime.now() - timedelta(days=7)
    news = NewsRepositoryImpl().query_by_tag("macro", since)
    pos = neg = 0
    items = []
    for n in news:
        title = (n.get("title") or "") + " " + (n.get("summary") or "")
        p = sum(1 for kw in MACRO_POS_KW if kw in title)
        q = sum(1 for kw in MACRO_NEG_KW if kw in title)
        if p > q:   pos += 1; items.append({"title": n["title"], "dir": "+", "score": 1})
        elif q > p: neg += 1; items.append({"title": n["title"], "dir": "-", "score": -1})
    # 7 天内净方向，±5 条为满分
    raw = (pos - neg) / 5.0
    score = max(-1.0, min(1.0, raw))
    return score, items[:20]   # 只保留 20 条解释性明细避免 JSON 过大
```
