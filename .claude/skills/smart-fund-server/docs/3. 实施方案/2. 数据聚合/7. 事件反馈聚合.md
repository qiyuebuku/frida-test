**优先级：** P2 — 策略进化
**目标表：** ft_events（回填字段）
**状态：** 待实现
**前置依赖：** 前 5 个聚合 task + ft_events 表（数据处理层产出）

---

## 职责

事件入库后并非结束 — 系统需要**回填事件发生后的市场反应**，形成闭环。本聚合不采集新数据，复用已有聚合的数据做计算。

包含两个子任务：
1. **事件市场反应回填**：T+1/T+3 回填板块涨跌、资金流入
2. **事件流衰退监控**：持续追踪事件流的发酵/衰退状态

---

## 1. 事件市场反应回填

每天盘后扫描近 3 天的事件，回填市场反应字段到 `ft_events`：

| 回填字段 | 数据来源 | 计算方式 |
|---------|---------|---------|
| `sector_change_1d` | 基础市场聚合（板块指数） | 事件对应板块 T+1 涨跌幅 |
| `sector_change_3d` | 基础市场聚合（板块指数） | 事件对应板块 T+3 涨跌幅 |
| `sector_volume_change` | 基础市场聚合（板块成交量） | T+1 成交量 / 5 日均量 |
| `north_flow_1d` | 资金流聚合（北向资金） | T+1 北向净流入 |
| `reaction_delay_minutes` | 基础市场聚合 + ft_events | 事件发布时间 → 板块明显波动的时间差 |

**触发时机：** 每天盘后 15:30

**用途：**
- 判断消息是否已被市场消化（板块已涨 3%+ → price-in）
- 历史类比：找相似事件后查看历史市场反应
- 策略复盘：高 strength 事件是否确实带动了板块上涨

---

## 2. 事件流衰退监控

买入基金后，持续追踪关联事件流的发酵/衰退状态，作为**事件失效止损**的依据。

| 监控维度 | 数据来源 | 衰退信号 |
|---------|---------|---------|
| 新闻密度 | 新闻事件聚合（ft_news 计数） | 该行业近 24h 新增 < 3 条/天 |
| 资金方向 | 资金流聚合（板块资金流） | 该行业连续 2 天净流出 |
| 情绪变化 | 情绪舆情聚合（舆情数据） | 情绪从正面转中性/负面 |
| 事件流 momentum | ft_event_streams.trend | 从 increasing 变为 decreasing |

**触发时机：**
- 盘后：每天 15:30（全量扫描）
- 盘中：每小时（仅扫描已持仓关联的行业）

**产出：** 当多个衰退信号同时触发时，产生"事件失效"止损信号

## 依赖关系

```
ft_events（数据处理层产出）
    ↓ 读取未回填的事件
事件反馈聚合
    ├── 基础市场聚合 → 板块涨跌、成交量
    ├── 资金流聚合 → 北向资金、板块资金流
    ├── 新闻事件聚合 → ft_news 新闻密度计数
    └── 情绪舆情聚合 → 情绪变化趋势
    ↓ 回填
ft_events.market_reaction 字段
```

这是唯一一个**依赖其他聚合服务**的聚合，因此优先级最低（P2），需要前 5 个聚合都就绪后才能建设。
