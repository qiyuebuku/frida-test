# 数据聚合 — 待优化项

## ✅ 已完成

### 增量采集机制（2026-04-15 完成）

**问题：** `watchlist_data` 每轮全量拉取所有历史数据（~15000 条），入库耗时 4+ 分钟。

**已实施：**
1. `_fetch_watchlist_data` 接收 `cp`，根据 `newest_time` 计算 gap 动态选择 API 参数
   - 首次：`nav=year, kline=60, stock_flow=20`（全量回填）
   - 增量：`nav=month, kline=gap, stock_flow=gap`（按需拉取）
2. `_expand_timeseries(since=newest_time)` 客户端过滤，只保留 > newest_time 的新数据
3. `save_batch` 改为真正批量 VALUES（1000 条/批），入库从 4 分钟降到 ~10 秒
4. 进度日志：开始/每 10 只/入库开始/入库完成

**效果：**
| 指标 | 优化前 | 优化后 |
|------|-------|--------|
| 每轮数据量 | ~15000 条 | ~760 条（增量） |
| 入库耗时 | 4 分钟 | ~5 秒 |
| 总耗时 | 331 秒 | ~63 秒 |

### 快照维度历史数据展开（2026-04-15 完成）

**问题：** 6 个含历史日期的维度被当作 `trade_date=今天` 的快照存储，历史数据被浪费。

**已实施：** 在 `_expand_timeseries` 中增加 6 个展开规则：

| 维度 | 展开键 | 展开效果 | API 返回深度 |
|------|--------|---------|-------------|
| `holdings` | `stock[0].endDate` (如 `20251231`) | 每期季报一条 | 最新一期 |
| `scale` | `gmbd` 字典键 (如 `2025-12-31`) | 每期规模一条 | ~18 期（多年） |
| `holder_ratio` | `[].date` (如 `2025-12-31`) | 每期持有人结构一条 | ~26 期 |
| `dividend` | `dividends[].payDate` (如 `2022-01-14`) | 每次分红一条 | 全部历史 |
| `flow_trend` | `quarters[].date` + 今日摘要 | 每季度一条 + 趋势摘要 | ~8 季 |
| `year_return` | `[].time` → `"2014年"` → `2014-12-31` | 每年一条 | ~12 年 |

全部支持 `since` 增量过滤。

### nav API 粒度限制（2026-04-15 确认）

同花顺 `get_nav_trend` 的 `period` 参数只支持 3 个值：

| period | 返回天数 | 含义 |
|--------|---------|------|
| `month` | ~22 天 | 近一月（最小粒度） |
| `nowyear` | ~66 天 | 今年以来 |
| `year` | ~243 天 | 近一年 |

不支持 `day/week/1d/3d/5d/7d/today` 等自定义天数（均返回空字符串）。
当前方案：增量用 `period="month"` 拉 22 天，`since` 过滤只入库新数据。

### 场内基金市场前缀 Bug 修复（2026-04-15 完成）

**问题 1（_is_exchange_traded 误判）：** `519xxx` 开头是场外基金（OTC），但 `startswith("51")` 误将其识别为场内。
导致 519601/519674/519702/519712/519736 这 5 只 OTC 基金被错误采集 quote/stock_flow/minute_data/kline（均返回空数据）。

**问题 2（16xxxx LOF 前缀错误）：** 16xxxx 是深交所 LOF（应用 `sz` 前缀），但代码中 `prefix = "sz" if code.startswith("15") else "sh"` 给了 `sh` 前缀。
导致 161028/161116/161725/162605/163406/164908 共 6 只 LOF 的 kline/quote/minute_data/stock_flow 用错误代码查询，全部返回空。

**修复（fund_flow.py）：**
```python
def _is_exchange_traded(code):
    if code.startswith(("15", "16")): return True
    if code.startswith("51") and not code.startswith("519"): return True
    return False

prefix = "sz" if code.startswith(("15", "16")) else "sh"
```

**清理：** 200+ 条错误空数据已于 2026-04-15 手动从 ft_watchlist_data 清除，下次采集将重新写入正确数据。

### 标的级并发采集（2026-04-15 完成）

**问题：** 59 只标的串行遍历，总耗时 = 单只耗时 × 59（~53 秒）。

**已实施：**
- `_fetch_watchlist_data` 内定义 `_collect_one(item)` 协程，使用 `asyncio.Semaphore(8)` 控制并发上限
- 主循环改为 `asyncio.gather(*[_collect_one(item) for item in enabled])` 并发跑所有标的
- 每只内部各维度仍保留 `asyncio.gather` 并发

**效果：** 59 只标的理论并发 8 批，耗时从 ~53 秒降至 ~8 秒（受限于最慢的一批）

### 快照维度按频率分级（2026-04-15 完成）

**问题：** 每 30 分钟对所有维度无差别采集 API，变化极慢的维度造成无效请求。

**已实施：**

三档分级（`fund_flow.py` 中 `FUND_DIMENSIONS_*` 常量 + `_fetch_watchlist_data` 中 `collect_daily/collect_low` 标志）：

| 档位 | 维度 | 触发条件 |
|------|------|---------|
| 高频 | `nav`, `realtime` | 每次都采 |
| 日频 | `performance`, `flow_trend` | gap > 1（上次采集不是今天） |
| 低频 | `holdings`, `scale`, `holder_ratio`, `dividend`, `year_return`, `max_drawdown`, `holding_overview`, `fund_detail`, `style_preference` | gap > 7（超过一周未采） |

日志输出示例：
```
[watchlist] 开始采集 59 只标的（增量 gap=1d, since=2026-04-15, 维度层级=高频, 并发=8: nav=month, kline=3, flow=3d）
```

**效果：** 日常 30 分钟采集从 13 个 API → 2 个 API（节省 85% 接口调用量）
