# Step 9 · L1L2L3与投研问答接入技术实施方案

> 对应设计文档：`../../5. 设计方案/1. 知识图谱/4. 金融领域适配器设计方案.md`  
> 前置步骤：Step 8 · Financial KG Adapter 第一版  
> 本步骤目标是让事件抽取、主线识别、基金映射和投研问答消费 KG，而不是各自维护规则。

---

## 0. 一句话说清楚

Step 9 把 KG 接入业务链路：

```text
KG
  -> L1 entity normalization / candidate expansion
  -> L2 graph path / community / storyline
  -> L3 event-to-fund exposure
  -> research QA context
```

业务层只能通过 KnowledgeService / Retrieval Runtime 消费 KG，不直接写 `kg_*`。

---

## 1. L1 接入

### 1.1 L1 消费 KG

L1 事件识别调用：

```text
resolve_entities(text)
expand_candidates(mentioned_entities)
get_concept_neighborhood(entity)
get_known_policy_terms(text)
```

KG 提供：

- 标准实体 ID。
- alias。
- 歧义候选。
- 概念/行业邻域。
- 候选股票/基金影响对象。

### 1.2 L1 输出回写 KG

L1 输出作为 `event_record`：

```text
event_id
event_type
event_time
mentioned_entities
affected_entities
evidence_refs
confidence
```

回写产物：

- event node。
- mentions edge。
- affects candidate edge。
- evidence。

### 1.3 禁止事项

- L1 不直接写 `kg_edges`。
- L1 不维护独立金融 ontology。
- `affected_stocks` 不能无 evidence 变成 active edge。

---

## 2. L2 接入

### 2.1 L2 消费 KG

L2 主线识别使用：

| 信号 | 来源 |
|---|---|
| 共享实体 | event -> mentions |
| 共享概念 | event -> concept |
| 图路径 | event -> concept -> stock |
| 社区 | graph analytics |
| 时间连续性 | event_time |
| 证据来源 | evidence source |
| 弱边过滤 | confidence/status |

### 2.2 L2 输出回写

L2 可以输出：

- storyline candidate。
- event merge feedback。
- theme page candidate。
- weak relation downgrade feedback。

这些通过 `feedback_record` 回写。

---

## 3. L3 接入

L3 使用影响传播路径：

```text
event / policy
  -> concept / industry
  -> stock
  -> fund holding
  -> fund exposure
```

### 3.1 Hard score

允许进入硬评分：

- active `holds`。
- 高置信 `belongs_to`。
- 人工确认的关键产业链关系。
- evidence 充分的 active `affects`。

### 3.2 Explanation only

只能解释或候选：

- `related_to`。
- `causal_hint`。
- 低置信 `benefits_from`。
- 仅由 LLM 推断的路径。

### 3.3 输出协议

L3 必须输出：

```text
path
path_confidence
hard_score_edges
explanation_edges
evidence_refs
unsupported_assumptions
```

---

## 4. 投研问答接入

投研问答调用：

```text
build_answer_context(query, domain="financial")
```

上下文必须包括：

- matched nodes。
- matched edges。
- graph paths。
- wiki pages。
- evidence chunks。
- confidence。
- consumption scope。

问答不能只拿 Wiki 摘要回答，必须能返回 evidence。

---

## 5. API/Service 边界

建议在应用层提供：

```text
KnowledgeService.resolve_financial_entities()
KnowledgeService.expand_financial_candidates()
KnowledgeService.find_financial_paths()
KnowledgeService.build_research_context()
KnowledgeService.record_kg_feedback()
```

接口层只包装 HTTP/CLI，不直接访问 repository。

## 7. 验收标准

Step 9 完成必须满足：

1. L1 消费 KG 做实体归一和候选扩展。
2. L1 输出通过 Adapter/Compiler 回写 KG。
3. L2 使用图路径和共享实体，不只靠标签重叠。
4. L3 能区分 hard score 与 explanation only。
5. 投研问答上下文可追溯 evidence。
6. 业务层不直接写 `kg_*`。
