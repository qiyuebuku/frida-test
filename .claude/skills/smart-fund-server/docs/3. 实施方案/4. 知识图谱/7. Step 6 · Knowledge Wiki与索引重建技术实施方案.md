# Step 6 · Knowledge Wiki与索引重建技术实施方案

> 对应设计文档：`../../5. 设计方案/1. 知识图谱/2. 通用知识基础设施设计方案.md`  
> 前置步骤：Step 5 · Knowledge Compiler 最小闭环  
> 本步骤目标是把事实库编译成 Agent 可读 Wiki 和可重建索引。

---

## 0. 一句话说清楚

Step 6 实现写入时沉淀的可读知识层：

```text
Fact Store
  -> Wiki Builder
  -> entity/topic/timeline/contradiction pages
  -> FTS / graph index / optional vector index
```

Wiki 和索引不是事实源。它们必须可以删除并从 Fact Store 重建。

---

## 1. 本步骤范围

### 1.1 要做

1. 定义 Wiki 页面数据模型。
2. 实现通用 Wiki Builder。
3. 实现 Toy Adapter 的 Wiki 页面生成。
4. 实现索引重建任务。
5. 实现 Wiki lint 最小规则。
6. 写集成测试验证可重建。

### 1.2 不做

| 不做 | 原因 |
|---|---|
| 不把 Wiki 当事实源 | 事实源只能是 `kg_*` |
| 不做复杂 LLM 页面润色 | 第一版先用确定性模板 |
| 不做金融 Wiki | Step 8 |
| 不做问答 Runtime | Step 7 |

---

## 2. Wiki Builder 设计

模块：

```text
src/domain/knowledge/wiki.py
src/application/services/knowledge_service.py
```

Wiki 页面类型：

| page_type | 内容 |
|---|---|
| entity_page | 单个节点的关系、证据、历史 |
| topic_page | 一组节点和边的主题摘要 |
| timeline_page | 按时间变化的事实 |
| contradiction_page | 冲突事实和复核项 |
| index_page | 页面目录和导航入口 |

第一版使用模板生成，不调用 LLM。

---

## 3. Wiki 存储方案

第一版建议仍保存到 PostgreSQL，避免文件系统和数据库状态分裂。

建议表：

```text
kg_wiki_pages
```

字段：

```text
page_id
adapter_name
page_type
subject_type
subject_id
title
summary
content
source_node_ids
source_edge_ids
source_evidence_ids
version
created_at
updated_at
```

如果后续要导出 markdown，可由 `kg_wiki_pages` 生成。

---

## 4. 索引重建

第一版索引：

| 索引 | 作用 |
|---|---|
| PostgreSQL FTS | keyword_search |
| graph adjacency material | graph_search |
| wiki page table | wiki_search |
| source/evidence chunk table | chunk_read |
| pgvector 或外部 embedding | semantic_search，可选 |

重建原则：

- index 由 Fact Store 重建。
- 重建可以按 adapter、node、edge、source 范围局部执行。
- 删除索引不影响事实。

---

## 5. Wiki Lint

第一版 lint：

1. 页面是否有 subject。
2. 页面引用的 node/edge/evidence 是否存在。
3. 页面是否陈旧。
4. 页面是否没有入链。
5. 页面是否包含无 evidence 的关键结论。


测试：

1. Toy fixture compile 后能生成 Wiki。
2. 删除 Wiki 后可重建。

4. graph adjacency 能查邻居。
5. chunk_read 能读取 evidence content。

## 7. 验收标准

Step 6 完成必须满足：

1. Wiki 从 Fact Store 生成。
2. Wiki 可删除重建。
3. Wiki 关键内容能回溯 evidence。
4. FTS、graph adjacency、chunk_read 最小索引可用。
5. 不引入金融字段到通用层。
