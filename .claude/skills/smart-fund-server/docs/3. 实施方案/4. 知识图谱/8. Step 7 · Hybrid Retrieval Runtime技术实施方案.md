> 对应设计文档：`../../5. 设计方案/1. 知识图谱/2. 通用知识基础设施设计方案.md`  
> 前置步骤：Step 6 · Knowledge Wiki 与索引重建  
> 本步骤目标是提供统一查询上下文构建能力，而不是让业务各自拼检索逻辑。

---

## 0. 一句话说清楚

Step 7 实现生产主路径检索：

```text
query
  -> keyword_search
  -> semantic_search
  -> graph_search
  -> wiki_search
  -> chunk_read
  -> RRF / rerank / dedupe
  -> context budget
  -> structured answer_context
```

常规查询默认走 deterministic hybrid。  
Agentic retrieval 只作为复杂交互能力，不作为默认线上成本。

---

## 1. 本步骤范围

### 1.1 要做

1. 定义统一检索结果协议。

5. 实现 chunk_read。
6. 接入 semantic_search 的接口占位。

## 4. 融合策略

第一版使用 RRF：

```text
score = sum(1 / (k + rank_i))
```

默认：

```text
k = 60
```

融合步骤：

1. 多路召回。
2. 标准化为 RetrievalHit。
3. 按 canonical object 去重。
4. RRF 融合。
5. 按 context budget 截断。
6. 保留 evidence 和 confidence。

---

## 5. Context Budget

预算必须显式管理：

| 类型 | 默认策略 |
|---|---|
| node | 只保留核心属性 |
| edge | 保留 relation、confidence、evidence_refs |
| wiki | 读取摘要和关键章节 |
| evidence | 读取短片段，必要时 chunk_read 精读 |
| graph path | 保留最短或最高置信路径 |

禁止把整页 Wiki 或完整 source 无脑塞入 prompt。
