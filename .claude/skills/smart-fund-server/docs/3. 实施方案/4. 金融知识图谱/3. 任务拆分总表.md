## 2. T0：GraphRAG 接入预检

状态：`进行中`

目标：

- 确认 GraphRAG 能按当前架构接入
- 确认 LLM Proxy 可作为 completion 接口
- 确认 BYOG 最小流程可跑
- 确认 LLM Proxy 的 `/v1/embeddings` 可复用 `.env` 配置的远程 embedding 服务

任务拆分：

### T0-1 代理层接入检查

状态：`已完成`

内容：

- `/api/llm-proxy/health`
- `/v1/chat/completions`
- 沙盒隔离策略确认

完成标准：

- 接口已真实返回
- 代理层能稳定处理结构化输出

### T0-2 GraphRAG completion 对接验证

状态：`已完成`

内容：

- 用 GraphRAG 实际发起 completion 请求
- 验证协议兼容性
- 验证 GraphRAG 是否能继续消费响应

完成标准：

- 至少一次真实 GraphRAG completion 请求成功

当前进展：

- GraphRAG 临时运行环境已建立
- GraphRAG completion 调用已能打到当前代理接口
- 已确认 `claude -p` 在当前 GLM 路线下容易触发 `429`
- 代理层已切换为交互式 tmux Claude `tmux_pool` backend
- `pool_size=10` / `max_concurrency=10` 已验证可启动
- `/v1/chat/completions` 已通过真实 HTTP 请求返回结构化 JSON
- GraphRAG local query 已通过 completion 代理层成功返回
- 长 prompt 已验证走 `request-contexts/*.md` + Claude `Read`

遗留问题：

- 上游 GLM-5.1 在多会话并发下会出现 `429 code=1302`
- 代理层当前会把部分后端失败包装为 HTTP 502，后续需要细分错误码
- 返回 session_id 当前可能指向 `/clear` 后的新会话，后续需区分 request_session_id / post_clear_session_id

### T0-3 BYOG 最小样例验证

状态：`未开始`

内容：

- 构造极小 `entities / relationships / text_units`
- 跑通最小 workflow

完成标准：

- 最小样例能成功生成索引产物

### T0-4 查询链路最小验证

状态：`进行中`

内容：

- community reports
- Global Search
- Local Search

完成标准：

- 至少各有一条真实成功查询

当前进展：

- 默认 GraphRAG workflow 已成功生成 community reports
- Global / Local / Basic 查询已使用真实 embedding 跑通
- Local 查询已验证长 prompt 文件上下文策略
- DRIFT 能启动并调用真实 embedding，但默认链路过重，需单独调优

未完成项：

- BYOG 最小样例下的查询链路仍需在 T0-3 完成后复测

### T0-5 GraphRAG embedding 能力边界确认

状态：`已完成`

内容：

- GraphRAG 不使用 mock embedding
- 通过 OpenAI-compatible `/v1/embeddings` 接入 `.env` 中的 `EMBEDDING_URL`
- 确认 GraphRAG 本身需要的 embedding 能力和启用边界
- 明确哪些查询模式当前可启用，哪些后续再启用

完成标准：

- 后续不再反复讨论“GraphRAG embedding 是否复用现有 embedding 服务”
- `/v1/embeddings` 可被 GraphRAG / LiteLLM 正常调用

当前进展：

- `/v1/embeddings` 已接远程 Qwen3-Embedding 服务
- 返回维度为 1024，与 `EMBEDDING_DIM` 一致
- GraphRAG index 的 `generate_text_embeddings` 已使用真实 embedding
- Local / Basic 查询已确认会调用真实 embedding
- T0 明确不使用 mock embedding

交付物：

1. GraphRAG 接入记录
2. 最小 BYOG 样例
3. 最小查询验证记录
4. GraphRAG embedding 能力边界结论

状态：`未开始`

- 冻结 `node_id / relation_type / evidence / confidence / version`

### T1-5 事实层 DDL 冻结

### T1-6 混合召回协议冻结

内容：

- `keyword_search`
- `semantic_search`
- `graph_search`
- `chunk_read`
- RRF / 去重 / token budget
- `retrieval_context_builder` 输入输出边界

明确边界：

- 当前不引入 Milvus
- 当前只把 A-RAG 的多工具、多粒度、混合召回思想落成协议
- 后续底层从 PostgreSQL 替换为 Milvus 时，不影响上层接口

统一完成标准：

- 形成正式清单
- 后续实现不再各自发明协议
- 后续查询层不再退回“单次 embedding Top-K”作为默认方案

交付物：

1. Phase 0 实施文档
2. DDL 初版
3. 节点和关系类型清单
4. 证据与版本协议说明
5. 混合召回协议说明
