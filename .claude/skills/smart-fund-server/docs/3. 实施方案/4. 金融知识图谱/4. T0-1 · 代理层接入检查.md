## 2. 已确认事项

### 2.1 API 服务已启动

当前服务启动方式：

```bash
python -m src.interfaces.cli.main api
```

已确认：

- API 服务可正常启动
- LLM 代理接口已挂载到现有 FastAPI 服务

### 2.2 健康检查接口可用

已确认接口：

- `GET /api/llm-proxy/health`

已确认结论：

- 接口可正常返回
- 代理层状态可观测
- 当前 provider 为 `tmux_pool`
- 当前已验证 `max_concurrency=10`

### 2.3 Completion 接口可用

已确认接口：

- `POST /v1/chat/completions`

已确认结论：

- 请求可正常返回
- 结构化输出链路可用
- 代理层能够实际调用当前主 backend（交互式 `tmux_pool + Claude CLI`）

### 2.4 沙盒隔离已生效

当前结论：

- 代理层运行在 `hard sandbox`
- 不依赖当前项目目录作为默认上下文
- 不把本地持久化历史会话当成正式输入

### 2.5 长 prompt 文件上下文已生效

当前结论：

- GraphRAG 长 prompt 超过阈值后会写入 `/tmp/smart-fund-claude-proxy/request-contexts/*.md`
- Claude TUI 中只发送短指令
- Claude 会通过 `Read` 工具读取任务文件
- 已确认会话中不再出现旧的 `OpenAI-compatible` / `纯 LLM 后端` 提示词

### 2.6 错误边界已识别

当前结论：

- `claude -p` 在当前 GLM-5.1 路线下会触发 429，已弃用
- `tmux_pool` 是主路径
- 多会话并发下上游仍可能返回 `429 code=1302`
- 代理层当前可能把后端失败包装成 HTTP 502，后续需要细分错误码
