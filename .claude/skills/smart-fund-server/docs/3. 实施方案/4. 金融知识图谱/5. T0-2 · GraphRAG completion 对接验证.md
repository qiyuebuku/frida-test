## 5. 当前状态

状态：`已完成`

已处理的问题：

1. `claude -p` 直接调用当前 GLM 路线会返回 `429`
   - 错误码：`1302`
   - 错误信息：`您的账户已达到速率限制，请您控制请求频率`
2. 交互式 Claude CLI 是当前主路径，但高并发下上游仍可能返回 429
3. 因此代理层主路径从 `claude -p` 改为：

```text
OpenAI-compatible HTTP
  -> LLM Proxy
  -> tmux_pool 持久 Claude 会话池
  -> 短 prompt 直接 paste / 长 prompt 写入任务文件后由 Claude Read
  -> Claude JSONL 会话文件解析结果
```

判断：

> **429 更像是 `claude -p` / headless 调用路线触发的上游风控或速率限制，不应继续把它作为 GraphRAG 接入的主路径。**

已采取的收敛措施：

- 将代理层会话池扩展到 `10`
- 将代理层最大并发扩展到 `10`
- 将代理层超时调整为 `180s`
- 增加代理层请求间隔：`CLAUDE_PROXY_MIN_INTERVAL_SECONDS=5`
- 增加上游限流冷却：`CLAUDE_PROXY_RATE_LIMIT_COOLDOWN_SECONDS=180`
- hard sandbox 下改为最小环境，不再继承 API 进程里的 `CLAUDE_*` 运行态变量
- 新增交互式 tmux pool backend，启动隔离 HOME / XDG 目录，避免读取项目历史上下文
- 使用 tmux bracketed paste，避免多行 prompt 被拆成多次提交
- 长 prompt 写入 `/tmp/smart-fund-claude-proxy/request-contexts/*.md`，让 Claude 用 `Read` 渐进读取
- 从 Claude JSONL 会话文件读取完整 assistant 输出和 token usage
- 调用完成后执行 `/clear`，健康会话归还池；异常会话销毁重建

## 6. 遗留问题

T0-2 已完成，但留下三类后续工程问题：

1. **错误码治理**
   - 上游 `429 code=1302` 已实测出现。
   - 代理层当前可能把 tmux 调用失败、上游限流、超时统一包装成 HTTP 502。
   - 后续应区分 429、504、502、无有效输出。

2. **并发治理**
   - `pool_size=10` 只是本地会话池能力。
   - 是否能长期满速并发，取决于上游 GLM-5.1 限流。
   - GraphRAG indexing / query 应分别设置 rate limit。

3. **session id 治理**
   - 当前返回的 session_id 可能是 `/clear` 后的新会话 ID。
   - 后续应分别记录 request_session_id 与 post_clear_session_id，便于定位 JSONL。
