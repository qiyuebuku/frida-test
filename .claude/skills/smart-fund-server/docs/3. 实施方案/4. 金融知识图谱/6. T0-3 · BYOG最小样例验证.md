# T0-3 · BYOG最小样例验证

> **任务定位**：验证当前对 Microsoft GraphRAG BYOG 输入结构的理解是否正确。  
> 这一任务只做最小样例，不做正式金融知识图谱导出。

---

## 1. 任务目标

状态：`未开始`

需要验证：

1. 最小 `entities.parquet` 是否可被接受
2. 最小 `relationships.parquet` 是否可被接受
3. 最小 `text_units.parquet` 是否可被接受
4. 最小 workflow 是否能跑通索引产物生成

---

## 2. 最小样例边界

建议样例规模：

- `entities`：3 到 8 个
- `relationships`：3 到 10 条
- `text_units`：2 到 5 条

建议场景：

1. 一条政策或新闻事件
2. 一个概念
3. 两到三个股票
4. 一到两个文本证据

---

## 3. 完成标准

满足以下条件才算完成：

1. 最小 parquet 可成功被 GraphRAG 读取
2. workflow 能成功运行
3. 没有暴露出 BYOG 字段理解错误

---

## 4. 当前前置依赖

本任务开始前必须先满足：

- `T0-2 GraphRAG completion 对接验证` 已通过或至少解除环境阻塞

否则就算 parquet 结构准备好了，也无法完成真实联调。

当前说明：

- `T0-2` 已完成，completion provider 阻塞已解除。
- 目前已经跑通的是 GraphRAG 默认 workflow 的最小样例，不等同于 BYOG 验收。
- 本任务仍需单独构造 `entities.parquet / relationships.parquet / text_units.parquet`，验证 Bring Your Own Graph 输入结构。
- BYOG 样例通过后，`T0-4 查询链路最小验证` 需要基于同一 BYOG 输出再复测一次。
