# LLM Proxy 待优化

### 厂商模型目录尚未自动同步能力元数据（2026-07-19 记录）

**问题：** 当前每个厂商 Provider 已拥有独立模型目录和上游模型 ID 映射，但目录由配置维护，尚未自动同步 JSON mode、tool calls、thinking、上下文等能力元数据。

**最佳方案：** 建立可更新的模型级能力注册表，记录每个模型支持的 API 类型、JSON mode、tool calls、thinking 参数、上下文和最大输出，并在路由后、请求前完成能力校验和参数裁剪。

**当前方案：** 已完成厂商级模型目录、canonical-to-upstream 映射、Provider 级能力差异和受控 `extra_body`；能力元数据仍需人工维护，因为当前没有稳定的机器可读目录接入链路。

**整改条件：** 确定模型目录数据源和同步频率，或接入第二个存在明显能力差异的聚合厂商时。

**优先级：** P1

### 非 Chat Completions 模型尚未接入统一契约（2026-07-19 记录）

**问题：** 阿里云模型目录同时包含 Embedding、Realtime Audio、图像和视频模型，当前 LLM Proxy 请求与响应契约只覆盖文本 Chat Completions，不能调用这些模型。

**最佳方案：** 在统一网关治理下按能力拆分 Chat、Embedding、Realtime 和多媒体接口，分别定义类型安全的请求响应契约、路由能力和观测指标。

**当前方案：** 本阶段只交付文本 Chat Completions 多厂商接入，并在设计和实施文档中明确边界，不用聊天协议伪装支持其他 API。

**整改条件：** 业务提出 Embedding、实时语音或多媒体模型的明确调用场景与验收要求时。

**优先级：** P2

### 上游调用失败后的跨厂商自动切换尚未实现（2026-07-19 记录）

**问题：** 当前会在调用前跳过未启用、未配置 Key 或不支持目标模型的厂商；如果首选厂商已被选中但随后返回认证、限流、额度或服务故障，请求不会在同一次调用内自动切到下一厂商。

**最佳方案：** 根据错误类型、幂等边界和任务策略实现跨厂商 failover，保留每次物理调用审计，并限制总重试时间和成本。

**当前方案：** 已完成同一 canonical model 的多厂商目录、优先级选择和厂商显式选择；网络调用发生后的跨厂商切换暂不隐式执行，避免在缺少成本与错误策略时产生不可控重复计费。

**整改条件：** 明确哪些错误允许 failover、各任务最大尝试次数以及跨厂商成本策略后。

**优先级：** P1
