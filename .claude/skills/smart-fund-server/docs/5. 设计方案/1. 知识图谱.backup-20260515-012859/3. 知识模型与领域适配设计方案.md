# 知识模型与领域适配设计方案

## 1. 本文解决什么问题

本文说明知识图谱如何表达知识，以及为什么要把底层知识基础设施和上层领域适配器拆开。

知识图谱不能只做成金融专用系统。当前项目第一阶段服务金融投研，但后续可能接入其他业务场景。如果底层实体、关系、抽取策略、检索策略都写死为金融语义，系统很快会变成只能服务单一场景的业务脚本。

因此本设计把系统分为通用知识模型和领域适配器两层：通用层提供稳定的知识基础设施，领域适配器负责解释具体业务含义。

## 2. 本文不解决什么问题

本文不讨论原始数据如何投影为 Source Record；这属于“数据源投影与 Source Record”模块。

本文不讨论同义词、别名、重复实体和规则维护闭环；这属于“实体标准化与去重治理”模块。

本文不讨论如何检索、排序和拼装 Query Context；这属于“检索与 Query Context”模块。

本文不讨论如何生成 Wiki 或组织具体消费场景；这属于“Wiki 与消费场景”模块。

本文不列具体数据库字段和代码类名；这些属于实施方案。

## 3. 核心业务对象

### 3.1 Node

Node 表示知识图谱中的实体。实体可以是股票、基金、行业、政策、事件、机构、地区、商品、主题，也可以是其他领域中的自定义对象。

通用层只关心 Node 是一个可识别、可引用、可挂载属性、可参与关系的对象。它不直接判断“新能源车产业链”到底应该是行业还是主题，这类判断由领域适配器和治理规则完成。

### 3.2 Edge

Edge 表示实体之间的关系。关系必须有方向、类型、来源证据和置信边界。

关系不是简单的文本描述。它决定后续检索、路径扩展、策略解释和事件影响传导，因此关系类型必须由领域适配器约束，不能让 LLM 任意生成。

### 3.3 Evidence

Evidence 表示事实来源。每条关系都应该能追踪到证据；没有证据的关系只能作为候选或推断，不能作为强事实消费。

### 3.4 Domain Adapter

Domain Adapter 是领域适配器。它负责定义某个领域的实体类型、关系类型、抽取策略、置信度规则和消费边界。

金融适配器是第一个领域适配器，但不是通用层的一部分。

领域适配器不是业务脚本集合，而是通用知识基础设施和具体业务语义之间的协议层。通用层不直接理解 `news_articles`、`policy_news`、`market_flow.*` 这类领域标签；这些标签必须由领域适配器解释。

## 4. 输入和输出

### 4.1 输入

本模块接收已经标准化为 Source Record 的业务数据，以及领域适配器提供的本体规则和抽取策略。

输入包括：

- Source Record 的内容形态、source type、时间、来源和 metadata。
- 领域实体类型定义。
- 领域关系类型定义。
- 领域来源可信度规则。
- 领域抽取策略，包括规则抽取、LLM 候选抽取和跳过策略。
- 置信度和消费规则。

### 4.2 输出

本模块输出可进入编译链路的知识草稿和适配器判断：

- 实体草稿。
- 关系草稿。
- 证据引用。
- 置信来源。
- 消费边界。
- 校验结果。
- 是否需要 LLM 参与。
- 不确定项和降级原因。

## 5. 核心设计决策

### 5.1 通用层不写死金融字段

通用层只定义知识图谱的基础能力：实体、关系、证据、版本、Wiki、索引、检索上下文、质量治理。

金融字段、金融关系、金融事件类型都由金融适配器定义，不能渗透到通用模型里。

### 5.2 领域适配器决定业务语义

领域适配器负责回答这些问题：

- 这个领域有哪些实体类型。
- 哪些关系是合法关系。
- 哪些来源可以生成高置信事实。
- 哪些事实只能用于解释，不能用于硬评分。
- 哪些 Source Record 可以规则抽取。
- 哪些 Source Record 存在语义不确定性，需要 LLM 生成候选。
- 哪些 Source Record 缺少基础字段，只能跳过或降级。

这样通用层可以保持稳定，领域层可以持续迭代。

### 5.3 领域适配器协议必须稳定

领域适配器至少要提供四类能力：

1. 类型协议：定义本领域允许出现的实体类型、事件类型、关系类型和消费层级。
2. 解释协议：解释 Source Record 中的 `source_type`、metadata、来源可信度和内容形态。
3. 抽取协议：决定某条 Source Record 走规则抽取、LLM 候选抽取、混合抽取还是跳过。
4. 校验协议：判断候选实体和候选关系是否符合领域约束，并给出置信度、降级原因和质量告警。

通用编译核心只能调用这些协议，不能直接内置某个领域的业务判断。新增领域时，理想改动点应该集中在新的领域适配器，而不是通用编译、写入、检索基础设施。

### 5.4 “是否需要 LLM”由适配器先判断

“是否需要 LLM”本身不能由 LLM 判断，否则会变成每条数据都先调用一次模型，成本和链路复杂度都不可控。这个判断必须由领域适配器先用规则完成。

判断依据包括：

1. Source Record 是否具备强 ID，例如股票代码、基金代码、行业代码、外部事件 ID。
2. 关键字段是否完整，例如主体、客体、关系类型、时间、来源和证据内容。
3. 已有规则是否能唯一确定实体类型、关系类型和关系方向。
4. 名称是否存在多类型歧义，例如同一个词可能是政策、概念、行业、事件或公司。
5. 关系是否存在语义歧义，例如“利好”“承压”“驱动”“约束”等表达需要上下文判断影响对象和方向。
6. payload 是否只是结构化指标，还是包含需要解释的复杂嵌套语义。

如果这些检查能稳定解释 Source Record，就走规则路径；如果规则能明确指出存在语义歧义，才进入 LLM 候选抽取；如果缺少主键、来源、时间或证据等基础字段，则应该跳过或失败，而不是交给 LLM 兜底。

LLM 参与的判断标准不是“是否文本类”，而是“是否存在规则无法可靠解决的语义问题”。

### 5.5 LLM 只生成候选事实包

LLM 可以参与实体识别、事件归纳、关系候选生成、证据片段标注和歧义说明，但不能直接决定最终主图事实。

领域适配器应向 LLM 提供受控输入：

1. Source Record 中的标题、摘要、正文、结构化 payload 摘要或可读化内容。
2. 当前领域允许的实体类型和关系类型。
3. 投影层已经给出的 source type、时间、来源和 metadata。
4. 可选的已知实体候选、别名、代码、词表或上下文约束。
5. 明确的输出格式要求。

LLM 输出必须是结构化候选包，而不是自然语言结论。候选包至少应该表达：

1. 候选实体：名称、类型、别名、出现位置、置信度。
2. 候选事件：事件标题、事件摘要、发生时间、相关实体、置信度。
3. 候选关系：关系类型、source、target、方向、证据片段、置信度。
4. 不确定项：歧义原因、可能候选、是否需要降级处理。

LLM 不负责生成最终稳定实体 ID，不负责决定实体最终归一到哪个标准实体，不允许绕过关系白名单创建新关系类型，也不能在没有证据片段的情况下创造事实。

### 5.6 金融适配器第一版聚焦投研闭环

金融适配器第一版不追求覆盖所有金融知识。它应该优先覆盖事件驱动交易最需要的实体和关系：

- 资产：股票、基金、商品。
- 业务分类：行业、概念、主题。
- 外部影响：政策、事件、地区、机构。
- 传导关系：影响、提及、归属、持有、相关。

第一版目标是支撑新闻入图、事件上下文检索、行业/资产影响传导和投研问答，而不是构建完整金融百科。

### 5.7 关系类型必须受控

LLM 可以提出关系候选，但不能发明无限关系类型。关系类型必须在领域适配器中定义，否则后续检索、路径扩展和策略消费会失控。

对金融场景而言，第一版应该限制在少量稳定关系上，并通过质量回放逐步扩展。

### 5.8 事实消费需要分层

不是所有事实都能进入同一消费层。结构化高置信事实可以进入硬消费，LLM 抽取结果更适合进入候选、解释或问答上下文。

金融决策链路尤其需要区分：

- 可以参与硬评分的确定性关系。
- 只能作为解释和辅助判断的语义关系。
- 需要进一步验证的候选关系。

## 6. 模块边界

本模块负责：

- 定义通用知识模型的业务含义。
- 定义领域适配器的职责边界。
- 定义领域适配器如何决定规则抽取、LLM 候选抽取和跳过策略。
- 定义金融适配器第一版覆盖范围。
- 定义实体类型、关系类型、LLM 候选包和消费分层的设计原则。

本模块不负责：

- 从数据库读取原始数据。
- 维护实体标准化规则表。
- 实现检索排序和上下文拼装。
- 编写具体代码、接口和数据库表结构。

## 7. 和其他模块的关系

“知识编译与写入”依赖本模块提供的实体和关系定义，否则无法判断 Source Record 应该编译成什么知识。

“实体标准化与去重治理”依赖本模块提供的类型边界，否则无法判断同名不同类型、近义不同名、主题和行业冲突等问题。

“检索与 Query Context”依赖本模块提供的事实语义，否则检索结果无法解释，也无法判断哪些关系能进入策略决策。

“Wiki 与消费场景”依赖本模块提供的事实语义，否则 Wiki 摘要和业务解释无法保持证据边界。

## 8. 验收口径

该设计成立的标准是：

- 通用层不包含金融专用字段。
- 新领域可以通过新增领域适配器接入，而不是重写通用基础设施。
- 金融适配器可以表达第一版投研场景需要的实体和关系。
- 关系类型受控，不允许 LLM 任意扩展关系语义。
- LLM 只生成候选事实包，不能直接写入主图。
- 不同置信来源的事实有清晰消费边界。
