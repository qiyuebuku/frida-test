## 当前结论

- `300750 / 宁德时代` 实体缺口已修复。
- `宁德时代 300750 最近受哪些事件影响` bad case 已能通过 graph 和 Milvus 命中相关新闻。
- 已建立第一版 bad case replay，可校验 hit、top-k、node、relation。
- 已建立第一版 trace replay，可按记录的 tool input 重放 Agentic 检索路径。
- 已建立第一版系统化评测字段，可校验 channel coverage 和最小 hit/evidence/node/edge 覆盖。
- 当前真实库回放已能验证 deterministic fast path 和 Agentic A-RAG 观测路径，但 Agentic 查询耗时高且存在策略波动，不适合作为低延迟在线默认路径。
- 在线默认路径已回到 fast path：Milvus hybrid search -> evidence graph expansion -> optional rerank -> answer context。
- Agentic A-RAG 保留为深度研究、低置信补救和观测评测路径。
- 文本召回统一依赖 Milvus hybrid，不再建设 Postgres text fallback。
- TrustGraph 更像完整上下文平台，当前不引入其整套分布式平台形态；LightRAG 的节点/边 Key-Value、双层检索、增量更新模式更适合当前系统演进。
- Milvus hybrid index 已从 evidence-only 扩展为 LightRAG-style 混合对象索引，可召回 evidence、node、edge、wiki。
- compile 写入后已能按变更集增量刷新 graph adjacency、evidence chunk、wiki page 和 Milvus hybrid documents；incremental refresh 在真实 compile 路径下优先复用 compile 产生的增量刷新结果。
- PG 的 `kg_*` 表是知识图谱主存储，Milvus 是可重建检索索引；后续优化应围绕增量同步，而不是每次全量 rebuild。
- 下一步进入真实库 bad case trace 调参、增量刷新后台任务化，以及 Milvus stale object 清理。

## 下一步优先级

1. 基于真实库 bad case trace 调整 Agentic 工具选择和停止策略。
2. 将增量刷新从 CLI/API 编排升级为可追踪、可重试、可恢复的后台任务。
3. 补 Milvus 增量 delete / stale object 清理，以及独立 entity alias/code 索引。
