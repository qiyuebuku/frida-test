# Tasks 启动说明

本文只说明 `src/interfaces/tasks` 这一套 jettask-rs 任务系统如何启动、初始化和排查。API 服务、知识图谱脚本和其他调试脚本不在本文范围内。

## 1. 当前任务系统组成

| 组件 | 作用 | 是否常驻 |
|---|---|---|
| `persist` | 消费 jettask `_commands` 队列，将调度注册等命令落库 | 是 |
| `scheduler` | 从数据库读取 schedule，按时间向任务队列投递消息 | 是 |
| `worker` | 消费具体业务队列并执行任务函数 | 是 |
| `trigger` | 手动向队列投递一次性任务 | 否 |

当前任务系统负责数据采集、情绪信号物化，以及新闻入库后的知识图谱高维索引增量构建。旧 `ft_events -> ft_event_streams` 事件链路已经删除；事件抽取和高维索引由知识库链路负责。

核心入口：

| 文件 | 职责 |
|---|---|
| `src/interfaces/tasks/__init__.py` | 创建 `Jettask` app、初始化 `ft_raw_data`、注册任务 router |
| `src/interfaces/tasks/collection_tasks.py` | 注册数据采集 task handler |
| `src/interfaces/tasks/knowledge_tasks.py` | 注册知识图谱高维索引 task handler |
| `src/application/services/knowledge_news_ingestion_service.py` | 新增新闻入知识图谱的应用层编排 |
| `src/interfaces/cli/main.py` | 提供 `worker` / `scheduler` / `persist` / `trigger` / `init schedules` 命令 |
| `src/interfaces/cli/schedules.py` | 定时调度配置 |

## 2. 启动前检查

进入项目目录并激活环境：

```bash

配置来源：

- `REDIS_URL` 用于 jettask 队列和 Redis 锁。

首次部署或重建环境后，先执行：

```

## 3. 推荐启动顺序

### 3.1 启动 Persist

```bash
python -m src.interfaces.cli persist
```

`persist` 负责把调度注册命令落库。它不执行业务采集，但没有它时，`init schedules` 发送的调度注册命令可能不会持久化。

如果是首次部署，启动 `persist` 后再注册调度：

```bash
python -m src.interfaces.cli init schedules
```

### 3.2 启动 Scheduler

```bash
python -m src.interfaces.cli scheduler
```

### 3.3 启动 Worker

默认 worker 消费全部采集队列：

```bash
python -m src.interfaces.cli worker -c 1
```

当前默认队列来自 `src/interfaces/cli/main.py`：

```text
collect_news
collect_fund_flow
collect_market
collect_macro
collect_sentiment
kg_news_ingest
```

`collect_news` 覆盖雪球快讯；`collect_sentiment` 覆盖雪球热门话题、雪球热股、股吧、涨跌停池等情绪源。

`kg_news_ingest` 消费 `collect_news` 直接投递的 jettask 消息，消息体携带新增 `ft_news.id`，批量编译进知识图谱和 Community 高维索引。

如果要消费指定队列，直接把队列名写在命令后面：

```bash
python -m src.interfaces.cli worker -c 1 collect_sentiment
```

## 5. 手动触发任务

查看可触发队列：

```bash
python -m src.interfaces.cli trigger --list
```

触发单个任务：

```bash
python -m src.interfaces.cli trigger collect_news
```

触发多个任务：

```bash
python -m src.interfaces.cli trigger collect_news collect_sentiment
```

手动触发指定新闻进入知识图谱：

```bash
python -m src.interfaces.cli trigger kg_news_ingest --news-id 85829
```

不传队列名时会触发全部已注册队列。生产环境不要随手执行无参数 `trigger`。

## 7. 新闻入知识图谱增量链路

`collect_news` 每次完成新闻采集后，会把真实新增的 `ft_news.id` 直接投递为 jettask 消息：

```text
queue=kg_news_ingest
kwargs={"news_ids": [ft_news.id, ...]}
```

`kg_news_ingest` 只处理消息体里的 `news_ids`，不扫描数据库、不维护二级 Redis Stream。处理逻辑：

1. 获取 Redis 分布式锁 `kg:news_ingest`，锁 TTL 为 3 分钟。
2. 有 `news_ids` 时获取锁失败会抛异常，让 jettask-rs 重试当前消息；不能返回成功，否则消息会被 ack。
3. 获取锁成功后，每 30 秒续租一次锁。
4. 每批最多处理 30 个 `ft_news.id`。
5. 按 ID 读取 `ft_news`，投影成金融知识图谱输入记录。
6. 调用 `KnowledgeService.compile_kg()` 写入 KG、Cognitive Card、Community 高维索引和 Milvus 索引。
7. 如果批处理异常，任务异常直接抛给 jettask-rs，由框架负责重试和恢复。

如果进程崩溃，锁会在 3 分钟后自动过期，jettask-rs 会把未完成消息恢复给后续 Worker 继续处理。

## 8. 日志与常见问题

### 8.1 `ft_raw_data` 分区初始化

Worker 进程不经过 FastAPI lifespan，所以 `src/interfaces/tasks/__init__.py` 会在导入时执行 `raw_data.init_raw_data_tables()`。

正常日志示例：

```text
ft_raw_data 分区已通过受控函数初始化
```

如果出现 `no partition of relation "ft_raw_data" found for row`，说明当前月份分区缺失，或数据库缺少 `public.ensure_ft_raw_data_partition(int, int)` 受控函数执行权限。

### 8.2 jettask 队列表分区初始化

jettask-rs 的持久化表使用月分区。`persist` 启动前会检查并初始化当前月份前后若干个月的分区。

当前会检查的框架表：

- `tasks`：按 `trigger_time` 分区。
- `task_runs`：按 `trigger_time` 分区。
- `task_metrics_minute`：按 `time_bucket` 分区。
- `task_runs_metrics_minute`：按 `time_bucket` 分区。
