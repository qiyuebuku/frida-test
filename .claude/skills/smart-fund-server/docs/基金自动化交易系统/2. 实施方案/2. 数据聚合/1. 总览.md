# 数据聚合总览

聚合层位于客户端层之上，按**数据类型**（而非数据来源）组织。每个聚合维度对应一个定时任务和一张结果表，负责定时从多个数据源采集数据、统一格式、去重后入库，同时对外提供查询 API。

**前置依赖：**
- 客户端层 ✅ 已完成（9 个客户端、150+ 方法）
- ft_raw_data 表 + 客户端缓存机制 ✅ 已完成

---

## 一、核心设计：每维度一个串行任务

### 问题

同一个聚合维度（如新闻）有多个数据源，每个源的请求频率不同：

| 数据源 | 频率 | 原因 |
|--------|------|------|
| 财联社快讯 | 3 分钟 | A 股最快新闻源 |
| 东方财富资讯 | 15 分钟 | 覆盖面广 |
| 政府网站 | 3 小时 | 日更 |
| 人民银行 | 24 小时 | 每天早上发一次 |

### 方案：定时任务 + 源级间隔控制

```
每个聚合维度 = 一个定时任务 + 一张结果表

任务触发（按该维度最高频率的源决定，如新闻=3分钟）
  → 串行遍历所有数据源：
      源1(cls): 上次3分钟前，间隔要求3分钟 → 到期 → 请求 → 立即入库 ft_news
      源2(em):  上次10分钟前，间隔要求15分钟 → 未到期 → 跳过
      源3(gov): 上次1小时前，间隔要求3小时 → 未到期 → 跳过
      源4(pboc): 上次25小时前，间隔要求24小时 → 到期 → 请求 → 立即入库 ft_news
      ...
```

**关键特征：**
- **每张表只有一个任务在写** → 串行 → 无死锁
- **每个源拿到数据立即入库** → 不用等所有源完成
- **频率控制在聚合层自己管理** → 不依赖客户端缓存 TTL
- **源的间隔控制是程序级的**（内存中记录 `last_fetch_time`），不是缓存级的

### 与客户端缓存的关系

| | 客户端 @cached | 聚合层间隔控制 |
|--|---------------|--------------|
| 粒度 | 请求级（相同参数命中） | 源级（到没到时间） |
| 控制方 | 被动（被调用时判断） | 主动（到时间才调） |
| 作用 | 防止重复请求外部 API | 控制采集节奏 |
| 是否冲突 | **不冲突，双层保护** | 聚合层控频 + 客户端兜底 |

两者互补：聚合层主动控制"该不该调"，客户端缓存兜底防止"万一多调了"。

## 二、设计原则

| | 客户端层 | 聚合层 |
|--|---------|--------|
| 划分维度 | 按数据来源 | 按数据类型 |
| 职责 | 对接外部 API + 透明缓存 + 原始数据入库 | 定时采集 + 格式转换 + 去重 + 写入结果表 + 查询 API |
| 输出格式 | 各客户端自定义 | **统一格式**，面向业务层消费 |
| 写入 | ft_raw_data（原始数据） | ft_news / ft_market_flow / ...（聚合结果） |

### 核心规则

- **每个维度一个定时任务 + 一张结果表**：避免多任务并发写同一张表
- **任务内串行遍历所有源**：每个源独立的间隔控制，到期才请求
- **拿到即入库**：不等所有源完成，单个源请求成功立即写入
- **异常隔离**：单个源失败不影响其他源，记录日志继续
- **不直接对接外部 API**：只调用客户端层
- **对外提供查询 API**：业务层通过 API 读取已入库的聚合结果
- **支持历史重放**：从 ft_raw_data 重放历史数据，用新逻辑重新聚合

### 文件组织

```
services/aggregators/
  __init__.py
  base.py              # 聚合基类（定时任务框架 + 源级间隔控制）
  news.py              # 新闻事件聚合
  market.py            # 基础市场数据聚合
  macro.py             # 宏观政策聚合
  fund_flow.py         # 资金流聚合
  sentiment.py         # 情绪舆情聚合
  event_feedback.py    # 事件反馈聚合
```

## 三、聚合基类设计

```python
class BaseAggregator:
    """聚合基类：定时任务 + 源级间隔控制 + 查询 API"""

    # 子类定义数据源列表
    sources = [
        # (名称, 客户端方法, 间隔秒数, normalize函数)
        ("cls", cls.get_telegraph_since, 180, normalize_cls),
        ("eastmoney", em.get_news_by_keyword_since, 900, normalize_em),
        ("gov", gov.get_announcements_since, 10800, normalize_gov),
    ]

    def __init__(self):
        self._last_fetch: dict[str, float] = {}  # 每个源的上次请求时间

    async def tick(self):
        """定时任务入口：串行遍历所有源，到期的才请求"""
        now = time.time()
        for name, fetch_fn, interval, normalize_fn in self.sources:
            # 间隔控制：未到期则跳过
            last = self._last_fetch.get(name, 0)
            if now - last < interval:
                continue

            # 请求数据
            try:
                raw_items = await fetch_fn(self._get_checkpoint(name))
                if not raw_items:
                    self._last_fetch[name] = now
                    continue

                # 转换为统一格式
                items = normalize_fn(raw_items)

                # 立即入库（不等其他源）
                saved = self._save(items)
                self._last_fetch[name] = now
                logger.info(f"[{name}] 采集 {len(raw_items)} 条，入库 {saved} 条")

            except Exception as e:
                logger.warning(f"[{name}] 采集失败: {e}")
                # 失败不更新 last_fetch，下次继续尝试

    def _save(self, items: list[dict]) -> int:
        """写入结果表（子类实现）"""
        raise NotImplementedError

    def _get_checkpoint(self, source_name: str):
        """获取增量采集的断点（子类实现）"""
        raise NotImplementedError

    async def query(self, **filters) -> list[dict]:
        """查询 API：从结果表读取数据（子类实现）"""
        raise NotImplementedError

    async def replay(self, start: str, end: str) -> list[dict]:
        """重放模式：从 ft_raw_data 读历史数据，用当前逻辑重新处理"""
        from services.db import raw_data as rd
        records = rd.query_raw(
            data_domain=self.data_domain,
            start_time=start, end_time=end,
        )
        items = []
        for record in records:
            normalize_fn = self._get_normalize_fn(record["source"], record["method"])
            if normalize_fn:
                items.extend(normalize_fn(record["data"]))
        return self.deduplicate(items)
```

## 六、两个入口

每个聚合服务有两个入口：

### 1. 定时采集（写入）

```python
# 由定时框架触发（如 APScheduler、asyncio 定时器等）
await news_aggregator.tick()
```

每次 tick：串行遍历所有源 → 到期的请求+转换+入库 → 未到期的跳过。

### 2. 查询 API（读取）

```python
# 由路由/业务层调用
items = await news_aggregator.query(since="2026-03-21", category="policy")
```

直接读结果表，不触发采集。

### 3. 历史重放（可选）

```python
# 聚合逻辑变更后，从 ft_raw_data 重跑
items = await news_aggregator.replay(start="2026-03-01", end="2026-03-21")
```

从 ft_raw_data 读取历史原始数据，用新逻辑重新处理。

## 九、错误处理

```python
async def tick(self):
    """单个源失败不影响其他源"""
    for name, fetch_fn, interval, normalize_fn in self.sources:
        if not self._should_fetch(name, interval):
            continue
        try:
            raw = await fetch_fn(self._get_checkpoint(name))
            items = normalize_fn(raw)
            self._save(items)               # 拿到即入库
            self._last_fetch[name] = now
        except Exception as e:
            logger.warning(f"[{name}] 失败: {e}")
            # 不更新 last_fetch → 下次继续尝试
```

## 十、定时任务框架

使用 jettask 分布式任务框架驱动定时采集。参考 `/home/yuyang/easy-task/backend/examples/quick_start/`。

### 架构

```
jettask scheduler → 读取定时任务配置 → 到期后发任务到 Redis 队列
jettask worker    → 从 Redis 消费 → 执行聚合任务（tick）
```

### 每个聚合维度注册一个 Schedule

```python
from jettask import Jettask, TaskRouter, Schedule

app = Jettask(redis_url="redis://localhost:6379/0")
router = TaskRouter()

@router.task(queue="aggregator_news")
async def news_tick():
    """新闻聚合定时任务"""
    await news_aggregator.tick()

@router.task(queue="aggregator_fund_flow")
async def fund_flow_tick():
    """资金流聚合定时任务"""
    await fund_flow_aggregator.tick()

app.include_router(router)

# 注册定时调度
schedules = [
    Schedule(scheduler_id="news_3min", queue="aggregator_news",
             interval_seconds=180, description="新闻采集 每3分钟"),
    Schedule(scheduler_id="fund_flow_5min", queue="aggregator_fund_flow",
             interval_seconds=300, description="资金流采集 每5分钟"),
    Schedule(scheduler_id="macro_1h", queue="aggregator_macro",
             interval_seconds=3600, description="宏观指标采集 每1小时"),
    Schedule(scheduler_id="sentiment_15min", queue="aggregator_sentiment",
             interval_seconds=900, description="情绪采集 每15分钟"),
    Schedule(scheduler_id="market_1min", queue="aggregator_market",
             interval_seconds=60, description="市场数据采集 每1分钟"),
    Schedule(scheduler_id="event_feedback", queue="aggregator_feedback",
             cron_expression="30 15 * * 1-5", description="事件反馈回填 盘后"),
]
```

### 为什么用 jettask 而不是 APScheduler

- **分布式**：多机部署时不会重复执行（Redis 队列天然去重）
- **可监控**：任务执行状态、失败重试、结果查询
- **限流**：`QPSLimit` / `ConcurrencyLimit` 可控制对外部 API 的请求速率
- **与现有架构统一**：项目已在使用 jettask
