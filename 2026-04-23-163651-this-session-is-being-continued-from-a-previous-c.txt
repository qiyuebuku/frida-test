  核心问题

  我们一直在"妥协绕过语义能力"，根本原因是我们缺少一个金融领域的知识图谱基础设施
  。没有这个底座：

  - L2 聚类只能靠 concept 标签做扁平匹配 → 标签不对齐就失败
  - L3 打分缺乏多跳推理 → "算力需求爆发 → 服务器扩容 → 液冷订单增加"
  这种链条无法发现
  - L1a 反馈闭环无法结构化 → 不知道哪些概念应该合并

  graphify 能做什么、不能做什么

  能用的核心组件：
  - build.py → NetworkX 图构建（实体 + 关系 + 置信度标签）
  - cluster.py → Leiden 社区发现（基于图拓扑，不需要 embedding）
  - analyze.py → 关键节点发现、跨社区关联、知识缺口检测
  - wiki.py → 每个社区生成可导航的 wiki 页面
  - serve.py → MCP 服务，暴露 query_graph、shortest_path、get_neighbors 等工具

  不能直接用的：
  - extract.py 是 tree-sitter AST 抽取器，面向代码，不适合金融数据
  - graphify 的输入是"文件夹"，我们的是"数据库表"

  所以不是"直接跑 /graphify"，而是复用 graphify 的图管线（build → cluster → 
  analyze → wiki → serve），自研领域抽取层。

  参考文章的启示

  货拉拉 GraphRAG 的核心经验：
  1. 多索引结合（图 + 向量 + 全文）→ 我们的场景也需要
  2. 实体权重计算 → 我们的事件 strength 可以直接用
  3. 增量更新（以实体 ID 为主键）→ 这正是我们需要的

  Anthropic Contextual Retrieval 的启示：
  1. 给 chunk 加上下文再存向量 → 我们的 ft_events 已经有 summary + affected_*
  字段，天然带上下文
  2. 成本极低（$1.02/百万 tokens）→ 对我们的 embedding 生成不是问题
