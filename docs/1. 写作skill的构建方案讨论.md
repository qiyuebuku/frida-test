构建小说续写智能体的挑战与准备
上下文长度限制。 现代大模型的输入上下文窗口通常只有数千到数十万 tokens（例如GPT-3.5约4K，GPT-4最高32K，Anthropic Claude扩展至100K tokens
），远小于一部百万字小说的长度。直接将整本小说输入模型会造成“长文档效应”：模型往往在信息过载时遗漏中间情节，给出简短或不连贯的回答
。因此，需要 拆分输入、逐步引导 的方法，让模型像人类读者一样分段理解小说。例如，可先让模型列出主要人物和关系，然后按章节依次总结故事，再综合归纳全书主题
。实践表明，逐章生成并结合前文摘要进行衔接是写长文的最佳实践：先与模型协同制定详细大纲，再分章节续写，每章开头加入剧情提示确保连贯，每次生成文本长度控制在模型上下文窗口内
。在处理特别重要或敏感的长文本时，还应结合人工审核，避免模型输出出现累积误差
。
预处理：知识提取与索引构建
为了让模型“理解”要续写的目标小说，需要在生成阶段之前构建知识库并索引关键信息：
小说大纲与章节摘要：先整体梳理故事脉络，写出书籍大纲（包括主要冲突、结局设想等）。然后对每章或每个情节段落生成简短摘要，记录关键转折和细节。这类似读书笔记的过程：模型可以先列出书中主要人物和关系，再按顺序总结每章剧情
。提前准备好全书大纲和分章提要，有助于模型快速定位续写时所需的前后文。
人物与关系信息：建立角色档案，包括人物性格、动机和彼此关系（如家族、师徒、敌友等）。可以通过AI辅助或手工提取小说中的人物与事件，“卡片化”记录人物性格和关系网，并在续写时注入提示。NovelForge 等工具就集成了 Neo4j 知识图谱，将文本中的人物关系自动提取并存入图数据库
。对后续生成来说，动态注入此类结构化“事实”信息可大幅提高一致性，减少模型“幻觉”错误
。
世界观与设定：整理小说的世界观、时代背景、地点图（如空间地图、家谱、魔法体系等），并制作参考资料。将这些信息梳理成结构化文档或图谱，可帮助AI在续写时遵循原作设定。
向量索引与检索：将拆分后的文本块（如每章原文或摘要）用嵌入向量存入数据库（如FAISS、Pinecone等），构建检索索引。在续写过程中，可用当前情节或提示文本检索出最相关的章节信息送入模型，做到检索增强生成（RAG）。传统RAG流程包括文档解析、长文分块、多级摘要和Embedding入库
，这些步骤同样适用于小说文本。通过相似度检索，只将最相关的上下文片段提供给模型，可以显著压缩输入长度，减少无关信息干扰。
读者反馈与评论：将已有的读者评论（尤其高点赞评论）作为额外素材分析。评论往往透露了读者关注的情感点、细节亮点或设定疑问。可对评论文本做情感分析和主题提取，找出读者喜欢或不满的地方。例如，某些评论可能指出故事节奏慢还是高潮缺乏、某人物行为违和等。将这些用户需求整理为写作指导要素，在续写时作为参考，但不完全照搬，避免照本宣科。虽然这部分技巧暂无公开文献直接参考，但实践中常将用户反馈作为创作参考的一环。
写作流程设计与多智能体分工
借鉴新闻编辑部或出版团队的流程，可以将小说续写任务拆分为多个角色（智能体）并行协作，提高效率和质量
。一个典型的多智能体写作架构包括：
规划（策划）智能体：负责制定故事大纲和章节安排，确定主题、人物、核心冲突等
。它从宏观出发回答“这本小说下一步要讲什么”的问题，可与人类创作者共同头脑风暴，以确保续写方向符合预期。
写作（生成）智能体：根据策划大纲逐章续写内容，每次根据当前情节提示生成一小段（如1000字）文本
。该智能体在每章开头接收上文摘要、关键角色信息等提示，保证续写与前文连贯一致。章与章之间，可交替进行情节概述更新和正文生成的工作流。
编辑智能体：对生成的草稿进行润色校对，检查语言流畅性、语法和文风一致性
。它可以模拟不同风格要求（言简意赅或文采铺张），还可使用比如Claude、GPT-4之类擅长编辑任务的模型对文本进行细节优化。
审核/校对智能体：从故事逻辑和内容准确性角度检查草稿。这包括事实核查（确保设定背景、历史与情节一致）、情节合理性（角色动机和行为符合设定）等
。类似于事实查证员，它可以提示“这里逻辑是否合理？”、“角色动机是否清晰？”等，辅助修订故事漏洞。
出版（排版）智能体：将最终稿进行格式整理，处理章节标题、目录等细节，使文本符合出版规范
。
此多角色分工方式能让各智能体“各司其职”，相互协作。例如在实际应用中，可以采用并行审稿团队：多个编辑智能体从不同角度（语言风格、角色一致性、逻辑连贯等）同时审阅一个章节，再由一个汇总智能体整合反馈修改（类似真实编辑部多审稿人工作流）
。这样能捕捉更多细节问题，最终由写作智能体或人工根据审稿意见进行修改润色。
迭代生成与复核机制
在实践中，小说续写通常需要多轮迭代：模型生成一个版本后，结合审稿意见修改，再继续写下一段。每一轮迭代都应保持上下文连续性：续写时可在提示中附上之前章节的摘要或关键事件信息，避免模型忘记已发生的情节。根据经验，要避免一次性输入过多信息，而是让模型逐步检索与构建上下文
。例如，每生成完一章，可让编辑智能体和校对智能体审阅该章，然后由写作智能体（或规划智能体）结合反馈生成下一章。 此外，整个过程需设置检查与人类复核环节：对于重要或核心情节，可邀请人类作者或主编参与审阅。在AI主导的续写流程中加入人机混合审查，可显著提高质量，避免让模型产生“累积误差”
。实践中常用链式提示或链式思考（Chain-of-Thought）技术，引导模型自问自答以检查逻辑，例如让模型自己扮演审稿人角色提出问题、指出矛盾，以增强自我评估能力
。最终，可由人工或强编辑模型（如Gemini或人类）对全文进行一次性最终校对，确保角色称呼、细节设定和风格前后一致。
技术框架与实践工具
具体实现时，可以借助常见的RAG及Agent框架：
分块摘要与检索：利用 LangChain、LlamaIndex 等工具，将小说文本按章节或情节拆分并摘要，再把摘要和重要片段建立向量数据库索引。续写时，使用关键词或当前情节摘要检索相关内容，提供给模型作为提示。这与蚂蚁金服经验中提到的离线文档处理类似，包括文档解析、分片、多级摘要和Embedding入库
。
知识图谱注入：可使用 Neo4j 或其他图数据库来存储前述角色、关系、事件等结构化信息。每次写作时，将与当前情节相关的图谱实体和关系动态作为提示注入模型。这种图谱增强检索可以提高检索召回和内容一致性
。
多模型协作：不同模型擅长不同任务，可结合使用。例如使用Claude Code等代码技能平台编写多智能体工作流，让一个模型负责草稿生成，另一个专门负责细节润色或逻辑检查
。实践表明，采用多模型多智能体体系可以发挥各家模型优势，就像真正的编辑团队一样分工合作
。
上下文策略：利用“分步提示”（Step-by-Step Prompts）或对话式交互，让模型在续写过程中自己检索上下文。比如在生成新段落前，让模型先回顾上一章提要或回答“上一章发生了什么”、“主角现在在什么状态”，迫使模型主动加载关键信息，这与前文所述的引导式阅读策略类似
。
评论与风格反馈：可把高赞评论内容抽象为创作指导提示，例如“根据读者反馈，这部小说的某些情感描写很打动人，我们可以在续写时增加情感细节”，从而引导模型注重读者期待。这虽缺乏公开指南，但可视为一种高级提示工程。
小结
综上所述，要构建一个专注于小说续写的AI agent，需要在生成前做好全局把控与知识准备。核心思路是：分块+总结+索引+检索+多轮。即先对目标小说进行拆分和分析（提纲、摘要、人物关系、世界观等），建立知识索引（向量索引、知识图谱等），再在续写阶段让模型有选择地检索使用相关信息。整个流程可设计成多智能体协作：规划智能体制定大纲，写作智能体分章节续写，编辑和审核智能体并行校稿，然后迭代修订。这样既避免一次性给模型过多冗长上下文，也让AI像人一样逐步“读懂”小说背景。实践中还需结合人工审校，确保续写质量。参考资料中提到的长文本处理最佳实践和多智能体编排经验
对这一方法论提供了重要启示。 参考资料： 长文本处理与小说写作相关文献

# 一、为什么不用向量库反而更好

先给你一个很关键的认知：

**向量检索 ≠ 最适合小说**

它有几个天然问题：

### 1）向量会丢失结构

向量库把一切变成“相似文本块”。

但小说最重要的是：

* 时间线
* 因果关系
* 人物状态演化
* 世界设定一致性

这些是**结构关系**，不是语义相似。

你要找的是：

* 第一次相遇
* 上一次战斗
* 当前人物状态
* 未完成伏笔

而不是“找一段类似的文字”。

---

### 2）小说检索是“人类式查资料”

当人类写同人或续写时，他不会：

> “让我搜语义最相似的段落”

他会：

* 看人物卡
* 看时间线
* 看大纲
* 看最近几章
* 查某个设定

这叫 **导航式检索（navigational retrieval）**
不是 semantic search。

所以你现在的思路其实非常对：

> 让AI像人一样翻资料

这比向量RAG更高级。

---

### 3）Claude 非常擅长读文件夹

Claude Code 的强项就是：

它可以：

* 浏览目录
* 打开文件
* 决定要不要继续深入
* 逐层展开上下文

这正是你说的：

> “让 AI 自己探索上下文”

这件事用文件系统比向量库自然得多。

```
- 战力崩坏
- 配角消失

## 读者期待
- 希望主角复仇
- 希望揭开世界真相
```

这会变成：
👉 “市场反馈引导写作”

非常强。

---

## 7️⃣ 章节摘要库

```
chapters/
├── arc1/
│   ├── ch001.md
│   ├── ch002.md
│   └── arc_summary.md
```

每章摘要控制在 **150~300字**。

这是续写时最常读取的部分。

很好，这一步其实是**整个项目最难、最关键、最决定上限的阶段**。
因为续写能力 ≈ 预处理质量 × 上下文调度能力。

你现在问的是：

> 在“只做预处理，不写作”的阶段，究竟要抽取哪些知识？

我们可以把它理解为：
**把一部小说“解构成 AI 可以理解的形态”**

不是摘要，而是 **小说结构化建模**。

---

# 先给你一个核心模型

小说 ≠ 文本
小说 = 5层结构叠加

```
文本层（文字）
剧情层（发生了什么）
角色层（谁参与）
世界层（规则与设定）
读者层（读者期待）
```

预处理就是把这五层全部抽出来。

下面我们逐层拆。

---

# 一、剧情层（Plot Layer）

这是最核心的一层。

目标：让AI知道
**故事是怎么一步步走到现在的**

注意：不是摘要，而是**剧情结构化**

---

## 1️⃣ 章节摘要（你已经想到）

但需要升级为三层：

### ① micro summary（章节级）

每章 150–300字。

包含：

* 发生的关键事件
* 新登场角色
* 角色关系变化
* 伏笔/悬念
* 重要物品

示例：

```
ch12_summary.md

关键事件：
- 林修首次觉醒能力
- 被学院列为重点观察对象

关系变化：
- 与导师关系从陌生 → 信任

伏笔：
- 神秘组织开始关注他
```

不是文章，是结构化条目。

---

### ② arc summary（篇章级）

每 20–50 章一个 story arc。

```
学院篇
战争篇
逃亡篇
```

记录：

* 这一篇的核心冲突
* 主角成长变化
* 重要转折点
* 新世界信息

这对续写 **极其重要**。

---

### ③ global plot line（全书主线）

```
主线A：主角成长
主线B：世界真相
主线C：反派阴谋
```

每条主线记录：

* 起点
* 已推进到哪
* 未完成部分

这是续写“方向感”的来源。

---

# 二、角色层（Character Layer）

这是决定“像不像原作”的关键。

大模型最容易崩的地方：
👉 人物行为不符合人设

所以人物库必须非常重。

---

## 每个角色要抽取 5 个模块

### 1️⃣ 人物设定（static）

```
性格
价值观
恐惧
执念
说话风格
```

---

### 2️⃣ 人物弧光（character arc）

这是超级关键。

```
初始状态：懦弱
ch50：开始反抗
ch120：主动承担责任
当前阶段：成长中期
```

否则 AI 会让角色“突然变人”。

---

### 3️⃣ 关系演化（dynamic relationships）

不是“谁和谁是朋友”。

而是时间变化：

```
林修 ↔ 苏晚

ch10 陌生
ch40 同伴
ch80 信任危机
ch110 关系修复
```

这是避免感情线崩坏的关键。

---

### 4️⃣ 人物时间轴

记录角色经历的关键事件：

```
林修
- ch12 觉醒能力
- ch47 重伤
- ch88 杀死导师
```

---

### 5️⃣ 当前状态（写作最常用）

```
位置：
身体状态：
心理状态：
未完成目标：
当前同行角色：
```

写作时90%会读取这一块。

---

# 三、世界层（World Model）

很多续写失败不是剧情问题，是**设定崩坏**。

所以世界观必须结构化。

---

## 必备模块

### 1️⃣ 力量体系

```
等级
限制
代价
上限
已出现能力
```

### 2️⃣ 组织/势力

```
目标
立场
敌对关系
已知成员
```

### 3️⃣ 地理/空间

```
国家
城市
重要地点
空间距离关系
```

### 4️⃣ 规则与限制（超重要）

例如：

* 魔法不能复活死人
* 时间旅行只能一次
* 皇室不能公开出手

这些就是“不能打破的规则”。

---

# 四、读者层（你的独特优势）

你有评论数据，这是**杀手级资产**。

要从评论中提炼四种信息：

---

## 1️⃣ 情绪触发点（为什么爽）

```
读者最喜欢：
- 逆袭
- 打脸
- 情感互动
```

---

## 2️⃣ 高赞角色

```
最受欢迎角色排行
最讨厌角色排行
```

这会影响出场频率。

---

## 3️⃣ 读者不满点

```
节奏慢
战力崩
感情线拖
```

续写必须避坑。

---

## 4️⃣ 读者期待

```
希望揭开世界真相
希望主角复仇
希望CP在一起
```

这是“市场导向”。

---

# 五、伏笔与未完成事项（超级关键）

这是续写 agent 的“任务列表”。

必须单独建一个文件：

```
open_loops.md
```

记录：

```
未揭开的谜团
未兑现的承诺
未完成的目标
未出现的角色
```

这是续写剧情的燃料。

---

# 六、风格层（很多人忽略）

否则写出来不像原作。

需要提取：

```
叙事视角（第一/第三人称）
句长分布
对话比例
文风标签
常用意象
节奏特点
```

这可以用 AI 自动分析生成。

---

# 七、最终总结（核心）

预处理阶段你要构建的是：

```
剧情结构   → 故事走到哪
角色系统   → 谁在参与
世界模型   → 能做什么不能做什么
读者模型   → 市场想看什么
未完成事项 → 接下来写什么
风格模型   → 怎么写才像
```

这六大块完成后
AI 才算真正“读过这本小说”。

# 一、先纠正一个最关键的误区

现在不能直接进入“写章节”。

必须先设计一个新的 Agent：

👉 **Research Agent（写作前研究员）**

因为真正的流程应该是：

```
用户说：写第 201 章

→ Research Agent：查资料
→ Planner Agent：规划本章
→ Writer Agent：写正文
→ Editor Agent：审稿
```

没有 Research 这一步，KB=摆设。

---

# 二、写作前真正会发生什么（真实流程）

假设你让 Claude：

> 续写下一章

在优秀系统里，Claude **第一件事不是写作**。

而是执行：

```
STEP 0 读取 guide.md
STEP 1 确定当前写到哪
STEP 2 确定本章属于哪个 story arc
STEP 3 收集写作所需资料
STEP 4 生成“写作上下文包”
STEP 5 才开始写
```

重点来了：

👉 **写作前要生成一个 Context Bundle**

这就是 KB 真正的用途。

---

# 三、Context Bundle（最核心概念）

每一章写作前，都要自动生成一个文件：

```
context_bundle.md
```

它是“本章写作专用上下文”。

里面只包含：
**本章真正需要的信息**

而不是整个知识库。

---

## Context Bundle 包含什么？

固定六块：

```
1. 当前剧情位置
2. 相关主线进度
3. 当前活跃角色状态
4. 本章相关世界设定
5. 读者期待提示
6. 未完成伏笔
```

你会发现——
这正好对应你KB的六大层。

现在我们讲 **如何生成它**。

---

# 四、Research Agent 如何从 KB 抽取信息

假设要写 **ch0201**

Research Agent 要执行下面的“查资料流程”。

这就是你未来要写成 Claude skill 的核心 prompt。

---

## STEP 1：确定当前剧情位置

读取：

```
plot/chapters/index.md
```

找到：

* 最近 3–5 章摘要
* 当前 arc

然后读取：

```
plot/outline/arc_xx.md
plot/outline/plot_lines.md
```

得到：

```
当前剧情阶段
当前 arc 的目标
主线推进到哪里
```

写入 bundle：

```
## 当前剧情阶段
```

---

## STEP 2：找出“本章涉及角色”

从最近章节摘要提取角色名。

然后打开：

```
characters/{name}.md
```

只提取：

```
当前状态
人物弧光阶段
未完成目标
关系变化
```

写入：

```
## 当前角色状态
```

⚠️ 这一块权重极高。

---

## STEP 3：收集伏笔（剧情燃料）

读取：

```
plot/open_loops.md
```

筛选：

* 与当前 arc 相关
* 与当前角色相关

写入：

```
## 可推进伏笔
```

这一步决定剧情不会乱写。

---

## STEP 4：读取读者期待（市场导向）

读取：

```
reader/feedback/emotions.md
reader/feedback/expectations.md
reader/feedback/complaints.md
```

抽取：

```
本阶段应强化的情绪
需要避免的问题
```

写入：

```
## 写作注意事项（读者导向）
```

这一步非常关键。

---

## STEP 5：读取风格规则

读取：

```
style/index.md
```

写入：

```
## 写作风格约束
```

避免“像AI写的”。

---

# 五、最终生成的 Context Bundle 长这样

示例结构：

```
# Chapter 201 Writing Context

## 当前剧情阶段
主角刚逃离帝都，进入逃亡篇中段…

## 主线推进状态
主线A：复仇 → 准备阶段
主线B：世界真相 → 已出现新线索

## 当前角色状态
林修：
- 重伤恢复期
- 心理：愧疚+愤怒
- 未完成目标：找到叛徒

苏晚：
- 与主角关系修复初期

## 可推进伏笔
- 神秘组织仍未现身
- 叛徒身份未揭露

## 写作注意事项（读者）
- 强化情感互动
- 避免节奏拖慢

## 风格要求
- 第三人称近距离视角
- 对话比例高
```

这个文件通常只有 **1k–2k tokens**。

但信息密度极高。

检查爽点/节奏
