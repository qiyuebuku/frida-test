# T5：世界层提取

> 状态：✅ 已完成

## 目标

从章节摘要 + 弧文件 + 角色档案中提取世界观设定，构建完整的世界层知识库。世界观设定崩坏是续写中最常见的致命问题之一（"很多续写失败不是剧情问题，而是设定崩坏"），所以世界层必须做到精确、完整、结构化。

## 核心难题（6 大挑战）

1. **设定分散**：世界设定散布在 900+ 章中，不像角色信息集中在出场章节
2. **设定演化**：修炼等级等设定随剧情推进逐步揭示，需追踪"首次揭示章节"
3. **隐式设定**：部分规则未明说但可从角色行为推断（如等级限制）
4. **设定冲突**：前后矛盾的设定需要识别和标注（如等级描述不一致）
5. **分类模糊**：部分设定跨类别（如"仙宗"既是势力也关联力量体系）
6. **数据稀疏**：相比角色层，世界设定条目密度低但每条信息量大

## 前置条件

- T2（章节摘要）已完成：`{book-dir}/plot/chapters/chNNNN.md`
- T3（剧情层）已完成：`{book-dir}/plot/outline/arc_XX.md`
- T4（角色层）已完成：`{book-dir}/characters/*.md`

## 数据来源分析

### 来自 T2 章节摘要

每章摘要包含两个世界观相关字段：

- `## 新增设定`：显式的世界观设定（修炼体系、地理、社会规则等）
- `## 重要物品`：法宝、灵物等，可关联力量体系

格式示例：
```
## 新增设定
- 修仙世界的存在：有仙宗、仙人、神通、妖怪、鬼神
- 月华修炼体系：可吞吐月光精华获得能量

## 重要物品
- 青灰色铜镜：陆江仙附身的载体，可吞吐月华产生发光和感知能力
```

### 来自 T3 弧文件

每个 `arc_XX.md` 包含 `## 新世界信息` 段落，是该弧设定的汇总：

```
## 新世界信息
- **修仙体系**: 存在仙宗、仙人、神通、妖怪、鬼神等概念
- **月华修炼**: 月光可汇聚成月晕被吸收...
- **地理信息**: 大黎山是修仙者活动区域...
```

### 来自 T4 角色档案

角色档案中的身份信息可提取势力归属：
- 例：角色身份含"赤璧宗长老" → factions 增加赤璧宗成员

### 来自原文（阶段 3 按需回查）

对于关键设定（如修炼等级体系），可回查原文获取更详细的描写。

## 核心设计：分段扫描 + 全局融合 + 精修补充

### 与 T4 角色层的关键差异

| 维度 | T4 角色层 | T5 世界层 |
|------|----------|----------|
| 信息分布 | 按角色分散 | 按类别累积 |
| 处理策略 | 逐角色深度分析 | 分段分类 + 全局去重融合 |
| 数据密度 | 高（~20 条/章） | 低（~1-3 条/章） |
| Claude 调用 | ~30-57 次 | ~6-22 次 |
| 核心难点 | 别名合并 | 设定去重与演化追踪 |

## 四阶段 Pipeline 设计

### 阶段 0：Python 预处理（0 次调用）

Python 正则解析全部数据源，汇总为统一的 JSON：

- 遍历 T2 章节摘要：提取 `## 新增设定` + `## 重要物品`
- 遍历 T3 弧文件：提取 `## 新世界信息`
- 遍历 T4 角色档案：提取身份中的势力归属

输出：`world/.build/raw_world_data.json`

### 阶段 1：分段提取与分类（~1-10 次调用）

每 100 章的设定数据发送给 Claude，按 4+1 类分类：

- `power_system`：修炼等级、功法、法术、法宝能力
- `geography`：地点、区域、距离关系
- `factions`：组织、势力、门派
- `rules`：世界规则、社会习俗、禁忌
- `misc`：无法归类的条目

每条设定标记 `first_chapter`（首次揭示）和演化记录。

输出：`world/.build/segment_XX.json`

**小规模优化**：章节数 ≤50 时跳过阶段 1，直接进入阶段 2。

### 阶段 2：全局融合（1-2 次调用）

合并全部段级 JSON → 去重 + 演化追踪 → 生成 4 个 MD 文件 + index.md。

输入：段级 JSON + T4 角色势力信息
输出：`world/power_system.md`, `geography.md`, `factions.md`, `rules.md`

### 阶段 3：精修与原文补充（~0-10 次调用）

针对关键设定：
- 力量体系精修：补充修炼等级、法术细节
- 地理空间精修：补充距离关系、地点特征
- 组织势力精修：结合 T4 角色档案补充成员
- 一致性验证：检查设定冲突

输出：更新 4 个 MD 文件 + 验证报告

## 产出文件规格

### `power_system.md`（架构设计 5.3.1）

```markdown
# 力量体系

## 修炼等级
- 等级1：描述

## 等级限制
每个等级能做什么、不能做什么

## 修炼代价
提升等级需要付出什么

## 能力上限
当前已知的最强存在是什么级别

## 已出现的重要能力/法术
- {能力名}：效果，使用者，首次出现章节
```

### `geography.md`（架构设计 5.3.2）

```markdown
# 地理空间

## 主要区域/国家
- {区域名}：简述

## 重要城市/地点
- {地点名}：位于哪里，有什么特殊之处

## 空间距离关系
- A 到 B：大约多远/多久的路程

## 已发生关键事件的地点
- {地点}：chXX 发生了什么
```

### `factions.md`（架构设计 5.3.3）

```markdown
# 组织势力

## {势力名}
- 目标：
- 立场：
- 与其他势力的敌对/合作关系：
- 已知成员：
- 在故事中扮演的角色：
```

### `rules.md`（架构设计 5.3.4）

```markdown
# 世界规则与限制

## 硬性规则（绝对不能违反）
- 规则：描述

## 软性限制（通常情况下如此，但有例外）
- 限制：描述（例外情况）

## 社会规则/禁忌
- 规则：描述
```

### `index.md`

由 Python 直接生成，包含：
- 各类别条目数统计
- 链接到 4 个子文件
- 最后更新时间

## 验收标准

1. `--phase preprocess` 后 `raw_world_data.json` 正确解析全部设定条目
2. 全流程后 5 个 MD 文件格式符合架构设计模板
3. `--validate` 检查文件完整性和格式合规性
4. 设定条目有章节出处标注
5. 与 T4 角色档案中的势力信息一致
