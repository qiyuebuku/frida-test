## 1. 概述

### 1.1 系统目标

本系统解决的核心问题：**让 AI 从零开始写一部原创长篇网文小说，做到风格统一、设定零矛盾、节奏可预测、质量可量化**。

与已有的续写系统（novel-write）的区别：

| 维度 | 续写系统 (novel-write) | 原创系统 (本方案) |
|------|----------------------|-------------------|
| 输入 | 已有小说原文 + 知识库 | 一个创意点子 |
| 知识库来源 | 从原文自动提取 | 人工设计 + AI 辅助生成 |
| 风格参照 | 从原文学习 | 人工选定参考作品 + 风格定义 |
| 剧情来源 | 延续已有剧情 | 从大纲逐章展开 |
| 角色来源 | 已有角色档案 | 从角色设计文档创建 |
| 读者数据 | 有真实评论可分析 | 无（需通过设定目标读者画像替代） |
| 验证基准 | stats.json 从原文推导 | stats.json 从参考作品 + 人工设定推导 |

### 1.2 核心理念

**设计先行，写作执行。**

续写系统的核心是"上下文工程"——从已有文本中提炼结构化知识，按需加载。原创系统的核心则是"知识工程"——先设计完整的小说世界，再按设计图施工写作。

核心理念转化为三个阶段：

1. **设计阶段（Phase 0-3）**：人主导，AI 辅助。人类确定方向、做关键决策，AI 帮助拓展、细化、发现矛盾。
2. **初始化阶段（Phase 4）**：将设计阶段的产出转化为与续写系统完全兼容的知识库结构。
3. **写作阶段（Phase 5-7）**：最大程度复用续写系统已有的三 Subagent 架构和 L1-L3 验证体系。

### 1.3 与已有系统的复用关系

```
已有系统                          本方案复用方式
─────────────                    ──────────────────
novel-kb (T1-T7)                 复用知识库目录结构 + guide.md 模板
                                 跳过 T1（无原文）、T6（无评论数据）
                                 T2-T5 改为"从设计文档生成"而非"从原文提取"
                                 T7 改为"从参考作品学习 + 人工定义"

novel-write (7步流程)            完整复用 Step 2-7（Researcher/Enricher/Reviewer）
                                 Step 1（确定章节号）逻辑不变
                                 Step 4（用户确认）保留，且更重要

world-swarm                      复用蜂群模式并行处理世界观实体扩充

L1 定量检测                       完整复用 batch_verify.py + 12项指标
                                 stats.json 基线从参考作品 + 人工定义推导

L2 深度分析                       复用盲测对比 + 5维评分（对比参考作品段落）

L3 读者对齐                       无真实读者数据，改为"目标读者画像对齐"

验证评分公式                       切换到无读者数据模式：L1 x 0.45 + L2 x 0.55

6大写作技巧                       作为默认写作铁则内置
```

## 2. Phase 0：选题与创意

### 2.1 目标

确定小说的基本方向：写什么、怎么写、给谁看。

### 2.2 执行步骤

#### Step 0.1：确定题材类型

**人类角色**：做出最终选择。AI 可以分析各题材的市场特点、写作难度、读者群体。

**执行方式**：直接与 Claude 对话讨论。

**决策维度**：

| 维度 | 选项示例 | 影响范围 |
|------|----------|----------|
| 大类 | 仙侠 / 玄幻 / 都市 / 历史 / 科幻 / 悬疑 | 世界观复杂度、力量体系 |
| 子类 | 家族种田 / 升级流 / 系统 / 重生 / 穿越 | 剧情节奏、爽点模式 |
| 时代 | 古代 / 近代 / 现代 / 未来 | 用词体系、时间表达、禁忌词 |
| 基调 | 热血 / 沉稳 / 黑暗 / 轻松 / 严肃 | 叙事风格、情感表达方式 |

**产出**：`novel_kb/{book_name}/book_detail.md`

```markdown
# {书名}

- 作者：{笔名}
- 类型：{大类}/{子类}
- 时代背景：{时代}
- 基调：{基调关键词}
- 标签：{3-8 个标签}
- 目标字数：{XX 万字}
- 预计章节数：{XXX 章}
- 目标读者：{读者画像一句话}
- 简介：{200 字以内简介}
- 核心卖点：{1-3 个核心卖点}
```

#### Step 0.2：选定参考作品（风格锚定）

**人类角色**：选择 1-3 部风格接近的优秀作品作为风格参照。

**为什么需要参考作品**：原创写作没有"原文"可供学习。参考作品充当风格锚点——不是抄袭内容，而是学习叙事手法、节奏模式、用词习惯。

**执行方式**：

1. 人类选定参考作品
2. 用 `novel-kb` 对参考作品运行 T1 + T7，生成 `style/` 和 `stats.json`
3. 以参考作品的风格分析为基础，结合人工调整，确定本小说的风格参数

```bash
# 对参考作品构建风格层
/novel-kb novel_kb/参考作品名 --stage t1
/novel-kb novel_kb/参考作品名 --stage t7
```

**产出**：参考作品的 `style/narrative.md`、`style/vocabulary.md`、`style/rhythm.md`、`style/.build/stats.json`

#### Step 0.3：定义写作风格

基于参考作品的风格分析结果，人工确定本小说的风格参数。

**执行方式**：AI 辅助生成风格定义草案，人类审核修改。

**产出**：`novel_kb/{book_name}/style/`（初始版本）

```markdown
# style/narrative.md（初始版本）

## 叙事视角
{第一人称/第三人称近距离/第三人称全知}

## 情感表达方式
{参考 6 大技巧：克制情感表达，用动作替代直白情感词}

## 对话特征
{对话风格描述：口语化/书面化，标签偏好："道"系/现代}

## 动作描写手法
{简洁/华丽，偏实写/偏意象化}

## 叙述节奏
{快节奏/慢铺垫，场景切换频率}
```

```markdown
# style/vocabulary.md（初始版本）

## 禁忌词
- 现代时间表达（古代背景时）：下午3点、几分钟后...
- 直白情感词：十分愤怒、心中一喜、满心欢喜...
- 现代网络用语（非穿越角色）：卧槽、666...
- AI 味浓的表达：只见、忽然间、不禁...

## 时间表达
- 使用传统时辰：寅时、卯时、子时...
- 使用模糊表达：半柱香、一盏茶、片刻...

## 称呼系统
{根据题材定义：师兄/师叔/道友/掌门/族长 等}
```

```markdown
# style/rhythm.md（初始版本）

## 章均字数目标
{3000-5000 字，根据题材和节奏定}

## 章首类型偏好
{动作开场/环境开场/对话开场}

## 章尾类型偏好
{悬念结尾/场景结束/情感落点}

## 段落结构
{对话+动作融合，60-150 字段落}
```

#### Step 0.4：定义初始 stats.json

基于参考作品的统计数据 + 人工调整，生成初始量化基线。

**执行方式**：AI 从参考作品的 `stats.json` 提取关键指标，人类根据本小说的风格定位做调整。

**产出**：`novel_kb/{book_name}/style/.build/stats.json`

```json
{
  "source": "人工定义 + 参考作品 {参考作品名} 校准",
  "total_chars": {"avg_per_chapter": 3500, "range": [2800, 4500]},
  "sentence": {"avg_length": 40, "range": [30, 52]},
  "dialogue": {"ratio": 0.40, "range": [0.25, 0.55]},
  "paragraph": {"avg_length": 100, "range": [60, 150]},
  "short_sentence_rate": {"target": 0.30, "max": 0.40},
  "dialogue_tag": {"dao_style_ratio": {"target": 0.60, "min": 0.45}},
  "chapter_start_types": {"preferred": ["action", "environment"]},
  "chapter_end_types": {"preferred": ["suspense", "scene_end"]},
  "traditional_time": {"min_count": 1},
  "direct_emotion_words": {"max_count": 0},
  "modern_time_words": {"max_count": 0},
  "taboo_words": {"max_count": 0}
}
```

## 3. Phase 1：世界观构建

### 3.1 目标

设计完整的虚构世界，包括力量体系、地理空间、组织势力、世界规则。

### 3.2 与续写系统的区别

续写系统中，世界观由 `novel-kb` 的 T5 阶段从原文自动提取。原创系统中，世界观需要**从零设计**，然后写入相同的目录结构。

### 3.3 执行步骤

#### Step 1.1：力量体系设计

**人类角色**：确定力量体系的核心规则、限制、代价。这是最关键的设计决策之一——力量体系的严谨程度直接决定后续剧情的可信度。

**AI 角色**：辅助拓展细节（境界名称、突破条件、战力对比），检查逻辑一致性。

**设计维度**：

| 维度 | 说明 | 示例 |
|------|------|------|
| 境界体系 | 从低到高的修炼/实力层级 | 练气、筑基、金丹、元婴... |
| 突破条件 | 每个境界的晋升要求 | 资质、资源、悟性、机遇 |
| 战力上限 | 最高境界的能力边界 | 毁山、灭城、碎大陆 |
| 限制与代价 | 力量使用的限制 | 寿命消耗、反噬、消耗灵石 |
| 差异化 | 同境界内的实力差异 | 功法品质、战斗经验、法宝 |

**产出**：`novel_kb/{book_name}/world/power_system/`

```
world/power_system/
├── index.md              # 力量体系总览（境界表格 + 核心规则）
├── {境界体系名}.md        # 详细境界说明
├── {特殊能力}.md          # 特殊能力/功法/技能
└── {法宝体系}.md          # 法宝/装备/道具
```

#### Step 1.2：地理空间设计

**人类角色**：确定故事发生的主要地理范围、关键地点。

**AI 角色**：辅助填充细节（地形、气候、资源、相邻关系），生成地理描述。

**设计维度**：

| 维度 | 说明 |
|------|------|
| 主要区域 | 故事发生的世界/大陆/国家 |
| 关键地点 | 城市、秘境、宗门、家族驻地 |
| 地理关系 | 距离、方位、通行方式 |
| 各地特色 | 资源、气候、势力、文化 |

**产出**：`novel_kb/{book_name}/world/geography/`

```
world/geography/
├── index.md              # 地理总览（世界地图级）
├── {区域名}.md            # 区域详情
└── {重要地点}.md          # 重要地点详情
```

#### Step 1.3：组织势力设计

**人类角色**：确定主要势力、势力间关系、势力目标。

**AI 角色**：辅助细化势力结构（内部层级、成员、运作方式），检查势力间关系的逻辑一致性。

**设计维度**：

| 维度 | 说明 |
|------|------|
| 势力列表 | 宗门、家族、帝国、商会、暗组织等 |
| 势力关系 | 同盟、敌对、从属、暗中合作 |
| 势力目标 | 每个主要势力的核心诉求 |
| 势力实力 | 势力的综合实力评估 |

**产出**：`novel_kb/{book_name}/world/factions/`

```
world/factions/
├── index.md              # 势力总览（势力关系图 + 实力对比）
├── {势力名}.md            # 势力详情
└── {势力间关系}.md        # 重要势力关系详情
```

#### Step 1.4：世界规则设计

**人类角色**：确定"不能打破的规则"——这是防止后续剧情崩坏的关键。

**AI 角色**：辅助检查规则间的矛盾，提示潜在漏洞。

**设计维度**：

| 维度 | 说明 | 示例 |
|------|------|------|
| 硬性规则 | 绝对不能违反的规则 | 死人不能复生、时间不能倒流 |
| 经济规则 | 资源的获取与消耗 | 修炼资源稀缺性、交易规则 |
| 社会规则 | 社会运行的基本法则 | 宗门等级制度、家族继承规则 |
| 自然规则 | 世界运行的自然法则 | 天劫、灵气浓度、气运 |

**产出**：`novel_kb/{book_name}/world/rules/`

```
world/rules/
├── index.md              # 规则总览
├── {规则类别}.md          # 规则详情
```

#### Step 1.5：生成 world/index.md

AI 自动从以上各子目录汇总生成世界层总览。

**产出**：`novel_kb/{book_name}/world/index.md`

### 3.4 使用 world-swarm 并行处理

当世界观实体数量较多（超过 20 个）时，可使用 world-swarm 的蜂群模式并行生成实体详情：

```bash
# 先完成 index.md 和基础实体列表
# 然后用 world-swarm 并行扩写每个实体
/world-swarm novel_kb/{book_name} --phase refine --concurrency 4
```

## 4. Phase 2：角色设计

### 4.1 目标

创建立体、有深度的人物角色，包括性格、动机、成长弧线、关系网络。

### 4.2 与续写系统的区别

续写系统中，角色档案由 `novel-kb` 的 T4 阶段从原文自动提取。原创系统中，角色需要**从零设计**，但写入相同的 `characters/` 目录结构，使后续写作阶段可以无缝使用。

### 4.3 执行步骤

#### Step 2.1：确定核心角色清单

**人类角色**：确定主要角色名单——主角、重要配角、主要反派。

**AI 角色**：根据题材和故事类型，建议常见角色类型和配置。

**设计维度**：

| 角色分级 | 数量 | 说明 |
|----------|------|------|
| 核心角色 | 1-3 个 | 主角 + 核心对手/伙伴，每章必出场或被提及 |
| 重要角色 | 5-10 个 | 关键配角，频繁出场，有独立弧线 |
| 次要角色 | 10-30 个 | 阶段性角色，服务于特定剧情 |
| 背景角色 | 不限 | 一笔带过的路人，不需要独立档案 |

#### Step 2.2：创建角色档案

**每个核心/重要角色**需要完整的 5 模块档案（与续写系统角色档案结构完全兼容）：

```markdown
# {角色名}

## 模块 1：基本设定

- 姓名：{全名}
- 别名/称号：{外号、道号、笔名等}
- 年龄：{出场年龄}
- 身份：{社会身份/职业/势力归属}
- 外貌：{关键外貌特征（2-3 个辨识度高的特征即可）}
- 核心性格（3-5 个关键词）：{如：沉稳、隐忍、重情义}
- 核心动机：{驱动这个角色行动的根本原因}
- 核心恐惧：{角色最害怕的事情}
- 执念：{角色放不下的东西}

## 模块 2：说话特征

- 语气风格：{如：沉稳少言、说话带刺、啰嗦热情}
- 常用句式：{如：反问句、短句为主}
- 口头禅/标志性表达：{如有}
- 称呼习惯：{对上级/平级/下级的不同称呼}
- 特殊用词：{如：文言腔、方言、现代俚语}

## 模块 3：能力与成长

- 当前实力：{境界/等级/能力水平}
- 核心能力：{最擅长什么}
- 短板：{不擅长什么}
- 成长路线（计划）：{从起点到终点的实力成长轨迹}

## 模块 4：关系网络

| 对象 | 关系 | 态度 | 演化方向（计划） |
|------|------|------|------------------|
| {角色B} | 师徒 | 尊敬 | 后期信任危机 |
| {角色C} | 敌对 | 警惕 | 中期合作 |

## 模块 5：角色弧线（计划）

- 起点：{初始状态，如：懦弱的少年}
- 第一转折：{触发改变的事件}
- 中期状态：{如：开始主动承担责任}
- 第二转折：{更大的挑战或挫折}
- 终点：{最终状态，如：独当一面的领袖}
```

**产出**：`novel_kb/{book_name}/characters/{角色名}.md`

#### Step 2.3：构建关系网

AI 根据各角色档案中的关系模块，自动生成全局关系网。

**产出**：`novel_kb/{book_name}/characters/relationships.md`

```markdown
# 角色关系网

## 核心关系

### {角色A} ↔ {角色B}
```

## 5. Phase 3：大纲规划

### 5.1 目标

规划整体剧情结构，包括主线、支线、节奏曲线、伏笔网络。这是整个系统中最依赖人类创造力的环节。

### 5.2 与续写系统的区别

续写系统中，剧情结构由 T2（章节摘要）+ T3（剧情层）从原文自动提取。原创系统中，剧情需要**从零规划**，但写入相同的 `plot/` 目录结构。

### 5.3 执行步骤

#### Step 3.1：确定全局主线

**人类角色**：确定 1-3 条贯穿全书的主线。

**AI 角色**：辅助检查主线间是否有矛盾，是否覆盖足够的故事空间。

**设计维度**：

| 维度 | 说明 |
|------|------|
| 主线数量 | 1-3 条（1 主 + 0-2 副） |
| 主线目标 | 每条主线的终点是什么 |
| 主线起点 | 从哪里开始铺垫 |
| 主线节奏 | 大约多少章推进一次 |

**产出**：`novel_kb/{book_name}/plot/outline/plot_lines.md`

```markdown
# 全局主线追踪

## 主线 A：{主线名称}（核心主线）
- **目标**：{这条主线的终点}
- **起点**：ch001，{如何铺垫}
- **推进节奏**：每 20-30 章推进一次
- **当前状态**：未开始

| 章节 | 推进内容 | 状态 |
|------|----------|------|
| ch001-030 | {铺垫阶段} | 未开始 |
| ch031-060 | {第一次推进} | 未开始 |
| ... | ... | ... |

```

#### Step 3.2：规划故事弧

将全书划分为若干故事弧（每弧 20-50 章），每个弧有明确的起承转合。

**人类角色**：确定弧的划分、核心冲突、转折点。

**AI 角色**：辅助检查弧与弧之间的衔接、节奏分布。

**设计维度**：

| 维度 | 说明 |
|------|------|

| 弧核心冲突 | 每个弧要解决的核心矛盾 |
| 弧转折点 | 弧内 2-3 个关键转折 |
| 弧间衔接 | 上一弧结尾如何过渡到下一弧 |

## 7. Phase 5：章节写作

### 7.1 核心原则

**最大程度复用 `novel-write` 的三 Subagent 架构。**

原创小说的章节写作与续写在机制上几乎相同——都是从知识库中提取信息，规划章节，写正文，验证质量。区别仅在于：

| 区别点 | 续写 | 原创 |
|--------|------|------|
| 上一章衔接 | 读原文最后 500 字 | 读上一章草稿最后 500 字（无原文时读大纲的衔接指引） |
| 风格锚点 | 从原文精选 | 从参考作品精选 |
| 剧情来源 | 延续已有剧情 | 按大纲展开 |
| 验证基准 | 与原文对比 | 与参考作品对比 + 大纲一致性检查 |

### 7.2 写作流程（7 步，复用 novel-write）

#### Step 1：确定章节号

```bash
/novel-write novel_kb/{book_name} --chapter 1
```

系统读取 `guide.md` 和 `plot/chapters/index.md`，确定下一章章节号。

#### Step 2：Research（Researcher Subagent）

Researcher 读取知识库生成 Context Bundle。

**与续写的区别**：
- S1（故事位置）：从 `plot/outline/arc_01.md` 和 `plot_lines.md` 获取，而非从已有章节摘要推断
- S2（场景角色）：从 `characters/{name}.md` 的初始状态获取
- S5（上一章衔接）：第一章时，使用弧描述中的开篇指引替代；后续章节使用 `drafts/ch{N-1}.md` 的最后部分

**额外输入**：当前章节对应的大纲规划（从 `arc_XX.md` 的关键节点表中提取），Researcher 需要基于大纲规划生成具体的章节大纲。

#### Step 3：Enrich（Enricher Subagent）

与续写完全一致——按名词清单从知识库搜索角色档案、世界设定，生成 Scene Plan。

#### Step 4：用户确认

**原创小说中这一步更加关键**——因为大纲是"规划"而非"已有事实"，人类作者需要确认 AI 的理解和展开方向是否符合创作意图。

#### Step 5：写全章正文

与续写完全一致——主 Agent 基于极度干净的上下文写全章。

#### Step 6：Review（Reviewer Subagent）

**与续写的区别**：
- L2 盲测对比：对比参考作品段落而非原文段落
- L3 读者对齐：改为"大纲一致性检查"——验证草稿是否忠实于大纲规划

#### Step 7：结果处理

与续写一致。

### 7.3 操作模式

与续写系统完全一致的命令接口：

```bash
# 正常写作
/novel-write novel_kb/{book_name}

# 带提示写作
/novel-write novel_kb/{book_name} --hint "本章重点写主角第一次使用灵力"

# 自动循环
/novel-write novel_kb/{book_name} --auto

# 修复
/novel-write novel_kb/{book_name} --revise 5

# 验证
/novel-write novel_kb/{book_name} --verify 5

# 反哺
/novel-write novel_kb/{book_name} --promote 5
```

## 8. Phase 6：质量控制

### 8.1 三级验证体系（复用）

#### L1 定量检测（完全复用）

12 项指标，从 `stats.json` 动态推导阈值。`stats.json` 在原创场景下来自 Phase 0.4 的人工定义 + 参考作品校准。

**无需改动**——`batch_verify.py` 只读 `stats.json`，不关心数据来源。

#### L2 深度分析（小幅调整）

| 调整点 | 续写 | 原创 |
|--------|------|------|
| 盲测对比源 | 原文段落 | 参考作品段落 |
| 一致性检查 | 与原文风格一致 | 与定义的风格一致 |
| 评分基准 | stats.json 来源于原文统计 | stats.json 来源于人工定义 |

**实施方式**：Review subagent 的模板 (`reviewer_agent.md`) 需要支持"无原文"模式——当 `text/` 目录中无对应原文时，自动切换到参考作品对比模式。

#### L3 大纲一致性检查（替代读者对齐）

原创小说没有真实读者数据，L3 从"读者对齐"改为"大纲一致性检查"：

| 检查维度 | 说明 |
|----------|------|
| 剧情节点命中 | 本章是否推进了大纲中规划的剧情节点 |
| 角色行为一致 | 角色行为是否符合角色档案中的性格设定 |
| 伏笔执行 | 是否按计划铺设/推进了伏笔 |
| 节奏匹配 | 本章的紧张度是否符合弧节奏曲线的规划 |

**评分公式**：

```
原创模式：总分 = L1 × 0.40 + L2 × 0.35 + L3 × 0.25
```

## 9. Phase 7：知识库维护

### 9.1 核心原则

**每写完一章，知识库都要同步更新。** 这是保证长篇写作设定一致性的关键。

### 9.2 反哺流程（复用 --promote）

每章完成后执行 `--promote`，系统自动：

1. 将正文复制到 `text/ch{NNNN}.md`
2. 调用 Claude 生成结构化摘要，保存到 `plot/chapters/ch{NNNN}.md`
3. 更新 `plot/chapters/index.md` 章节索引

### 9.3 人工维护项

以下项目需要人工（或 AI 辅助）在每弧结束后更新：

| 项目 | 更新频率 | 说明 |
|------|----------|------|
| 角色当前状态 | 每 5-10 章 | 更新 `characters/{name}.md` 的当前状态模块 |
| 角色关系变化 | 每弧结束 | 更新 `characters/relationships.md` |
| 伏笔状态 | 每章 | 更新 `plot/open_loops.md`（铺设/推进/回收） |
| 时间线 | 每章 | 更新 `plot/timeline/index.md` |
| 主线进度 | 每弧结束 | 更新 `plot/outline/plot_lines.md` |
| 弧完成状态 | 每弧结束 | 标记弧文件状态为"已完成" |
| stats.json | 每 50 章 | 用已写章节重新校准量化基线 |

### 9.4 AI 辅助维护

可以在每弧结束后，用 AI 辅助批量更新知识库：

```bash
# 对已写章节重新运行 T2-T5，更新知识库
/novel-kb novel_kb/{book_name} --stage t2    # 重新生成章节摘要
/novel-kb novel_kb/{book_name} --stage t3    # 更新剧情层
/novel-kb novel_kb/{book_name} --stage t4    # 更新角色层
/novel-kb novel_kb/{book_name} --stage t7    # 重新校准风格基线
```

这种"设计 → 写作 → 重新提取"的循环，会随着写作推进，让知识库越来越丰富，越来越准确。前 50 章主要由大纲驱动，50 章之后知识库中有了足够的已写文本，系统行为会越来越像续写模式。

```
  - 检查所有文件完整性
  - 生成 guide.md

```

## 11. 典型工作流

### 11.1 从零到第一章

```bash
# ========== Phase 0：选题 ==========
# 与 Claude 对话讨论题材、参考作品、风格

# 创建知识库目录
mkdir -p novel_kb/我的仙侠小说

# 手动创建 book_detail.md（或让 novel-create 辅助）

# 对参考作品构建风格层
/novel-kb novel_kb/玄鉴仙族 --stage t7

# 将参考作品风格文件复制到新书目录，人工调整
cp novel_kb/玄鉴仙族/style/.build/stats.json novel_kb/我的仙侠小说/style/.build/
# 人工编辑 style/narrative.md, vocabulary.md, rhythm.md

# ========== Phase 1：世界观 ==========
# 人工设计力量体系、地理、势力、规则
# 写入 world/ 目录

# ========== Phase 2：角色 ==========
# 人工设计角色档案
# 写入 characters/ 目录

# ========== Phase 3：大纲 ==========
# 人工规划主线、弧、伏笔
# 写入 plot/ 目录

# ========== Phase 4：初始化 ==========
/novel-kb novel_kb/我的仙侠小说 --stage guide

# ========== Phase 5：开始写作 ==========
/novel-write novel_kb/我的仙侠小说 --chapter 1 --hint "主角在村子里被发现有灵根"

# 满意后反哺

# 继续下一章
/novel-write novel_kb/我的仙侠小说

# ========== 循环写作 ==========
# 每章：写 → 验 → 修 → 反哺 → 下一章
```

## 12. 命令速查表

### 12.1 知识库初始化

```bash
# ========== 创建目录结构 ==========
mkdir -p novel_kb/{book_name}/{text,plot/chapters,plot/outline,plot/timeline,characters,world/power_system,world/geography,world/factions,world/rules,style/.build,drafts}

# ========== 参考作品风格提取 ==========
/novel-kb novel_kb/{参考作品} --stage t7    # 仅提取风格层

# ========== 生成 guide.md ==========
/novel-kb novel_kb/{book_name} --stage guide
```

### 12.2 章节写作（完全复用 novel-write）

```bash
# ========== 正常写作 ==========
/novel-write novel_kb/{book_name}
/novel-write novel_kb/{book_name} --chapter 1
/novel-write novel_kb/{book_name} --hint "..."

# ========== 自动循环 ==========
/novel-write novel_kb/{book_name} --auto

# ========== 修复 ==========
/novel-write novel_kb/{book_name} --revise N

# ========== 验证 ==========
/novel-write novel_kb/{book_name} --verify N

# ========== 反哺 ==========
/novel-write novel_kb/{book_name} --promote N

# ========== 历史 ==========
/novel-write novel_kb/{book_name} --history
```

### 12.3 知识库维护

```bash
# ========== 每弧结束后更新知识库 ==========
/novel-kb novel_kb/{book_name} --stage t2    # 更新章节摘要
/novel-kb novel_kb/{book_name} --stage t3    # 更新剧情层
/novel-kb novel_kb/{book_name} --stage t4    # 更新角色层
/novel-kb novel_kb/{book_name} --stage t7    # 重新校准风格基线

# ========== 重新生成 guide.md ==========
/novel-kb novel_kb/{book_name} --stage guide
```

## 附录 B：与续写系统的差异对照表

| 环节 | 续写系统 | 原创系统 | 复用比例 |
|------|----------|----------|----------|
| 知识库来源 | novel-kb T1-T7 自动提取 | Phase 0-3 人工设计 + AI 辅助 | 结构 100% 复用 |

| T4 角色层 | 从摘要提取 | 人工设计角色 | 产出格式复用 |

| T7 风格层 | 从原文分析 | 参考作品 + 人工定义 | 产出格式复用 |
| Researcher | 从 KB 提取上下文 | 同左（增加大纲读取） | ~90% 复用 |
