│  Android App    │ ──────────────────►  │  smart-fund-server   │

│  - SSE 接收结果  │                      │  - 保存 sa_ocr_records│

**问题**：
1. App 发送截图后**必须等待**服务端 OCR + LLM 处理完毕（SSE 阻塞）
2. 持仓分析等重操作需要额外手动在 CLI 执行 `claude -p` 才能获得深度分析
3. 所有结果都是**一次性的**，无法回溯历史
4. App 只有「截屏→返回文字」的单一交互模式，无法展示结构化的分析报告

## 三、核心思路

### 3.1 「提交即走」模式

**改造前**：App 截图 → 等待 SSE → 收到结果（阻塞数十秒到数分钟）
**改造后**：App 截图 → 提交到服务端 → 立即返回 task_id → 提示「稍后查看结果」

```
用户操作流程:
1. 点击悬浮球 → 选择「持仓分析」→ 自动截屏+拼接
2. App 上传截图到服务端，收到 task_id
3. App 弹出 Toast：「已提交分析，稍后在任务列表中查看」
4. 用户随时打开 App 查看任务列表 → 看到进度 → 点进去看完整报告
```

### 3.2 统一任务系统

所有异步操作统一为「任务」概念，不限于持仓分析：

| 任务类型 | 触发方式 | 处理时长 | 输出 |
|----------|----------|----------|------|
| `fund_holdings` | 截屏 | 2-5 分钟 | 持仓分析报告（Markdown） |
| `chat_reply` | 截屏 | 10-30 秒 | 智能回复建议 |
| `ocr` | 截屏 | 5-10 秒 | 识别文字 |
| `table` | 截屏 | 5-10 秒 | 表格数据 |
| `fund_trade_run` | 定时/手动 | 5-10 分钟 | 今日交易决策报告 |
| `fund_review` | 定时/手动 | 3-5 分钟 | 持仓审视报告 |

### 3.3 服务端全权处理

**关键改变**：分析逻辑**完全在服务端执行**，App 只负责截屏和展示。

服务端通过 `claude -p` 调用 Claude CLI：
```bash
# 示例：持仓分析
claude -p "$(cat prompts/ocr_analyze.md)" --skill fund-trade
```

这意味着 `/home/yuyang/frida-test/.claude/skills/fund-trade` 需要部署到远端服务器。

### 3.4 保留快速响应通道

对于**轻量任务**（OCR 文字识别、表格识别），保留现有 SSE 同步模式：
- 耗时 < 15 秒的任务 → SSE 直接返回（兼容旧逻辑）
- 耗时 > 15 秒的任务 → 异步任务模式

判断标准写在 `ActionConfig` 中，由 App 端决定走哪条路径。

## 四、技术选型

| 组件 | 方案 | 理由 |
|------|------|------|
| 异步任务执行 | Python `threading` + `subprocess` | 简单可靠，`claude -p` 本身是独立进程 |
| 进度追踪 | 数据库轮询（GET /api/tasks/{id}） | 实现简单，任务粒度粗（分钟级），无需 WebSocket |
| AI 分析 | `claude -p`（Claude Code CLI pipe 模式） | 可直接使用 fund-trade skill，无需拆分逻辑 |
| App 端渲染 | Markdown → HTML WebView | 分析报告是 Markdown 格式，WebView 渲染最灵活 |
| 图片存储 | 服务器本地文件 + 数据库记录路径 | 现有方案，无需改动 |
