# 03 - App UI 改造（v2 重新设计）

## 设计原则

**用户打开 App 的目的**：
1. 查看任务结果（最高频）— 截屏分析、交易决策的报告
2. 配置任务行为（中频）— 设置每种任务类型的系统提示词、分析规则
3. 手动触发 AI 分析（偶尔）— 每日决策、持仓审视

**v1 的问题**：
- 快捷操作（OCR/回复/表格/搜索）放在首页毫无意义 — 这些操作需要先打开其他 App 再通过悬浮球截图，在自己的主页里点击没有任何效果
- AI 分析只有 2 个按钮，单独一个区域浪费空间
- 首页和任务列表功能重叠（都展示任务卡片），两个 tab 没必要

**v2 方案**：砍掉首页，任务列表作为主页面，两个 tab 足够。

**布局说明**：

**与 v1 的区别**：
- 去掉了无用的「快捷操作」2x2 网格
- AI 分析从独立区域压缩为一行按钮条
- 合并了原来的「首页」和「任务列表」两个 tab，消除重复
- 底部导航从 3 tab 减为 2 tab

**配置项说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 系统提示词 | 多行文本 | 发送给 LLM 的 system prompt，控制输出风格和内容 |
| 输出规则 | 多行文本 | 附加约束条件，拼接在提示词之后 |
| 处理模式 | 下拉选择 | 同步 SSE（轻量）或 异步任务（重型），决定走哪个 API |
| 超时时间 | 数字 | 任务最大执行时间（秒） |

**各任务类型的默认配置**：

| 任务类型 | 默认提示词 | 默认模式 | 默认超时 |
|----------|-----------|---------|---------|
| ocr | "识别图片中的文字，保持原始格式" | 同步 SSE | 30s |
| chat_reply | "根据聊天截图生成 3 种风格回复" | 同步 SSE | 60s |
| table | "识别图片中的表格，输出 Markdown 表格" | 同步 SSE | 30s |
| search | "在识别的文字中搜索相关内容" | 同步 SSE | 30s |
| fund_holdings | "分析基金持仓，采集市场数据，输出分析报告" | 异步任务 | 600s |
| full_page | "识别完整页面内容" | 异步任务 | 120s |

**配置存储**：
- App 端：SharedPreferences 或 DataStore，key 为 `task_config_{taskType}`
- 提交任务时：将配置作为 `system_prompt` 和 `rules` 字段一并发送给服务端
- 服务端：`sa_tasks` 表新增 `config` JSONB 字段存储任务配置

**数据模型变更**：

当前 `ActionConfig` 是硬编码的：
```kotlin
object Actions {
    val ALL = listOf(
        ActionConfig("ocr", "识别文字", "text_fields", CaptureType.NORMAL, "提取屏幕文字"),
        ActionConfig("chat_reply", "智能回复", "chat", CaptureType.NORMAL, "分析聊天并推荐回复"),
        // ... 7 个固定操作
    )
}
```

改造后：
```kotlin
// 内置操作（不可删除，可编辑提示词/规则/顺序/显隐）
val BUILTIN_ACTIONS = listOf(
    ActionConfig("ocr", "识别文字", "text_fields", CaptureType.NORMAL, "提取屏幕文字"),
    ActionConfig("chat_reply", "智能回复", "chat", CaptureType.NORMAL, "分析聊天并推荐回复"),
    ActionConfig("table", "表格识别", "table_chart", CaptureType.NORMAL, "识别表格数据"),
    ActionConfig("search", "搜索内容", "search", CaptureType.NORMAL, "识别后搜索"),
    ActionConfig("fund_holdings", "持仓分析", "account_balance", CaptureType.LONG_SCROLL, "自动滚动采集完整持仓"),
    ActionConfig("full_page", "完整页面", "article", CaptureType.LONG_SCROLL, "自动滚动截取完整页面"),
    ActionConfig("manual_scroll", "手动长截", "pan_tool", CaptureType.MANUAL_SCROLL, "手动滑动，自动采集"),
)

// 扩展后的 ActionConfig
data class ActionConfig(
    val id: String,
    val name: String,
    val icon: String,
    val captureType: CaptureType,
    val description: String,
    val isBuiltin: Boolean = true,      // 内置操作不可删除
    val enabled: Boolean = true,         // 是否在悬浮窗中显示
    val sortOrder: Int = 0,             // 排序权重
    val systemPrompt: String? = null,   // 自定义系统提示词（null 用默认）
    val rules: String? = null,          // 自定义输出规则
    val processingMode: String = "auto", // auto / sync_sse / async_task
    val timeoutSec: Int = 120,          // 超时时间
)

// Actions 从 DataStore 读取，合并内置 + 自定义
object Actions {
    fun getAll(context: Context): List<ActionConfig> {
        val saved = dataStore.load()    // 用户自定义配置
        val custom = dataStore.loadCustomActions()  // 用户创建的自定义操作
        return (BUILTIN_ACTIONS.map { mergeWithSaved(it, saved) } + custom)
            .filter { it.enabled }
            .sortedBy { it.sortOrder }
    }
}
```

**悬浮窗菜单数据流**：
```
DataStore (持久化)
    ↓ 读取
Actions.getAll()
    ↓ 过滤 enabled + 排序
FloatingWindowService 菜单渲染
    ↓ 用户点击
发送截图 + 附带该操作的 systemPrompt / rules
    ↓
服务端使用自定义提示词处理
```
