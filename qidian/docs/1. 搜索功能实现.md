**Hook 目标类**：

### Phase 2：手动搜索收集日志

在 App 中手动搜索关键词 `zheguang`，通过 Hook 日志捕获完整调用链。

### Phase 3：分析日志定位入口

从日志中提取出完整的搜索流程：

```
打开搜索页
  → QDSearchActivity.onCreate()
  → API: booksearch/getbooksearchconf
  → API: booksearch/getsearchpage

输入关键词（逐字触发）
  → getOperateKey("z" → "zh" → ... → "zheguang")
  → API: booksearch/autocomplete（每字符 8 次并发）

点击搜索
  → onClick → goSearch → search("zheguang", Integer)      ← 核心入口
  → searchAlias("zheguang", Integer, Boolean)
  → API: searchalias/get?key=zheguang
  → I(activity, "zheguang", Integer)                       ← 实际执行
  → API: booksearch/searchbooks                            ← 核心 API
  → setResultStatus("1")
```

**核心发现**：
- 搜索入口方法：`QDSearchActivity.search(String keyword, Integer type)`
- 搜索 API：`POST https://druidv6.if.qidian.com/argus/api/v2/booksearch/searchbooks`

### Phase 4：实现 RPC 搜索

**方案选择**：

| 方案 | 结论 | 原因 |
|------|------|------|
| 调用 `QDSearchActivity.search()` | 放弃 | 需要 Activity 实例和 UI 线程 |
| 调用 Repository/ViewModel 方法 | 放弃 | 类名被混淆，参数复杂 |
| **复用 OkHttpClient 直接发 HTTP** | **采用** | 无需 UI，签名拦截器自动处理 |

**OkHttpClient 捕获演进**：

| 尝试 | 方法 | 结果 |
|------|------|------|
| 1 | Hook `Builder.build()` afterCall | 失败 — 捕获的是第一个 build 的客户端，往往是 Glide 等非 API 客户端，**不带签名拦截器** |
| 2 | Hook `newCall()` 捕获第一个 client | 部分成功 — 同上问题，可能捕获到非 API 的 client |
| 3 | 从 searchbooks 请求的 RealCall 提取 | 成功但需手动搜索一次 |
| 4 | 从任意 `qidian.com` URL 的 RealCall 提取 | 部分成功 — 但条件 `savedOkHttpClient == null` 导致 Builder.build() 已先占位 |
| **最终** | 从 `druidv6.if.qidian.com/argus` 请求的 RealCall 提取 | **完全成功** — 精确匹配 API 域名，使用 `apiClientCaptured` 标志确保只捕获一次 |

> **重要教训**：OkHttpClient 捕获是所有 RPC 功能的基础。捕获错误的客户端会导致所有请求返回 HTTP 402 签名错误。必须确保从**带签名拦截器的 API 客户端**捕获，而非通用的 HTTP 客户端。

**Fallback 硬编码模板**（100% 免 UI 的关键）：

App 启动时无需手动搜索来捕获模板，直接使用硬编码的 fallback：
- URL：`https://druidv6.if.qidian.com/argus/api/v2/booksearch/searchbooks`
- 方法：POST（FormBody）
- 参数：`keywordType=1&siteId=1&keyword={keyword}&pageSize=20&pageIndex={page}`

如果后续有真实搜索请求经过，会自动升级为动态捕获的模板。

**搜索模板双路径机制**：

搜索 RPC 命令内部同时支持两种模板来源，由 `searchUrlTemplate` 是否为 null 决定：

| 路径 | 条件 | URL 来源 | Body 来源 | 使用场景 |
|------|------|----------|----------|----------|
| **Fallback 硬编码** | `searchUrlTemplate == null` | `FALLBACK_SEARCH_URL` 常量 | `FALLBACK_SEARCH_BODY` 常量中替换 `{keyword}` 和 `{page}` | App 刚启动、用户从未手动搜索过 |
| **动态模板** | `searchUrlTemplate != null` | 从上次搜索请求中捕获的 URL | 从上次搜索请求中捕获的 Body | 用户手动搜索过一次后 |

动态模板在 `RealCall.enqueue/execute` hook 中捕获：当请求 URL 包含 `searchbooks` 时，自动保存 URL、HTTP 方法和 Body 为模板（代码位置：`MainHook.java:1524-1539`）。参数替换在 `buildSearchUrl()` 和 `buildSearchBody()` 中完成，使用正则匹配已知的参数名（keyword/kw/key/query/q 等）进行值替换。

> **重要**：两种路径都依赖 `savedOkHttpClient`（带签名拦截器），不同的只是 URL 和 Body 模板来源。

## 三、关键技术决策

### 3.1 必须用 FormBody 构造 POST body

App 的签名拦截器从 `FormBody` 键值对中读取内容计算签名。如果用 `RequestBody.create()` 构造 body，拦截器无法解析，导致签名不匹配（HTTP 402）。

### 3.2 HTTP 402 签名错误调试

连续遇到 4 次 402，每次原因不同：

| 次数 | 原因 | 修复 |
|------|------|------|
| 1 | POST 请求时错误修改了 URL | POST 时 URL 保持原样 |
| 2 | 用 `RequestBody.create()` 构造 body | 改用 `FormBody.Builder` |
| 3 | 捕获的 OkHttpClient 来自非 API 请求 | 改为从 `qidian.com` URL 的 RealCall 精确提取 |
| 4 | `Builder.build()` 抢先设置了非 API 客户端，`null` 检查阻止了后续 API 客户端覆盖 | 移除 `null` 检查，改为精确匹配 `druidv6.if.qidian.com/argus` + `apiClientCaptured` 标志 |

> HTTP 402 是起点 API 的签名校验失败响应，响应体为 `{"Result":-3,"Message":"签名错误"}`。遇到 402 时首先检查 `savedOkHttpClient` 是否为正确的 API 客户端。

### 3.3 两种响应格式

API 返回两种结构，客户端需兼容：
- **CardList 格式**：`Data.CardList[].Body[].ItemData.BookName`
- **BookList 格式**：`Data.BookList[].BookName`

## 四、搜索 API 参考

### 4.1 核心搜索 API

| 项目 | 值 |
|------|------|
| URL | `https://druidv6.if.qidian.com/argus/api/v2/booksearch/searchbooks` |
| 方法 | POST |
| Content-Type | application/x-www-form-urlencoded（FormBody） |
| 签名 | OkHttp 拦截器自动处理 |

**POST 参数**：

| 参数 | 值 | 说明 |
|------|------|------|
| `keywordType` | 1 | 固定 |
| `siteId` | 1 | 固定（起点中文网） |
| `keyword` | 搜索词 | URL 编码 |
| `pageSize` | 20 | 每页结果数 |
| `pageIndex` | 1 | 页码（从 1 开始） |

### 4.2 搜索相关 API 全览

| API 路径 | 触发时机 | 说明 |
|----------|---------|------|
| `booksearch/getbooksearchconf` | 打开搜索页 | 搜索配置 |
| `booksearch/getsearchpage` | 打开搜索页 | 搜索页数据 |
| `booksearch/shardWord` | App 启动 | 热词 |
| `booksearch/autocomplete` | 输入关键词 | 自动补全 |
| `searchalias/get?key=` | 提交搜索 | 别名查询 |
| **`booksearch/searchbooks`** | **提交搜索** | **核心搜索** |

### 4.3 RPC 调用方式

```json
{"cmd": "search", "keyword": "斗破苍穹", "page": 1}
```
