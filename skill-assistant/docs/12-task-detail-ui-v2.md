# 任务详情页 UI 重设计方案

## 现状问题

基于截图和代码分析（`TaskDetailScreen.kt`），当前 UI 存在以下问题：

### 标题栏
- 标题字体 14sp，太小，在深色背景上辨识度低
- 状态圆点 8dp 太小，不够醒目
- 返回箭头 18dp 偏小，点击区域不够友好
- 时间/进度信息和标题挤在同一行，信息层级不清晰

### 底栏
- 停止按钮放在底部输入框下方，占用固定高度（36dp 占位）
- 任务完成后停止按钮消失，底部留白浪费空间
- 之前为了防止底栏高度变化导致终端跳动，用 `Spacer(36.dp)` 占位，方案不优雅

### 其他
- 复制按钮（右上角）用处不大，删除
- 进度条在之前的改动中加到了标题栏下方，但用户反馈看不到

---

## 设计方案

### 1. 标题栏重设计

**布局**：两行结构，信息层级分明

```
┌──────────────────────────────────────────────┐
│  ←  基金智能交易 - 持仓绩效审视        ■ 停止 │  ← 主标题行
│     ● 处理中  06:37  1m59s  45%              │  ← 副信息行
│  ════════════════════════════ (进度条)        │
└──────────────────────────────────────────────┘
```

**具体改动**：

| 元素 | 现状 | 改为 |
|------|------|------|
| 标题字体 | 14sp Medium | **16sp Bold** |
| 标题行数 | 1行（标题+时间挤一起） | **主标题独占一行**，副信息另起一行 |
| 状态圆点 | 8dp 在标题前 | **移到副信息行**，搭配文字（如"处理中"） |
| 返回箭头 | 18dp icon / 36dp 区域 | **20dp icon / 40dp 区域** |
| 复制按钮 | 右上角 ContentCopy | **删除** |
| 停止按钮 | 底栏输入框下方 | **右上角 actions 区域**，红色 Stop 图标 |
| 进度条 | content 区域顶部 2dp | **TopAppBar 底部**，紧贴标题栏 |

**副信息行格式**：`● 处理中  06:37  1m59s  45%`
- 状态圆点 + 状态文字（处理中/已完成/失败/已停止）
- 创建时间
- 耗时（有则显示）
- 进度百分比（处理中显示）

### 2. 底栏精简

**改动**：
- 删除停止按钮区域（已移至右上角）
- 删除 `Spacer(36.dp)` 占位
- 底栏只保留输入行：`❯ [输入框] [发送]`

```
┌──────────────────────────────────────────────┐
│  ❯  追问...                              ➤  │
└──────────────────────────────────────────────┘
```

**解决高度跳动问题**：停止按钮移到顶部后，底栏高度始终固定，不再需要占位 hack。

### 3. 进度条位置

将 `LinearProgressIndicator` 从 Scaffold content 顶部移到 TopAppBar 的 `bottom` 参数内，或在 `CliTopBar` 的 Column 底部渲染。这样进度条紧贴标题栏，视觉上更自然。

## 代码改动清单

### `TaskDetailScreen.kt`

1. **CliTopBar**
   - TopAppBar title 改为 Column 两行布局
   - 第一行：标题文字 16sp Bold，单行省略
   - 第二行：Row(状态圆点 + 状态文字 + 时间 + 耗时 + 进度%)，12sp 灰色
   - actions：删除复制按钮 → 改为停止按钮（仅处理中显示）
   - 返回箭头 icon 20dp，按钮区域 40dp
   - TopAppBar 底部或 Column 底部追加 LinearProgressIndicator

2. **CliBottomBar**
   - 删除 `onStop` 参数
   - 删除停止按钮 Row + Spacer(36.dp) 整段
   - 只保留输入行 Row

3. **TaskDetailScreen (Scaffold)**
   - `topBar` 传入 `onStop` 回调
   - 从 content Column 中移除 LinearProgressIndicator
   - `bottomBar` 不再传 `onStop`

4. **删除 `copyToClipboard` 函数**（不再使用）

### 预估影响
- 纯客户端 UI 改动，不涉及服务端
- 底栏高度固定后，终端 WebView 的跳动问题自然消失
