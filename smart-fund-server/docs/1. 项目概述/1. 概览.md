# 项目概览：AI 驱动的事件流交易系统

## 一、系统定位

**本质**：这不是传统量化系统，而是一个 **AI 驱动的事件流交易系统**（Event-driven Trading System），覆盖 A 股股票、场内基金（ETF/LOF）、场外基金及 QDII 等多品种市场。

**核心观察**：A 股市场本质上是 **政策 + 情绪 + 事件驱动** 的，这比纯技术指标更能解释市场行为。政策发布、产业扶持、突发事件才是 α 的主要来源。

### 核心闭环

```
数据采集 → AI 事件抽取 → 事件流聚合 → 决策打分 → 交易执行 → 市场反馈 → 策略进化
   ↑                                                                  │
   └──────────────────── 反哺数据采集优先级 ─────────────────────────┘
```

每一步都有明确的数据产出和消费方，没有哪一步是"黑盒"。

## 四、关键设计原则

### 1. 信息 ≠ Alpha

系统会采集大量信息，但**大部分信息是市场已经消化的**。

- 解决：关注"发布时间 vs 市场反应时间差"，找"滞后机会"
- 体现：ft_events 有 `reaction_delay_minutes` 字段，打分模型过滤已被 price-in 的事件

### 2. AI 很会编理由，规则必须兜底

AI 会"事后解释很合理，但当时并不可交易"。

- 解决：AI 只做**事件抽取**和**打分**，不做**买卖决策**
- 决策由纯规则模型做（硬过滤 → 打分 → 触发）

### 3. 基金 ≠ 股票

基金反应慢，不适合超短线。

- 策略：**事件驱动 + 持有 2-10 天**
- 仓位：单次最大 30%，同行业 40%，总仓位 60%（永远留 40% 现金）

### 4. 每一层都要可追溯

- **ft_raw_data**：客户端原始返回值永久保留
- **ft_news**：所有入库的新闻（含真实正文）
- **ft_events**：AI 抽取结果（保留 embedding）
- **ft_events.market_reaction**：盘后回填的市场反应
- **ft_decisions**：每次决策的依据和打分

→ 任何一次错误交易都能复盘到"当时看到什么、算出什么、为什么决定买"。

## 五、核心数据流（以一次完整交易为例）

```
T+0 09:15
  ├─ cls 采集到快讯："发改委：加快推进算力基础设施建设"
  ├─ 财联社详情页抓取，content 2000 字入库 ft_news
  │
T+0 09:16
  ├─ AI 事件抽取 task 触发
  ├─ Claude 抽取为结构化事件：
  │    type=policy, subtype=support, impact.direction=positive,
  │    impact.strength=0.85, industries=["AI", "算力"],
  │    certainty=0.95（官媒）, novelty=0.7（新提法）
  ├─ 写入 ft_events，生成 embedding
  │
T+0 09:17
  ├─ 事件流聚合：检测到"算力政策"事件流 momentum = increasing
  ├─ 决策引擎扫描 ft_events
  │    硬过滤：certainty ✅, novelty ✅, event_age ✅,
  │           sector_rise_3d(算力)=2% < 5% ✅（未过热）
  │    打分：0.82（通过阈值 0.75）
  │
T+0 09:18
  ├─ 查映射表：算力 → 中证人工智能 → 159819 人工智能 ETF
  ├─ 计算仓位：base_position(30%) × winrate_factor(1.0) × market_factor(1.1) = 33%
  ├─ 分批买入：第一批 60% = 19.8% 仓位
  ├─ 写入 ft_decisions（含完整推理链）
  │
T+1 09:30
  ├─ 监控事件流：新闻密度继续增加 ✅，北向资金流入 ✅
  ├─ 满足"加仓条件"，买入第二批 40% = 13.2%
  │
T+3 15:00
  ├─ agg_event_feedback 回填：sector_change_3d = +6.8%
  ├─ 事件流检测：新闻密度开始下降，momentum → decreasing
  ├─ 止盈信号触发，分批卖出
  │
T+4 复盘
  └─ 策略胜率更新 → 影响下次交易的 winrate_factor
```

## 六、最大的 3 个坑（必须警惕）

### 坑 1：AI 事件抽取的幻觉

AI 会把"发改委某个官员在会议上提到的想法"抽取为"政策利好"，实际强度远不及真正的政策文件。

**对策**：
- 在 schema 中强制要求 `source_level`（国务院 > 部委 > 地方 > 其他）
- `certainty` 硬阈值：官媒 0.9，专业财经 0.85，自媒体 0.4
- 打分时 `certainty` 权重不低于 15%

### 坑 2：embedding 的语义污染

embedding 相似度高 ≠ 可交易。一个"AI 监管趋严"的事件可能和"AI 扶持政策"embedding 很接近，但方向完全相反。

**对策**：
- embedding 只用于"候选发现"，不做最终决策
- 总是结合 `impact.direction` 做二次过滤
- 历史类比时强制检查"反向案例"

### 坑 3：同源重复 + 跨源重复

同一条新闻会被多个平台转发，措辞略有不同。sina 还会把同一次发言拆成多篇文章（实测已遇到）。

**对策**：
- 数据库层：`fingerprint = SHA256(title + source)` UNIQUE 约束
- 聚合层：批次内 `SHA256(content)` 去重（同内容不同标题只保留一条）
- Phase 2：跨源标题相似度 > 0.85 去重（待实现）
