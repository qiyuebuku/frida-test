# 增量采集机制

## 核心原则

**一切以时间为准**。不管数据源是翻页、游标还是时间过滤，采集系统只关注一个问题：
**"我要的时间范围内的数据拿齐了没有？"**

- 没拿齐 → 继续抓（翻下一页、加大 limit、用游标……手段随意，但时间是唯一的停止条件）
- 拿齐了 → 停止，切换到增量模式

---

## 一、Checkpoint 模型

每个 `(aggregator, source_name)` 在 `ft_collection_state` 表维护一条记录：

### 1.1 checkpoint 字段（JSONB）

```jsonc
{
  "mode": "backfill",               // "backfill"(回填历史) | "incremental"(增量)
  "target_time": "2026-02-12",      // 回填目标：要采集到的最早日期（初始化时计算：now - target_days）
  "newest_time": "2026-04-12",      // 已采集到的最新时间点
  "oldest_time": "2026-03-20",      // 已采集到的最早时间点（回填进度指示器）
  "cursor": null                    // 翻页游标（CLS=ctime, THS/Sina=page, 雪球=max_id）
}
```

### 1.2 两种模式的时间方向

```
                    target_time              oldest_time     newest_time       now
                        │                        │               │             │
  ──────────────────────┼────────────────────────┼───────────────┼─────────────┤
                        │     ← 回填方向          │  已覆盖范围    │  增量方向 →  │
                        │    (从新往旧翻页)        │               │ (从旧往新拉) │

  回填模式: 不断翻页，oldest_time 向左推进，直到 <= target_time → 切换为增量
  增量模式: 每次拉取 newest_time 之后的新数据，newest_time 向右推进
```

### 1.3 模式切换

```python
if oldest_time <= target_time:
    mode = "incremental"   # 回填完成，后续只做增量
```

一旦切换为增量，不再回退。如需重新回填，手动重置 checkpoint。

## 二、自动初始化

### 2.1 源模板配置（仅用于初始化）

每个源在代码中有一份初始化模板，**只在首次创建 DB 记录时使用**，写入后不再参与运行时：

```python
SOURCE_CONFIGS = {
    "cls":           {"target_days": 60, "page_size": 50, "interval": 180},
    "gov":           {"target_days": 90, "page_size": 20, "interval": 10800},
    "pboc_omo":      {"target_days": 180, "page_size": 50, "interval": 86400},
    "pboc_monetary": {"target_days": 180, "page_size": 50, "interval": 86400},
    "em_news":       {"target_days": 60, "page_size": 50, "interval": 900},
    "em_reports":    {"target_days": 60, "page_size": 50, "interval": 7200},
    "ths":           {"target_days": 60, "page_size": 20, "interval": 1800},
    "sina":          {"target_days": 60, "page_size": 20, "interval": 3600},
    "xueqiu":        {"target_days": 60, "page_size": 50, "interval": 1800},
}
```

### 2.2 启动时自动初始化

```
程序启动 → 遍历 SOURCE_CONFIGS
  → 查 ft_collection_state 有没有该源的记录
  → 没有 → 自动创建：
      checkpoint = {
        "mode": "backfill",
        "target_time": "now - target_days",
        "newest_time": null,
        "oldest_time": null,
        "cursor": null
      }
      config = {
        "target_days": 60,
        "page_size": 50,
        ...  (从 SOURCE_CONFIGS 模板写入)
      }
  → 有 → 不覆盖（尊重 DB 中已有的进度和配置）
```

**SOURCE_CONFIGS 只在初始化时使用，写入 DB 后就不再参与运行时逻辑。**

### 2.3 参数来源：DB 是唯一真相源

```
代码 SOURCE_CONFIGS ──(初始化时写入)──→ ft_collection_state.config
                                              ↓
                                        运行时只读 DB
```

运行时所有参数从 `ft_collection_state.config` 读取，不回退到代码默认值。
要改参数直接改 DB，不需要改代码、重新部署。

### 2.4 config 字段（JSONB）

```jsonc
{
  "target_days": 60,        // 目标覆盖天数（回填用）
  "page_size": 50,          // 每页条数
  "max_content_fetch": 30,  // 每轮最多抓详情页数
  "content_batch_size": 10  // 详情页并发批大小
}
```

## 三、采集流程

### 3.1 回填模式（mode = "backfill"）

```
每次 tick:
  1. 从 checkpoint 读 cursor（首次为 null）
  2. 循环翻页：
     a. 用 cursor 拉取一页数据（从最新向历史方向）
     b. normalize → save
     c. 提取本页最早时间 page_oldest
     d. 更新 cursor 为本页末尾位置
     e. 停止判断（任一条件满足即停止，切换到增量模式）：
        ✅ 时间达标：page_oldest <= target_time
        ✅ 数据源触顶：本页返回空 / 本页条数 < page_size（说明没有更早数据了）
        ✅ 进度停滞：page_oldest 和上一页相同（翻页无效，API 在循环返回同一批数据）
     f. 安全阀：超过 max_pages_per_tick（默认 100）→ 暂停，保存 cursor，下次 tick 继续
  3. 更新 checkpoint（newest_time / oldest_time / cursor / mode）
```

**关键：每一页数据都立即入库**，不需要全部拉完才写。即使中途 worker 重启，进度不丢（cursor 已保存）。

### 3.2 采集触顶检测

有些数据源 API 本身不存储那么久的历史数据（比如目标 60 天，但 API 只有 7 天），
回填不可能达到 target_time。系统通过以下信号自动检测并停止：

| 信号 | 含义 | 处理 |
|------|------|------|
| 返回空列表 | API 没有更早数据了 | 立即切增量 |
| 返回条数 < page_size | 已到 API 最后一页 | 立即切增量 |
| 本页 oldest == 上页 oldest | 翻页无效，数据在循环 | 立即切增量 |

切换时记录实际覆盖范围：

```python
if hit_ceiling:
    cp["mode"] = "incremental"
    logger.info(f"[{source}] 采集触顶，实际覆盖 {cp['newest_time']} ~ {cp['oldest_time']}，"
                f"目标 {cp['target_time']} 未达到（数据源历史深度不足）")
```

**触顶不是错误**，只是说明数据源本身没有那么多历史数据。checkpoint 中 `oldest_time` 如实记录实际采集到的最早时间。

### 3.2 增量模式（mode = "incremental"）

```
每次 tick:
  1. 从 checkpoint 读 newest_time
  2. 用 newest_time 作为起点拉取新数据：
     - 有 _since API 的源 → 服务端过滤
     - 无 _since API 的源 → 拉最新一页 → 本地时间过滤（> newest_time）
  3. normalize → save
  4. 更新 checkpoint.newest_time = max(本批时间)
```

### 3.3 各源的翻页手段

虽然翻页手段不同，但停止条件统一 —— **数据时间 <= target_time**：

| 源 | 回填翻页方式 | 游标（cursor） | 增量方式 |
|----|------------|---------------|---------|
| **CLS** | `get_telegraph_list(last_time=cursor)` | `ctime`（Unix 时间戳） | `get_telegraph_since(newest_ctime)` |
| **THS** | `get_news_feed(page=cursor)` | 页码 `1,2,3...` | 拉 page=1 → 时间过滤 |
| **Sina** | `get_news(page=cursor)` | 页码 `1,2,3...` | 拉 page=1 → 时间过滤 |
| **雪球** | `get_live_news(max_id=cursor)` | `max_id`（条目 ID） | 拉最新一页 → fingerprint 去重 |
| **EM 资讯** | `get_news_by_keyword(page=cursor)` | 页码（需加翻页支持） | `get_news_by_keyword_since(date)` |
| **EM 研报** | `get_research_reports(page=cursor)` | 页码（需加翻页支持） | `get_research_reports_since(date)` |
| **Gov** | `get_announcements(limit=大)` | 无（单次拉取） | `get_announcements_since(date)` |
| **PBOC** | `get_omo_announcements(limit=大)` | 无（单次拉取） | `get_omo_announcements_since(date)` |

### 3.4 各源全量实际覆盖能力

| 源 | 默认 target_days | 翻页方式 | 实际能达到的深度 | 说明 |
|----|-----------------|---------|----------------|------|
| **CLS** 财联社 | 60 天 | 游标无限翻 | **可达 60+ 天** | 逐页翻，直到时间满足 |
| **THS** 同花顺 | 60 天 | 页码无限翻 | **可达 60+ 天** | 逐页翻，直到时间满足 |
| **Sina** 新浪 | 60 天 | 页码无限翻 | **可达 60+ 天** | 逐页翻，直到时间满足 |
| **雪球** | 60 天 | 游标翻页 | **受 WAF 限制，约 1-3 天** | 深翻可能被封，需控制频率 |
| **EM 资讯** | 60 天 | 页码翻页 | **待加翻页支持** | 当前只拉 1 页 |
| **EM 研报** | 60 天 | 页码翻页 | **待加翻页支持** | 当前只拉 1 页 |
| **Gov** 政府 | 90 天 | 单次拉取 | **~1-3 月**（发布频率低） | 20 条已覆盖很久 |
| **PBOC** 央行 | 180 天 | 单次拉取 | **~3-6 月**（频率极低） | 50 条覆盖半年 |

## 四、ft_collection_state 表

### 4.1 完整字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `aggregator` | VARCHAR(32) | 领域标识 |
| `source_name` | VARCHAR(64) | 数据源名 |
| `checkpoint` | JSONB | 采集断点（mode / target_time / newest_time / oldest_time / cursor） |
| `config` | JSONB | 采集参数（target_days / page_size 等），启动时由代码模板初始化，运行时从 DB 读取 |
| `enabled` | boolean | 是否启用 |
| `interval_override` | integer | 采集间隔覆盖（秒） |
| `last_run_at` | TIMESTAMPTZ | 上次运行时间 |
| `last_success_at` | TIMESTAMPTZ | 上次成功时间 |
| `consecutive_failures` | integer | 连续失败次数 |
| `last_error` | TEXT | 最近错误信息 |
| `total_runs` / `total_saved` | bigint | 累计统计 |

## 五、时间提取工具

### 5.1 _extract_item_date — 自动适配各源时间字段

```python
@staticmethod
def _extract_item_date(item: dict) -> str:
    """返回 YYYY-MM-DD，自动尝试:
       - Unix 时间戳字段: ctime / rtime / time / created_at
       - 日期字符串字段: date / published_at / publishDate
    """
```

不管哪个源，只要用了常见字段名，就能自动提取日期用于和 target_time / newest_time 比较。

### 5.2 其他工具方法

| 方法 | 说明 |
|------|------|
| `_filter_newer_items(items, cp_date)` | 增量模式下过滤旧条目 |
| `_fetch_content_for_items(items, client)` | 批量并发抓取详情页正文 |
| `_unwrap_items(raw)` | 解包嵌套结构 `{"data":{"list":[...]}}` |
| `_compute_checkpoint(source, items, prev_cp)` | 计算新 checkpoint（更新 newest/oldest/cursor/mode） |

## 六、运维操作

### 6.1 查看回填进度

```sql
SELECT source_name,
       checkpoint->>'mode' AS mode,
       checkpoint->>'target_time' AS target,
       checkpoint->>'oldest_time' AS oldest,
       checkpoint->>'newest_time' AS newest,
       total_saved
FROM ft_collection_state
WHERE aggregator = 'news'
ORDER BY source_name;
```

### 6.2 调整目标覆盖天数（下次回填生效）

```sql
-- CLS 改为覆盖 90 天
UPDATE ft_collection_state
SET config = jsonb_set(COALESCE(config, '{}'), '{target_days}', '90'),
    checkpoint = jsonb_set(checkpoint, '{mode}', '"backfill"') ||
                 jsonb_build_object('target_time', (CURRENT_DATE - 90)::text, 'cursor', null)
WHERE aggregator = 'news' AND source_name = 'cls';
```

### 6.3 重新回填某源

```sql
-- 重置为回填模式，从头开始
UPDATE ft_collection_state
SET checkpoint = jsonb_build_object(
    'mode', 'backfill',
    'target_time', (CURRENT_DATE - 60)::text,
    'newest_time', null,
    'oldest_time', null,
    'cursor', null
)
WHERE aggregator = 'news' AND source_name = 'cls';
```

### 6.4 手动指定采集起止时间

```sql
-- 从 2026-01-01 开始回填
UPDATE ft_collection_state
SET checkpoint = jsonb_build_object(
    'mode', 'backfill',
    'target_time', '2026-01-01',
    'newest_time', null,
    'oldest_time', null,
    'cursor', null
)
WHERE aggregator = 'news' AND source_name = 'cls';
```

### 6.5 禁用/启用 & 间隔调整

```sql
-- 禁用
UPDATE ft_collection_state SET enabled = false
WHERE aggregator = 'news' AND source_name = 'gov';

-- CLS 改为 60 秒采集一次
UPDATE ft_collection_state SET interval_override = 60
WHERE aggregator = 'news' AND source_name = 'cls';
```

### 6.6 查看异常源

```sql
SELECT aggregator, source_name, consecutive_failures, last_error
FROM ft_collection_state
WHERE consecutive_failures > 0
ORDER BY consecutive_failures DESC;
```

## 七、对接新数据源

### 步骤

1. **Client 层** — 添加 `get_xxx_list(page/limit)` + 可选 `get_xxx_since(date)` + 可选 `fetch_article_content(url)`
2. **Normalize** — 添加 `normalize_xxx(raw) -> list[dict]`，确保有 `published_at` 字段
3. **SOURCE_CONFIGS** — 添加模板：`"xxx": {"target_days": 60, "page_size": 20, "interval": 1800}`
4. **Fetch 方法** — 添加 `_fetch_xxx(cp)`，支持回填循环 + 增量
5. **注册** — `SourceDef("xxx", self._fetch_xxx, interval, normalize_xxx)`
6. **可选** — 覆写 `_compute_checkpoint()` 自定义游标字段

### Fetch 方法模板

```python
async def _fetch_xxx(self, cp: dict) -> list:
    from src.infrastructure import clients
    mode = cp.get("mode", "incremental")

    if mode == "backfill":
        # 回填：循环翻页直到 target_time
        all_items = []
        cursor = cp.get("cursor")  # 首次为 None
        target = cp.get("target_time", "")
        while True:
            raw = await clients.xxx.get_list(page_size=50, cursor=cursor)
            items = self._unwrap_items(raw)
            if not items:
                break
            all_items.extend(items)
            page_oldest = min(self._extract_item_date(i) for i in items if self._extract_item_date(i))
            if page_oldest <= target:
                break
            cursor = items[-1].get("id")  # 或 page += 1，取决于翻页方式
        self._backfill_cursor = cursor
        return all_items

    else:
        # 增量：拉取 newest_time 之后的数据
        newest = cp.get("newest_time")
        if newest:
            return await clients.xxx.get_list_since(newest)
        return await clients.xxx.get_list()
```
