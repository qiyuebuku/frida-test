# 服务部署待优化

### 生产迁移账户不是业务表 owner（2026-08-19 记录）

**问题：** 生产 `DB_USER=jettask`，但部分历史业务表（如 `ft_news`）owner 为 `postgres`，导致幂等 DDL 无权执行。旧部署脚本还会因远程命令末尾清理文件而吞掉 `psql` 失败状态。

**最佳方案：** 配置独立、最小权限的 migration role，使其拥有业务 schema/table DDL 权限；应用运行账户继续只保留 DML 权限，并维护正式 migration ledger。

**当前方案：** 已修复脚本，任何 `psql` 错误都会阻断部署。仅当 Git diff 已确认本次 revision 没有 schema 变化时，允许显式设置 `SKIP_SCHEMA_MIGRATIONS=1`；默认仍执行并严格检查迁移。

**整改条件：** DBA 创建 migration role 并统一历史表 owner/授权后，删除跳过开关。

**优先级：** P1

### Milvus 公网入口尚未启用访问控制（2026-07-28 记录）

**问题：** `119.23.227.187:19530` 通过 FRP 映射到生产 Milvus。当前 Milvus 未启用认证，公网客户端不仅可以查询，也可能执行写入、删除 Collection 等管理操作。

**最佳方案：** 启用 Milvus Authentication，为生产业务进程和开发验收分别配置独立凭据，并在公网入口增加来源 IP 白名单。凭据只通过 EnvironmentFile 管理，不写入部署脚本或仓库。

**当前方案：** 为了让开发机直接使用生产 Milvus 完成关系图检索验收，暂时开放 TCP 映射。FRP 传输链路启用了加密和压缩，但这不能替代公网客户端鉴权。

**整改条件：** 确认 Milvus 现有数据和所有生产调用方能够在开启认证后平滑迁移，并具备阿里云安全组或主机防火墙的来源 IP 管理权限。

**优先级：** P1

### General Worker 缺少队列级配额与优先级（2026-08-19 记录）

**问题：** HTTP 与 internal 历史 Worker 已合并为并发 12 的 `smart-fund-worker-general`，进程数量减少且总并发保持不变，但 JetTask 当前按任务名集合启动 Worker，没有为长耗时 Research Agent 和短 HTTP 采集提供独立 slot 配额。Agent 突发占满并发时，普通 HTTP 队列可能增加等待时间。

**最佳方案：** JetTask 支持队列优先级、加权公平消费或每类任务并发配额，由同一 Worker 进程在内部保证短任务和长任务的资源份额。

**当前方案：** 保持 `general` 总并发 12，并继续将设备受限的 THS 与高频 `ths-sector` 隔离；通过任务延迟指标观察 general 队列。没有用重复注册队列的方式制造多个 owner。

**整改条件：** JetTask Worker 暴露队列权重/并发配额能力，或生产监控确认 Agent 任务导致 HTTP 任务延迟超过调度周期。

**优先级：** P2

### Smart Fund systemd 到 Compose 尚未执行生产切换演练（2026-08-19 记录）

**问题：** 单镜像、多 Compose service、旧 systemd 自动回滚和 Milvus/etcd 原数据目录复用均已实现，生产 Docker/Compose 版本与 Compose 配置解析也已验证，但当前代码尚未提交推送，因此尚未真实构建生产镜像或停止在线 systemd 服务执行首次迁移。

**最佳方案：** 在维护窗口先构建 commit 镜像并运行一次性容器导入检查，再执行首次迁移，持续验证 API、JetTask Persist/Scheduler、三个 Worker、THS 实时流、KG Worker、Milvus 与 etcd；确认容器重启和宿主重启均能由 `smart-fund-compose.service` 恢复。

**当前方案：** 部署器只在全部 Compose 服务、API 和 THS command broker 验收成功后写迁移标记；首次启动失败会 `docker compose down` 并重新启用旧 `smart-fund-collector.target`。Claude CLI 使用只读二进制挂载和隔离的配置副本，不直接写宿主用户原始 `~/.claude`。

**整改条件：** 当前改动提交并推送，安排允许 Smart Fund Python 服务短暂停机的生产维护窗口。

**优先级：** P1

### 公网 MCP 尚未启用 Bearer 与 HTTPS（2026-07-29 记录）

**问题：** 关系图 Streamable HTTP MCP 已部署到公网 `/mcp`，但当前生产 EnvironmentFile 尚未配置 `SMART_FUND_MCP_BEARER_TOKEN`，公网入口也仍使用 HTTP。MCP 只提供与既有公开 REST 图谱接口等价的只读能力，但当前传输和访问控制不满足长期生产安全要求。

**最佳方案：** 通过 HTTPS 反向代理暴露 `/mcp`，在生产 EnvironmentFile 注入随机 Bearer Token，并让 Codex 使用 `bearer_token_env_var` 从本地安全环境读取 Token。Token 不写入仓库、项目 TOML 或部署脚本。

**当前方案：** MCP 接口层已经完整支持静态 Bearer 校验；为避免在 Codex 进程尚未获得密钥时导致全部工具不可用，当前生产暂未启用 Token。六个工具均声明为只读、幂等、非破坏性。

**整改条件：** 公网 HTTPS 域名或反向代理就绪，并完成生产 Token 向 Agent 运行环境的安全分发。

**优先级：** P1。
### THS 1+8 新机部署尚缺空白机灾备演练（2026-08-19 记录）

**问题：** 仓库已具备带双层校验的发布包、脱敏采集模板、users 10–17 恢复、服务启动和健康门禁，但尚未在第二台空白宿主机执行完整恢复；生产采集用户启动还会因 Android 前台用户切换杀死交易 user0，因此未在在线交易环境覆盖验证模板跳过 UI 的效果。

**最佳方案：** 在隔离的镜像构建机生成停机 AVD 制品，并在一次性空白验收机完整执行“下载发布包—恢复—1 交易 + 8 采集—重启—故障恢复—息屏”演练；同时彻底移除采集启动对 `switch-user` 的依赖。

**当前方案：** 已从匿名 user12 导出并校验脱敏黄金模板，完成所有仓库脚本和静态拓扑测试；生产在线环境暂不启动采集实例，避免破坏交易会话。

**整改条件：** 提供一台空白 Linux 验收机，或安排允许交易实例短暂重启的维护窗口，并提供受保护的 AVD/SDK 制品仓库。

**优先级：** P1
