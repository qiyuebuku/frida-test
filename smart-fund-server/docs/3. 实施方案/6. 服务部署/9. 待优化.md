# 服务部署待优化

### Milvus 公网入口尚未启用访问控制（2026-07-28 记录）

**问题：** `119.23.227.187:19530` 通过 FRP 映射到生产 Milvus。当前 Milvus 未启用认证，公网客户端不仅可以查询，也可能执行写入、删除 Collection 等管理操作。

**最佳方案：** 启用 Milvus Authentication，为生产业务进程和开发验收分别配置独立凭据，并在公网入口增加来源 IP 白名单。凭据只通过 EnvironmentFile 管理，不写入部署脚本或仓库。

**当前方案：** 为了让开发机直接使用生产 Milvus 完成关系图检索验收，暂时开放 TCP 映射。FRP 传输链路启用了加密和压缩，但这不能替代公网客户端鉴权。

**整改条件：** 确认 Milvus 现有数据和所有生产调用方能够在开启认证后平滑迁移，并具备阿里云安全组或主机防火墙的来源 IP 管理权限。

**优先级：** P1

### 公网 MCP 尚未启用 Bearer 与 HTTPS（2026-07-29 记录）

**问题：** 关系图 Streamable HTTP MCP 已部署到公网 `/mcp`，但当前生产 EnvironmentFile 尚未配置 `SMART_FUND_MCP_BEARER_TOKEN`，公网入口也仍使用 HTTP。MCP 只提供与既有公开 REST 图谱接口等价的只读能力，但当前传输和访问控制不满足长期生产安全要求。

**最佳方案：** 通过 HTTPS 反向代理暴露 `/mcp`，在生产 EnvironmentFile 注入随机 Bearer Token，并让 Codex 使用 `bearer_token_env_var` 从本地安全环境读取 Token。Token 不写入仓库、项目 TOML 或部署脚本。

**当前方案：** MCP 接口层已经完整支持静态 Bearer 校验；为避免在 Codex 进程尚未获得密钥时导致全部工具不可用，当前生产暂未启用 Token。六个工具均声明为只读、幂等、非破坏性。

**整改条件：** 公网 HTTPS 域名或反向代理就绪，并完成生产 Token 向 Agent 运行环境的安全分发。

**优先级：** P1。
