# Research Agent 前四步实施方案

## 1. 实施范围

本轮把《Research Agent（研究智能体）投资观点形成与持续演化设计方案》中当前报告、运行输入、自主研究、
观点结构、结果评估和正式输出等章节的文字约束落实为服务端业务契约，范围为：

1. 唯一 Current Research Report 与正式 Investment View Proposal；
2. 有界 Research Context Pack；
3. 自主研究循环及确定性审计；
4. Forecast、实际市场观察和 Outcome Evaluation。

本轮不实现 Portfolio Agent（组合管理智能体）、Trading Agent（交易智能体）和订单能力。
现有市场采集和 WebUI API（网页用户界面应用程序编程接口）不会被当成 Agent MCP（智能体模型上下文协议）上游。
生产 Market State Frame（市场状态框架）、目录、主题、维度、数据域、统一证据定位、运行授权、
自动上下文准备、结果提交和记忆读取已经在《Research Agent MCP（研究智能体模型上下文协议）接入实施方案》中落地。

## 2. 唯一当前报告与观点状态

Research Agent 的唯一任务类型收敛为 `research_review`。正式输出从通用自然语言结果改为
`CurrentResearchReportProposal`，并强制包含：

- 固定 `report_id=research:current`；
- Run、Trigger、Market State Frame 和 cutoff 身份；
- 数据质量判断、Research Question、三类竞争性假设和 Evidence Plan；
- 反证搜索结果和相关研究记忆的使用说明；
- 当前观点快照和本次不可覆盖 View Revision；
- Observation Requirement、Evidence Gap 或 `no_change`。

`updated` 必须创建新的报告 Revision 并包含至少一个 View Revision；`no_change` 不创建报告
Revision，只更新唯一报告指针对象的检查时间、状态和原因；`blocked`、
`insufficient_evidence`、`incomplete` 只写入 Run 审计，不发布为当前报告。

PostgreSQL 保存稳定 Report/View 身份、不可覆盖 Revision、逐条 Claim、Forecast、观察要求、
Outcome 和当前指针。更新当前报告和多个观点使用同一数据库事务，并通过
`base_report_revision_id`、`base_revision_id`、cutoff 和行锁拒绝迟到 Run 或并发旧版本。

## 3. 有界 Research Context Pack

Runtime 不再接受一段无边界 Prompt，而只接受以下四层输入：

| 层 | 正式对象 | 服务端约束 |
|---|---|---|
| Trigger | Research Trigger Envelope | 原因、来源、运行模式、cutoff、工具和时间预算 |
| 市场起点 | Market State Frame | 统一时间边界、最多 12 个维度、质量问题和下钻句柄 |
| 当前观点 | Active View Pack | 最多 20 个当前观点，不携带完整历史 |
| 研究经验 | Research Memory Pack | 最多 12 条，过期项先剔除，保留适用范围和反例 |

Context Builder 拒绝未来数据、重复对象和超过字符预算的 Context Pack，不静默截断。所有
业务时间必须带时区；Market State Frame 中任一维度的 `as_of` 不得晚于 Frame cutoff，
Frame cutoff 不得晚于 Trigger cutoff。

Context Pack（上下文包）由服务端 `research_run_prepare`（准备研究运行）根据签名截止时间自动组装。
CLI（命令行界面）默认只提交触发原因、时段和运行模式，不要求人工准备 JSON（JSON 数据格式）。
`session_id`（会话标识符）只用于 Trace（追踪）关联，不把会话历史当作研究记忆；正式经验由
Role Memory Service（角色经验记忆服务）按截止时间检索。

## 4. 自主探索与审计

Research Agent Prompt（研究智能体提示词）不再规定固定步骤。Agent 每轮根据当前假设、证据缺口和
剩余预算，自主选择复合 MCP 工具、原子下钻、记忆、反证或结束提交。以下是可选择的研究动作，
不是必须按顺序经过的 Workflow（工作流）：

1. 数据时点和质量检查；
2. 可证伪 Research Question；
3. primary、alternative、data_quality 三类假设；
4. 假设到 Evidence Plan；
5. overview、dimension、object、history、source 渐进下钻；
6. 主动查找反证和更简单解释；
7. 结合带适用范围与反例的经验形成有界结论。

完成的 Evidence Plan 项必须列出本次真正打开的引用。服务端从 MCP 工具结果收集 Card、
Edge、Community、外部 URL 和市场定位符，并拒绝未打开引用、未来引用、重复 Citation、
未知 Hypothesis 和同一 Run 对同一 View 的多个 Revision。市场引用由原来的“调用过任一
市场工具即可”提高为“引用字符串必须实际出现在已打开市场结果中”。

Runtime（运行时）使用 Trigger（触发器）中的最大耗时和最大工具调用数，并在边界处检查预算。
Research Agent（研究智能体）只能提交 Proposal（提案）；服务端 Result Committer（结果提交器）
根据实际证据台账、运行授权和版本在审计通过后执行正式写入。

## 5. Forecast 与实际市场反应

每个需要验证的判断可在 View Revision 中事前声明 Forecast：对象、指标、方向或区间、
比较基准、基线、验证窗口和失效条件。服务端要求验证窗口从报告 cutoff 之后开始，
Observation Requirement 也只能等待未来事实。

`ResearchOutcomeEvaluator` 只确定性计算可由数值直接判断的方向、区间和相对基准结果。
事实、机制、时机、表达和定价五类语义判断不会从价格涨跌中自动推断；调用方必须在实际
打开 Outcome 证据后明确提供，否则保持 `unknown`。Outcome Observation 和 Evaluation
分别保存，避免事后覆盖当时 Forecast。

## 6. 运行与发布边界

`FinancialAgentRuntime`（金融智能体运行时）只负责 OpenAI Agents SDK（OpenAI 智能体软件开发工具包）
模型工具循环、预算和本地提案审计，不负责决定何时运行。Jettask（任务调度系统）负责盘前、盘中和
盘后触发；`ResearchReviewApplicationService`（研究复核应用服务）调用远程准备和提交契约，
并且只有 `publish=true`（允许发布）且 `run_mode=production`（生产模式）时发布权威状态。

Shadow、Debug 和 Replay Run 可以使用相同 Agent 和 Schema，但不能写入生产当前报告。
阻塞结果保留完整 Proposal 供审计，当前指针保持不变。

## 7. 数据库对象

本轮 DDL 位于 `schema/21_agent_research.sql`，包含：

- `agent_research_runs`；
- `agent_current_research_reports`、`agent_research_report_revisions`；
- `agent_investment_views`、`agent_investment_view_revisions`；
- `agent_research_claims`、`agent_research_forecasts`；
- `agent_research_observation_requirements`；
- `agent_research_outcome_observations`、`agent_research_outcome_evaluations`。
- `agent_role_memory_items`、`agent_role_memory_cases`；
- `agent_runtime_runs`、`agent_tool_invocations`。

表之间使用逻辑引用，不新增物理外键；业务写入统一通过 SQLAlchemy ORM 和批量 Repository
接口完成。

## 8. 测试用例

### 8.1 单元测试

| 用例名 | 验证内容 |
|---|---|
| `test_context_builder_filters_expired_memory_and_rejects_future_frame` | 过期记忆剔除、未来 Frame 数据拒绝 |
| `test_report_status_contract_keeps_blocked_run_unpublishable` | 阻塞 Run 必须有关键 Gap 且不可发布 |
| `test_no_change_does_not_create_report_revision` | no_change 不制造业务报告版本 |
| `test_evidence_audit_requires_exact_market_locator_from_opened_result` | 市场引用必须来自真实打开结果 |
| `test_prompt_and_run_input_contain_autonomous_bounded_context` | 自主研究 Prompt、只读策略和 Context Pack 注入 |
| `test_conclusion_tool_exposes_small_non_updating_schema` | 普通结论使用小型 Schema，完整观点修订使用独立契约 |
| `test_outcome_evaluator_uses_predeclared_window_and_baseline` | 只按事前窗口、基线和基准验证结果 |
| `test_research_orm_registers_current_revision_and_outcome_tables` | Research ORM 表完整注册 |
| `test_research_ddl_contains_every_registered_agent_table` | ORM 与 `schema/21_agent_research.sql` 表清单同步 |
| `test_older_cutoff_cannot_replace_a_more_recent_report_check` | 迟到 cutoff 不能覆盖较新检查状态 |

### 8.2 集成测试

| 用例名 | 验证内容 |
|---|---|
| `test_research_review_publishes_one_current_report` | 真实 PostgreSQL（关系数据库）中仅一个当前指针，历史 Revision（修订）不覆盖 |
| `test_late_research_run_cannot_replace_newer_cutoff` | 并发和迟到 Run 的乐观版本拒绝 |
| `test_blocked_run_preserves_current_report` | MCP 关键来源故障时只保存审计 Run |
| `test_outcome_due_uses_cutoff_market_evidence` | 到期 Forecast 使用真实记录级市场证据生成 Outcome |
| `test_replay_never_writes_production_state` | Replay 使用相同 Runtime 但隔离生产状态 |

此外必须执行 MCP（模型上下文协议）真实协议发现、真实市场数据逐层下钻、真实 Milvus（向量数据库）
图谱读取、外部研究和一次生产式模型运行；验收结果记录在 MCP 接入实施方案中。
