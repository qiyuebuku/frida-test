# Research Agent（研究智能体）MCP（模型上下文协议）接入实施方案

## 1. 完成范围

本方案已经把 Research Agent（研究智能体）接到服务端远程 Streamable HTTP MCP
（可流式超文本传输模型上下文协议），形成以下完整运行链路：

```text
定时任务或人工触发
→ 服务端准备最新研究上下文；历史重放才固定时间边界
→ 本地 FinancialAgentRuntime（金融智能体运行时）连接远程 MCP（模型上下文协议）
→ 模型由浅入深读取市场、研究状态、记忆和证据
→ 模型返回结构化研究提案
→ 服务端核对运行授权、证据台账和版本
→ 调试运行只记审计；生产运行发布当前报告和观点修订
```

Agent（智能体）不连接 PostgreSQL（关系数据库）或 Milvus（向量数据库），也不请求
WebUI API（网页用户界面应用程序编程接口）。数据库、向量库、外部研究供应商和数据源凭据
只存在于服务端。

本方案完成公共底座 M0（第零阶段）和 Research M1（研究第一阶段）。Portfolio Agent
（组合管理智能体）和 Trading Agent（交易智能体）使用同一底座，但各自业务工具随对应阶段实施。

## 2. 一次运行怎样开始

`research_run_prepare`（准备研究运行）是编排器调用的内部契约，不提供给模型。它接收触发原因、
运行模式，然后从真实服务端状态组装 `ResearchContextPack`（研究上下文包）：

- `MarketStateFrame`（市场状态框架）：准备时最新的市场概览、最多十二个认知维度、显著变化和数据质量；
- 当前研究报告和有效观点；
- 与当前问题相关且当前有效的研究经验；
- 研究问题、工具预算、时间预算和运行身份。

CLI（命令行界面）和自动任务都调用 `FinancialAgentRuntime.prepare_and_run()`（准备并运行），
不再人工编写 JSON（JSON 数据格式）上下文。旧任务包排查使用单独的 `agent run-context` 命令，
不会形成第二套模型工具循环。

## 3. 单次运行授权

外层 Bearer Token（持有者令牌）只证明调用方是受信任的 Agent Runtime（智能体运行时）。
每次运行还会签发短期 HMAC Run Authorization（基于散列的消息认证码单次运行授权），其中固定：

- `run_id`（运行标识符）、role（角色）和 task（任务）；
- `run_mode`（运行模式）；Replay（历史重放）额外固定历史数据边界；
- 本次允许调用的工具；
- 可读取的账户范围和过期时间。

每个 MCP（模型上下文协议）处理器都验证该授权。正常实时运行在每次工具调用时读取最新可用数据，
不把整次运行冻结在启动时刻。Replay（历史重放）运行不能调用开放互联网或实时上游工具，过期、伪造、跨角色、
越权工具和非法历史重放边界都会被拒绝。

## 4. 模型怎样探索数据

模型从浅到深使用四层入口：

```text
目录和市场框架
→ 单个市场主题、认知维度或数据域
→ 板块、标的、观点、记忆或图谱对象
→ 指定字段、Card（证据卡片）、Edge（关系边）或外部原文
```

### 4.1 市场导航和精确证据

| 工具 | 用途 |
|---|---|
| `research_data_catalog_open`（打开研究数据目录） | 查看全部已采集数据域、对象范围、数量、最新时间和质量 |
| `market_frame_open`（打开市场框架） | 查看统一市场概览、当前有数据的认知维度和相对上一可比时点的显著变化 |
| `market_change_brief_open`（打开市场变化简报） | 把普通复核中重复的 Frame、基线变化、相关维度和质量检查合并为一次有界读取 |
| `market_topic_open`（打开市场主题） | 按 A 股、板块、ETF（交易型开放式指数基金）、期货、黄金、美股、基金、新闻、宏观等主题进入相关数据 |
| `market_dimension_open`（打开市场维度） | 打开价格宽度、资金、情绪、板块、跨市场、宏观、估值等单一维度 |
| `market_domain_open`（打开市场数据域） | 对十四个真实持久化数据域做有界分页和筛选 |
| `market_evidence_open`（打开市场证据） | 用稳定定位符精确打开一条记录的指定字段、事实时间、来源和口径 |
| `market_instrument_realtime_open`（打开实时标的） | 不经过跟踪列表和数据库，直接查询同花顺股票/ETF 最新数据；用 `fields`（字段组）按需分别读取行情、走势、业绩、持仓、配置、规模、基金经理、规则、公告或新闻，单次最多四组 |

持续采集与临时探索是两条不同路径。`market_instrument_open`（打开已采集标的）和历史工具服务于历史比较、持仓监控与事件触发；实时标的工具服务于 Agent（智能体）研究过程中临时想到的对象。Agent 形成 Observation Requirement（观察需求）后，采集调度器才持续抓取增量数据，并在估值、价格、资金或观点失效条件命中时触发新研究运行。

目录映射覆盖当前 PostgreSQL（关系数据库）十四个真实数据域和全部已入库快照类型，不存在静默
漏映射。框架使用中国交易所日历识别交易日、盘前、盘中、盘后和非交易日，并按各指标明确配置的
比较方法生成 `significant_changes`（显著变化），不使用猜字段的通用算法。

市场证据定位符使用 `market:v1:<payload>`（市场证据第一版载荷）格式，能够重新定位数据域、
对象、记录、字段和事实时间。审计按定位符解码后的证据身份比较，兼容模型复制时补上的可选
Base64（Base64 编码）结尾填充符，但任何载荷内容变化仍会被拒绝。完整定位符只在 Runtime
（运行时）与服务端审计边界使用；模型侧统一看到 `market_ref:M1`（市场证据短引用）一类 Run
（运行）内别名。模型调用下钻工具时由 MCP Client（模型上下文协议客户端）恢复完整定位符，
提交后再由 Runtime 恢复后交给服务端校验和保存，避免长载荷在每轮上下文重复消耗 Token
（词元）。概览只返回决策所需的显著变化和紧凑记录句柄；完整预览与原始精度由精确证据工具打开。

模型侧 Context Pack（上下文包）同样采用紧凑投影：运行、触发器和市场框架使用 `R1`、`T1`、
`F1` 短引用，时间统一精确到秒，维度导航句柄不重复携带截止时间。服务端可信上下文仍保存完整
ID、微秒和时区。概览数值在输出边界按单位格式化，计数保持整数，常规数值和变化率通常保留
两位，高精度利率与比率最多保留四位；数据库原值不被修改。

Research MCP Client（研究模型上下文协议客户端）按当前运行状态重新投影工具。初始只暴露市场
变化简报、目录/主题入口、研究状态、记忆/结果入口、持仓暴露摘要、图谱/外部搜索入口和证据账本；
打开相应入口后，才出现市场对象与历史、Card/Edge（证据卡片/关系边）、外部原文或持仓详情。
这只是缩小工具注意力面，不规定 Agent 必须采用哪条研究路径。完全相同参数的只读调用在同一 Run
（运行）中返回 `duplicate_skipped`（已跳过重复调用）；不同参数的下钻不受影响。

### 4.2 研究状态、结果和记忆

| 工具组 | 用途 |
|---|---|
| `research_current_report_open`（打开当前研究报告） | 实时运行读取最新当前报告；历史重放读取边界前版本 |
| `research_view_list/open`（列出/打开研究观点） | 读取有效观点、不可覆盖修订、主张、预测和失效条件 |
| `role_outcome_search/open`（搜索/打开角色结果） | 查看当时预测与后来实际结果 |
| `role_memory_search/open/case`（搜索/打开角色经验/案例） | 查看已评测经验、适用条件、反例、失效条件和原始案例 |
| `research_exposure_summary_open` 等（打开研究持仓暴露） | 读取研究所需的持仓和盈亏；券商事实投影未接入时明确返回 `unavailable`（不可用），不伪造空仓 |
| `agent_run_state_open`（打开运行状态） | 查看当前任务、预算和可恢复检查点 |
| `agent_evidence_ledger_open`（打开证据台账） | 查看服务端登记的本次实际打开证据 |

工作记忆留在本次 Session（会话）；事实记忆仍在市场库、图谱和原文存储；观点记忆保存为
Investment View Revision（投资观点修订）；结果记忆保存为 Outcome Evaluation（结果评估）；
经验记忆保存为带有效期、适用条件和反例的 Role Memory Item（角色经验项）。它们不会混入一份
Markdown（标记语言）报告，也不会被观点反向改写。

### 4.3 图谱、板块、标的和外部研究

Research（研究）模型还可以读取：

- 关系图谱搜索，以及 Card/Edge/Community（证据卡片/关系边/图谱社区）的打开和扩展；
- 板块概览、排行、单板块详情与历史；
- 股票、ETF（交易型开放式指数基金）等标的详情与历史；
- 外部网页搜索/正文、代码仓库搜索/结构/文件和分段正文。

Community（图谱社区）和搜索结果只能导航。事实必须打开 Card（证据卡片），关系必须打开 Edge
（关系边），外部主张必须打开正文。实时图谱查询读取当前有效版本，历史重放查询应用重放边界。

## 5. 为什么服务端有些契约不提供给模型

同一 MCP Server（模型上下文协议服务端）承载三类契约：

| 契约 | 调用方 | 模型是否可见 |
|---|---|---|
| `research_run_prepare`（准备研究运行） | 编排器 | 否 |
| 三十八个 Research Read Tools（研究读取工具） | Research Agent（研究智能体） | 是，只读且有界 |
| `research_proposal_commit` / `research_run_abort`（提交研究提案/中止研究运行） | 运行时 | 否 |

模型只负责研究和提出结论。它不能伪造任务包、扩大权限、直接保存观点或把失败运行改成成功。

## 6. 证据和结果提交

服务端为每次运行保存运行记录和工具调用记录。搜索命中不算“已打开证据”，只有打开工具返回的
精确市场定位符、Card（证据卡片）、Edge（关系边）或正式原文才进入 Evidence Ledger
（证据台账）。

模型根据结论选择本地 `submit_research_conclusion`（提交研究结论）或
`submit_investment_view_revision`（提交投资观点修订）工具返回结构化提案。如果提案
缺字段、缺反证、缺引用或引用格式错误，校验信息会返回给模型修正，而不是立即结束运行。
模型输出最终通过本地审计后，运行时再调用服务端 `research_proposal_commit`（提交研究提案）：

1. 核对提案运行身份和运行模式；历史重放另核对签名边界；
2. 核对每条引用确实存在于服务端证据台账；
3. 调试、影子和历史重放只完成审计；
4. 只有 Production（生产）运行可以事务性发布报告和观点修订；
5. 失败或超时运行调用 `research_run_abort`（中止研究运行），保留失败原因且不发布业务状态。

MCP（模型上下文协议）业务错误通过协议的 `isError`（错误标志）返回。运行时显式检查该标志，
准备或提交被服务端拒绝时整次运行失败，不能误报完成。

## 7. 调度和手动运行

Research Agent（研究智能体）是独立任务，不与组合或交易角色共享长上下文。生产调度时间为：

- 盘前 08:50；
- 盘中 11:35；
- 盘后 15:35。

非交易日由交易所日历跳过。自动任务使用 Production（生产）模式并允许发布；人工生产式检查可运行：

```bash
conda activate frida-test
python -m src.interfaces.cli agent check
python -m src.interfaces.cli agent run \
  --trigger-slot intraday \
  --reason "人工生产式复核" \
  --run-mode debug \
  --json-output
```

本地只需连接服务器的 MCP URL（模型上下文协议地址），不需要启动本地 API（应用程序编程接口）
或配置数据库。服务器使用自身内网连接 PostgreSQL（关系数据库）、Milvus（向量数据库）和外部研究服务。

## 8. 数据库对象

`schema/21_agent_research.sql` 和 `schema/migrations/20260809_agent_mcp_runtime.sql` 维护：

- 当前研究报告、报告修订、投资观点、观点修订、主张、预测和观察要求；
- 结果观察和结果评估；
- 角色经验、经验案例；
- 智能体运行记录和工具调用证据台账。

业务代码全部通过 SQLAlchemy ORM（SQLAlchemy 对象关系映射）访问，不直接拼接业务 SQL
（结构化查询语言）。

`research_quality_open`（打开研究质量）追踪历史分数。后续结果评估会回填
`outcome_adjusted_score`（结果校准分）。

## 10. 完成定义

只有以下条件同时成立才算 Research MCP（研究模型上下文协议）接入完成：模型不接数据库；上下文
由服务端自动准备；实时读取在每次调用时取最新可用数据，历史重放受签名边界约束；市场数据可以从概览下钻到精确字段；研究状态、结果、
记忆和证据可读；模型只见只读工具；提案由服务端证据台账和版本校验后提交；失败运行可审计；自动调度
与人工运行复用同一运行时；真实 PostgreSQL、Milvus、外部研究和模型链路均通过验收。
