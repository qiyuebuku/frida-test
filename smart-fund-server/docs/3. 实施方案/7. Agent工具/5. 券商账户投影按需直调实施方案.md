# 券商账户投影按需直调实施方案

> 创建时间：2026-08-17（Portfolio Agent 第一阶段第六步：Account Projection）
> 数据源：同花顺交易 SDK 进程内端点（真机 hook 服务器，MainHook，见逆向交接说明 §3.7~3.12）
> 状态：**已实施并真机验证**（六只读端点 + Research Exposure Pack 三工具接线）

## 1. 背景与设计决策

Portfolio Agent 第一阶段完成同花顺交易 SDK 逆向后，六个只读查询端点
（positions/funds/today_order/today_deal/hist_order/hist_deal）与四个写端点
（买/卖/撤单/转账）已在真机 hook 服务器（默认 `http://10.168.1.158:18900`）就绪。

**设计决策（2026-08-17 用户指定）：交易型接口不挂调度任务、不建快照表。**
每次有需求（Agent 工具调用）时直接调用真机端点获取权威数据，仅在客户端
内做短 TTL 内存缓存（默认 20s，只缓存成功结果）。理由：交易数据时效性
要求高、调用频率低（研究/交易决策时点触发），定时快照既浪费设备配额
又引入数据陈旧问题。

## 3. THSTradeClient 契约

### 3.1 只读方法（短 TTL 内存缓存，仅缓存 ok 结果）

| 方法 | 设备端点 | 协议 | 说明 |
|---|---|---|---|
| `positions()` | `GET /stock/trade/query?name=positions` | 1891 | 持仓表（14 列 schema） |
| `funds()` | `...name=funds` | 1807 | 资金字段（语义键 fields） |
| `today_orders()` | `...name=today_order` | 1811 | 当日委托 |
| `today_deals()` | `...name=today_deal` | 1810 | 当日成交（旧协议号陷阱设备端已处理） |
| `hist_orders()` | `...name=hist_order` | 1825 | 历史委托（静态日期模板 2025-01-01 起） |
| `hist_deals()` | `...name=hist_deal` | 1824 | 历史成交 |
| `normalized_funds()` | — | 1807 | funds.fields 语义化（金额转 float） |
| `status()` | `GET /stock/trade/status` | — | 诊断（不缓存、不抛业务错误） |

### 3.2 写方法（真实交易动作，客户端强制 confirm=True 门控）

| 方法 | 设备端点 | 门控 |
|---|---|---|
| `submit_order(action,code,price,qty,confirm)` | `POST /stock/trade/order` | confirm 必须 True，否则抛 `trade_confirm_required` |
| `cancel_order(entrust_no,stock_code,stock_name,market_code,shareholder_account,withdrawable_qty,confirm)` | `POST /stock/trade/cancel` | 同上（六段式 entry 设备端组装） |
| `transfer_banks()` | `GET /stock/trade/transfer/banks` | 只读 |
| `transfer(amount,bank_password,confirm,allow_unverified)` | `POST /stock/trade/transfer` | **双重禁用**：默认拒绝（`trade_transfer_disabled`），需显式 `allow_unverified=True` 且协议经人工重放验证后才能开启 |

### 3.3 关键机制

- **全局串行锁**（`threading.Lock`）：设备端交易协议按 protocolId 注册观察者
  （固定协议页路由），并发请求会互相覆盖/串帧（逆向 pitfalls #24）。全部
  请求经进程级单例（`THSTradeClient.shared()`）的锁串行。
- **错误分类**：设备端 `ok=false` 的 error 文本映射为稳定原因码
  （`trade_account_not_logged_in` / `trade_runtime_not_ready` /
  `trade_account_not_recovered` / `trade_response_timeout` /
  `trade_confirm_required` / `trade_endpoint_unreachable` 等），上层据此降级。
- **实现形态**：同步 httpx.Client + threading.Lock。MCP 层
  （`relation_graph._call_agent_market`）经 `asyncio.to_thread` 调用同步函数，
  同步实现最贴合现有架构。
- **配置**：环境变量 `THS_TRADE_BASE_URL`（默认 `http://10.168.1.158:18900`）、
  `THS_TRADE_TIMEOUT`（默认 30s）、`THS_TRADE_READ_CACHE_TTL`（默认 20s）。

## 4. TradeAccountProjectionService 契约

三个投影方法（Research Exposure Pack 契约，逐次调用 positions+funds 组装）：

| 方法 | 成功 | 无持仓 | 端点失败 |
|---|---|---|---|
| `exposure_summary(cutoff_at,account_ids)` | `status=available` + funds 字段 + 持仓行 + summary 聚合（含 cash_ratio） | available（position_count=0） | `status=unavailable` + 原因码 |
| `position_open(...,instrument_id)` | available + 匹配持仓行 | `status=not_found` | unavailable |
| `position_performance(...,instrument_id)` | available + 盈亏/盈亏率/市值/成本/现价 | not_found | unavailable |

- 持仓行提取：优先 `data.records`（键序已校准的语义对象），否则
  `data.rows`+`data.columns` 按位组装；按 `代码`/`名称` 字段匹配 instrument_id。
- 失败降级映射：`trade_endpoint_unreachable→trade_device_unreachable`、
  `trade_account_not_logged_in→trade_account_not_logged_in` 等，响应携带
  `reason_code` + 中文 `reason`，**绝不用市场数据伪造持仓**。

## 5. MCP 工具接线

`relation_graph.py` 三个工具从静态 `exposure_unavailable`（`reason_code=
broker_account_projection_not_connected`）切换为真实投影：

- `research_exposure_summary_open` → `exposure_summary`
- `research_position_open(instrument_id)` → `position_open`
- `research_position_performance_open(instrument_id)` → `position_performance`

工具描述同步更新（明示 on-demand、不可用时返回带原因的 unavailable）。

## 8. 已知边界（详见 9. 待优化.md）

- 静默重登窗口（冷重启后 2~3.5 分钟）内调用返回 unavailable（原因码
  trade_account_not_logged_in），上层应提示等待/重试而非伪造数据
- positions 行的键序映射（TRADE_TABLE_KEY_COLUMNS）当前仅 hist_order 校准，
  持仓有真实行后需校准（当前空仓输出 rows+columns 原样）
- 设备端 ensureTradeRuntimeReady 在仓库未加载时可能长时间阻塞（待优化记录）
- 写端点未在本客户端层做二次风控（金额上限等）——Trading Agent 接入时补
