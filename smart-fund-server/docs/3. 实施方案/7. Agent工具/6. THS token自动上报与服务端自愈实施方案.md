# THS token 自动上报与服务端自愈实施方案

> 版本：2026-08-17（第十五轮）
> 前置：`5. 券商账户投影按需直调实施方案.md`（THSTradeClient / 投影服务）、
> 逆向交接说明 §3.13（token 跨设备共享实验：export/import 端点、解密 key=UDID、livetime=1440min）

## 1. 背景与目标

token 跨设备共享实验（第十四轮）已证明：真机导出明文 token → 另一设备 import 重加密 → 登录成功。
但当时导出/注入全靠 USB 连接电脑跑脚本。本方案目标：

1. **全自动上报**：用户在真机上打开同花顺 App（或探针主动登录）后，设备端自动捕获有效
   token 明文，经网络 POST 到服务端接口，入库 PostgreSQL（`ft_ths_tokens`）。无需数据线、无需手动脚本。
2. **服务端自愈**：服务端调设备端点遇到 token 类失败（过期/未登录）时，自动从库中取最新
   有效 token，经设备端 import 端点注入并重新登录，然后重试原查询。
3. **敏感约束**：token 是券商交易登录凭证明文。上报接口必须 X-Api-Key 认证（未配置 key 时
   接口直接 503 拒绝）；token 不写日志、不回显、不提交代码库；公网部署必须走加密通道。

## 2. 总体链路

```
真机（打开 App / 探针主动登录）
  ├─ 触发点1：z7m.w hook（token 明文唯一经过点，登录响应到达即触发）
  ├─ 触发点2：doActiveTradeLogin 成功后 3s，export 解密自校验兜底上报
  └─ POST url（filesDir 或 /data/local/tmp 配置）+ X-Api-Key
        ↓ http
服务端 POST /api/ths/token （FastAPI :8900）
  └─ TradeTokenService.store_report → ft_ths_tokens（幂等：同 user+token 跳过）
        ↓
服务端任意投影查询（exposure_summary / position_open / ...）
  └─ THSTradeError(reason_code ∈ {trade_token_unavailable, trade_account_not_logged_in})
       └─ TradeTokenService.ensure_device_logged_in：
            client.login() 失败（token 类）→ latest_valid_token()
            → client.import_token()（设备端 z7m.o 官方入口重加密入库 + 主动登录）
            → 重试 positions+funds 一次
```

## 3. 数据库

`schema/03_trading.sql` 追加 `ft_ths_tokens`（幂等 DDL，IF NOT EXISTS）：

| 字段 | 说明 |
| --- | --- |
| user_id / device_id | 上报来源标识（device_id = 机型+ANDROID_ID 后 6 位） |
| token / token_time | 明文 token 及其签发时间戳（秒） |
| livetime_min / expire_at | 有效期（分钟）与到期时间 = token_time + livetime |
| qsid / account / wtid / accounttype / account_nature_type | TokenInfo 携带的账户元数据（可选） |
| source | 上报来源：z7m_w_capture / post_login_export:decrypt / ... |
| reported_at | 入库时间（默认 now()） |

索引：`(user_id, reported_at DESC)`、`(expire_at)`。
ORM：`ThsTokenReport`（`src/infrastructure/persistence/models/trading.py`）。

有效期语义：`expire_at` 为空（探针未携带 livetime）视为"未知"，`latest_valid_token` 保守跳过。
token 为复用型（登录后不滚动），livetime=1440min=24h，每天打开一次 App 即可持续续命。

## 4. 服务端接口

### 4.1 POST /api/ths/token（真机探针上报）

- 认证：请求头 `X-Api-Key: {THS_TOKEN_REPORT_API_KEY}`。key 未配置（空）→ 503；不匹配 → 401。
- 请求体（pydantic）：`token`、`time` 必填；`user_id`、`device_id`、`livetime`、`qsid`、`account`、
  `wtid`、`accounttype`、`accountNatureType`、`source` 可选。
- 响应：`{"ok": true, "stored": bool, "duplicate": bool, "id": int, "expire_at": ...}`——**不回显 token**。
- 实现：`src/interfaces/api/routes/ths_token.py` + `TradeTokenService.store_report`。

### 4.2 GET /api/ths/token/latest（内部/运维）

- 同样 X-Api-Key 认证。返回最新有效 token 明文及元数据（含敏感字段，仅限受控通道调用）。
- 无有效记录返回 `{"ok": false, "reason": "no valid token in store"}`。

### 4.3 配置

`.env`：`THS_TOKEN_REPORT_API_KEY=<48 位随机 hex>`（留空=上报接口整体禁用）。

## 5. 设备端（MainHook，18900 端点新增）

| 项 | 说明 |
| --- | --- |
| 触发点 1 | `z7m.w` hook（beforeCall）：捕获 WtToken/Time 明文 → `reportTokenAsync` |
| 触发点 2 | `doActiveTradeLogin` 成功后调度（锁外 executor + 3s 延迟）：`handleTradeTokenExport` 解密自校验后上报；同 token 被 sha256 去重跳过 |
| 上报器 | 单线程 executor（`ths-token-report`）；payload 含 user_id/device_id/账户元数据（反射 ulm.e() + TokenInfo 字段）；HttpURLConnection POST + X-Api-Key + Connection: close；3 次退避重试（5s/15s）；401/503 不重试 |
| 去重 | 进程内 `lastReportedTokenHash`（sha256）；App 重启清空，服务端幂等兜底 |
| 配置来源 | 优先 `filesDir/thshook_report.json`（端点可写、重启保留），兜底 `/data/local/tmp/thshook_report.json`（adb push 只读）；未配置时上报禁用 |
| 新端点 | `GET /stock/trade/token/report`（状态+配置打码）；`POST /stock/trade/token/report`（body `{url, api_key, enabled, force}`，force=true 立即触发一次导出上报） |
| 日志纪律 | 状态机只记结构信息（http code / attempt / hash 前 8 位），永不打印 token |

## 6. 服务端自愈接线

`TradeAccountProjectionService._open_snapshot`：positions/funds 抛 `THSTradeError` 且
`reason_code ∈ {trade_token_unavailable, trade_account_not_logged_in}` 时，调
`TradeTokenService.ensure_device_logged_in(client)`：

1. `client.login()` 直成（already_logged_in / success）→ 重试查询；
2. 失败仍为 token 类 → `latest_valid_token()`（无则抛最后一次错误，上层降级 unavailable）；
   → `client.import_token(token, time)`（设备端 z7m.o 重加密 + 登录验证）→ 重试查询；
3. 重试仍失败 → 按最终 reason_code 降级 unavailable（不伪造数据）。

`ths_trade.py` 客户端配套：错误分类新增 `trade_token_unavailable`（"token unavailable/expired"），
新增 `export_token()` / `import_token()` 方法。

## 7. 部署与运维

- DDL：对目标库执行 `schema/03_trading.sql` 的 ft_ths_tokens 段（幂等，可重复执行）。
  当前已应用：`jettask`（主库）、`jettask_test`（测试库，tests/conftest.py 约定）。
- 服务端：随 FastAPI 主服务部署；`THS_TOKEN_REPORT_API_KEY` 必须配置强随机值。
- 设备端配置（一次性，二选一）：
  - HTTP：`POST http://<设备IP>:18900/stock/trade/token/report`，
    body `{"url": "http://<服务端>/api/ths/token", "api_key": "...", "enabled": true}`（持久化 filesDir）；
  - adb：push `{"url": "...", "api_key": "..."}` 到 `/data/local/tmp/thshook_report.json`。
- 探针上报 URL 生产建议 `https://` + 公网域名；当前实验环境为 `http://`（见待优化）。
- 生产 8 实例只许 1 个实例登录（用户指定），主实例指定机制另案设计（任务 #21）。
