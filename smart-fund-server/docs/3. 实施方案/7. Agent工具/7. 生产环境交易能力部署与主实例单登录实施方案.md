# 生产环境交易能力部署与主实例单登录实施方案

> 版本：2026-08-18（第十六轮，端到端验收通过）
> 前置：`5. 券商账户投影按需直调实施方案.md`（THSTradeClient）、
> `6. THS token自动上报与服务端自愈实施方案.md`（token 链路）、
> 交接说明 §3.13~§3.14（token 跨设备实验）

## 1. 背景与目标

第一阶段交易能力（六查询 + 写交易 + 主动登录 + token 链路）此前只在测试真机验证。
本方案把它部署到生产 AVD（8 Android 用户实例），并实现用户指定的约束：
**只允许 1 个主实例（owner/user 0）登录券商，交易类接口只路由到该实例**。

三个未决问题在本轮实测定论：
1. **跨设备 token 是否被券商接受**（第十四轮 P1）——定论：直接注入被拒
   （"非交易密码方式登录失败，请输入交易密码登录并重新绑定"），但**移植
   真机设备指纹后接受**（详见 §3）。
2. AVD 无头环境登录链的多处阻断点——全部定位并修复（§4）。
3. 主实例单登录的路由隔离——三层防护落地（§5）。

## 2. 总体架构

```
生产 api（smart-fund-api）
  └─ THSTradeClient → http://127.0.0.1:49301（owner 专用 native-proxy）
                        └─ adb forward 49300 → 设备 18900（owner/user 0 独占端口）
                              └─ MainHook hook 服务器（trade role 门禁）
                                    └─ 登录链 → libweituo.so → 券商

LB 49350（行情采集）：OWNER_AFFINITY_PREFIXES 追加 /stock/trade（防御纵深）
其余 7 实例（user 10~16）：filesDir 无 role 配置 → trade role=false
  → 设备端 403 trade disabled（预热/import/login/查询全拒）
```

单登录的会话约束：token 为**单活会话**（同 token 双端并发登录互踢，实测
1Hz 重登风暴）。生产期真机 role 必须关闭（`POST /stock/trade/role
{"enabled":false}`），token 每日由真机正常使用时刷新上报入库，AVD 由
服务端自愈链注入（`ft_ths_tokens` → import → 登录）。

## 3. 跨设备 token：设备指纹移植（本轮核心突破）

券商的"设备绑定"校验依据客户端上报的设备标识，移植真机标识后跨设备
token 登录被接受。移植项（均在 owner 实例）：

| 层 | 项 | 来源与值 |
| --- | --- | --- |
| SP 文件 | `shared_prefs/hardwareinfo.dat.xml`：`sp_key_wt_hardware_unique`（WT 模块层设备 ID，头号绑定因子）、`sp_key_hardware_unique`、`sp_key_hardware_unique_server`（服务端签发设备 ID）、`sp_key_hardware_mac` | 真机同文件原值（`su -c cat` 读取→写入 AVD，注意属主改回 app uid） |
| Build | MODEL=PLQ110、BRAND=OnePlus | `POST /stock/trade/device-spoof`（反射改静态字段，filesDir/thshook_spoof.json 持久化+启动恢复） |
| getConfigInfo | native→Java 要配置的唯一通道；已实现**字段级合并**伪造（`getconfiginfo` 传 JSON 对象覆盖指定键，动态字段保持本机值） | MobileType=PLQ110 随 Build 自动生效；实测伪造 Userid 反而登录失败（身份与 THS 会话不一致），不伪造 |

设备指纹观测端点：`GET /stock/trade/device-info`（UDID/机型/最近一次
getConfigInfo query+result 原文），跨设备 diff 数据源。

## 4. AVD 无头环境登录链修复（全部实测定位）

登录链 `f2s.q → t9m…s9m 14 级拦截器 → jniRequest → 券商`，逐点修复：

| 阻断点 | 症状 | 修复 |
| --- | --- | --- |
| `lzr.e`=false（native 路径标志仅登录成功回调置位，内存不持久化） | 登录走 CBAS socket 会话检查死路（AVD 上 CBAS 地址未被 PushConnect 设置） | doActiveTradeLogin 发送前强制 `mzr.a.b(mgr).p(true)`（=登录成功回调效果），路由到 jniRequest native 路径 |
| `z9m`（ZLBindWTPhoneInterceptor，r8m.e 智联分支） | a() 检查**本设备**智联绑定手机号，无头环境无记录 → 停链等绑定流程永不回 | hook z9m.a() 强制 false（等价"设备已绑定"） |
| `r0s.u().H()`（isWeituoLogining）僵尸标志 | 非静默登录走死路后标志最长 1h 不清，后续 f2s.q 被 k2s.b 静默丢弃 | 等待超时后 `i0(false)` 强制清除（官方复位同款） |
| x9m（WTModuleInterceptor） | 模块初始化未完成时等回调，AVD 慢初始化+实例重启导致永久等待 | bridge 重试链自续（原 3 档改 6 档 ~15 分钟；失败路径自身续排下一档） |
| 会话被 90B 失效推送打断 | 查询发在旧会话上超时 | 查询超时后**强制登录**（force=true 跳过 already_logged_in 短路）重建服务端会话 + 3s 稳定窗 + 重试一次 |
| fail(null)("null stuff") 误判 | App 内部重登与主动登录并发竞争，竞争超时方以 fail(null) 回调 | fail 后轮询 izr.a.l 5s，置位则按成功收编 |
| token 读取路径 livetime=0 | x7m.i(pzr) 重算使 z7m.i 恒 null（重启后 token "不可用"但文件有效） | seed 文件（thshook_trade_seed.json）并入 token/token_time，登录门自动重播官方 import 链 |
| 账户 seed 失败后永不重试 | tradeSeedAutoPlayed 在失败时也消耗 | 改为成功才消耗一次性标志 |

部署回路注意：**增量 `adb install -r` 不杀进程**，新代码不生效——部署后
必须 force-stop 重启。诊断探针（hookTradeLoginPathDiagnostics）全量保留：
f2s.q/k2s.b/k7r.Q/onChannelOk/Bad/hrv.r/u/C/Socket.connect(9528)/
resetCbasServer/14 级拦截器链/e2s.a0/z9m——热路径（hrv.r）限频 5s。

## 5. 主实例单登录三层防护

1. **设备端 role 门禁**：`filesDir/thshook_trade_role.json`（owner=true 持久化）；
   未配置实例对全部 `/stock/trade/*` 返回 403（role 端点自身豁免）；
   `injectedViaLsposed` 判据：LSPosed 注入（生产）默认禁用、zygisksu（真机）默认启用。
2. **owner 专用 proxy**：`THS_TRADE_BASE_URL=http://127.0.0.1:49301`
   （deploy_113.sh install_production_config 固化，--config 重建不回退）。
3. **LB 亲和兜底**：ths-app-load-balancer.py `OWNER_AFFINITY_PREFIXES`
   追加 `"/stock/trade"`（.bak-trade-affinity 备份），/stock/trade/* 恒路由 owner。

## 10. 交易专属实例切换：user 17（2026-08-18 实施完成）

### 10.1 背景与动机

写操作压测（挂单/撤单闭环）在 owner 复用实例上发现不稳定：撤单响应帧被 App
常驻观察者竞争消费导致响应丢失；且交易会话与采集负载耦合（8 实例 ANR 风暴连带
交易实例重启）。决策：**同 emulator 增设第 9 个 Android user（user 17 "trade"）
作为交易专属实例**，采集 8 实例不动。

### 10.2 拓扑（切换后）

| 层 | owner 复用形态（旧） | user17 专属形态（现） |
| --- | --- | --- |
| 设备 user | user 0（owner，采集主力） | user 17（trade，仅交易） |
| 设备端口 | 18900 | **18980**（=18900+userId×10 规则） |
| 宿主 forward | 49300→18900 | **49390→18980** |
| THS_TRADE_BASE_URL | 49301（owner proxy） | **49390（直连 forward）** |
| trade role | owner=true（现 false） | user17=true（filesDir 持久） |
| 采集角色 | 不变 | 无（role 门禁外的端点与采集隔离） |

### 10.3 全新 user 实例的三层状态移植（关键坑）

新建 user 后 App 是"出厂态"，仅复制 SP 指纹不够，需三层全移植：

1. **设备指纹 SP**（跨设备 token 的前提）：
   `shared_prefs/hardwareinfo.dat.xml`（sp_key_wt_hardware_unique 等 6 键）
   → udid_l 与真机一致（`device-info` 验证）
2. **THS 身份层**（否则 `z7m.i` 读回恒 null=token unavailable）：
   - `files/{userId}_authorization.bat`（token 持久化，文件名含 userId）
   - 身份 SP：`user_md5.xml`、`_sp_last_username.xml`、`sp_key_newuser.xml`、
     `sp_default_group.xml`、`sp_wt_expected_login_account.xml`
   （userId=893668630；ulm.e() 取该值，文件名不匹配则读回 null）
3. **交易通道状态层**（否则登录链卡死在 y9m、hrv 无 Socket.connect）：
   - `files/cbas_mt_*.txt`、`cbas_temp_username.txt`（CBAS 用户名）
   - `files/_weituo_yybinfo.dat`、`_weituonew_third_new.dat`、
     `mt_*_weituo_*.dat`、`yybnature_cached.dat`（营业部/委托缓存）
   - `shared_prefs/sp_weituo_login.xml`、`sp_user_sid.xml`、
     `push_setting.dat.xml`（推送/CBAS 地址源）
   - `files/893668630/` 用户数据目录、`user_info.dat`
4. **role/seed 配置**：`files/thshook_trade_role.json`（enabled=true）、
   `thshook_trade_seed.json`（token 重播）；**不复制** thshook_report.json
   （避免 token 上报双实例竞争；上报仍由真机/owner 侧负责）

移植后登录链走通：14 级拦截器 → e2s.a0 发送阶段 → s9m → 竞争期 fail(null)
→ 复查 `logged_in_state:true`。

### 10.4 实例启动运维要点（多用户启动坑）

- 新建 user 必须 `settings put --user N secure user_setup_complete 1`
  （默认 0 时 am start 静默无效：task 建立、ActivityRecord 存在但 app=null）
- **后台 user 无法启动 activity**：需 `am switch-user 17` 切前台
  （+ `wm dismiss-keyguard` + `input keyevent 82`）→ `am start .Hexin`
  → 等 /health → `am switch-user` 切回（采集框架 launch_ths 同款套路）
- LSPosed scope 加 user：scope 表 INSERT 后需 lspd 随系统正常启动重读
  （**手动 kill/重启 lspd 会引发 system_server 崩溃软重启**，事故已发生并
  通过模拟器重启恢复；正确做法是重启 emulator 让 service.sh 正常拉起）
- 模拟器重启后 user 17 的 App 归属保留（install-existing 持久），
  但 files/ 数据保留需确认（本轮重启未丢）

### 10.7 已知边界

- 撤单/废单类写操作的响应时长上界（两轮+登录最坏 ~120s）超出客户端预期，
  MainHook 已加"撤单在途二次确认"（order-state-2nd），待收盘后全量部署回归。
- user17 的 token 上报未配置（thshook_report.json 未复制），token 生命周期
  仍由真机/服务端库供给；后续可在 user17 配上报（切换前先停旧的上报源）。
- u17 实例无保活 supervisor：进程死亡需手动按 10.4 套路拉起（后续可挂
  systemd lane，复用 ths-collector-bridge@ 模板）。
