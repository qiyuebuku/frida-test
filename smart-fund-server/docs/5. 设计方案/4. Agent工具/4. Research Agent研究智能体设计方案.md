# Research Agent（研究智能体）投资观点形成与持续演化设计方案

> 一句话定位：Research Agent（研究智能体）模拟研究员。它不是行情扫描器、新闻摘要器或买卖信号生成器，而是系统中唯一负责形成、验证和修订投资观点的 Agent（智能体）。

## 1. 先看它怎样完成一次研究

假设盘中出现以下变化：

- 黄金价格上涨；
- 黄金 ETF（交易型开放式指数基金）资金流入；
- 黄金股没有同步上涨；
- 美元和实际利率变化不大；
- 新闻将上涨归因于避险情绪。

Research Agent（研究智能体）不能直接得出“黄金要涨，应该买入”。它应该这样工作：

```text
先检查数据是否新鲜、完整、处于同一时间截面
→ 提出问题：这次上涨主要由避险、资金、利率还是短期拥挤驱动？
→ 同时建立多个可能解释
→ 为每个解释列出应该看到和不应该看到的现象
→ 从市场概览逐层查到资产、标的、历史和精确证据
→ 主动寻找反证，而不是只找支持材料
→ 与当前已有观点和历史经验比较
→ 新证据足够：修订观点
→ 新证据不足：明确返回 no_change（无变化）
```

它最终维护的是一份当前研究报告和其中最新有效的 Investment View（投资观点），不是一条订单。

## 2. 它负责什么，不负责什么

Research Agent（研究智能体）负责：

- 判断市场相对上一次有效判断发生了什么变化；
- 把值得解释的变化转成可以证伪的 Research Question（研究问题）；
- 同时比较多个竞争性解释；
- 查询市场、图谱、外部材料、历史和账户结果；
- 形成、加强、削弱、修订或终止 Investment View（投资观点）；
- 声明接下来需要持续观察什么；
- 用后来真实发生的市场反应评估原预测；
- 把经过验证的教训沉淀为研究经验。

它不负责：

- 决定账户应该持有什么、持有多少；
- 因为当前持仓盈利就加强观点，或因为亏损就推翻观点；
- 输出加仓、减仓、止损、执行计划或订单；
- 用热榜、推荐标签、搜索摘要或图谱社区直接证明结论；
- 覆盖旧观点版本或事后修改当时的理由。

Portfolio Agent（组合管理智能体）和 Trading Agent（交易智能体）可以质疑观点，但只有 Research Agent（研究智能体）可以提出正式观点修订。

## 3. 系统只维护一份当前研究报告

盘前、盘中、盘后、重大事件和深度研究只是不同运行时机，不是五种不同报告。

整个交易系统只读取一份 Current Research Report（当前研究报告）：

```text
Current Research Report（当前研究报告）
→ 当前市场状态和数据质量
→ 当前仍有效的 Investment View（投资观点）
→ 每个观点最新有效的 Revision（修订版本）
→ 下一步需要观察的事实和仍未解决的问题
```

一次运行有观点变化时，先提交观点修订，再重建当前报告；没有变化时只记录本次已经检查以及为什么没有变化，不制造新的业务报告。

旧运行、旧报告快照和旧观点版本仍然保存，用于审计和历史重放。“只有一份报告”指只有一个当前有效入口，不是删除历史。

## 4. 每次运行先拿到什么

系统会根据本次触发准备六类输入。正常实时运行不冻结数据截止时间：每次工具调用都读取调用时可获得的最新数据；只有历史重放使用固定时间边界。

| 输入 | 用途 |
|---|---|
| Trigger Envelope（触发信封） | 说明为什么现在运行、必须回答什么以及运行模式；只有历史重放携带固定数据边界 |
| Market State Frame（市场状态框架） | 给出市场概览、重要变化、数据健康和下钻入口 |
| Research Data Catalog（研究数据目录） | 告诉 Agent（智能体）还有哪些数据可以查询，避免视野只被异常摘要限制 |
| Active View Pack（有效观点包） | 提供与本次变化有关的现有观点及最新版本 |
| Research Exposure Pack（研究持仓暴露包） | 提供与研究有关的只读持仓、盈亏、基准和观点关联 |
| Research Memory Pack（研究经验记忆包） | 提供少量与当前问题相关的历史经验和反例 |

这些内容是起点，不是全部上下文。Agent（智能体）需要根据研究问题继续查询。

## 5. Research Exposure Pack（研究持仓暴露包）为什么必要

Research Agent（研究智能体）需要知道真实账户正在承担哪些观点风险，否则它可能不断研究热门方向，却忽略已经持仓且正在恶化的观点。

它可以读取：

- 当前持仓、数量、市值和组合占比；
- 平均成本、首次/最近建仓时间和持有期；
- 对应的 Investment View/Revision（投资观点/修订版本）；
- 已实现和未实现 P&L（盈亏）；
- 建仓以来和当前观点版本生效以来的表现；
- 基准、板块和风格同期表现；
- 对账、冻结、新鲜度和账户快照状态。

这些数据只用于：

- 优先复核账户真正持有的观点；
- 检查原预测和验证窗口是否兑现；
- 发现“有持仓但没有有效观点”的断链；
- 区分研究、组合选择、风险限制和成交带来的不同结果；
- 触发新的反思和研究问题。

必须遵守：

- 盈利不能证明观点正确，亏损也不能证明观点错误；
- 账户结果可以证明“持有什么、赚亏多少”，不能证明市场因果；
- Research（研究）不能据此输出目标仓位、加减仓、止损或订单；
- `empty`（为空）表示账户真实存在但没有持仓，`unavailable`（不可用）表示账户没有接入或数据读取失败，两者不能混淆。

## 6. Research（研究）可以探索哪些数据

Research Agent（研究智能体）原则上应能只读访问几乎全部已经采集且具有研究意义的同花顺数据，而不是只看行情、新闻和板块。

| 数据范围 | 主要内容 | 研究用途 |
|---|---|---|
| 交易时钟 | A 股、ETF（交易型开放式指数基金）、期货夜盘、美股盘前/常规/盘后和交易日历 | 防止混淆闭市沿用值、跨会话数据和未来信息 |
| A 股整体状态 | 指数、上涨/下跌家数、成交额、涨跌停、炸板、大小盘和成长价值 | 判断风险偏好、市场宽度和行情扩散 |
| 资金、估值和债市 | 大盘资金、成交结构、估值、利率、债市和货币环境 | 判断流动性和定价环境 |
| 竞价与异动 | 集合竞价、大盘/个股/板块异动、涨停和热门股竞价 | 发现盘中状态切换 |
| 股票排行和动态分组 | 各类排行、热榜、精选池、候选池和动态选股分组 | 发现异常对象，但不能直接当结论 |
| 指定股票 | 当前行情、分时、历史、异动、所属板块和资料 | 验证板块扩散、龙头贡献和具体反例 |
| 板块 | 行业、概念、地域、指数、风格、热度、资金、轮动、景气、商品联动和成分 | 识别主线、扩散、拥挤和退潮 |
| ETF（交易型开放式指数基金） | 全量行情、分类排行、跟踪指数、溢价、估算流、正式份额和实时行情 | 验证资金、拥挤和可交易表达 |
| 期货 | 交易状态、资金、主连、商品指数、品种流入流出和历史 | 验证产业链、通胀和跨资产信号 |
| 黄金 | 金银油汇、境内外价差、黄金 ETF（交易型开放式指数基金）资金、储备、相关性、季节性和事件 | 区分利率、汇率、避险、资金和季节驱动 |
| 美股 | 指数、市场宽度、行业/概念、股票排行和 ETF（交易型开放式指数基金） | 提供隔夜及全球风险偏好验证 |
| 基金 | 净值、盘中估值、规模、经理、持仓、分红、公告和交易规则 | 研究场外表达及披露变化 |
| 新闻、公告和研报 | 同花顺资讯、热榜、热点、研报和公告 | 发现催化；正式结论必须打开原文 |
| 情绪和社区 | 市场温度、涨跌停池、雪球、股吧、腾讯热股和派生信号 | 识别拥挤和风险偏好，必须交叉验证 |
| 宏观 | 央行操作、利率、汇率、CPI（居民消费价格指数）、PPI（工业生产者出厂价格指数）、GDP（国内生产总值）、PMI（采购经理指数）、M2（广义货币供应量）等 | 建立中期环境，区分报告期、发布时间和修订 |
| 标的资料和披露 | 股票、ETF（交易型开放式指数基金）、基金资料、规模、持仓、分红、公告和交易规则 | 补充身份、机制和表达限制 |
| 数据健康 | 数据覆盖、最后事实时间、采集状态、错误、空增量、截断和缺口 | 判断“没有变化”还是“数据没有更新” |

拥有完整视野不等于每次加载全部数据。Research Data Catalog（研究数据目录）负责告诉 Agent（智能体）“有什么”，
Market State Frame（市场状态框架）负责提示“哪里最值得先看”。Agent（智能体）仍然可以主动打开未被推荐但与反证或活跃观点有关的数据域。

### 6.1 这些设计来自实际接口，不是凭空假设

2026-08-09 已经逐项请求生产 Market Observatory（市场观测站）的数据清单、仪表盘、采集任务、股票排行、动态分组、板块、
快照、历史、宏观、情绪和基金资料接口。完整接口载荷和交接信息保留在数据能力交接文档，本文只保留直接影响 Agent（智能体）设计的结论：

| 实际看到的情况 | 为什么必须重新设计 Agent（智能体）工具 |
|---|---|
| 数据清单约 280 万条；最近 24 小时的仪表盘仍包含约 43 万条快照，一次响应约 5.3 MB（兆字节）、耗时约 17 秒 | WebUI（网页用户界面）可以消费大聚合接口，模型必须先看小摘要再下钻 |
| 非交易日仍有部分数据标记为“实时”，交易日期也可能落在非交易日 | 不能只信 `realtime`（实时）标签，必须结合交易日历判断数据实际属于哪个会话 |
| 103 个采集任务中 99 个成功、4 个运行，但部分板块数据仍停留在更早交易日 | 任务成功不等于业务数据新鲜，必须检查每个数据域的最后有效事实 |
| 板块概览把热度、排行、资金、轮动、机会和景气放在一起，但各部分日期并不一致 | 不能给整个响应只标一个截至时间，必须让每个维度带自己的时间和质量 |
| 单个 ETF（交易型开放式指数基金）专区约 1.2 MB（兆字节），两个黄金模块约 0.7 MB（兆字节），并保留大量原始嵌套字段 | 需要稳定的业务摘要和分页句柄，不能直接透传数据提供方原始载荷 |
| 动态分组包含“更可能涨停”等推荐语，宏观派生状态也出现过不合适的贡献项 | 推荐和系统派生结果只能作为线索，必须与客观市场事实分开 |
| 通用快照、记录和历史接口要求调用者理解内部数据类型和原始字段 | Agent（智能体）不应该猜数据库结构，需要按市场、板块、标的和证据语义提供专用工具 |

因此，正式 MCP（模型上下文协议）不是把现有 HTTP API（超文本传输应用程序编程接口）换个名字。现有接口只用于理解真实数据；
正式工具要直接读取权威存储，完成时间对齐、字段归一化、来源分层、质量检查和上下文压缩。

## 7. 一次研究的七个步骤

### 7.1 先检查数据是否值得相信

首先确认：

- 当前市场是否开市；
- 数据属于哪个交易日和会话；
- 来源时间、实际查询时间和市场交易时段是否一致；历史重放再检查是否越过重放边界；
- 数据是否过期、截断、沿用旧值或采集失败；
- 不同来源是否使用了不同单位和口径。

如果数据质量不足，结论必须包含限制，不能把缺失误写成市场没有变化。

### 7.2 把变化变成可以证伪的问题

坏问题是：“黄金是不是要涨？”

好问题是：

> 如果这次上涨主要由实际利率下行驱动，那么未来几个交易时段应该看到黄金、黄金 ETF（交易型开放式指数基金）资金和相关资产继续确认；如果实际利率不动且只有热度上升，这个解释会被削弱。

问题必须包含研究对象、时间范围、可能机制、应该看到的现象和什么结果会否定它。

### 7.3 同时建立竞争性解释

至少建立两个能够解释同一现象的假设，例如：

- 利率驱动；
- 避险驱动；
- ETF（交易型开放式指数基金）资金驱动；
- 事件刺激；
- 短期拥挤或技术性反弹；
- 数据异常。

如果只建立一个解释，后续查询很容易变成只寻找支持材料。

### 7.4 把每个假设变成证据计划

对每个假设写清楚：

- 如果它成立，应该看到什么；
- 如果它不成立，应该看不到什么；
- 哪些数据可以区分它和其他解释；
- 哪些事实已经具备；
- 哪些证据需要继续查询；
- 什么情况必须停止研究或降低结论强度。

### 7.5 自主选择下一项研究动作

```text
当前研究状态
→ 判断最大信息缺口
→ 选择信息价值最高的 MCP（模型上下文协议）工具
→ 更新假设、反证和证据账本
→ 继续下钻或停止并提交结论
```

这不是固定 Workflow（工作流）。Agent（智能体）不必每次依次经过市场、板块、标的、历史和原文。
高频、稳定、可复用的机械研究操作应封装成复合 MCP 工具，例如市场变化简报、市场宽度诊断、
板块归因和证据账本读取；Agent 负责选择工具、解释结果和决定是否继续。原子读取工具保留给真正
需要精确下钻的场景。

复杂且可以独立研究的开放问题可以临时委派给专题子 Agent（子智能体），但子 Agent 不是固定
阶段，也不能直接创建正式观点。单个 Agent 和复合工具足以完成时不得机械拆分。

### 7.6 主动寻找反证

Research Agent（研究智能体）必须问：

- 哪些现象与当前解释矛盾；
- 是否只是市场整体上涨带来的相关性；
- 是否存在更简单的解释；
- 价格、资金、宽度和跨市场是否互相确认；
- 来源是否可能有利益或推荐偏差；
- 当前持仓盈亏是否让自己产生确认偏误。

### 7.7 结合经验形成有边界的结论

结论必须说明：

- 当前最可信的解释；
- 仍然可能成立的替代解释；
- 已经确认和仍未知的部分；
- 预测窗口；
- 后续验证条件；
- 什么事实会削弱或推翻判断；
- 是否需要新建、修订观点，或者保持 `no_change`（无变化）。

## 8. 事实、信号、推断和猜想必须分开

Research Agent（研究智能体）处理的内容至少分成五类：

| 类型 | 例子 | 能不能直接证明观点 |
|---|---|---|
| 事实 | 某指数在某时点上涨、某公告正式发布 | 可以作为证据，但仍要说明口径和时间 |
| 来源声明 | 新闻称上涨由避险驱动 | 只能证明“来源这样说”，不能证明原因成立 |
| 来源派生信号 | 同花顺机会标签、热度和推荐分组 | 用于导航，不能单独证明结论 |
| 系统派生信号 | 系统计算的宽度、资金确认或异常 | 必须说明计算口径，不能伪装成原始事实 |
| 推断或猜想 | “资金可能在交易降息预期” | 必须附支持、反证和验证条件 |

关系图谱也有硬边界：

- Community（图谱社区）只能帮助确定研究范围；
- 关系主张必须打开实际 Edge（关系边）；
- `observed`（已观测）和 `inferred`（推断）必须分开；
- 搜索结果摘要不能当证据，必须打开 Card（证据卡片）或正式原文。

## 9. Investment View（投资观点）到底是什么

Investment View（投资观点）不是一句“看多黄金”，而是一份可验证、可修订的结构化判断。

每个观点有稳定 `view_id`（观点标识符），每次变化新增 Revision（修订版本），不覆盖历史。

一个观点版本至少回答：

| 内容 | 要回答的问题 |
|---|---|
| 研究问题 | 这次究竟在解释什么？ |
| 核心主张 | 当前最相信什么？ |
| 机制 | 为什么这些事实可能导致这个结果？ |
| 竞争性解释 | 还有哪些解释仍可能成立？ |
| 预测 | 未来什么时间内应该看到什么？ |
| 支持与反证 | 哪些证据支持，哪些事实矛盾？ |
| 市场确认 | 方向、宽度、资金、持续性、流动性、跨市场和拥挤度怎样？ |
| 失效条件 | 什么事实出现后必须放弃或重写判断？ |
| 观察需求 | 接下来需要持续观察哪些对象和指标？ |
| 不确定性 | 哪些关键问题仍然不知道？ |

置信度不能只给一个随意分数。至少分开考虑证据质量、机制可信度、市场确认、反证强度、数据质量和历史校准情况。

## 10. 观点怎样持续演化

新事实到来时，Research Agent（研究智能体）先查找已有观点，而不是重复创建相同观点。

可能的动作包括：

- `create`（创建）：确实是新的研究问题和稳定观点；
- `strengthen`（加强）：新证据提高了原判断可信度；
- `weaken`（削弱）：出现反证或确认减弱；
- `extend`（延展）：核心机制未变，但预测窗口或适用范围变化；
- `challenge`（挑战）：竞争性解释明显增强；
- `invalidate`（失效）：失效条件命中或核心机制不再成立；
- `no_change`（无变化）：新事实不足以修改观点。

加强和削弱是修订事件，不是用来替代清晰生命周期的模糊状态。历史版本永远保留：

```text
View（观点）稳定身份
→ Revision 1（修订版本 1）：当时相信什么
→ Revision 2（修订版本 2）：哪些新事实改变了判断
→ Revision 3（修订版本 3）：为什么失效或继续有效
```

每个版本都必须记录形成时间、触发原因、来源运行、支持证据、反证和与上一版本的差异；历史重放另记重放边界。

## 11. 怎样用实际市场反应验证观点

研究结果不能只看账户最终赚没赚钱。账户盈亏还受到仓位大小、表达载体、风险限制和成交影响。

系统应根据观点事先保存的预测，在验证窗口结束后生成 Outcome Evaluation（结果评估）：

- 原来预测了什么；
- 实际发生了什么；
- 哪些验证条件命中；
- 哪些反证或失效条件出现；
- 方向、幅度、持续时间和市场确认是否符合预期；
- 观点本身、组合表达和交易执行分别贡献了什么；
- 结果是正确、部分正确、错误、仍无法判断还是数据不足。

不能在结果出来以后更换预测窗口、比较基准或成功标准。

## 12. Research Agent（研究智能体）的五层记忆

一份 Markdown（Markdown 文本文档格式）报告不能同时承担事实、观点、结果和经验存储。五层记忆必须分开：

| 记忆层 | 保存什么 | 权威位置 | 生命周期 |
|---|---|---|---|
| 工作记忆 | 本次问题、工具结果、假设状态和未解决冲突 | Agent Session（智能体会话）与 Run Context（运行上下文） | 运行结束后不作为正式业务状态 |
| 事实记忆 | 行情、公告、新闻原文、Card、Edge、宏观和账户结果事实 | 市场库、证据库、图谱和账户事实服务 | 不能被观点反向修改 |
| 观点记忆 | 当前相信什么、为什么、什么会推翻 | Investment View（投资观点）与 Revision（修订版本） | 不覆盖，持续演化 |
| 结果记忆 | 当时预测什么，后来实际发生什么 | Outcome Evaluation（结果评估） | 验证窗口结束后生成 |
| 经验记忆 | 哪些模式有效、哪里经常错、在什么条件下适用 | Research Memory Item（研究经验记忆项） | 经评测晋升，可降权和失效 |

### 12.1 猜想、事实、做对和做错怎样体现

- 待证实想法放在观点版本的假设、竞争性解释和未知项中；
- 已确认事实留在事实库，并由观点引用，不复制成“模型记忆”；
- 原预测留在观点版本，后来实际结果留在结果评估；
- “为什么做对或做错”先形成 Reflection Candidate（反思候选）；
- 只有经过多个案例、反例和历史重放验证后，才晋升为正式研究经验。

### 12.2 正式经验至少包含什么

- 经验结论；
- 适用市场、资产、时间尺度和前提条件；
- 来源运行、原观点和真实结果；
- 支持案例和反例；
- 哪些情况下不适用；
- 评测结果、版本、有效期和失效条件。

Research Agent（研究智能体）只能提交经验候选，不能把自己刚产生的反思立即变成永久规则。

### 12.3 每次运行怎样读取经验

系统根据当前研究问题、市场状态、资产、观点和时间尺度召回少量相关经验，同时保留必要反例。Agent（智能体）还可以继续打开
经验关联的原观点、原证据和真实结果，不能只读一句脱离背景的“经验总结”。

## 13. 观察需求和持续采集

Research Agent（研究智能体）可以声明 Observation Requirement（观察需求）：

- 观察哪个对象和指标；
- 需要多长时间和什么频率；
- 什么变化算支持、削弱或失效；
- 数据新鲜度要求；
- 需求与哪个观点版本关联。

日常自主探索不要求标的先进入跟踪列表。Agent（智能体）可以直接查询任意少量股票或 ETF（交易型开放式指数基金）的同花顺最新概览，确认有研究价值后再对选中对象请求有界详情。

Observation Requirement（观察需求）才进入持续采集：统一采集系统根据估值阈值、价格变化、成交、资金、公告或观点失效条件建立增量采集和确定性判断；条件满足后触发 Agent（智能体）重新研究。持续采集的价值是低成本监控和事件触发，不是替代 Agent（智能体）临时探索时的实时查询。

必须区分：

```text
正在采集某标的
≠ 它是投资候选
≠ 系统已经形成观点
≠ 账户真实持有
```

## 14. 什么时候运行

常见触发包括：

- 盘前、盘中重要变化和收盘；
- 重大新闻、公告、研报或宏观数据；
- 活跃观点达到验证、复核或到期时间；
- Portfolio（组合管理）提交研究请求或观点质疑；
- Trading（交易）发现市场反应或风险现象与观点冲突；
- 持仓表现显著偏离观点预测；
- 历史重放和离线评测。

确定性程序负责发现“数值变了多少”，Research Agent（研究智能体）负责解释“为什么变化、是否足以改变观点”。

多个短时间事件应先聚合，避免同一市场变化重复触发多次研究。

## 15. 一次运行的正式输出

模型根据结论选择两种结束契约之一：

- `submit_research_conclusion`（提交研究结论）：观点不变、阻塞、证据不足或预算耗尽时使用，
  只提交小型研究结论；
- `submit_investment_view_revision`（提交投资观点修订）：确实创建或修订观点时使用，提交完整
  竞争假设、证据、机制、市场结构、预测和决策边界。

服务端把两种输入统一绑定为一份 Current Research Report Proposal（当前研究报告提案），其中可以包含：

- 当前市场和数据质量摘要；
- 新建或修订的 Investment View Revision（投资观点修订版本）；
- 后续 Observation Requirement（观察需求）；
- 当前无法取得但需要记录的 Evidence Gap（证据缺口）；
- Reflection Candidate（反思候选）；
- 没有足够新事实时的 `no_change`（无变化）。

模型不能直接写数据库。服务端必须检查：

- 引用的证据是否在本次运行实际打开；
- 实时证据是否为查询时最新可用版本；历史重放证据是否越过重放边界；
- 观点版本是否仍然是当前版本；
- 状态迁移是否合法；
- 是否与已有观点重复；
- 结构化输出和防重复键是否有效。

校验通过以后，才保存正式观点版本并重建当前研究报告。

### 15.1 Research Quality Evaluator（研究质量评估器）

Research Agent（研究智能体）的历史条件校准、原子证据映射、语义评测、固定回放集和结果评测升级，统一见《8. Research Agent研究能力与质量评测升级设计方案》。本节只保留质量评估在 Research Agent（研究智能体）生命周期中的职责边界。

结构化格式正确不等于研究质量优秀，但研究质量不能靠固定规则代替 Agent（智能体）思考。
每次提案提交后由 Research Quality Evaluator（研究质量评估器）独立评分，不接受模型自报分数。
评估器同时使用结构化提案和服务端实际工具调用台账，评估十个维度：

- 事实完整性、证据覆盖度和证据独立性；
- 探索深度、竞争性假设和反方证据；
- 因果机制完整性、市场结构分析和可证伪性；
- 对组合决策的可用性。

评分只用于长期观测、不同版本对比和结果校准，不作为研究提案的发布门槛，也不通过“调用了几种
工具”强迫 Agent（智能体）执行固定工作流。提交边界只拒绝可确定判定的错误：Schema（结构）
不合法、运行身份或版本不匹配、越权、状态迁移非法，以及引用了本次未实际打开的证据。
导航句柄、搜索摘要、Edge（关系边）附带的端点 Card ID（知识卡片标识）仍不算已读正式证据。

每次评估必须持久化分项分数、观察到的不足、改进建议、工具覆盖和证据数量，但不得把建议注入
同次运行形成反复改稿循环。
后续 Outcome Evaluation（结果评估）产生后，再生成 `outcome_adjusted_score`
（结果校准分），用于追踪“当时写得好”是否真的转化为“后来判断对”。

## 16. 失败时怎样处理

| 问题 | 处理方式 |
|---|---|
| 数据源失败或返回旧快照 | 明确标记旧数据；关键事实不足时降低结论强度或停止修订 |
| 不同来源冲突 | 同时保留并解释口径，不能自行平均 |
| 只有图谱社区或搜索摘要 | 只能继续导航，不能作为正式证据 |
| 缺少关键关系证据 | 关系保持待验证推断 |
| 账户持仓不可用 | 仍可完成市场研究，但不能声称完成持仓观点复核 |
| 模型超时或超过预算 | 本次运行失败，不写半成品观点版本 |
| 输出结构或证据引用不合法 | 拒绝业务写入并记录错误 |

## 17. 建设顺序

1. 建立完整 Research Data Catalog（研究数据目录）和有界 Market State Frame（市场状态框架）；
2. 打通从概览、数据域、对象、历史到精确证据的渐进查询；
3. 建立稳定观点、不可覆盖修订、证据校验和唯一当前研究报告；
4. 建立结果评估、反思候选和研究经验治理；
5. 在账户权威层完成后接入只读 Research Exposure Pack（研究持仓暴露包）；
6. 让定时、事件、人工调试和历史重放复用同一运行时和工具。

## 18. 验收标准

- Research（研究）可以发现几乎全部已采集且有研究价值的数据域，但单次上下文仍然有界；
- 能按市场概览、维度、对象、历史和精确证据逐层查询；
- 每个观点从可证伪问题产生，并包含竞争性解释、预测、反证和失效条件；
- 每条实质主张引用本次实际打开的最新可用证据；历史重放不得引用边界之后的证据；
- 能稳定输出 `no_change`（无变化），不会为了每次运行制造新观点或新报告；
- 观点版本不可覆盖，历史重放看不到未来事实、观点和经验；
- 工作、事实、观点、结果和经验五层记忆拥有不同权威位置；
- 持仓和盈亏只用于研究优先级、结果评估和反思，不能产生仓位或订单决定；
- Research（研究）能主动寻找反证，并明确区分事实、来源声明、系统信号、推断和未知项。
