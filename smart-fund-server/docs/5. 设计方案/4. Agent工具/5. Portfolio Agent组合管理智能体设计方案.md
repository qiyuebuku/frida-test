# Portfolio Agent（组合管理智能体）设计方案

> 一句话定位：Portfolio Agent（组合管理智能体）模拟投资组合经理。它不研究市场真相，而是决定已经形成的观点是否值得在当前账户中持有，以及持有多少。

Portfolio Agent（组合管理智能体）管理整个交易账户的跨资产组合，包括股票、ETF（交易型开放式指数基金）、场外基金、
期货、黄金、美股、现金和后续接入的其他资产。所有候选、持仓和组合意图统一使用通用标的与资产类型表达。

## 1. 先看一个完整例子

Research Agent（研究智能体）形成了一个观点：

> 实际利率可能下行，黄金中期偏强；如果实际利率重新上升并且黄金资金持续流出，这个观点失效。

Portfolio Agent（组合管理智能体）不会重新研究这个观点对不对。它要解决的是：

```text
当前账户是否适合表达这个观点？
→ 用黄金 ETF（交易型开放式指数基金）、黄金股还是期货？
→ 现有组合是否已经有类似暴露？
→ 加入以后集中度、流动性和最大损失怎样变化？
→ 是新建、增加、减少、替换，还是不行动？
```

假设账户已经持有较多资源股，而且黄金期货需要的风险和保证金过高，最终结果可能是：

> 使用流动性更好的黄金 ETF（交易型开放式指数基金），目标增加 2% 组合权重；如果溢价过高则暂不执行。

这是一份 Portfolio Intent（组合意图），不是订单。怎样成交还要交给 Trading Agent（交易智能体）。

## 2. 它负责什么，不负责什么

Portfolio Agent（组合管理智能体）负责：

- 把有效 Investment View（投资观点）转换成可以比较的投资候选；
- 比较股票、ETF（交易型开放式指数基金）、场外基金、期货、黄金、美股和现金等不同表达方式；
- 判断候选加入以后对整个组合的影响；
- 决定目标持仓或目标暴露；
- 复核当前持仓是否仍值得保留；
- 比较调仓、保持现金和其他机会之间的机会成本。

它不负责：

- 创建或修改 Investment View（投资观点）；
- 因为持仓盈利就加强观点，或因为亏损就宣布观点失效；
- 决定拆单、限价、交易节奏或订单类型；
- 绕过 Trading Agent（交易智能体）和确定性风控直接下单。

如果它发现研究逻辑有问题，只能提交 Research Request（研究请求）或 View Challenge（观点质疑），让 Research Agent（研究智能体）重新研究。

## 3. 每次运行先拿到什么

系统会为它准备一份有统一决策截止时间的组合上下文。主要包含：

| 内容 | 回答的问题 |
|---|---|
| 当前研究报告和有效观点 | 当前有哪些仍然有效的投资判断？ |
| 可用表达载体 | 同一个观点可以通过哪些标的表达？ |
| 当前持仓、成本、权重和现金 | 账户现在处于什么位置？ |
| 冻结资金和待成交订单 | 哪些资金或仓位已经被占用？ |
| 行业、主题、因子、地区和币种暴露 | 新候选是否与现有持仓重复？ |
| 相关性、集中度、流动性、费用和压力结果 | 加入以后组合会不会太危险或难以退出？ |
| 历史组合决定和未交易机会 | 过去在类似情况下做得怎样？ |
| 组合经验 | 哪些历史教训与当前问题有关？ |
| 对账、冻结和账户连接状态 | 当前能不能形成可执行的组合意图？ |

初始上下文只给摘要和异常。需要时再打开单个观点、持仓、候选、暴露或历史结果，不能一次把全部账户流水塞给模型。

## 4. 从观点到候选

Opportunity Candidate（机会候选）表示“这个标的可能适合表达某个观点”。它不是新观点，也不是买入信号。

每个候选必须回答：

- 它关联哪个有效观点和修订版本；
- 为什么这个标的能表达该观点；
- 预期收益来自什么，预计持续多久；
- 流动性、费用、溢折价、杠杆、到期和容量有什么限制；
- 与现有持仓是否重复；
- 是否有更便宜、更纯或更容易交易的替代品；
- 什么情况下入选、暂缓或淘汰。

同一个观点可以有多个候选，也可以没有合适候选。观点有效不等于组合必须持有。

候选状态至少区分：

- `research_only`（仅研究）：信息还不够，不能进入组合；
- `shadow_eligible`（可进入影子组合）：可以模拟，但不能形成真实意图；
- `intent_eligible`（可形成组合意图）：具备进入正式组合评估的条件；
- `rejected`（已拒绝）：当前不适合作为表达载体。

## 5. 怎样判断应该持有多少

Portfolio Agent（组合管理智能体）不能把模型置信度直接换算成仓位。它需要同时考虑五类问题。

### 5.1 观点是否适合当前组合

- 观点是否仍有效，预测窗口是否还没有结束；
- 当前是否已经接近验证或失效条件；
- 候选和观点之间是否有真实的暴露机制；
- 研究中未解决的问题是否足以阻止真实持仓。

### 5.2 选择哪种表达

- 哪个标的对观点的暴露更纯；
- 跟踪误差、基差、费用、杠杆和交易时段是否合适；
- 是否存在停牌、涨跌停、申赎、跨境额度或容量问题；
- 是否引入了大量与观点无关的风险。

### 5.3 加入以后整个组合怎样变化

不能只看单个标的，必须计算调整后的全组合：

- 总暴露、行业、主题、因子、地区和币种变化；
- 与现有持仓的相关性和重复暴露；
- 集中度、流动性、换手、费用和现金缓冲；
- 正常、压力和流动性枯竭情况下可能亏多少。

数值和硬规则由确定性计算服务给出，模型只负责解释多个目标之间的取舍。

### 5.4 现有持仓是否还值得保留

每次复核都要问：

- 关联观点是否仍有效；
- 当前权重是否因为价格变化偏离原计划；
- 收益来自观点兑现、市场整体上涨、风格、标的自身还是执行；
- 如果今天没有这笔持仓，还会不会重新选择它；
- 是否出现了更好的替代表达。

Portfolio Agent（组合管理智能体）可以因为组合不再适合而减仓或退出，但不能因此宣告研究观点失效。

### 5.5 不行动是不是更好

系统必须把以下方案放在一起比较：

- 新增候选；
- 保留当前持仓；
- 替换最弱持仓；
- 保持现金；
- 暂时不做任何事。

如果小幅优化不足以覆盖费用、滑点和不确定性，`no_action`（不行动）就是正确结果。

## 6. 正式输出：Portfolio Intent（组合意图）

Portfolio Intent（组合意图）描述“组合希望变成什么样”，不描述“订单怎样成交”。它至少包含：

| 内容 | 说明 |
|---|---|
| 身份和版本 | 意图、账户、来源运行、决策截止时间和防重复键 |
| 研究关联 | 对应的观点、观点修订版本和候选 |
| 当前与目标 | 当前数量/权重、目标数量/权重或目标区间 |
| 调整原因 | 为什么选择这个表达，加入后组合怎样变化 |
| 允许边界 | 最大变化、现金缓冲、流动性、容量和最晚生效时间 |
| 复核条件 | 什么变化需要重新评估、减仓、退出或更换表达 |
| 数据状态 | 使用的账户快照、观点版本、市场快照和对账状态 |

合法动作包括新建、增加、保持、减少、退出、替换和不行动。

Trading Agent（交易智能体）可以批准、缩减或拒绝该意图，但不能把目标扩大到 Portfolio Agent（组合管理智能体）没有提出的范围。

## 7. 发现研究问题时怎么办

Portfolio Agent（组合管理智能体）有两种正式反馈：

- Research Request（研究请求）：缺少关键机制、数据、验证条件或候选比较，导致组合无法决定；
- View Challenge（观点质疑）：组合或市场事实与当前观点发生冲突，并且已经打开了具体反证。

它们会触发新的 Research Run（研究运行），但不会直接修改观点。

## 8. 一次运行的完整过程

```text
确认为什么运行，以及账户是否正常
→ 打开相关观点和上次组合决定
→ 查看持仓、现金、待成交活动和约束摘要
→ 生成或复核候选
→ 比较表达质量、组合影响、机会成本和不行动方案
→ 输出组合意图、研究请求、观点质疑或不行动
→ 服务端检查版本、账户、约束和重复提交
→ 发布正式结果
```

它可以因为新观点运行，也可以因为组合漂移、现金变化、集中度、相关性或固定复核点独立运行。

## 9. 组合经验怎样积累

Portfolio Memory（组合经验记忆）主要记录：

- 哪类表达在什么市场环境下更稳定；
- 仓位、流动性和组合结构怎样共同影响结果；
- 历史相关性什么时候失效；
- 哪些持仓实际属于重复暴露；
- 哪些调仓被费用和滑点吞噬；
- 哪些未交易机会或保持现金的决定后来更好。

每条经验候选都必须关联原组合决定、当时的组合快照、实际结果、比较基准、反例和适用条件。一次盈利不能直接变成永久经验。

## 10. 调度与失败处理

常见触发包括新观点、观点重大修订、组合漂移、现金变化、固定复核和 Trading（交易）拒绝/缩减反馈。

以下情况不允许发布新增风险意图：

- 账户或持仓快照不可用；
- 对账未完成或账户被冻结；
- 待成交活动与组合快照不一致；
- 观点已经过期或在运行过程中换了版本；
- 关键相关性、流动性或压力数据缺失，却被错误地当成零风险。

## 11. 建设顺序

1. 先提供观点、候选、持仓、现金和账户状态的只读上下文；
2. 再提供暴露、相关性、集中度、流动性和机会成本计算；
3. 在 shadow（影子模式）建立候选和组合意图状态；
4. 建立组合结果、未交易机会和经验闭环；
5. 与 Trading（交易）、运营和模拟账户打通；
6. 达到评测门槛后，才允许向真实交易阶段发布有限范围的意图。

## 12. 验收标准

- Portfolio（组合管理）不能创建、修改或宣告 Investment View（投资观点）失效；
- 每个候选和意图都关联一个有效观点及明确表达机制；
- 能同时比较新候选、现有持仓、替代品、现金和不行动方案；
- 以调整后的全组合风险为依据，不只看单个标的分数；
- 仓位不由模型置信度直接换算，并受到确定性约束；
- Portfolio Intent（组合意图）与执行计划、订单意图严格分开；
- 可以独立运行并稳定输出 `no_action`（不行动）；
- 缺少权威账户、对账或关键风险数据时不会假装完成组合决策。
