# Portfolio Agent（组合管理智能体）设计方案

> 一句话定位：Portfolio Agent（组合管理智能体）读取 Research Agent（研究智能体）已经形成的有效观点，结合账户、持仓、现金和全组合约束，决定当前组合应该保持什么、调整什么以及调整到什么范围。

它不重新研究市场，也不负责怎样下单。它负责把“研究上相信什么”转换成“组合上愿意承担什么暴露”。

## 1. 它在三个智能体之间处于什么位置

```text
Research Agent（研究智能体）
形成或修订 Investment View（投资观点）
        ↓
Portfolio Agent（组合管理智能体）
比较表达、持仓、现金和机会成本，形成 Portfolio Intent（组合意图）
        ↓
Trading Agent（交易智能体）
复核风险并在获准边界内管理成交
```

三者不是一条每次必须走完的固定流水线：

- Research（研究）可以形成观点，但 Portfolio（组合管理）认为没有合适表达或组合已经过度暴露，因此不行动；
- Portfolio（组合管理）可以因现金、持仓漂移或旧意图到期而独立运行，不要求 Research（研究）先运行一次；
- Trading（交易）可以缩减或拒绝组合意图，但不能替 Portfolio（组合管理）选择一个更大的目标；
- Portfolio（组合管理）发现观点和账户事实冲突时，只能质疑 Research（研究），不能修改观点。

## 2. 当前系统基础与设计起点

本方案以已经运行的 Research Agent（研究智能体）和现有数据能力为起点，不再使用最初设计时的假设。

### 2.1 已经具备的上游能力

- Current Research Report（当前研究报告）、Investment View（投资观点）、Revision（修订版本）、Claim（主张）、Forecast（预测）、反证、失效条件和 Observation Requirement（观察要求）已经结构化保存；
- Research Agent（研究智能体）能够读取全市场、板块、股票、ETF（交易型开放式指数基金）、基金、期货、黄金、美股、历史 K 线、资金、新闻图谱和精确证据；
- `market_expression_compare_open（市场表达比较）` 已能实时比较 ETF 的身份、跟踪指数、流动性、持仓和重叠；
- Role Memory（角色经验记忆）、运行授权、证据账本、Langfuse（大语言模型可观测平台）和结构化 Proposal（提案）提交链路已经具备可复用基础；
- Research Agent（研究智能体）会明确给出“不支持方向押注”，因此 Portfolio（组合管理）必须把 `no_action（不行动）` 当作正常且重要的正式结果。

### 2.2 尚未具备的关键基础

项目当前存在同花顺基金交易账户接口，也存在旧的 `ft_positions（旧基金持仓表）`、`ft_trades（旧交易表）` 和基金专用决策表，但它们不能直接成为 Portfolio Agent（组合管理智能体）的权威输入：

- 旧表围绕基金代码设计，无法统一表达股票、ETF、场外基金、期货、黄金、美股和现金；
- 缺少稳定 `account_id（账户标识符）`、快照版本、币种、冻结、待成交占用和对账状态；
- 本地持仓聚合、同花顺账户实时返回和券商事实之间还没有确定性优先级与对账关系；
- 目前 Research 持仓工具会明确返回 `broker_account_projection_not_connected（券商账户投影未接入）`，不能把市场数据或旧表推测成真实账户状态。

因此，Portfolio Agent（组合管理智能体）的第一个工程前置条件不是写 Prompt（提示词），而是建立只读、版本化、跨资产的 Account and Portfolio Projection（账户与组合投影）。

## 3. 它负责什么

Portfolio Agent（组合管理智能体）负责六件事：

1. 判断哪些有效观点值得进入当前组合评估；
2. 比较股票、ETF、场外基金、期货、黄金、美股或现金等表达方式；
3. 复核现有持仓是否仍适合当前组合；
4. 比较调整前后全组合的暴露、集中度、相关性、流动性、现金和机会成本；
5. 提出目标权重、目标暴露或允许区间，而不是订单；
6. 在信息不足、改善太小或成本太高时正式选择不行动。

它不负责：

- 新建、加强、削弱或宣告 Investment View（投资观点）失效；
- 把持仓盈利解释成观点正确，把持仓亏损解释成观点错误；
- 生成限价、拆单、参与率、交易节奏或订单类型；
- 修改风险限额、账户事实、订单、成交或对账结果；
- 绕过 Trading Agent（交易智能体）、Risk Engine（确定性风控引擎）和 Order Gateway（订单网关）。

## 4. Research 应向 Portfolio 交付什么

Portfolio（组合管理）不读取 Research（研究）的整段聊天记录。它读取服务端已经校验并发布的对象。

### 4.1 最小研究交付包

每个进入组合评估的观点至少提供：

| 内容 | Portfolio（组合管理）怎样使用 |
|---|---|
| `view_id（观点标识符）` 和 `revision_id（修订版本标识符）` | 锁定本次判断所依赖的研究版本 |
| 状态和有效期 | 过期、失效或仅研究状态的观点不能新增风险 |
| 核心论点和对象 | 明确要表达的风险来源，而不是只看板块名称 |
| 支持、直接反证和数据限制 | 决定是否需要更保守的组合表达 |
| 历史校准和最不利结果 | 用于比较候选和限制目标范围，不能直接换算仓位 |
| 失效条件和观察要求 | 变成组合复核条件，而不是由 Portfolio 改写 |
| 决策边界 | 明确 Research 当前不支持哪些方向或行为 |
| 表达候选 | 只作为待比较候选；未经身份核验的导航 ETF 不能直接入选 |

### 4.2 没有方向观点时怎么办

Research（研究）当前经常会形成“结构焦点存在，但不支持方向押注”的高质量结论。这种情况下：

- Portfolio（组合管理）不能为了产生动作而自行补出方向；
- 可以复核现有持仓是否与已披露风险冲突；
- 可以保持现金、维持原组合或降低无观点支持的暴露；
- 可以建立影子候选和观察条件，但不能把它升级成真实新增风险意图；
- 如果组合确实需要方向判断，应提交 View Challenge（观点质疑）或 Research Request（研究请求）。

## 5. 账户与组合权威投影

### 5.1 为什么必须单独建设

Portfolio（组合管理）的结论依赖“现在到底持有什么”。这个事实不能由大模型整理接口返回，也不能从交易记录临时累加。

推荐的数据链路是：

```text
券商/交易平台账户事实
→ Account Connector（账户连接器）
→ Operations Service（运营服务）标准化和对账
→ 版本化 Account Snapshot（账户快照）
→ 版本化 Portfolio Snapshot（组合快照）
→ Portfolio MCP（组合模型上下文协议）只读投影
```

### 5.2 Account Snapshot（账户快照）至少包含什么

- `account_id（账户标识符）`、账户类型、市场和基础币种；
- 总资产、可用现金、冻结现金、保证金和待交收金额；
- 持仓数量、市值、成本、可用数量、冻结数量和未实现盈亏；
- 待成交订单和已经占用的现金或持仓；
- 数据来源、券商事实时间、采集时间和快照版本；
- 对账状态、连接状态、冻结状态和异常代码。

账户接口返回成功不等于账户快照可用。只有对账状态满足要求、版本完整且关键字段不缺失时，Portfolio（组合管理）才能形成新增风险意图。

### 5.3 通用跨资产标识

后续正式对象统一使用：

```text
instrument_id（标的标识符）
asset_type（资产类型）
market（市场）
currency（币种）
account_id（账户标识符）
```

不能再把 `fund_code（基金代码）` 作为组合系统的通用主键。不同资产额外字段进入各自详情：

- 股票/ETF：交易所、交易单位、停牌和涨跌停；
- 场外基金：确认日、申购赎回规则、限购、费用和净值时滞；
- 期货：合约、乘数、保证金、到期和换月；
- 黄金和跨境资产：交易时段、汇率、额度和基差。

## 6. Portfolio Context Pack（组合上下文包）

初始上下文只给本次决策需要的摘要和异常，不一次传入全部持仓、观点和交易流水。

### 6.1 初始摘要

| 模块 | 初始只返回什么 |
|---|---|
| Trigger（触发器） | 为什么运行、关联观点/账户、任务类型和模式 |
| Account Health（账户健康） | 可用、为空、不可用、冻结或对账异常 |
| Portfolio Summary（组合摘要） | 总资产、现金比例、持仓数、主要集中和漂移 |
| Research Changes（研究变化） | 新增/重大修订观点及决策边界 |
| Active Intents（活动意图） | 未完成、已交给 Trading 或需要复核的意图 |
| Constraint Summary（约束摘要） | 接近限额、流动性和现金异常；不返回整套规则 |
| Memory Hints（经验提示） | 与本次账户、资产和任务最相关的少量经验句柄 |

### 6.2 按需下钻

Agent（智能体）根据当前最大信息缺口选择读取：

```text
组合概览
→ 相关观点或异常持仓
→ 表达候选比较
→ 调整前后组合模拟
→ 压力、成本和机会成本
→ 历史组合案例或经验反例
```

这不是固定 Workflow（工作流）。如果触发原因只是现金到账，可能无需重新打开全部研究；如果是新观点，则需要先检查观点和表达；如果是集中度漂移，则应先定位暴露来源。

## 7. 从观点到可投资表达

### 7.1 Opportunity Candidate（机会候选）

Opportunity Candidate（机会候选）表示某个标的可能用于表达某个观点。它不是新观点，也不是买入决定。

候选至少包含：

- 关联的观点和修订版本；
- 标的身份、资产类型、市场和币种；
- 表达机制：标的为什么能获得目标暴露；
- 纯度和非目标暴露；
- 流动性、费用、跟踪误差、基差、杠杆、容量和交易限制；
- 与现有持仓及其他候选的重叠；
- 数据质量、有效期和淘汰条件。

候选状态为：

- `discovered（已发现）`：仅完成身份发现；
- `verified（已核验）`：身份、表达机制和关键数据已核验；
- `shadow_eligible（可用于影子组合）`：可以参与模拟比较；
- `intent_eligible（可形成组合意图）`：满足当前账户的正式评估条件；
- `rejected（已拒绝）`：当前不适合作为表达；
- `expired（已过期）`：观点、行情或候选数据已经失效。

### 7.2 ETF 导航候选的边界

板块工具返回的 `etf_navigation_candidates（ETF 导航候选）` 只是同花顺页面入口，不是稳定代理。Portfolio（组合管理）若要使用具体 ETF，必须调用表达比较能力核验：

- 基金名称和类型；
- 跟踪指数；
- 最新持仓和主题纯度；
- 成交、规模、费用和申赎限制；
- 与其他候选及现有持仓的重叠。

如果信息不足，结论是“没有已核验表达”，而不是从多个导航代码中随便选择一个。

## 8. Portfolio Agent 怎样形成决策

### 8.1 先判断是否允许承担新增风险

以下任一情况成立时，不得形成新增风险意图：

- 账户快照不可用、版本不完整或对账异常；
- 账户被冻结或待成交占用无法确认；
- 观点已经失效、过期或明确不支持方向押注；
- 没有经过核验的表达载体；
- 调整后的组合风险和流动性无法计算；
- 运行期间观点、账户或组合快照版本发生变化。

这不阻止 Agent（智能体）形成降低风险、退出、保持或质疑研究的 Proposal（提案），但服务端仍会按账户状态判断能否发布。

### 8.2 比较当前持仓、候选和现金

每次真正的组合判断至少比较：

1. 保持当前持仓；
2. 新增或增加候选；
3. 减少或退出弱持仓；
4. 用更合适的表达替换当前持仓；
5. 保持现金；
6. 不采取行动。

如果今天没有某笔持仓，Portfolio（组合管理）必须问“现在是否仍愿意重新建立它”。但答案不能只由盈亏决定。

### 8.3 盈亏怎样使用

持仓盈亏是组合状态，不是市场证据：

- 盈利可能来自观点兑现、市场 Beta（整体市场暴露）、风格、汇率或执行；
- 亏损可能来自短期波动、观点错误、表达不纯、仓位过大或成交成本；
- Portfolio（组合管理）可以因组合约束减仓，但不能因此修改研究观点；
- 若实际表现与观点预测冲突，应向 Research（研究）提交带具体事实的 View Challenge（观点质疑）。

### 8.4 仓位不是模型置信度乘一个系数

模型不能使用“高置信度=10%仓位”之类的机械公式。目标范围需要综合：

- 观点有效期、历史校准、直接反证和数据限制；
- 候选表达纯度和非目标风险；
- 当前已有相同或相关暴露；
- 组合集中度、相关性、现金和流动性；
- 正常、压力和相关性上升情景；
- 调整成本、滑点、费用和机会成本；
- 当前是否存在更重要的候选或更值得保留的现金选择。

确定性计算服务负责计算每个目标方案的数值结果。Agent（智能体）负责在多个可行方案之间作取舍，程序不能替模型决定哪个机会更值得持有。

## 9. 确定性组合计算服务

Portfolio Agent（组合管理智能体）不能自己心算相关性、权重和压力损失。服务端至少提供以下确定性计算：

| 服务 | 输出 |
|---|---|
| Portfolio Valuation（组合估值） | 资产、市值、成本、现金、权重和币种折算 |
| Exposure Aggregation（暴露聚合） | 标的、行业、主题、因子、地区、币种和观点暴露 |
| Overlap Analysis（重叠分析） | ETF/基金持仓重叠、成分重叠和重复风险来源 |
| Correlation Analysis（相关性分析） | 使用明确窗口和缺失规则的相关性及稳定性 |
| Liquidity Capacity（流动性容量） | 可交易状态、成交、规模、退出时间和容量边界 |
| Scenario Analysis（情景分析） | 市场下跌、相关性上升、流动性枯竭、汇率和观点失效情景 |
| Portfolio What-if（组合试算） | 当前组合与候选目标组合的逐项差异 |
| Cost and Opportunity（成本与机会） | 费用、预估交易成本、现金收益和被替换机会 |

这些服务只计算，不决定买卖。硬限额的正式批准仍属于后续 Trading（交易）风险复核和 Risk Engine（确定性风控引擎）。

## 10. Portfolio MCP（组合模型上下文协议）工具

Portfolio（组合管理）的 MCP（模型上下文协议）工具遵守“概览→对象→比较→精确事实”的顺序。

### 10.1 第一批必需工具

| 工具 | 用途 |
|---|---|
| `portfolio_context_open（打开组合上下文）` | 返回账户健康、组合摘要、触发原因、研究变化和活动意图 |
| `portfolio_view_list/open（列出/打开组合可见观点）` | 读取有效观点、修订、边界和待评估表达 |
| `portfolio_snapshot_open（打开组合快照）` | 打开指定账户快照、现金、持仓和占用摘要 |
| `portfolio_position_list/open（列出/打开持仓）` | 分页读取持仓、成本、盈亏、观点关联和数据状态 |
| `portfolio_candidate_list/open（列出/打开候选）` | 读取候选身份、表达机制、状态和淘汰条件 |
| `portfolio_expression_compare_open（比较组合表达）` | 比较候选身份、持仓纯度、重叠、费用和流动性 |
| `portfolio_what_if_open（打开组合试算）` | 对模型提出的一个或多个目标方案计算调整后组合 |
| `portfolio_exposure_open（打开组合暴露）` | 按行业、主题、因子、币种、地区或观点下钻 |
| `portfolio_scenario_open（打开组合情景）` | 读取当前组合和候选方案的压力结果 |
| `portfolio_activity_open（打开组合活动）` | 读取未完成意图、Trading 反馈和待成交占用 |
| `role_memory_search/open/case_open（搜索/打开角色经验与案例）` | 读取 Portfolio 命名空间中的经验和真实结果 |

### 10.2 不提供给模型的能力

- 任意数据库查询；
- 修改账户、现金、持仓或成本；
- 直接保存正式 Portfolio Intent（组合意图）；
- 修改观点、风险限额或 Trading（交易）决定；
- 下单、撤单或连接券商。

模型返回 Proposal（提案），Runtime（运行时）再交给 Portfolio Result Committer（组合结果提交器）校验。

## 11. 一次运行怎样自主探索

推荐的思考顺序不是强制工作流，而是一组必须回答的问题：

```text
为什么现在要复核？
→ 相关观点是否允许形成方向表达？
→ 当前组合已经承担了哪些相同风险？
→ 有哪些经过核验的表达和替代品？
→ 当前、调整、替换、现金和不行动哪个更合适？
→ 最强反对理由是什么？
→ 目标组合希望变成什么样？
```

Agent（智能体）可以并行读取互不依赖的观点、持仓和候选，可以反复修改候选方案并调用 `portfolio_what_if_open（打开组合试算）`。但已经读取且版本未变化的对象不应重复打开。

## 12. 正式输出

### 12.1 Portfolio Decision Proposal（组合决策提案）

每次运行只提交一份组合决策提案，其中可以包含多个相关的 Target Change（目标变化）。提案至少包括：

- 运行、账户和组合快照版本；
- 使用的观点和修订版本；
- 被比较的候选、现有持仓、现金和不行动方案；
- 选择方案和被淘汰方案；
- 当前组合与目标组合摘要；
- 关键暴露、集中度、相关性、流动性、压力和成本变化；
- 最强反对理由及为什么仍选择当前方案；
- 复核、过期和撤销条件；
- Research Request（研究请求）或 View Challenge（观点质疑）；
- `no_action_reason（不行动原因）`。

### 12.2 Portfolio Intent（组合意图）

只有提案通过服务端校验后，才能发布正式 Portfolio Intent（组合意图）。它描述目标，不描述成交方式：

| 字段组 | 内容 |
|---|---|
| 身份 | `intent_id`、`account_id`、运行、版本和幂等键 |
| 上游 | 观点、修订版本和候选标识符 |
| 目标 | 当前权重、目标权重/暴露区间、最大允许变化和方向 |
| 边界 | 最低现金、最大容量、最晚生效时间和复核条件 |
| 组合影响 | 调整前后组合摘要及 What-if（试算）引用 |
| 状态 | proposed（已提议）、active（有效）、superseded（已替代）、cancelled（已取消）、expired（已过期） |

Portfolio（组合管理）可以输出新建、增加、保持、减少、退出、替换或不行动。它不输出限价单、市价单、子单数量和成交节奏。

## 13. 服务端提交校验

Portfolio Result Committer（组合结果提交器）至少检查：

- 账户、组合快照、观点和候选版本仍然一致；
- 每个新增风险目标关联有效观点和已核验候选；
- Research 决策边界没有明确禁止该方向；
- 当前组合和目标组合均有确定性 What-if（试算）结果；
- 模型引用的现金、持仓、暴露和风险来自本次真实打开记录；
- 目标没有夹带订单参数或超出本次账户授权；
- 活动意图不存在无法解释的重复或冲突；
- 对账异常、账户冻结或关键数据缺失时没有新增风险；
- 幂等键、状态转换和最大字段数量合法。

这些校验只保证身份、状态、权限和安全边界，不用机械规则替模型判断某个机会是否值得持有。

## 14. 调度、并发与独立运行

### 14.1 编排器不是第四个智能体

`FinancialAgentOrchestrator（金融智能体编排器）` 是确定性的后端调度基础设施，不是 Agent（智能体）。它负责创建 Portfolio Run（组合运行）、准备上下文、路由正式产物以及管理幂等、重试和版本冲突，不参与资产表达和仓位判断。

三个角色共同遵守的调度、跨角色通信、运行实例隔离、Scope Key（范围键）、并发提交和反馈收敛机制，以[《交易型多 Agent（智能体）决策架构总纲》](./3.%20交易型多Agent决策架构总纲.md)为准。本章只说明 Portfolio（组合管理）特有的触发器和交付契约。

### 14.2 不是全局串行流水线

Portfolio（组合管理）可以与 Research（研究）和 Trading（交易）同时运行。它只在本次决策依赖某个尚未发布的上游对象时等待该对象，不进行全局串行排队。

### 14.3 Portfolio 的触发来源

| 触发器 | 先由程序判断什么 | 何时调用模型 |
|---|---|---|
| 新观点或重大修订 | 是否允许组合表达、是否影响当前持仓 | 需要选择表达或调整组合 |
| 组合漂移 | 权重、现金、集中度是否越过复核阈值 | 需要在多个目标间取舍 |
| 现金变化 | 到账、冻结、赎回或保证金变化是否实质影响机会 | 需要重新分配或保持现金 |
| 持仓/价格变化 | 是否只是数值更新，还是观点关联和组合结构变化 | 需要重新评估持有或替换 |
| Trading 反馈 | 意图被缩减、拒绝或长期无法执行 | 需要修改目标或选择替代表达 |
| 固定复核点 | 是否存在到期观点、意图或长期未复核持仓 | 有实质决策问题时 |

`FinancialAgentOrchestrator（金融智能体编排器）` 合并重复事件并创建 Portfolio Run（组合运行）。`FinancialAgentRuntime（金融智能体运行时）` 复用与 Research（研究）相同的模型、MCP、Langfuse 和 Proposal 提交架构，但使用独立角色提示词、上下文、工具白名单和记忆空间。

### 14.4 运行实例而不是常驻会话

每次 Portfolio Run（组合运行）拥有独立 Session（会话）、Context Pack（上下文包）、Langfuse Trace（链路记录）和 Proposal Draft（提案草稿）。同一 Portfolio Agent（组合管理智能体）可以同时处理不同账户或不同组合问题，但同一账户组合的正式提交必须检查 Portfolio Snapshot（组合快照）版本。

### 14.5 运行模式

- `replay（历史重放）`：只能看到当时存在的观点、账户、市场和经验；
- `shadow（影子）`：形成影子候选和意图，跟踪结果，但不能进入 Trading（交易）；
- `production（生产）`：通过校验的正式意图可以触发 Trading Risk Review（交易风险复核）；
- `debug（调试）`：保留完整审计，不发布正式状态。

第一阶段必须只开放 shadow（影子）和 replay（历史重放）。

## 15. Research 与 Portfolio 的双向联动

Research（研究）和 Portfolio（组合管理）不通过即时聊天互相交流，也不读取对方的完整模型上下文。它们通过服务端校验、版本化并持久化的业务对象与事件协作。

### 15.1 正向联动：研究观点进入组合评估

```text
Research Run（研究运行）
→ Investment View Revision（投资观点修订）通过提交校验
→ Orchestrator（编排器）发布 View Published（观点已发布）事件
→ 判断是否对组合具有实质相关性
→ 创建 Portfolio Run（组合运行）
→ Portfolio Agent 形成 Portfolio Decision Proposal（组合决策提案）
→ 校验后发布 Portfolio Intent（组合意图）
```

不是每次 Research（研究）运行都触发 Portfolio（组合管理）。编排器只做确定性的事件筛选，例如：

- 只有文字润色，方向、对象、有效性、失效条件和决策边界均未变化：不触发；
- 新建有效观点，或观点的方向、有效性、对象、边界发生实质变化：触发；
- 观点涉及现有持仓、活动组合意图或已登记候选：触发；
- 研究正式结论为 `no_change（无变化）` 且没有新的组合约束：不触发；
- 相同 `revision_id（修订版本标识符）` 已处理：依靠幂等键避免重复触发。

这里的筛选只判断“是否有组合问题需要模型处理”，不判断“应该买什么或持有多少”。

### 15.2 Portfolio 实际接收的内容

Portfolio Agent（组合管理智能体）接收的是 Portfolio Context Pack（组合上下文包），不是 Research Agent（研究智能体）的聊天记录。上下文包至少绑定：

- 本次 Trigger（触发器）及其上游事件；
- 已发布的 `view_id（观点标识符）` 和 `revision_id（修订版本标识符）`；
- 核心论点、直接反证、数据限制、历史校准、失效条件和决策边界；
- 已核验与仅供导航的表达候选；
- 权威 Account Snapshot（账户快照）和 Portfolio Snapshot（组合快照）版本；
- 现金、持仓、活动意图、待成交占用和组合约束摘要；
- 与本次任务有关的 Portfolio Memory（组合经验记忆）。

Portfolio（组合管理）必须忠实使用上游观点，但保留独立判断权：观点成立不代表必须持有；表达不合适、已有暴露过大、现金机会成本更低或组合风险不合适时，可以正式输出 `no_action（不行动）`。

### 15.3 反向联动：组合质疑如何回到研究

Portfolio（组合管理）不能新建或修改 Investment View（投资观点）。如果组合复核发现研究缺口，它可以在 Proposal（提案）中提交两类结构化对象：

- Research Request（研究请求）：现有观点未回答组合决策所需的问题；
- View Challenge（观点质疑）：新事实可能削弱、限制或推翻现有观点。

View Challenge（观点质疑）至少包含：

| 字段 | 作用 |
|---|---|
| `view_id（观点标识符）`、`challenged_revision（被质疑版本）` | 明确质疑哪一版观点 |
| `claim（质疑主张）` | 说明具体质疑，不允许只写“需要进一步研究” |
| `reason（质疑理由）` | 解释为什么影响组合决策 |
| `evidence_refs（证据引用）` | 引用 Portfolio 本次实际打开的账户、组合、市场或表达事实 |
| `requested_checks（请求核查项）` | 列出 Research 需要验证的关键问题 |
| `urgency（紧急程度）` | 区分普通复核与可能影响当前正式结论的紧急反证 |

Portfolio Result Committer（组合结果提交器）先校验证据、对象版本和字段完整性，再保存质疑并发布事件。编排器随后创建新的 Research Run（研究运行），而不是把消息强行插入已经运行中的模型上下文。

### 15.4 运行中反馈、并发与收敛

Portfolio（组合管理）发布质疑以后，即使 Research（研究）正在运行，也由编排器创建隔离的新 Research Run（研究运行）；不把质疑插入已有模型上下文。同一对象的并行分析、旧版本提交拒绝、重复质疑合并、长期记忆并发和角色间反馈收敛，统一遵守总纲第 5 章的全局机制。

## 16. Portfolio Memory（组合经验记忆）

Portfolio（组合管理）使用独立命名空间，不能直接把 Research Memory（研究经验）当作组合经验。

经验主要来自：

- 原组合决定与真实持有结果；
- 被选择表达与未选择替代品的相对表现；
- 调整前后组合风险、回撤和现金利用；
- Trading（交易）缩减、拒绝和实际成交成本；
- 未交易机会、保持现金和 `no_action（不行动）` 的反事实结果；
- 相关性、重叠和流动性在实际压力中的变化。

每条经验必须包含适用账户/资产/市场状态、原决策、实际结果、反例和失效条件。单次赚钱、亏钱或一次未成交不能直接晋升为长期经验。

## 17. Portfolio Quality Evaluator（组合质量评测器）

评测必须区分“当时决策质量”和“后来市场结果”，不能因为某次意外盈利就认为组合判断正确。

固定评分维度建议为：

1. Upstream Fidelity（上游观点忠实度）：是否尊重 Research 的状态、边界和版本；
2. Expression Quality（表达质量）：候选身份、纯度、费用、流动性和替代比较是否充分；
3. Portfolio Awareness（全组合意识）：是否考虑现有暴露、相关性、集中度和现金；
4. Sizing Rationale（目标范围依据）：是否解释目标范围而非用置信度机械换算；
5. Opportunity Cost（机会成本）：是否比较替换、现金和不行动；
6. Counterargument Quality（反对理由质量）：是否提出能真正推翻组合选择的理由；
7. Data and Version Discipline（数据与版本纪律）：账户、观点、快照和计算是否对齐；
8. Decision Usefulness（决策可用性）：是否给 Trading 清楚、有限且可复核的目标；
9. Restraint（克制性）：信息不足时是否拒绝伪造持仓、风险或动作。

结果评估再单独记录：相对基准表现、最大回撤、风险预算使用、未交易替代品表现、换手成本和 Trading 实际执行结果。

## 18. 第一阶段建设方案

Portfolio Agent（组合管理智能体）按以下顺序建设：

### 阶段一：权威只读地基

1. 设计跨资产 Account Snapshot（账户快照）、Position（持仓）和 Portfolio Snapshot（组合快照）Schema（结构契约）；
2. 接入同花顺基金账户作为第一种 Account Connector（账户连接器），但保留通用账户模型；
3. 建立数据来源优先级、版本、对账、冻结和不可用状态；
4. 实现账户与组合只读 Repository（数据仓储访问层）和 MCP 概览/下钻；
5. 旧 `ft_positions（旧基金持仓表）` 只用于迁移或核对，不作为新 Agent 的权威写入目标。

### 阶段二：候选与确定性试算

1. 读取 Research 正式观点和表达候选；
2. 建立通用 Opportunity Candidate（机会候选）及版本状态；
3. 复用实时标的和 ETF 表达比较能力；
4. 实现估值、暴露、重叠、相关性、流动性、情景和 What-if（试算）服务；
5. 建立现金和不行动基准。

### 阶段三：Portfolio Agent 影子运行

1. 建立 Portfolio Agent（组合管理智能体）角色、Prompt（提示词）和结构化 Proposal；
2. 建立 Run Prepare（运行准备）、工具投影、Result Committer（结果提交器）和 Langfuse；
3. 支持新观点、组合漂移、现金变化和固定复核触发；
4. 只发布 Shadow Portfolio Intent（影子组合意图），不进入 Trading；
5. 建立固定历史重放案例和九维质量评测。

### 阶段四：结果与下游联调

1. 跟踪影子组合、未选择替代品、现金和不行动结果；
2. 形成 Portfolio Memory Candidate（组合经验候选）；
3. 定义 Portfolio Intent（组合意图）交给 Trading Risk Review（交易风险复核）的正式契约；
4. 根据 Trading 缩减/拒绝反馈补充组合边界；
5. 影子评测稳定后，才讨论有限生产意图。

## 19. 第一阶段验收标准

- Portfolio Agent（组合管理智能体）只通过远程 MCP（模型上下文协议）读取观点、账户、组合和市场能力；
- 不使用旧基金专用表冒充跨资产权威组合；
- 账户不存在、为空、不可用、冻结和对账异常能够明确区分；
- 每次决策绑定账户、组合快照、观点和候选版本；
- 能比较现有持仓、新候选、替代品、现金和不行动；
- 新增风险必须关联有效观点与已核验表达；
- 能使用确定性 What-if（试算）反复比较方案，但程序不替模型选择方案；
- 目标仓位不是由模型置信度直接换算；
- Portfolio Intent（组合意图）不包含订单参数；
- 可以稳定输出 `no_action（不行动）`、Research Request（研究请求）和 View Challenge（观点质疑）；
- Research、Portfolio 和 Trading 可以跨角色并行运行，不被固定流水线串行化；
- 同一角色的不同 Scope Key（范围键）可以并行，不同运行的 Session（会话）、Trace（链路记录）和上下文相互隔离；
- Portfolio 的质疑通过结构化持久化对象触发新的 Research Run，不向运行中的无关任务动态插入消息；
- 同一对象并发提交具备版本检查，旧版本提案不能覆盖最新观点或组合状态；
- Research 与 Portfolio 的重复事件能够合并并幂等处理，不形成无限往返；
- shadow（影子）与 replay（历史重放）复用同一 Runtime（运行时）和校验路径；
- 质量评测与真实结果评测分开，未交易机会和现金也有反事实记录；
- 没有完成 Trading（交易）和确定性风控前，不把影子组合意图描述成可自动交易系统。
