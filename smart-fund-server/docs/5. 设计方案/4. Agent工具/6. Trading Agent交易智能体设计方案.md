# Trading Agent（交易智能体）设计方案

> 一句话定位：Trading Agent（交易智能体）的核心任务是先复核组合调整风险，再把获准调整安全地变成成交。风险复核和执行管理是两次独立运行。

## 1. 先看一次交易怎样完成

Portfolio Agent（组合管理智能体）提出：

> 将黄金 ETF（交易型开放式指数基金）的组合权重从 0% 提高到 2%，最多买入 10 万元，今天收盘前有效。

Trading Agent（交易智能体）不能马上下单。它先做风险复核：

```text
查看组合调整前后的风险
→ 检查账户、现金、限额、集中度和流动性
→ 判断最多允许买多少
→ 提交 Risk Assessment（风险评估）
→ Risk Engine（确定性风控引擎）生成正式 Risk Decision（风险决策）
```

假设风控只批准 6 万元，系统会创建一次新的执行任务：

```text
读取获准的 6 万元边界
→ 查看当前盘口、成交量和历史滑点
→ 形成 Execution Plan（执行计划）
→ 分批提出 Order Intent（订单意图）
→ Order Gateway（订单网关）逐笔检查并发送券商
→ 根据成交、拒单和行情变化继续、调整、暂停或终止
```

整个过程中，Trading Agent（交易智能体）不能把 6 万元重新扩大到 10 万元，也不能绕过订单网关直接调用券商。

## 2. 两个独立任务阶段

Trading Agent（交易智能体）包含两个任务阶段：

| 阶段 | 它能做什么 | 它看不到什么 |
|---|---|---|
| Risk Review（风险复核） | 读取意图、组合风险和限额，提交风险评估 | 执行计划和订单提议工具 |
| Execution Management（执行管理） | 读取有效风险决定，管理执行计划和有界订单意图 | 限额修改、组合目标扩大和观点修改能力 |

两个阶段分别运行。风险复核结束后，确定性风控生成正式决定；系统随后根据正式决定准备新的执行任务和权限。

## 3. 它负责什么，不负责什么

Trading Agent（交易智能体）负责：

- 解释组合调整带来的风险变化；
- 判断应该批准、缩减、拒绝还是暂时阻塞；
- 在获准范围内制定成交计划；
- 管理活动计划、剩余数量和订单状态；
- 在行情、流动性或账户变化时调整、暂停或终止执行。

它不负责：

- 创建或修改 Investment View（投资观点）；
- 改变 Portfolio Agent（组合管理智能体）的投资理由；
- 扩大组合希望承担的风险；
- 修改或放宽确定性限额；
- 直接产生正式 Risk Decision（风险决策）；
- 直接连接券商或改写订单、成交和对账事实。

## 4. 第一阶段：风险复核

### 4.1 它先读取什么

| 内容 | 回答的问题 |
|---|---|
| Portfolio Intent（组合意图） | Portfolio（组合管理）想调整什么，最多调整多少？ |
| 调整前后的组合风险 | 行业、主题、因子、币种、相关性、集中度和杠杆怎样变化？ |
| 账户健康 | 现金、持仓、冻结、保证金、待成交占用和对账是否正常？ |
| 版本化限额 | 哪些限制绝对不能突破？ |
| 压力情景 | 市场急跌、流动性枯竭或相关性上升时可能亏多少？ |
| 市场和流动性 | 当前是否能以合理成本进入和退出？ |
| 风险事件和经验 | 过去类似情况出现过什么问题？ |

风险数值和硬规则由确定性程序计算。Trading Agent（交易智能体）不自己编造风险数字，它负责解释风险之间的联动以及硬规则没有覆盖的软判断。

### 4.2 它输出什么

Risk Assessment（风险评估）至少说明：

- 使用的是哪个组合意图、账户快照和决策截止时间；
- 调整前后风险怎样变化；
- 哪些硬规则命中；
- 集中度、相关性、杠杆、回撤和流动性是否可接受；
- 建议批准、缩减、拒绝还是阻塞；
- 如果缩减，最多允许到什么范围；
- 执行阶段还要遵守哪些更严格条件；
- 是否需要 Portfolio（组合管理）重新评估或 Research（研究）补充材料。

Trading Agent（交易智能体）可以比硬限额更保守，但不能比硬限额更宽松。

### 4.3 谁做最终决定

Risk Engine（确定性风控引擎）检查风险评估、硬限制、账户版本和组合意图状态，生成正式 Risk Decision（风险决策）。

风险决定只有四种基本结果：

- 批准；
- 缩减后批准；
- 拒绝；
- 因数据、账户或系统问题阻塞。

模型不能覆盖正式风险决定。

## 5. 第二阶段：执行管理

### 5.1 什么情况下可以开始

必须同时满足：

- 存在未过期、未撤销的 Risk Decision（风险决策）；
- 组合意图、风险决定和账户版本仍然一致；
- 账户未冻结，对账和券商连接正常；
- 当前市场数据达到执行所需的新鲜度。

否则系统不会给模型提供执行计划和订单意图工具。

### 5.2 执行时读取什么

- 获准的数量、价格、时间和风险边界；
- 当前交易时段、停牌、涨跌停、盘口、成交量和波动；
- 最新持仓、现金、冻结和待成交占用；
- 当前计划的订单、成交、拒单、撤单和剩余数量；
- 费用、点差、预计冲击成本和历史滑点；
- 同标的、同订单类型和同流动性环境下的执行经验。

### 5.3 Execution Plan（执行计划）包含什么

执行计划至少规定：

- 总共允许成交多少、已经成交多少、还剩多少；
- 每笔最多多少，累计绝不能超过什么边界；
- 允许交易的时段、最晚结束时间和检查频率；
- 价格、最大滑点、点差和波动边界；
- 最大参与率、最低盘口深度和流动性要求；
- 子单大小、节奏以及偏被动还是偏主动；
- 部分成交、拒单、超时、停牌和行情过期时怎么办；
- 什么情况下算完成、部分完成、取消、终止或过期。

市场发生重大变化时，旧执行计划只能暂停、终止或重新申请风险复核，不能扩大解释范围继续交易。

## 6. Order Intent（订单意图）不是券商订单

Order Intent（订单意图）只是 Trading Agent（交易智能体）提出的下一笔订单建议。它必须绑定：

- 当前执行计划；
- 有效风险决定和组合意图；
- 账户、标的、方向、数量、价格和有效期；
- 已提交、已成交和剩余数量；
- 当前市场和账户快照；
- 防止重复下单的幂等键。

Order Gateway（订单网关）还要再次检查账户、现金/持仓、限额、数量、价格、交易时段、累计数量、冻结、过期和券商连接。
网关拒绝以后，Trading Agent（交易智能体）不能强行发送。

## 7. 活动计划怎样持续运行

计划执行期间，确定性 Order Monitor（订单监控器）持续处理行情、订单和成交。没有实质变化时，它只更新状态，不调用模型。

出现以下情况才唤醒 Trading Agent（交易智能体）：

- 价格、点差、波动、成交量或盘口越过计划边界；
- 部分成交明显过慢或超出预期；
- 订单拒绝、超时、撤单失败或状态冲突；
- 现金、持仓、冻结或对账状态变化；
- 风险决定被撤销、过期或风险明显恶化；
- 新组合意图与当前计划冲突；
- 到达复核点、收盘或计划结束时间。

模型只能建议：继续、在边界内调整、暂停、终止，或者请求重新进行风险复核。

## 8. “每分钟运行”到底是什么意思

推荐方式是：

```text
每分钟或更短运行确定性监控
→ 没有重要变化：不调用模型
→ 需要判断或调整：创建 Trading Run（交易运行）
→ Runtime（运行时）执行 Trading Agent（交易智能体）
→ 服务端校验新的计划或订单意图
```

因此，高频的是状态检查，不一定是大模型调用。没有活动执行计划时，不创建执行管理任务。

## 9. 交易经验怎样积累

Trading Memory（交易经验记忆）共用一个角色空间，但分成四类：

| 类别 | 记录什么 |
|---|---|
| 风险 | 限额接近、压力情景、相关性失效、尾部暴露和险情未遂 |
| 流动性 | 不同时段和市场状态下的盘口退化、容量和退出难度 |
| 执行 | 不同标的、时段和订单类型的滑点、成交率和冲击成本 |
| 异常 | 订单、账户、券商和计划之间的状态冲突及恢复条件 |

经验候选必须关联原风险评估或执行计划、正式风险决定、实际订单/成交结果、反例和适用条件。

风险判断和执行表现分开评价：成交赚钱不代表风险复核正确，价格后来反向也不代表当时合规的执行错误。

## 10. 与运营服务的边界

Operations Service（运营服务）和 Reconciliation Engine（对账引擎）负责核对账户、订单、成交、现金和持仓。

Trading Agent（交易智能体）只能读取异常和冻结状态，不能：

- 判断券商事实“应该是什么”；
- 冲正订单、成交、现金或持仓；
- 忽略对账差异；
- 解除账户冻结；
- 自行执行恢复流程。

运营异常影响交易时，Trading Agent（交易智能体）只能暂停或终止，等待确定性服务恢复。

## 11. 失败时怎样处理

| 问题 | 处理方式 |
|---|---|
| 没有有效风险决定 | 不创建执行上下文，不提供订单工具 |
| 意图、风险决定、计划或账户版本不一致 | 当前提案失效，重新准备任务 |
| 行情、盘口或账户数据过期 | 暂停新增订单意图 |
| 对账异常、账户冻结或券商断连 | 阻止新增风险，暂停或终止计划 |
| 硬规则拒绝 | 接受拒绝，不能覆盖；必要时返回 Portfolio（组合管理）重做 |
| 部分成交或拒单 | 按剩余数量重新判断，不能简单重复原订单 |
| 模型超时或输出不合法 | 不发布半成品，确定性监控继续保护账户 |
| 计划过期或收盘 | 停止创建新订单，按状态机处理剩余活动 |

## 12. 建设顺序

1. 提供组合意图、账户、组合风险、限额和压力情景的只读上下文；
2. 建立风险评估、确定性风控和正式风险决定；
3. 建立执行计划状态机和阶段间权限重签发；
4. 建立订单意图、订单网关、幂等和模拟券商；
5. 建立活动计划监控、部分成交、拒单、撤单、滑点和经验闭环；
6. 与运营对账完成端到端模拟；
7. 达到风险和执行评测门槛后，再逐步开放真实交易。

## 13. 验收标准

- 风险复核和执行管理是两次运行、两份上下文和两组权限；
- 风险阶段只能提交风险评估，正式风险决定由确定性风控生成；
- 没有有效风险决定时，模型看不到执行和订单工具；
- Trading（交易）只能缩减、拒绝或在获准范围内执行，不能扩大组合目标；
- 每个订单意图都绑定组合意图、风险决定、执行计划、账户/市场快照和幂等键；
- 活动计划可以高频检查，但没有实质变化时不强制调用模型；
- 部分成交、拒单、撤单、超时、收盘、行情过期和账户异常都有明确处理；
- Trading（交易）不直连券商、不改写对账结果、不解除冻结。
