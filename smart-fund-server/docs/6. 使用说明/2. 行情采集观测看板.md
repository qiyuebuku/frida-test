# 行情采集观测看板

## 1. 用途

行情采集观测看板用于检查系统实际写入数据库的市场数据，不直接请求行情
Provider。它可以暴露数据缺失、延时、采集失败、任务长期未运行和 Watchlist
未更新等问题。

## 2. 访问地址

启动 API 服务后访问：

```text
http://<server-host>:<server-port>/market-dashboard
```

本地默认地址：

```text
http://127.0.0.1:8900/market-dashboard
```

## 3. 页面视图

| 视图 | 内容 |
|---|---|
| 市场总览 | A 股市场广度、主要指数、行业涨跌、行业资金、跨市场行情和采集源状态 |
| 行情快照 | 各数据对象的最新持久化快照，可按数据类型和关键词筛选并查看完整 payload |
| 采集任务 | 每个任务和数据源最近一次运行状态、保存数量、耗时与异常 |
| 跟踪标的 | Watchlist 优先级、采集间隔、最新行情类型、最后成功时间和错误 |

页面默认统计最近 24 小时，并每 30 秒自动刷新。统计窗口可以切换为最近
1 小时、6 小时、3 天或 7 天。

## 4. 只读接口

| 接口 | 用途 |
|---|---|
| `GET /api/market-observability/dashboard` | 获取看板聚合数据 |
| `GET /api/market-observability/snapshots` | 查询各对象最新快照 |
| `GET /api/market-observability/history` | 查询单个对象和数据类型的历史快照 |

## 5. 状态解释

- `实时`：来源时间与抓取时间满足实时口径。
- `延时`：Provider 明确标记延时，或来源时间落后超过允许范围。
- `时间未知`：来源未提供可验证的数据时间。
- `部分成功`：同一任务中部分 Provider 成功、部分失败。
- `失败`：任务未获得可保存的有效数据。

看板显示“暂无数据”时代表对应持久化表确实没有可用记录，不会使用现场请求
补齐页面。
