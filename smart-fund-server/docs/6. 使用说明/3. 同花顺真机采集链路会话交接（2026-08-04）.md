## 2. 已完成架构

### 2.1 持久订阅

一个生产 App 同时维护：

- 七路行情订阅：大盘资金、市场温度、北向资金、富时 A50、道琼斯期指、逆回购、美元/人民币；
- 五路 Unified 事件订阅：大盘异动曲线、大盘异动事件、个股异动、板块异动、大单异动。

服务端通过一条 Socket 消费全部事件，分批幂等入库，并分别维护行情和事件 Redis 健康租约。租约有效时，周期任务不再重复拉取相同数据；租约失效后才启用请求/响应降级路径。

五路 Unified 事件订阅不能同时初始化。生产实验确认 App 全局初始化 Frame 同时只能承载一路请求。当前启动流程为：前一路收到首个 Native 成功响应后，立即初始化下一路；全部成功后再注册七路普通行情订阅。该过程由响应驱动，不使用固定等待时间。

Hook 返回的 `{"type":"subscribed"}` 只表示命令已被接收，不代表 Native 初始化成功。服务端必须继续等待匹配 Unified 事件的 `head.errorCode == 0`，只有此时才能启动下一路订阅。这是防止 `-131 请求超时` 的关键约束。

### 2.2 请求/响应能力

仍通过原子请求获取的主要能力包括：

- 集合竞价；
- 股票九类排行；
- 热门板块和动态分组；
- 板块排行、资金流、成分股和景气度；
- 商品联动中的期货派生表；
- 债市等非持续订阅数据。

App HTTP 和可直接访问的公开 HTTP 已移出 Native 门限。商品联动中的现货、产业列表和关联资产行情均并发走 HTTP，只有期货表占用 Native 通道。

### 4.2 板块成分

旧的 30～60 秒问题由两个因素造成：响应中的非法控制字符导致严格 JSON 解析失败，以及补齐任务把历史交易日的失效板块代码反复作为最高优先级候选。

当前处理：

- 兼容旧 Hook 返回的非法控制字符；
- 只使用最新交易日的活跃候选和当前 App 热门板块；
- `timeout_incomplete_rows` 等确定性结果不进行第二次完整重试；
- 有效板块继续按 100 行自动分页，完整保存全部成分。

## 5. 关键约束

1. Native 并发能力由 App 内 Manager、Frame 和回调槽决定，不由 HTTP 连接数决定。
2. 隔离实验中某些 Hurricane 请求可以并发，不代表它能与 Ranking、Unified 安全交叉并发；当前生产请求/响应采用单 App 单飞安全边界。
3. 吞吐优化优先使用持久订阅、完整表格复用、HTTP 外移、减少重复查询和分片持久化。
4. 原生崩溃不能作为普通网络错误盲目重试。
5. 板块成分是低频静态参考；动态行情字段缺失不得阻止有效成员关系保存。
6. 真机验收通过后才部署生产虚拟机，生产测试不得替代协议研究。
