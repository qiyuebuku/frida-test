### 3.5 加密与命令名位置（重要结论）

- Java 侧 `javax.crypto.Cipher` AES/ECB/ZeroBytePadding 加密发生在 `r9h.o` **之前**（明文长度≈载荷-头部），但明文中**没有** `cmd=` 字样。
- `cmd=cmd_zijin_query&...` 组装在 **libweituo.so 内部**完成（so 字符串证实）。
- 即：明文命令映射需要在 native 侧或解密侧获取，Java hook 拿不到（Cipher hook 已加 cmd 提取，当前未命中）。
- `receiveLog` 的 GBK 文本会被 App 以 `WtModuleInitProcessor` tag 打日志，但发布版被过滤，logcat 看不到。

### 3.13 token 跨设备共享实验（第十四轮，2026-08-17 设备端闭环 ✅ 跨设备待 AVD）

**目标**：生产 VM 复用手机端刷新的 token，避免 VM 内人工登录。

**逆向结论（token 存储机制）**：
- WtToken **不以明文落盘**：登录响应 → `z7m.w(pzr, WtToken, Time)` → `z7m.c` 构造
  TokenInfo 时把 WtToken 当密码材料，`BindingWTInfo.setBindingPwd` 用本机密钥加密成
  `encryptedPwd`（byte[]，Base64 后存 JSON）→ `filesDir/{userId}_authorization.bat`
- 登录时 `f2s.q → w3s.d → t3s.a` 组装请求，用 `getBindingMediumPwd(q3s.c)` 解密回明文
- **解密 key 实测 = UDID**（`TokenInfo.getBindingMediumPwd` 覆写版，
  `sp_key_hardware_unique` 或 `getSystemUDID`；基类的 `K(n6m.r().s())` 路径不成立）
- `livetime=1440` 分钟：**token 有效期 24 小时**（自 lastBindingTime 起）
- 登录成功后 token **不滚动下发**（复用型）

**两端点（MainHook）**：
- `GET /stock/trade/token/export`：进程内解密 + `n6m.a(明文)==mediumPwdId` 自校验
  （verify=true 才可信），`z7m.w` hook 捕获兜底（source=hook_capture）。⚠ 输出含登录
  凭证，仅限受控局域网，禁止入库/提交/记日志
- `POST /stock/trade/token/import` body=`{"token","time","login":true}`：官方入口
  `z7m.k().o(mgr, {"WtToken","Time"})` 用**本机**密钥重新加密入库（跨设备安全——
  不需要迁移加密材料），随即 doActiveTradeLogin 验证

**真机闭环验证（2026-08-17）**：删 authorization.bat + 重启 → 预热 6 次全
`token unavailable`（空库态 = VM 初始态）→ import 注入 → `result=success,
logged_in_state=true`（518ms）→ 六端点恢复真实数据。

**未决**：跨设备（VM）注入后登录，券商服务器是否校验 token 与设备绑定——只能
AVD 实测。**生产约束（用户指定）：8 实例只允许 1 个登录**，其余 7 个禁止

## 4. 重大教训（必须传承）

### 4.1 clinit 毒化导致 App 崩溃（已实测两次）

`Pine.hook` 内部 `Method.invoke` 会**强制执行目标类 `<clinit>`**。MasterModuleBridge 的 clinit 需要 `r9h.c`（context）非空；启动期触发 → `ExceptionInInitializerError` → ART 将类标记为 erroneous → **App 之后自己使用该类时 NoClassDefFoundError 崩溃**（系统弹"同花顺运行异常"）。

规则：**凡是 clinit 依赖 App 状态的类，绝不能在状态就绪前 Pine.hook**。当前实现：延迟重试（15s/45s/90s 线程 sleep）+ `r9h.d` 就绪门控，成功后不再重试。

### 4.2 F(119) 不是安全触发器

启动期账户恢复流程（`AccountDataManager`/`AccountRequestModel` 加密栈）会在 context 就绪前调用 F(119)。不能用 F(119) afterCall 触发 bridge 挂钩（已实测毒化）。

### 4.3 postAppSpecialize 时机没有主线程 Looper

`new Handler(Looper.getMainLooper())` 直接 NPE 并中断 installAllHooks（代理服务器都起不来）。延迟任务必须用 `Thread.sleep` 模式（代码库 startCookieDbWatcher 同款）。

### 4.4 Windows adb 的二进制破坏

`adb shell "su -c 'cat file'"` 经 Windows adb 会做 \n→\r\n 转换破坏二进制。拉 DEX 必须 `su -c 'cp ... /data/local/tmp/ && chmod'` 后 `adb pull`。

### 4.5 UI 自动化环境障碍

- `com.example.screenshotassistant`（截屏工具箱悬浮窗）导致 `uiautomator dump` 永远 "could not get idle state" 且 dump 到悬浮窗层级。
- 远程图像分析模型对 UI 截图会**编造布局**，不可信。
- **可行方案**：本地 OCR `/home/yuyang/anaconda3/envs/tamar-console/bin/python` + `rapidocr_onnxruntime`（实测精确）。
- 交易首页按钮坐标（1080x2378，OCR 实测）：买入(108,1074) 卖出(324,1073) 撤单(539,1074) 持仓(756,1074) 查询(972,1072)；底部 Tab：首页(108,2308) 行情(288) 自选(468) 交易(648) 资讯(828) 理财(1008)。
