## 0. ✅ 密码登录已打通（8/19 下午，commit 0a7e675）

**根因**：不是密码预处理——是 g6m builder 字段映射错误。真机探针（t3s.b hook，
dump 到 `filesDir/thshook_login_probe.log`）捕获 App 实际构造的登录报文：

- `g6m.b = R(密码)` ← 线上 tag3，券商的密码校验位
- `g6m.c = S("")` ← tag4 恒为空
- 旧代码 `S(密码)/R("0")` 导致券商把 `"0"` 当密码 → "[120047]客户交易密码错误"

**静态分析补充结论**（排除项）：
- `getCommonPwd` 只是"记住密码"取存储值，不加密；`tfm`（PasswordSecurityProcessor）
  只是安全键盘防截屏 UI 控制
- `w0s.a` = `URLEncoder.encode(Base64(pwd))`，仅用于改密码流程且受券商级
  EncodeComplexPassword 开关控制（AVD 上该开关关闭，登录链走明文 tag3）
- 登录线上 tag 布局：tag2=资金账号(N) / tag3=密码(R) / tag4=空(S) / tag6=yyb串(U)

**实验方法（可复用）**：真机部署带 t3s.b 探针的 dex（zygisksu 路线，
`/data/adb/modules/thshook_zygisk/dex/classes3.dex`）→ adb UI 自动化走
"交易→多账号登录→搜索 CCZQ→川财证券"，`input text` 填账号 9133857 + 密码 →
登录成功后从 `thshook_login_probe.log` 读 g6m 全字段 + buf_hex。
真机可从 WSL 用 Windows adb 控制：
`/mnt/d/123pan/Downloads/一加Ace6/adb命令行/adb.exe -s 3B15BJ00GZL00000`

**验证结果（AVD 5556）**：`POST /stock/trade/login` → `pwd_result=success`（1.4s）；
funds 查询回归通过（3138.60）；z7m.w 自动捕获新 token（len=746）。

### 0.1 强制登录接口（8/19 下午，commit fb95bde）

`POST /stock/trade/login` body 可选参数（组合使用均可）：

| body | 行为 | 场景 |
|---|---|---|
| `{}` | token 优先，过期自动密码 fallback；已登录短路 | 常规 |
| `{"force":true}` | 绕过 already_logged_in 短路强制重登（token 优先） | **被真机/90B 踢掉会话后立即恢复** |
| `{"method":"pwd"}` | 跳过 token 直接密码登录，拿全新会话+新 token | 最强重建（怀疑 token 本身有问题） |
| `{"password":"..."}` | 一次性密码（不落盘） | 临时换密码 |

实测（AVD 5556 冷启动）：`method=pwd` success 21s；`force` 恢复 14ms；
登录后 funds 1.8~2s。**查询/交易前置的 ensure 链已自动走密码 fallback**，
服务端发现 token 过期时调 `{"force":true}` 即可立即恢复。

**互踢结论（8/19 下午修正版）**：互踢只发生在**同 token 双端**（第十六轮
1Hz 风暴 + 今天 14:01 实测：AVD 沿用真机导入的同一 token，真机刷新该
token 后 AVD 手上旧 token 失效被踢）。**密码登录让 AVD 持有独立 token
后，双端可同时在线、同时查询**（14:50 实测：AVD funds 1.8s + 真机委托页
刷新均正常）。真机 hook role=false 不主动登录；即使被踢，`{"force":true}`
一键恢复。已知缺口：同 token 被踢时查询超时分级自愈偶发不接管
（14:01 实测两次 15s 超时未自愈），手动 force 登录即可恢复。

## 4. 关键机制与坑（新增三天沉淀）

1. **CBAS 通道（交易 TCP）在新环境不会自启**：需 root 手动拉起且**必须带 extra**：
   ```
   adb -s emulator-5556 shell "su -c 'am start-service -n com.hexin.plat.android/com.hexin.plat.android.CommunicationService --es hexin_connect_hangqing_flag_key hexin_connect_hangqing_flag'"
   ```
   （onStartCommand 只有收到该 extra 才调 mSocketConnectionPool.r0() 初始化连接池）
   隔夜/重启后通道死 → 登录卡 SessionInterceptor(r9m) → 40s timeout。先跑这条再登录
2. **CBAS 地址手动设置**（新环境推送组件不初始化地址）：
   `POST /stock/trade/cbas {"host":"8.134.137.28","port":9528}`（可用地址还有
   139.159.194.69 / 8.134.110.99，均 :9528）
3. **模拟器时钟是 UTC**：日志/dropbox 时间戳 -8 换算北京时间；曾因时区误判
   "token 时间源故障"（实际 token 真过期）
4. **rpv crash 循环根因**（已修）：`rpv.X/Y/C` 裸调 `this.d`（mqv 通信服务），
   冷启动未就绪窗口 NPE 主线程崩（每分钟一次）。防护：d==null 丢弃 + uqv.e 后补注入
5. **TokenInfo.isAvailable 时钟防护**（已加）：App 时间源 ghi.m().p() 异常时用
   系统时钟等价校验（真过期仍由券商拒绝，安全）
6. **LSPosed 手工 scope 在健康环境可用**：`INSERT INTO scope VALUES (mid,0,0)` +
   wal_checkpoint(TRUNCATE)；旧环境的清理行为是 SELinux 损伤症状而非机制
7. **zygisk 模块（thshook_zygisk）按进程名注入（含 hexin 即中）**，不限 user；
   LSPosed 桥（thshook APK + scope）提供 Pine 引擎 —— 双层依赖缺一不可
8. **卸载 thshook APK 会拆桥**（zygisk 装了 dex 但 Pine 调用无引擎 → hook server 不起）
9. 写操作铁律（8/17 验证）：写前强制登录（新鲜会话）；写超时必须查委托状态定论，
   禁止盲目重发（fire-and-forget + today_order 轮询确认模式）
10. HTTP body 必须字节流读（中文 UTF-8 时 char/Content-Length 错位 → 挂死，已修）
