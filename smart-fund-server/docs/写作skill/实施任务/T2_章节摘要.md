# T2：章节摘要生成

> 状态：🚧 已实现（待全量运行）
> Skill 目录：`.claude/skills/kb-chapter-summary/`（`batch_summary.py`、`summary_prompt.md`、`SKILL.md`）
> 输出目录：`{book-dir}/plot/chapters/`（通用，通过 `--book-dir` 参数指定）

---

## 目标

为知识库中全部章节正文生成结构化摘要，输出到 `plot/chapters/`。这是后续所有高级知识提取（剧情层、角色层、世界层等）的基础。

**通用性**：脚本和 prompt 不绑定任何特定小说，通过 `--book-dir` 参数指定知识库目录，小说背景从 `book_detail.md` 动态读取。

---

## 核心难题

| 难题 | 说明 | 解法 |
|------|------|------|
| 章节量大，不可能手动处理 | 数百至上千章，手动调用不可接受 | Python 编排脚本 + `claude -p` CLI 自动化 |
| 断点续跑 | 中途失败/中断后不能重头来 | 进度文件 + 文件存在性双重检查 |
| 质量一致性 | 数十至上百次独立调用，风格需统一 | 固定 Prompt 模板 + Few-shot 示例 |
| 角色追踪连续性 | 后面章节需知道前面出场过的角色 | 累积角色名册逐批传入 |

---

## 方案：Python 编排 + `claude -p` CLI

### 为什么选这个方案

| 方案 | 评估 |
|------|------|
| **A. 纯 Skill** | 需用户手动调用数十至上百次，不可接受 |
| **B. Python + Anthropic API** | 需要 API Key，当前环境无 |
| **C. Skill 内循环** | 单次会话 200K 上下文，处理约 8 章就撞上限，技术不可行 |
| **D. Python + `claude -p`** ✅ | 全自动、用订阅额度、每批独立上下文、天然支持断点续跑 |

### 架构

```
python batch_summary.py --book-dir {知识库目录}
  │
  ├─ 1. 读取 book_detail.md → 提取小说背景和初始角色名册
  ├─ 2. 读取进度文件 .progress.json → 确定下一批待处理章节（默认 5 章/批）
  ├─ 3. 构建 prompt = 模板 + 背景 + 角色名册 + 章节文件列表
  │
  ├─ 4. subprocess 调用:
  │     claude -p "{prompt}" --model sonnet --allowedTools "Read,Write" ...
  │     │
  │     ├─ Claude Code 用 Read 读取原文
  │     ├─ Claude Code 生成结构化摘要
  │     └─ Claude Code 用 Write 写入摘要文件
  │
  ├─ 5. 验证输出文件（格式 + 完整性）
  ├─ 6. 从新摘要中提取新角色 → 追加到角色名册
  ├─ 7. 更新 .progress.json
  └─ 8. 继续下一批，直到全部完成
```

## 数据规模估算

> 以下为通用估算，实际数值取决于具体小说。

| 指标 | 典型值 |
|------|--------|
| 单章大小 | 5-20KB |
| 单章 token（中文 2x 系数） | ~10K-34K |
| 每批章数 | 5（默认，可调） |
| 每批输入 token | ~200K（含 prompt + 角色名册） |
| 每批输出 token | ~2.5K（5 章 × 500 token/章） |
| 单批耗时 | ~20-30 秒（实测） |
| **N 章总耗时** | **约 N/5 × 20s（无人值守）** |

### 单章摘要格式（模板见架构设计 5.1.1）

```markdown
# 第一章 初入

## 关键事件
- 陆江仙熬夜猝死，灵魂附身在一面青灰色铜镜上，飘落到修仙世界小河中
- 铜镜在河底首次吞吐月华，体内产生淡淡气流

## 新登场角色
- 陆江仙：现代程序员，猝死穿越，灵魂附着在青灰色铜镜上

## 已有角色出场
- （无）

## 关系变化
- （无）

## 重要物品
- 青灰色铜镜：陆江仙的载体，满是裂痕，能吞吐月华

## 新增设定
- 铜镜能在月光下吸收月华产生气流
- 存在仙人、神通、妖怪的修仙世界

## 伏笔/悬念
- 梦中提到的《太阴吐纳练气诀》和《月华纪要秘旨》
- 朦胧女声要求交出功法，身份不明

## 一句话摘要
陆江仙猝死穿越附身铜镜，在修仙世界河底首次吞吐月华。
```

字段说明：
- **8 个段落全部必填**，无内容时写 `- （无）`
- **关键事件**：本章发生的核心情节，2-5 条
- **新登场角色**：首次出场的角色（不在已知角色名册中），含身份/特征简述
- **已有角色出场**：已出场过的角色在本章做了什么
- **关系变化**：角色间关系的新进展
- **重要物品**：出场的关键道具/法器/功法
- **新增设定**：新揭示的世界观/修炼体系/势力信息
- **伏笔/悬念**：未解开的线索、未回收的伏笔
- **一句话摘要**：≤ 30 字概括本章核心

## Skill 文件

### `.claude/skills/kb-chapter-summary/summary_prompt.md` — 通用 Prompt 模板

不含任何特定小说的硬编码内容，通过占位符动态填充：

| 占位符 | 来源 |
|--------|------|
| `{book_background}` | 自动从 `book_detail.md` 提取（书名、作者、分类、简介、标签） |
| `{characters_context}` | 累积角色名册（初始为空，逐批从摘要中提取累积） |
| `{chapter_list}` | 本批待处理章节的源文件路径 + 输出路径 |

### `.claude/skills/kb-chapter-summary/batch_summary.py` — 主编排脚本

#### 命令行接口

```bash
python batch_summary.py --book-dir {知识库目录}              # 从断点继续处理全部章节
python batch_summary.py --book-dir {知识库目录} --batch-size 5     # 每批 5 章（默认 10）
python batch_summary.py --book-dir {知识库目录} --range 1-50       # 只处理 ch0001-ch0050
python batch_summary.py --book-dir {知识库目录} --dry-run          # 只显示计划，不执行
python batch_summary.py --book-dir {知识库目录} --validate         # 验证已生成的摘要格式
python batch_summary.py --book-dir {知识库目录} --retry-failed     # 重试失败项
python batch_summary.py --book-dir {知识库目录} --gen-index        # 重新生成 index.md
python batch_summary.py --book-dir {知识库目录} --model haiku      # 使用 haiku 模型（默认 sonnet）
```

`--book-dir` 是唯一必需参数，脚本从中自动定位 `text/`、`book_detail.md`、`plot/chapters/`。

#### 核心模块

**进度管理**：

进度文件放在输出目录内：`{book-dir}/plot/chapters/.progress.json`

```json
{
  "completed": [1, 2, 3],
  "failed": [],
  "characters": {
    "陆江仙": "穿越者，灵魂附着在青灰色铜镜上",
    "李木田": "李家族长，眉尺河旁村落"
  },
  "stats": {
    "total_calls": 15,
    "total_time_seconds": 2700
  }
}
```

- 启动时读取 .progress.json + 扫描 `plot/chapters/` 目录，双重确认
- 以文件存在且通过格式验证为准

**批次划分**：
- 默认每批 5 章，按章节顺序
- 自动跳过已完成章节
- `--range` 可指定范围

**角色名册管理**：

```
初始名册 = 空（逐批从摘要中自动累积）
每批完成后：
  1. 从新摘要的 "## 新登场角色" 段落中正则提取角色名和描述
  2. 追加到名册 → 保存到 .progress.json
  3. 下一批调用时传入更新后的名册
```

**输出验证**：

每批完成后自动检查：
- 文件存在且非空
- 包含全部 8 个 `##` 段落标题
- 一句话摘要存在且 ≤ 30 字

验证失败的章节标记为 failed，可用 `--retry-failed` 单独重试。

抽样人工审查（每 100 章抽 1 章）。

## 质量保障

| 机制 | 说明 |
|------|------|
| 固定 Prompt | 所有批次使用同一 `summary_prompt.md`，保证风格一致 |
| 格式验证 | 自动检查 8 个 `##` 段落是否齐全 |
| 角色名册传递 | 累积角色列表逐批传入，确保"新登场 vs 已有角色"分类准确 |
| 首批人工审查 | 前 10 章先试运行，人工确认质量后再全量执行 |
| 抽样审查 | 每 100 章抽检 1 章 |

## 验收标准

1. `plot/chapters/` 下所有章节的摘要文件全部生成
2. 每个文件包含全部 8 个必要段落（`## 关键事件` ~ `## 一句话摘要`）
3. `index.md` 条目数与章节数一致
4. 断点续跑：中断后重新运行能正确跳过已完成章节
5. 抽样 20 章人工审查，事件提取准确率 > 90%
