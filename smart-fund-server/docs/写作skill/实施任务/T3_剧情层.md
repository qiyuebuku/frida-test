# T3：剧情层提取

> 状态：✅ 已实现（待 T2 全量完成后运行）
> Skill 目录：`.claude/skills/kb-plot-extract/`（`batch_plot.py`、6 个 prompt 模板、`SKILL.md`）
> 输出目录：`{book-dir}/plot/`（通用，通过 `--book-dir` 参数指定）

---

## 目标

从章节摘要中提取全局剧情结构，产出故事弧划分、主线追踪、伏笔汇总、事件时间线等结构化文件。这是后续写作 Skill 理解全书剧情的核心依据。

**通用性**：与 T2 一致，脚本通过 `--book-dir` 指定知识库目录，不绑定特定小说。

---

## 核心难题

| 难题 | 说明 | 解法 |
|------|------|------|
| 数据量超出上下文 | 完整摘要 ~200K token，接近/超出 200K 窗口 | 分段压缩 + 逐层融合的三阶段 pipeline |
| 需要全局视角 | 弧划分、主线追踪需要通览全书 | 每段分析时同时传入全局 index（~55K token）作为"望远镜" |
| 弧边界精度 | 初始划分可能偏差 1-5 章 | 阶段 3 专门回查边界附近章节做精修 |
| 伏笔配对 | 前期埋下的伏笔可能数百章后才回收 | 段级追踪 + 全局交叉验证 |

---

## 数据量分析

### 三个数据粒度

| 粒度 | 单条大小 | 以 901 章为例 | Token 估算 |
|------|----------|---------------|-----------|
| **完整摘要**（8 字段，~38 行） | ~1.6KB | ~1.4MB | ~180-200K |
| **index 行**（编号+标题+一句话摘要） | ~130B | ~120KB | ~50-60K |
| **纯一句话摘要** | ~60B | ~55KB | ~25-30K |

### 上下文预算（200K 窗口）

```
200K 总窗口
 - prompt 指令 + 模板:     ~5K
 - 输出预留:               ~15-30K
 ─────────────────────────
 可用于数据:              ~165-180K
```

完整摘要（~200K）放不进去。index（~55K）信息密度不够做弧划分。

### 分段策略：100 章一段

```
一段完整摘要 (100 章): ~20K token  ← 精细分析用
全部 index (901 章):   ~55K token  ← 全局视角用
prompt + 指令:         ~5K
输出预留:              ~15K
─────────────────────────
总计:                  ~95K << 200K ✓
```

## 三阶段 Pipeline

```
阶段 1: 分段扫描 (Segment Scan)
  每段 100 章的完整摘要 + 全局 index → 段级分析 JSON
  ~10 次 Claude 调用

阶段 2: 全局融合 (Global Merge)
  全部段级 JSON + 全局 index → 6 个产出文件初稿
  1 次 Claude 调用

阶段 3: 精修验证 (Refine)
  回查章节摘要细节 → 弧边界校正 + 弧内容充实 + 伏笔验证
  ~25 次 Claude 调用
```

### 阶段 1：分段扫描

**目标**：将每 100 章的完整摘要压缩为结构化 JSON（~3-5KB），保留全局分析所需的关键信息。

**每段 Claude 调用的输入**：
- 本段 100 章完整摘要（~20K token）—— "放大镜"
- 全局 index（~55K token）—— "望远镜"
- 分析指令（~5K token）

**输出 JSON 结构**（`plot/outline/.segments/segment_XX.json`）：

```json
{
  "segment": 1,
  "range": "ch0001-ch0100",
  "major_events": [
    {"ch": "ch0015", "event": "简述", "significance": "high|medium"}
  ],
  "plot_lines_progress": [
    {"name": "线名", "status": "introduced|active|paused|resolved", "start_ch": "ch0001", "progress": "描述", "end_state": "描述"}
  ],
  "arc_candidates": [
    {"name": "弧名", "start_ch": "ch0001", "end_ch": "ch0045", "conflict": "核心冲突", "turning_points": ["ch0003: 描述"], "resolution": "结局"}
  ],
  "foreshadowing": {
    "planted": [{"ch": "ch0001", "content": "描述", "importance": "high|medium|low"}],
    "resolved": [{"planted_ch": "ch0005", "resolved_ch": "ch0078", "content": "描述"}]
  },
  "timeline_events": [
    {"ch": "ch0001", "time_marker": "时间表述", "event": "简述"}
  ]
}
```

**关键设计**：JSON 输出直接在 stdout 捕获由 Python 解析（不需要 Claude 的 Read/Write 工具），更可靠。

### 阶段 2：全局融合

**目标**：综合所有段级 JSON，一次性生成 6 个产出文件初稿。

**输入**（总计 ~85-95K token，安全）：
- ~10 个 segment JSON（总计 ~30-50KB ≈ ~20-30K token）
- 全局 index（~55K token）
- Python 预计算的辅助信号（高重要性事件汇总、主线状态变化点、弧候选汇总）
- 6 个文件模板 + 生成指令（~8K token）

**生成顺序**（有依赖）：
1. `plot_lines.md` — 先确定主线（3-8 条）
2. `arc_XX.md` — 按主线划分弧（首尾相接覆盖全部章节）
3. `open_loops.md` — 伏笔分类汇总
4. `timeline/index.md` — 全书时间线
5. `outline/index.md` — 弧列表索引
6. `plot/index.md` — 导航页

此阶段需要 Claude 的 Write 工具。

### 阶段 3：精修验证

初稿基于压缩数据，需回查原始摘要做精修：

| 子步骤 | 说明 | 调用次数 |
|--------|------|---------|
| **3a. 弧边界验证** | 读取每个弧边界前后 5 章完整摘要，验证/调整边界 | 1 |
| **3b. 弧内容充实** | 每弧读取弧内全部章节摘要，重写详细弧摘要 | ~15-25 |
| **3c. 伏笔交叉验证** | 检查"未回收"伏笔是否实际已回收 | 1-2 |
| **3d. 最终更新** | 基于精修后的数据更新主线、时间线、导航文件 | 1-2 |

### `batch_plot.py` — 主编排脚本

#### 命令行接口

```bash
# 全流程运行（从断点继续）
python .claude/skills/kb-plot-extract/batch_plot.py --book-dir qidian/novel_kb/玄鉴仙族

# 只运行特定阶段
python batch_plot.py --book-dir ... --phase segment-scan
python batch_plot.py --book-dir ... --phase global-merge
python batch_plot.py --book-dir ... --phase refine

# 控制参数
python batch_plot.py --book-dir ... --segment-size 100   # 每段章数（默认 100）
python batch_plot.py --book-dir ... --model sonnet        # 模型（默认 sonnet）
python batch_plot.py --book-dir ... --dry-run              # 试运行
python batch_plot.py --book-dir ... --validate             # 验证产出
python batch_plot.py --book-dir ... --timeout 600          # 单次超时秒数（默认 600）
```

`--book-dir` 是唯一必需参数。

#### 核心模块

**进度管理**：

进度文件：`{book-dir}/plot/outline/.progress.json`

```json
{
  "phase": "segment_scan",
  "segment_scan": {
    "total_segments": 10,
    "completed": [1, 2, 3],
    "failed": [],
    "segment_size": 100
  },
  "global_merge": {
    "status": "pending",
    "arc_count": null
  },
  "refine": {
    "arc_boundary_validated": false,
    "arc_details_completed": [],
    "arc_details_failed": [],
    "foreshadow_validated": false,
    "final_updated": false
  },
  "stats": {
    "total_calls": 0,
    "total_time_seconds": 0
  }
}
```

- 三阶段各有独立的进度追踪
- 每个子步骤完成后立即保存进度
- 中断后重新运行自动从断点继续

**自动阶段流转**：
- 不指定 `--phase` 时，脚本根据 `.progress.json` 中的 `phase` 字段自动从当前阶段开始
- 分段扫描全部完成后自动进入全局融合
- 全局融合完成后自动进入精修

**Claude 调用方式**：
- 阶段 1：`claude -p` 纯文本输出（JSON），Python 解析后写文件
- 阶段 2/3：`claude -p --allowedTools Write,Read`，Claude 直接写文件

**辅助信号预计算**：
- Python 自动从段级 JSON 中提取高重要性事件、主线状态变化点、弧候选
- 作为阶段 2 的额外输入，帮助 Claude 做弧划分决策

## 验收标准

1. 6 个产出文件全部生成且格式正确
2. 故事弧首尾相接覆盖全部章节，无遗漏无重叠
3. 每个弧包含必要段落（核心冲突、主要角色、剧情梗概、转折点、涉及主线、新世界信息、弧结局）
4. 主线 3-8 条，每条有起点、进展、未完成部分
5. 伏笔按 5 类分类，标注章节号
6. 时间线按小说内时序排列
7. `plot/index.md` 可作为导航入口链接到全部子文件
8. `--validate` 命令无警告
