# T6：读者层分析

> 状态：✅ 已完成

## 目标

从 901 章的段落级评论数据（101 MB）中提炼读者反馈，构建读者层知识库。评论数据是**杀手级资产**——它告诉续写 AI 读者想看什么、讨厌什么、关注什么。

产出 5 个文件，直接服务于续写 Skill：
- `emotions.md`：情绪触发点（续写时复用类似手法）
- `popular_characters.md`：角色人气排行（影响出场频率）
- `complaints.md`：读者不满点（续写时必须避开）
- `expectations.md`：读者期待（续写方向参考）
- `index.md`：读者层总览导航

## 核心难题（5 大挑战）

1. **数据量极大**：901 个评论文件共 101 MB，每章 ~1000-3000 行，直接交给 Claude 不可行
2. **噪音极高**：大量表情包、图片评论、"前排打卡"、"二刷回来" 等无实质内容的评论，需要 Python 预过滤
3. **剧透评论干扰**：二刷/多刷读者的剧透评论对分析结果有偏差（评论的情感不代表当章读者的真实反应）
4. **重复评论**：同一用户同一评论出现多次（数据源去重不完全），需 Python 去重
5. **情感分类模糊**：同一条评论可能既包含赞美又包含吐槽，需要 Claude 进行语义理解

## 前置条件

- T1（数据提取）已完成：`{book-dir}/reader/comments/chNNNN.md`（901 个文件）

## 核心设计：Python 重预处理 + Claude 精分析

### 与 T3~T5 的关键差异

T6 和 T3~T5 最大的不同是**数据量与信息密度的比值极端不利**：

| 维度 | T3~T5 | T6 |
|------|-------|-----|
| 数据源 | 结构化摘要（~5KB/章） | 原始评论（~112KB/章） |
| 信息密度 | 高（每句都有用） | 低（大量噪音） |
| 预处理策略 | 轻量正则 | **重量级过滤+统计** |
| 交给 Claude 的数据 | ~80% 原始数据 | **<10% 精选数据** |

因此 T6 的核心思路是：**Python 做 90% 的脏活（去重、去噪、统计、聚合），Claude 只做 10% 的精活（语义分类、主题提炼、洞察生成）**。

### 三阶段 Pipeline

```
阶段 0: Python 预处理 (0 次调用, ~5-15 min)
  解析 901 个评论文件 → 去重 → 去噪 → 统计聚合
  输出: reader/.build/processed_data.json (~5-10 MB)

阶段 1: 分段分析 (~5-10 次调用, 100 章/段)
  每 100 章的精选评论数据 → Claude 情感分类/主题提炼
  输出: reader/.build/segment_XX.json

阶段 2: 全局融合 (1-2 次调用)
  合并全部段级 JSON → 生成 5 个 MD 文件
  输出: reader/feedback/emotions.md, popular_characters.md, complaints.md, expectations.md, index.md
```

> 注：相比 T5 的四阶段，T6 去掉了"精修验证"阶段。原因：读者反馈不像世界设定需要回查原文验证一致性，Claude 在阶段 2 直接生成最终产出即可。

#### 步骤 0a：解析与去重

解析每个评论文件，提取结构化数据并去重：

```python
def parse_comment_file(filepath: Path) -> dict:
    """解析单章评论文件"""
    content = filepath.read_text("utf-8")

    # 1. 提取章节信息
    title_match = re.match(r"# (.+?) · 评论", content)

    # 2. 提取章评
    chapter_comments = parse_chapter_comments(content)

    # 3. 提取段评（含原文引用）
    segment_comments = parse_segment_comments(content)

    # 4. 去重（同一用户+同一内容+同一点赞数 → 只保留一条）
    chapter_comments = deduplicate(chapter_comments)
    for seg in segment_comments:
        seg["comments"] = deduplicate(seg["comments"])

    return {"title": ..., "chapter_comments": ..., "segment_comments": ...}
```

去重规则：`(user, content_hash, likes)` 三元组相同 → 去掉重复。

#### 步骤 0b：噪音过滤

过滤无分析价值的评论：

```python
NOISE_PATTERNS = [
    r"^$",                          # 空评论（只有图片）
    r"^\[fn=\d+\]$",               # 纯表情
    r"^.{0,5}$",                    # 过短（≤5 字符）
    r"^(前排|打卡|签到|mark|催更)",  # 打卡类
    r"^\S+$",                       # 单个表情/符号
]

def is_noise(comment_content: str) -> bool:
    """判断是否为噪音评论"""
    clean = comment_content.strip()
    # 去掉图片标记后判断
    clean = re.sub(r"🖼️ \[图片\]\(.+?\)", "", clean).strip()
    for pattern in NOISE_PATTERNS:
        if re.match(pattern, clean):
            return True
    return False
```

## 关键设计决策

### 1. Python 预处理的去重策略

评论数据存在同一条评论出现多次的情况（数据源问题）。去重规则：

```python
def deduplicate(comments: list) -> list:
    seen = set()
    result = []
    for c in comments:
        key = (c["user"], hash(c["content"]), c["likes"])
        if key not in seen:
            seen.add(key)
            result.append(c)
    return result
```

### 2. 噪音过滤的保守策略

只过滤**确定无分析价值**的评论，不过滤模糊的评论：
- 过滤：空内容（仅图片）、纯表情、≤3 字符的无意义内容
- **不过滤**：短但有意义的评论（如"李中平"——这是读者给角色起的外号）
- **不过滤**：包含图片但也有文字的评论

### 3. 每段精选策略

不发送全量评论给 Claude（太多），而是精选：
- 每章 TOP 5 高赞评论（~500 条/100章）
- 每章 TOP 3 热度段落+对应高赞评论（~300 条/100章）
- 章级统计摘要（100 条统计数据）

**每段约 30K-40K token**，Claude 完全能处理。

### 4. 阶段 1 的四维分析框架

每个段落的分析结果按四个维度组织，与最终的 4 个产出文件一一对应：
- 情绪触发点 → emotions.md
- 角色讨论 → popular_characters.md
- 不满与批评 → complaints.md
- 期待与预测 → expectations.md

### 5. index.md 由 Python 生成

与 T4/T5 一致，统计数据和链接由 Python 直接生成，不消耗 Claude 调用。

### 6. 段评 vs 章评的不同处理

- **章评**：通常是对整章/整书的评价，更宏观，适合提取整体态度
- **段评**：精确到原文段落，适合提取具体的情绪触发点和读者对特定情节的反应
- 阶段 1 分析时同时处理两类，但在输出中区分来源

## CLI 接口

```bash
# 全流程运行
python .claude/skills/kb-reader-feedback/batch_reader.py \
    --book-dir qidian/novel_kb/玄鉴仙族

# 仅预处理（零 Claude 调用）
python batch_reader.py --book-dir ... --phase preprocess

# 仅分段分析
python batch_reader.py --book-dir ... --phase segment

# 仅全局融合
python batch_reader.py --book-dir ... --phase merge

# 验证产出
python batch_reader.py --book-dir ... --validate

# 其他选项
--model sonnet|opus|haiku    # 默认 sonnet
--timeout 120                # 秒
--segment-size 100           # 每段章数
--dry-run                    # 只打印不执行
```

## 验收标准

1. `--phase preprocess` 后 `processed_data.json` 正确解析 ≥95% 章节
2. 去重后评论数 < 原始评论数（确认去重生效）
3. 噪音过滤比例在 10-30% 范围内（过高说明过滤太激进，过低说明未生效）
4. 全流程后 5 个 MD 文件格式符合架构设计 5.4 模板
5. `emotions.md` 包含 ≥10 种场景类型 + ≥30 个具体段落
6. `popular_characters.md` 包含 ≥10 个角色的人气分析
7. `complaints.md` 覆盖节奏/设定/感情线/角色行为四个维度
8. `expectations.md` 包含剧情/角色/设定三类期待
9. `index.md` 统计数据准确
