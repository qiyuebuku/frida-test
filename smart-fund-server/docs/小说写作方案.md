## 1. 概述

### 1.1 系统目标

本系统的目标是：让 AI 在续写一部已有小说时，做到**风格高度一致、设定零矛盾、剧情自然衔接**，使续写章节与原文难以区分。

### 1.2 核心理念

**上下文工程，而非暴力喂文。**

一部网文动辄数百万字，直接塞给 AI 既超出上下文窗口，也会导致模型"降智"。本系统的核心思路是：

1. **预处理阶段**：用 AI 通读全书，将百万字原文提炼为六层结构化知识库（剧情/角色/世界/读者/风格/原文）
2. **写作阶段**：AI 不读全书，而是根据当前章节需要，精准加载知识库中的相关信息（约 7-9K 字），在极度干净的上下文中写作
3. **审核阶段**：独立的审核 AI 盲测续写质量，与原文对比打分，不合格则自动修复

这套方法让 AI 像一个读过全书、记住了所有设定的人类作者一样工作，而不是一个记忆力有限的机器。

### 1.3 系统架构总览

```
原始小说数据（JSON/TXT）
        │
        ▼
┌─────────────────────┐
│   novel-kb Skill    │  ← Phase 1：知识库构建
│   T1-T7 七阶段管道   │
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│   六层知识库 (KB)    │  ← 结构化产出
│   剧情/角色/世界/    │
│   读者/风格/原文     │
└─────────┬───────────┘
          │
          ▼
┌─────────────────────┐
│  novel-write Skill  │  ← Phase 2：续写 + Phase 3：质量保障
│  7步写作 + 3级验证   │
└─────────────────────┘
          │
          ▼
    续写章节草稿
```

### 1.4 两个核心 Skill

| Skill | 位置 | 功能 |
|-------|------|------|
| `novel-kb` | `.claude/skills/novel-kb/` | 知识库构建管道（T1-T7） |
| `novel-write` | `.claude/skills/novel-write/` | 续写创作 + 质量验证 |

## 2. 准备工作

### 2.1 环境要求

| 依赖 | 版本 | 用途 |
|------|------|------|
| Python | 3.12+ | 知识库构建脚本、验证脚本 |
| Claude CLI (`claude`) | 最新版 | AI 调用（T2-T7 构建、续写、审核） |
| `jieba` | 最新 | T7 风格分析、L1 定量检测（中文分词） |
| `pypinyin` | 最新（可选） | T4 角色名拼音处理 |

安装 Python 依赖：

```bash
pip install jieba pypinyin
```

### 2.2 原始数据准备

你需要准备的原始小说数据，通常是从起点等平台采集的 JSON 文件，包含：

- **章节正文**：每章的完整文本内容
- **段落评论**：每个段落的读者评论（含点赞数），这是可选但强烈推荐的数据

数据格式示例（采集后的 JSON）：

```json
{
  "chapterId": 123456,
  "chapterName": "第一章 初入仙门",
  "content": "正文内容...",
  "comments": [
    {
      "Content": "评论内容",
      "AgreeAmount": 150,
      "ParagraphId": "段落ID",
      "UserName": "用户名"
    }
  ]
}
```

### 2.3 创建知识库目录

为你的小说创建一个知识库目录。推荐的命名结构：

```bash
mkdir -p qidian/novel_kb/你的书名
```

例如：

```bash
mkdir -p qidian/novel_kb/玄鉴仙族
```

### 2.4 准备书籍元信息

在知识库目录下创建 `book_detail.md`，记录书籍基本信息：

```markdown
# 书名

- 作者：XXX
- 类型：仙侠/玄幻/都市/...
- 标签：修仙、家族、种田、...
- 当前总章数：XXXX
- 简介：...
```

## 3. Phase 1：知识库构建

知识库构建是整个系统的基础。它将数百万字的原始小说转化为六层结构化知识，供后续续写使用。

### 3.1 七阶段管道总览

```
T1（原文处理）→ T2（章节摘要）→ T3（剧情层）  ┐
                                   T4（角色层）  ├─ 可并行
                                   T5（世界层）  │
                                   T6（读者层）  ┘
                                        → T7（风格层）
```

| 阶段 | 脚本 | 功能 | 产出目录 | 前置依赖 |
|------|------|------|----------|----------|
| T1 | `process_chapters.py` | 原始 JSON 清洗为纯文本 + 结构化评论 | `text/`, `reader/comments/` | 原始 JSON 数据 |
| T2 | `batch_summary.py` | 为每章生成 8 段结构化摘要 | `plot/chapters/` | T1 |
| T3 | `batch_plot.py` | 提取故事弧、主线、伏笔 | `plot/outline/`, `plot/open_loops.md` | T2 |
| T4 | `batch_character.py` | 生成角色档案、关系网、索引 | `characters/` | T2 + T3 |
| T5 | `batch_world.py` | 世界观实体提取与扩写 | `world/` | T2 + T3 |
| T6 | `batch_reader.py` | 读者反馈分析（情绪/人气/不满/期待） | `reader/feedback/` | T1 的评论数据 |
| T7 | `batch_style.py` | 风格定量+定性分析（叙事/用词/节奏） | `style/` | T1 |

### 3.2 执行顺序与依赖

```
T1（独立运行，不在 --stage all 中）
 │
 ▼
T2（章节摘要）
 │
 ├──→ T6（读者层，可与 T3 并行）
 │
 ▼
T3（剧情层）
 │
 ├──→ T4（角色层）  ┐
 └──→ T5（世界层）  ├─ 可并行
                    ┘
 ▼
T7（风格层，最后执行）
```

`--stage all` 的实际执行顺序：T2 → T6 → T3 → T4 → T5 → T7

### 3.3 分步操作指南

#### Step 1：T1 原文处理

T1 将原始 JSON 数据转换为纯文本章节和结构化评论。这一步独立于编排器运行。

```bash
# 方式 1：通过 Skill 调用
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t1

# 方式 2：直接运行脚本
python .claude/skills/novel-kb/process_chapters.py --mode kb --input 原始JSON目录 --output qidian/novel_kb/玄鉴仙族
```

**产出**：
- `text/ch0001.md` ~ `text/chNNNN.md`：纯正文，每章一个文件
- `reader/comments/ch0001.md` ~ `reader/comments/chNNNN.md`：结构化评论

**验证**：检查 `text/` 目录下的文件数量是否与原书章节数一致。

#### Step 2：T2 章节摘要

为每一章生成结构化摘要，包含 8 个维度的信息提取。

```bash
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t2
```

**产出**：
- `plot/chapters/ch0001.md` ~ `plot/chapters/chNNNN.md`：每章的结构化摘要
- `plot/chapters/index.md`：章节索引（章节号 + 一句话概括）

#### Step 3：T3 剧情层

提取故事弧、主线脉络、伏笔追踪。

```bash
# 完整运行
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t3

# 分步运行（适合大型小说）
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t3 --phase segment-scan    # 分段扫描
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t3 --phase global-merge    # 全局合并
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t3 --phase refine          # 精修
```

**产出**：
- `plot/outline/index.md`：故事弧总览
- `plot/outline/arc_01.md` ~ `arc_XX.md`：每个故事弧的详细描述
- `plot/outline/plot_lines.md`：全局主线追踪
- `plot/open_loops.md`：伏笔状态追踪（待回收/已回收/推进中）

#### Step 4：T4 角色层

生成角色档案、角色关系网、角色索引。

```bash
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t4
```

**产出**：
- `characters/index.md`：角色索引（姓名 + 身份 + 文件链接）
- `characters/{角色名}.md`：每个角色的详细档案（身份/性格/能力/说话特征/关系/状态变化）
- `characters/relationships.md`：角色关系网

#### Step 5：T5 世界层

提取世界观实体并扩写为独立文件。

```bash
# 完整运行
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t5

# 分步运行
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t5 --phase segment-classify   # 分段分类
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t5 --phase global-merge       # 全局合并
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t5 --phase refine             # 精修
```

**产出**：
- `world/index.md`：世界观总览
- `world/power_system/`：力量体系（修炼境界、功法、法宝等）
- `world/geography/`：地理空间（地点、区域等）
- `world/factions/`：组织势力
- `world/rules/`：世界规则与限制

每个子目录都包含 `index.md`（索引表格）和独立的实体文件。

#### Step 6：T6 读者层

分析读者评论，提取情绪触发点、角色人气、读者不满点和期待。

```bash
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t6
```

**前提**：`reader/comments/` 目录必须存在（T1 产出）。如果没有评论数据，此阶段可跳过。

**产出**：
- `reader/feedback/emotions.md`：情绪触发点分析
- `reader/feedback/popular_characters.md`：角色人气排名与分析
- `reader/feedback/complaints.md`：读者不满点
- `reader/feedback/expectations.md`：读者期待

#### Step 7：T7 风格层

对原文进行定量和定性的风格分析，建立写作基线。

```bash
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t7
```

**产出**：
- `style/narrative.md`：叙事风格分析（情感表达方式、对话特征、动作描写手法）
- `style/vocabulary.md`：用词分析（高频词、禁忌词、称呼系统、时间表达）
- `style/rhythm.md`：节奏分析（章首/章尾类型偏好、段落结构、句长分布）
- `style/.build/stats.json`：定量统计基线（平均句长、对话占比、字数等数值指标）

`stats.json` 是后续验证系统的核心参照，所有 L1 定量指标的阈值都从此文件动态推导。

#### 一键全流程

如果你希望自动按依赖顺序执行 T2-T7 全部阶段：

```bash
# 先独立运行 T1
/novel-kb qidian/novel_kb/玄鉴仙族 --stage t1

# 再运行 T2-T7 全流程
/novel-kb qidian/novel_kb/玄鉴仙族 --stage all
```

#### 生成导航文件

全部阶段完成后，系统会自动生成 `guide.md`——知识库的使用指南，也是续写系统的必要前置文件。

```bash
# 手动生成（如需重新生成）
/novel-kb qidian/novel_kb/玄鉴仙族 --stage guide
```

## 4. Phase 2：续写创作

知识库构建完成后，就可以开始续写了。续写系统采用**三 Subagent 隔离架构**，确保信息流单向、上下文干净。

### 4.1 架构原理

```
┌──────────────────────────────────────────────────────┐
│                    主 Agent（写作者）                  │
│  上下文：Context Bundle(~3K) + 大纲(~1K)             │
│          + Scene Plan(~3-5K) + 续写铁则(~0.5K)       │
│  总计：~7-9K 有效信息                                │
└──────────────────────┬───────────────────────────────┘
                       │
         ┌─────────────┼─────────────┐
         ▼             ▼             ▼
  ┌─────────────┐ ┌──────────┐ ┌──────────┐
  │ Researcher  │ │ Enricher │ │ Reviewer │
  │ (Step 2)    │ │ (Step 3) │ │ (Step 6) │
  │ 读剧情+风格 │ │ 搜角色+  │ │ 盲测评审 │
  │ 生成 Bundle │ │ 世界设定 │ │ 独立打分 │
  │ + 大纲      │ │ 生成     │ │ 不看设计 │
  │             │ │ Scene    │ │ 图       │
  │             │ │ Plan     │ │          │
  └─────────────┘ └──────────┘ └──────────┘
   用完即释放      用完即释放    用完即释放
```

**隔离原则**：
- **Researcher** 只读章节级信息（剧情进度、伏笔、风格规则），不碰角色档案和世界设定
- **Enricher** 按名词清单从 KB 搜索角色和世界设定，补全到 Scene Plan
- **Reviewer** 完全独立评审，不看 Writer 的 Context Bundle、Scene Plan 和大纲（防止锚定偏差）
- 每个 Subagent 在独立 Task 中执行，产出保存到文件后上下文即释放

### 4.2 七步写作流程

#### Step 1：确定章节号

系统读取 `guide.md` 和 `plot/chapters/index.md`，自动确定下一章的章节号。

你也可以手动指定：

```bash
/novel-write qidian/novel_kb/玄鉴仙族 --chapter 902
```

#### Step 2：Research（Researcher Subagent）

Researcher 读取以下知识库文件：

| 文件 | 提取内容 |
|------|----------|
| `plot/chapters/index.md` | 章节进度 |
| `plot/outline/arc_XX.md` | 当前故事弧详情 |
| `plot/outline/plot_lines.md` | 主线状态 |
| `plot/open_loops.md` | 待回收伏笔 |
| `plot/chapters/ch{N-1}.md`, `ch{N-2}.md` | 近章摘要 |
| `text/ch{N-1}.md`（最后 500 字） | 上一章尾部衔接 |
| `style/narrative.md` | 叙事风格 + 情感禁忌 |
| `style/vocabulary.md` | 用词禁忌 |
| `style/rhythm.md` | 节奏指标 |
| `style/.build/stats.json` | 定量基线 |

**产出**：

1. **Context Bundle**（`drafts/context_bundle_ch{NNNN}.md`）：包含 5 个 Section：
   - S1. 故事位置（所属弧、主线进展、上一章尾、本章方向）
   - S2. 场景角色（出场角色简表、伏笔状态）
   - S3. 风格硬指标（从 stats.json 动态提取的目标值和红线）
   - S4. 禁忌速查（绝对禁止项 + 替代公式）
   - S5. 上一章衔接（原文最后一段，确保续写接得上）

2. **章节大纲**（`drafts/outline_ch{NNNN}.md`）：包含场景规划、伏笔计划、情绪曲线、**涉及名词清单**

名词清单是关键：它列出了本章涉及的所有专有名词（角色、地点、功法、势力等），供 Enricher 逐项搜索。

#### Step 3：Enrich（Enricher Subagent）

Enricher 按照名词清单，逐项搜索知识库：

- **角色**：从 `characters/{name}.md` 摘录身份、状态、说话特征、关系
- **地点**：从 `world/geography/` 搜索位置、特征、准入条件
- **功法/法宝**：从 `world/power_system/` 搜索效果、限制、等级
- **势力/组织**：从 `world/factions/` 搜索组织结构、势力范围
- **其他名词**：跨类别搜索

同时从近章原文中选取 3-5 个风格锚点段落。

**产出**：`drafts/scene_plan_ch{NNNN}.md`，包含：
- 角色设定摘要
- 世界设定摘要
- 未在 KB 中找到的名词（标注提醒）
- 风格锚点（含技法分析和格式要点）
- 写作注意事项（对话标签、情绪约束、段落融合指引）

#### Step 4：用户确认

系统展示大纲和 Scene Plan 的完整方案，等待你确认：

- **确认**：进入正文生成
- **调整**：你提供修改意见，系统修改后再次确认

这是唯一的人工介入点（自动模式下跳过）。

#### Step 5：写全章正文

主 Agent 基于极度干净的上下文写全章：

| 输入 | 大小 |
|------|------|
| Context Bundle（S1-S5） | ~3K 字 |
| 章节大纲 | ~1K 字 |
| Scene Plan（角色+世界+风格锚点+注意事项） | ~3-5K 字 |
| 续写铁则 | ~0.5K 字 |
| **总计** | **~7-9K 字** |

**续写铁则**（写作时必须遵守）：

1. **每句包含多重信息**：一句承载 >= 2 种信息（动作+情绪、状态+背景、细节+暗示），禁止一句只传达单一信息
2. **章首/章尾类型匹配**：严格遵守 `style/rhythm.md` 中的偏好（如 action/environment 开头）
3. **段落融合**：对话+标签+动作+环境必须融为同一段落，禁止一行一段的 ChatGPT 式格式

**正文硬指标**（每本书不同，从 Context Bundle S3 获取具体阈值）：

| 指标 | 示例目标 |
|------|----------|
| 总字数 | 基线章均字数 |
| 平均句长 | 30-52 字 |
| 对话占比 | 25%-58% |
| 对话标签偏好 | "道"系标签 >= 45% |
| 禁忌词 | 0 个 |
| 章首/章尾类型 | action/environment |
| 段落长度 | 60-150 字 |
| 短句率 | < 40% |

**产出**：`drafts/ch{NNNN}.md`

#### Step 6：Review（Reviewer Subagent）

Reviewer 完全独立审核，不看 Writer 的设计图。审核分三个层级：

**L1 定量检测**（纯 Python，<5 秒）：12 项定量指标检测

**L2 深度分析**（AI 审核）：
- 盲测对比：从草稿和原文各取段落，打乱后逐段评分（5 个维度），揭示来源后计算相似度
- 风格一致性：逐段评分（情感表达/对话自然度/动作描写/信息密度/节奏感）

**L3 读者对齐**（如有读者数据）：
- 爽点命中度、槽点规避度、角色人气对齐度、读者期待呼应度

**产出**：
- `drafts/ch{NNNN}_verification.md`：审核报告
- `drafts/ch{NNNN}_feedback.md`：修复建议（仅评级 C/D 时生成）

#### Step 7：结果处理

| 评级 | 处理 |
|------|------|
| A/B（80-100） | 完成。可用 `--promote` 反哺到正式知识库 |
| C（70-79） | 展示 feedback 摘要，询问是否修复 |
| D（<70） | 强提示修复 |

### 4.3 操作模式

#### 正常模式（默认）

```bash
/novel-write qidian/novel_kb/玄鉴仙族
```

走完 Step 1-7，Step 4 需要用户确认。

#### 指定章节 + 提示

```bash
/novel-write qidian/novel_kb/玄鉴仙族 --chapter 902 --hint "本章重点写李木田和张氏的矛盾"
```

`--hint` 会被传递给 Researcher，影响大纲规划方向。

#### 自动循环模式

```bash
/novel-write qidian/novel_kb/玄鉴仙族 --auto
```

全自动写作-验证-修复循环：
1. 正常写作（Step 1-7，跳过 Step 4 确认）
2. 评级 >= B 则完成
3. 评级 C/D 则自动修复，再次验证
4. 最多 3 轮修复，或连续 2 轮分数无提升时停止

#### 修复模式

```bash
/novel-write qidian/novel_kb/玄鉴仙族 --revise 902
```

加载已有的 Scene Plan + Context Bundle + 草稿 + Feedback，在既定设计图下修复正文。

核心原则：**不重新规划，只改正文**。Scene Plan 和大纲保持不变。

修复策略：

| 问题类型 | 修复方法 |
|----------|----------|
| 平均句长过短 | 合并对话+标签+动作为长段落 |
| 短句率过高 | 将独立短对话行与动作描写融合 |
| 段落长度偏短 | 嵌入背景信息、环境描写、心理活动 |
| "道"系标签不足 | 替换"说""回答"为"道""答道""笑道" |
| 直白情感词 | 替换为动作/细节/生理反应 |

## 5. Phase 3：质量保障

### 5.1 三级验证体系

```
┌─────────────────────────────────────────────┐
│              L1 定量检测                      │
│  纯 Python，<5 秒，12 项指标                  │
│  自动判定 PASS/WARN/FAIL                     │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│              L2 深度分析                      │
│  Reviewer Subagent，盲测对比 + 5 维评分       │
│  与原文段落对照，计算相似度                    │
└──────────────────┬──────────────────────────┘
                   ▼
┌─────────────────────────────────────────────┐
│              L3 读者对齐                      │
│  Reviewer Subagent，4 维评分                  │
│  爽点命中/槽点规避/角色人气/读者期待           │
└─────────────────────────────────────────────┘
```

### 5.2 L1 定量检测（12 项指标）

| 编号 | 指标 | 目标范围 | 说明 |
|------|------|----------|------|
| M1 | 平均句长 | 30-52 字 | 从 stats.json 动态推导 |
| M2 | 对话比例 | 0.25-0.58 | 从 stats.json 动态推导 |
| M3 | "道"系标签占比 | >= 45% | 中文网文对话标签特征 |
| M4 | 章首类型 | action/environment | 从 rhythm.md 推导 |
| M5 | 章尾类型 | action/environment | 从 rhythm.md 推导 |
| M6 | 直白情感词 | 0 个 | "十分愤怒""心中一喜"等 |
| M7 | 现代时间表达 | 0 个 | "下午3点"等（古代背景） |
| M8 | 短句率 | < 40% | 独立短句占比不宜过高 |
| M9 | 段落长度 | 60-150 字 | 均值需在范围内 |
| M10 | 传统时间 | > 0 个 | "寅时""卯时"等 |
| M11 | 禁忌词 | 0 个 | 书籍特定禁忌词 |
| M12 | 对话标签多样性 | > 15 种 | 标签种类丰富 |

注意：以上目标范围是示例值，实际阈值从每本书的 `style/.build/stats.json` 动态推导。

### 5.3 L2 深度分析

#### 盲测对比

从草稿和原文各选取 2-3 个段落，打乱顺序后逐段评分，避免锚定偏差。

5 个评分维度：

| 维度 | 5 分标准 | 1 分标准 |
|------|----------|----------|
| 段落融合度 | 对话+标签+动作+环境融为一段 | 一行一段 |
| 句长分布自然度 | 长短句交替自然 | 句式单调 |
| 对话标签多样性 | 标签丰富、带动作 | 反复"说道" |
| 情感表达方式 | 用动作/细节，含蓄克制 | 直白情感词 |
| 细节密度 | 一句包含多重信息 | 一句一信息 |

#### 风格一致性

逐段评分后计算均值。评分公式：

```
L2 = 盲测相似度 x 0.4 + 风格均值 x 20 x 0.6
```

### 5.4 L3 读者对齐

仅当 `reader/feedback/` 目录存在时执行。4 个维度各 1-5 分：

- 爽点命中度
- 槽点规避度
- 角色人气对齐度
- 读者期待呼应度

### 5.5 综合评分公式

```
有读者数据：总分 = L1 x 0.35 + L2 x 0.40 + L3 x 0.25
无读者数据：总分 = L1 x 0.45 + L2 x 0.55
```

评级标准：

| 评级 | 分数区间 | 含义 |
|------|----------|------|
| A | 90-100 | 优秀，与原文难以区分 |
| B | 80-89 | 良好，可直接使用 |
| C | 70-79 | 及格，建议修复后使用 |
| D | <70 | 不合格，需要修复 |

### 5.6 独立验证

无需重新写作，可以单独对已有草稿运行验证：

```bash
/novel-write qidian/novel_kb/玄鉴仙族 --verify 902
```

### 5.7 反哺到正式知识库

当草稿评级达到 B 及以上，可以将其纳入正式知识库：

```bash
/novel-write qidian/novel_kb/玄鉴仙族 --promote 902
```

反哺操作会：
1. 将正文复制到 `text/ch{NNNN}.md`
2. 调用 Claude 为新章节生成结构化摘要，保存到 `plot/chapters/ch{NNNN}.md`
3. 更新 `plot/chapters/index.md` 章节索引

注意：反哺仅对新章节号生效，不会覆盖已有原文。

## 6. 最佳实践

### 6.1 知识库构建

**分步执行，逐步验证**

不要一口气跑 `--stage all`。建议按阶段逐步执行，每完成一个阶段就抽查产出质量：

```bash
# 先跑 T2，抽查几个章节摘要是否准确
/novel-kb KB_DIR --stage t2

# 满意后再跑 T3
/novel-kb KB_DIR --stage t3
```

**T4+T5 预处理优化**

系统内置了 `kb_preprocess.py` 统一预处理（T4 和 T5 共享 phase0），可减少约 50% 的重复文件读取。这在 `--stage all` 中会自动触发。

**大型小说使用分步 phase**

超过 1000 章的小说，T3/T4/T5 建议使用 `--phase` 分步执行，便于中断恢复和错误定位。

### 6.2 续写创作

**善用 --hint**

`--hint` 是影响续写方向的最直接方式。你可以指定本章的重点：

```bash
/novel-write KB_DIR --hint "本章重点写主角突破筑基期的过程，要有波折"
```

**先跑正常模式，再考虑自动模式**

第一次续写建议使用正常模式，在 Step 4 仔细审查大纲和 Scene Plan。熟悉系统产出质量后，再尝试 `--auto` 模式。

**修复不要超过 3 轮**

如果自动修复 3 轮仍未达标，说明问题不在细节而在整体方案。此时应该重新审视大纲，或手动介入修改。

### 6.3 风格学习要点

从实践中总结的 6 个关键写作技巧（尤其适用于中文网文）：

1. **克制情感表达**：不写"他很愤怒"，写"他的手指攥紧了剑柄，指节发白"
2. **传统时辰**：古代背景用"寅时""卯时"，不用"凌晨三点"
3. **细节暗示**：用具体细节暗示状态，不直接说明
4. **视觉反差**：创造视觉对比增强画面感
5. **口语化对话**：对话内容要自然，不要书面腔
6. **信息密度**：一句话包含多重信息，动作+情绪+环境交织

### 6.4 常见问题

**Q: 知识库构建需要多长时间？**

A: 取决于小说长度和 Claude API 速度。以 1200 章（约 500 万字）为例：
- T1：几分钟（纯本地处理）
- T2：15-30 分钟
- T3-T5：各 10-20 分钟
- T6-T7：各 5-10 分钟
- 总计：约 1-2 小时

**Q: guide.md 不存在怎么办？**

A: 运行 `/novel-kb KB_DIR --stage guide` 手动生成，或者运行 `--stage all` 时会自动生成。

**Q: 续写的章节如何与原文衔接？**

A: Researcher 会读取上一章最后 500 字作为衔接段，写入 Context Bundle S5。主 Agent 写作时会确保第一段自然接续。

**Q: 评级一直是 C/D 怎么办？**

A: 检查以下几点：
1. `style/.build/stats.json` 是否正确生成
2. 风格锚点是否准确反映原文风格
3. 尝试减少对话比例、增加段落融合度
4. 手动调整 Scene Plan 中的注意事项

**Q: 可以同时续写多章吗？**

A: 每次只续写一章。完成并 `--promote` 后，知识库更新，才能续写下一章。这确保了剧情连贯性。

**Q: 没有读者评论数据能用吗？**

A: 可以。T6 阶段会被跳过，L3 读者对齐不执行，评分公式自动切换为双层（L1+L2）。
