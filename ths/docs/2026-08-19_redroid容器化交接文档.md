## 一、总目标（我们要干的事）

把同花顺 hook 采集栈从生产 AVD/QEMU 迁移到 Docker（redroid）容器化架构：

- 拓扑：**1 个交易实例 + 8 个采集实例**，一容器一实例（用户明确决策：单容器多用户无弹性扩容价值，实测单容器仅 ~1.05GiB 内存，资源不是问题）。
- 每容器内跑同花顺 App（arm64-only，经 libndk_translation 翻译）+ THSHook（LSPosed 模块）在 18900 端口暴露 HTTP 接口，供 smart-fund-server 与 agent 调用。
- 最终验收：`/native/unified`、`/native/realtime` 等真实业务接口返回真实行情数据。

## 二、已完成的事

### 1. Riru 直嵌注入链（核心突破，全部打通）

生产 AVD 用的 Zygisk/LSPosed 路线在 redroid（SELinux=Disabled）下三套 ptrace 方案均不可行，最终用 Riru v26.1.7 直嵌路线打通：

- `ro.dalvik.vm.native.bridge=libriruloader.so` 让 ART 在 zygote 启动时标准加载 Riru loader；loader 连 rirud socket 获取 magisk tmpfs 路径 + 原始 bridge 名，dlopen libriru.so 完成注入，再 dlopen 真 bridge（libndk_translation.so）并 memcpy NativeBridgeCallbacks 转发翻译功能。
- 镜像 `redroid:11.0.0_riru6`：bootanim.rc 含 magisk Delta 集成 + post-fs-data 中 `start ths-rirud`（--setup-sbin 之后）。
- rirud 两大坑已修：
  - `addAssetPath("rirud.apk")`/`module.prop` 是 cwd 相对路径 → start-rirud.sh 里 `cd /data/adb/modules/riru-core` 再 exec app_process。
  - socket 鉴权强制对端 SELinux 上下文 `u:r:zygote:s0` → apktool 2.9.3 反编译，把 `Objects.equals(context, "u:r:zygote:s0")` 检查块替换为 `goto :cond_0`（uid=0 放行）。
- LSPosed riru 模块布局：`system/lib64/liblspd.so`（真 so）+ mirror 的 `riru/lib64/liblspd.so`（带后缀直放，因 /system 只读）；`daemon.apk` 里 `/dev/..............` 是 **14 字符**占位，必须 **14 位 hex 等长替换**（16 位会导致 zip 偏移平移 → ClassNotFoundException）；daemon 必须绝对路径启动（`sh ./daemon` 会让 `${0%/*}`=`.` → UnsatisfiedLinkError）。
- ISA 映射三件套：`ro.dalvik.vm.isa.arm64=x86_64`、`ro.dalvik.vm.isa.arm=x86`、abilist 含 x86_64,arm64-v8a（ARM 翻译必配）。
- **data 卷状态中毒**：经历过 zygote crash 风暴的 data 卷会让 arm64 App 60ms 静默死亡（无栈无 tombstone），必须用干净卷。

## 三、当前卡点（正在处理，接手第一优先级）

**现象**：App 存活、UI 渲染正常（截屏白底+品牌红）、HTTP 服务正常，但 `MasterModule not initialized yet (r9h.d=false)` 持续，`/native/unified` 返回 `unified request dispatch timed out`。

**已确认的关键因果链（重要！）**：

1. **原始进程自然就绪**：容器启动 → am start `.Hexin` → 不干预运行约 25-30 分钟 → unified 就绪（15:2x 启动，15:53 collector2 实证成功）。
2. **force-stop 后的二次启动不会就绪**：被 force-stop 重启的 App（新 pid）unified 全部超时，MasterModule 迟迟不初始化，还伴随 `CookieDbWatcher: no Cookie DB found`。生产 AVD 的 `ensure_market_runtime`（force-stop + 二次启动 + 20s 就绪，见 `ths/deployment/internal/runtime/collector-bridge.sh` 约 211 行）**在容器不适用**。
3. **生产解锁手势在容器是毒药**：无锁屏容器里 `input swipe 540 1900 540 350`（生产用于解锁 keyguard）= HOME 手势，会把 App 划到后台（`mCurrentFocus=null`）。
4. WAKEUP 假设已排除：容器屏幕本来 `mWakefulness=Awake`、`Display Power: ON`。
5. uiautomator dump 返回 0 节点（App 自绘 UI，不能靠 UI 树导航）。

**已执行的动作与时间线**：

- 15:5x 起我误以为生产 force-stop 方案可复刻，批量脚本把 collector1-5 的 App 全 force-stop 重置（**教训：把已自然就绪的 collector2 也搞坏了**）。
- 16:05 `docker restart` 全部 9 容器 + `start-all-ths.sh` 重新拉起（意图：完全重走 deploy 路径恢复自然就绪）。
- 16:1x-16:34 两次探测：重启后 18 分钟，9 容器全部 `dispatch timed out`（自然就绪需 25-30 分钟，**尚未到判定时刻**）。

**接手后的建议动作**：

1. 先 `bash /tmp/probe_readiness.sh`（服务器上）看当前就绪状态。若已过 ~35 分钟仍全不就绪，说明 docker restart 路径与首次 deploy 有差异，转诊断：
2. **日志对比法（最有价值）**：拉取 collector2 成功时段（15:45-15:59，进程 pid 1801）的完整 logcat 与现在的对比，找 `UnifiedRequest`/`Hummer`/`CBAS hangqing` 初始化的触发点差异（注意 `logcat -d` 只剩缓冲区内的，可能需要看 `/data/adb/lspd/log` 或 hook 自己加日志）。
3. 检查成功就绪是否需要 App 有"真前台焦点"持续一段时间（redroid 虚拟显示/`dumpsys window` focus 状态）。
4. `screencap` 定期截图观察 App 页面演化（是否停在广告/引导页 vs 进入了行情 tab）。
5. 对比 RT_WIRE 流量密度（就绪的 App 有持续长连接流量）。
6. 若自然就绪不可复现，考虑给 THSHook 增加"主动触发 MasterModule 初始化"的路径（`MainHook.java` 里 MasterModuleBridge hook 逻辑，本地源码在 `ths/app/src/main/java/com/yuyang/thshook/MainHook.java`，`r9h.d` 是混淆类字段）。
7. **绝对不要再用 force-stop + swipe 的生产方案**，已证伪。

## 七、2026-08-20 收尾结果（替代上文旧卡点）

上文“等待 App 自然运行 25～30 分钟”的判断已被后续主动初始化方案替代，不再是
当前部署方式。最终运行版本为 `ths-redroid:1.2.38`：

1. 9 个容器均冷启动自动达到 `healthy`；行情运行时主动完成两次 unified 握手并
   dispatch realtime total client，实测约 1.8～9.7 秒。
2. collector 端口 49610～49617 并行 `/native/unified` 为 8/8 成功。
3. trade 端口 49600 无 UI 自动登录，资金、持仓、当日委托均查询成功，状态为
   `write_ready=true`。
4. 三市场路由已验证：上交所 11、深交所 24、北交所 27。
5. realtime 指标可能在没有新快照时不触发 callback，因此 ready 门禁检查原生
   transport dispatch；`realtime_verified` 单独保留为运行观测信息。
6. 容器必须携带完整 redroid native bridge 启动参数，尤其是
   `ro.dalvik.vm.native.bridge=libriruloader.so` 与 `androidboot.use_memfd=1`。
   `add-instance.sh` 和 compose 示例已固化，漏参会导致 Riru/LSPosed 无法进入
   zygote，这是确定性配置错误，不允许依靠重启矫正。
