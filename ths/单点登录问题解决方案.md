# 单点登录冲突解决方案

## 🎯 问题背景

**发现的问题**：同花顺基金交易账户有**单点登录限制**

```
程序使用密码登录 → 手机App被踢下线 ❌
```

这意味着：
- 如果程序自动用密码刷新token，手机App会自动退出登录
- 用户在手机上的操作会被中断
- 不能简单地每次都重新登录

---

## ✅ 解决方案

### 核心策略：智能刷新优先级

```
┌──────────────────────────────────────────────────┐
│  需要刷新token                                    │
└────────────────┬─────────────────────────────────┘
                 │
                 ▼
        ┌────────────────┐
        │ 手机已连接？    │
        └────┬───────┬────┘
             │ Yes   │ No
             ▼       ▼
    ┌─────────────┐  ┌──────────────────┐
    │ 从手机获取   │  │ 使用密码登录      │
    │ ✅ 不踢手机  │  │ ⚠️ 踢掉手机      │
    └─────────────┘  └──────────────────┘
```

---

## 📋 实现细节

### 1. 刷新优先级调整

**之前的逻辑**：
```python
# 总是优先使用密码登录（会踢掉手机）
1. 密码MD5登录 → 踢掉手机 ❌
2. adb控制手机（fallback）
```

**优化后的逻辑**：
```python
# 优先从手机获取（不踢手机）
1. 检查手机连接
2. 如果连接：从手机App获取token ✅ 不踢手机
3. 如果失败：才使用密码登录 ⚠️ 踢手机
```

### 2. 核心代码修改

**文件**: `/home/yuyang/frida-test/ths/api/auth_manager.py`

#### 新增方法

1. **`_check_phone_connected()`** - 检查手机连接状态
2. **`_refresh_from_phone()`** - 从手机App自动获取token

#### 修改方法

**`auto_refresh_auth(prefer_phone=True)`**

```python
def auto_refresh_auth(self, prefer_phone=True) -> bool:
    """
    优先级策略（避免单点登录冲突）：
    1. 如果手机连接，从手机App自动获取token（不踢掉手机端）
    2. 如果手机未连接或获取失败，使用密码MD5登录（会踢掉手机端）
    """
    if prefer_phone:
        # 优先从手机获取
        if self._check_phone_connected():
            if self._refresh_from_phone():
                return True  # ✅ 成功，手机不受影响

        # 手机获取失败，才用密码
        print("⚠️ 手机获取失败，使用密码登录（会踢掉手机端）")
        if self.refresh_by_password():
            print("⚠️ 注意：使用密码登录会导致手机App被踢下线")
            return True

    return False
```

## 🚀 自动化配置

### 1. 程序自动刷新（推荐）

```python
from auth_manager import AuthManager

# 初始化（默认优先手机）
manager = AuthManager(enable_auto_refresh=True)

# 每次API调用前自动检测过期并刷新
auth = manager.get_auth()

# 内部逻辑：
# 1. 检查token是否即将过期（提前3天）
# 2. 如需刷新，优先从手机获取
# 3. 手机失败才用密码
```

### 2. 定时任务刷新

```bash
# crontab -e
# 每天凌晨3点检查并刷新
0 3 * * * cd /home/yuyang/frida-test/ths/api && python auth_manager.py auto-refresh >> /tmp/token_refresh.log 2>&1
```

### 3. 持久化Hook服务（可选）

**功能**：后台监听，自动捕获token

```bash
# 启动服务
cd /home/yuyang/frida-test/ths/api
nohup python start_persistent_hook.py > /tmp/frida_persistent.log 2>&1 &

# 检查状态
ps aux | grep start_persistent_hook

# 查看日志
tail -f /tmp/frida_persistent.log
```

**好处**：
- 只要App在运行，就能自动捕获token
- 无需手动进入基金页面
- 完全后台运行

## 🔍 工作流程详解

### 场景A: 手机连接 + JSBridge运行

```
1. 检测token即将过期（提前3天）
2. 检查手机连接 → ✅ 已连接
3. 检测App运行 → ✅ 运行中
4. 等待OkHttp捕获HTTP请求
5. 从JSBridge获取token → ✅ 成功
6. 更新auth_cache.json
7. ✅ 完成（手机端正常运行）
```

### 场景B: 手机连接 + JSBridge未运行

```
1. 检测token即将过期
2. 检查手机连接 → ✅ 已连接
3. 检测App运行 → ⚠️ 未运行或未捕获
4. 等待30秒 → ⚠️ 超时
5. 使用密码MD5登录 → ✅ 成功
6. ⚠️ 手机端被踢下线
7. ✅ Token已刷新（但手机需重新登录）
```

### 场景C: 手机未连接

```
1. 检测token即将过期
2. 检查手机连接 → ❌ 未连接
3. 直接使用密码MD5登录 → ✅ 成功
4. ⚠️ 手机端被踢下线
5. ✅ Token已刷新（但手机需重新登录）
```
